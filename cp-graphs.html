Graph Algorithms

Graph algorithms turn a network of nodes and connections into a structure you can systematically reason about, and a small toolkit of traversal ideas (BFS and DFS) underlies nearly everything here: shortest paths, spanning trees, orderings of dependencies, and the discovery of tightly-connected or fragile parts of a graph. Competitive programming rarely asks for these algorithms in their textbook form; instead a problem's real difficulty is usually in recognizing which algorithm the story is hiding, and in adapting it correctly (counting paths, forcing an edge, propagating a property, or combining it with a second algorithm like binary lifting or DSU). This page works through six core techniques — shortest paths, minimum spanning trees, topological sort, strongly connected components, bridges/articulation points, and bipartite checking — with an emphasis on the exact invariants that make each algorithm correct, since that is precisely where subtle bugs (especially in Tarjan-style low-link algorithms) creep in. Beyond shortest paths, MST, topological sort, SCC, bridges/articulation points, and bipartiteness, these subtopics round out the graph toolkit with boolean-constraint satisfaction (2-SAT), edge-covering tours (Euler paths/circuits), weight-aware and multi-origin breadth-first search (0/1 BFS and multi-source BFS), and the special structure of graphs where every node has exactly one outgoing edge (functional graphs).

Shortest Paths (Dijkstra, Bellman-Ford, Floyd-Warshall)

3 worked examples

Dijkstra's algorithm maintains a tentative distance for every vertex and repeatedly finalizes the unvisited vertex with the smallest tentative distance, then relaxes its outgoing edges. The correctness invariant is: once a vertex is popped from the priority queue with its minimal tentative distance, that distance is final and can never be improved later, because all edge weights are non-negative — any future path to it would have to pass through a vertex with a tentative distance already >= the one just finalized, and adding more non-negative weight can only increase it further. This greedy, cut-property-based argument breaks down completely in the presence of negative edges, which is exactly why Dijkstra requires non-negative weights. Implementation-wise, the standard approach pushes (distance, vertex) pairs into a binary-heap priority_queue and lazily discards stale entries (an entry whose stored distance no longer matches the current best distance for that vertex) rather than trying to decrease-key in place, which is simpler and still O((V+E) log V). For dense graphs (E close to V^2), a simple O(V^2) array scan for the minimum untouched vertex, without any heap, is actually faster in practice and asymptotically no worse.

Bellman-Ford relaxes every edge up to V-1 times: after k rounds, every shortest path using at most k edges is guaranteed to be correctly computed, and since a simple shortest path visits at most V-1 edges, V-1 rounds suffice whenever no negative cycle is reachable. Its major advantage over Dijkstra is that it handles negative edge weights, and a bonus (n-th) relaxation round doubles as a negative-cycle detector: if any edge can still be relaxed after V-1 rounds, a negative cycle exists that is reachable from the source. A common trap (as in the 'maximize path score with possible unbounded loop' family of problems) is that detecting *a* negative/positive cycle somewhere in the graph is not the same as detecting one that lies on a path from source to the specific target — the fix is to propagate an 'unbounded' flag forward along edges from every vertex where relaxation still succeeds in the bonus round, so only vertices actually reachable through the runaway cycle (and reachable further from it) get flagged.

Floyd-Warshall computes all-pairs shortest paths via dynamic programming over allowed intermediate vertices: dist[i][j] after considering intermediates {1..k} equals min(dist[i][j], dist[i][k]+dist[k][j]) using only intermediates {1..k-1}. It runs in O(V^3), so it is the right choice only when V is small (roughly up to a few hundred to a couple thousand depending on the time limit), but it is extremely convenient whenever you need distances between *every* pair of vertices, or whenever a problem's twist (like allowed edge-weight modifications) is most naturally expressed as a query over precomputed all-pairs distances.

Recognize it by

Single-source shortest paths with non-negative weights (the overwhelming majority of 'find the cheapest/fastest route' problems) is Dijkstra. As soon as a problem mentions negative weights, or asks you to detect whether a value can be made arbitrarily large/small along some path (an exploitable cycle), reach for Bellman-Ford. When a problem needs distances between many or all pairs of vertices and the vertex count is small, or when the twist requires combining forward and backward distances through an arbitrary edge (like 'what if we could improve one edge'), Floyd-Warshall's precomputed all-pairs table is the natural base to build on.

Complexity

Dijkstra: O((V+E) log V) with a binary heap, O(V^2 + E) with a plain array (better when the graph is dense). Bellman-Ford: O(V*E) time, O(V) space. Floyd-Warshall: O(V^3) time, O(V^2) space.

Shortest Distance and Path Count

Problem

You are given a directed graph with n nodes (1..n) and m weighted edges (all weights are positive integers), representing one-way roads between cities. Find the length of the shortest route from city 1 to city n, and also the number of distinct shortest routes, modulo 1,000,000,007. It is guaranteed city n is reachable from city 1.

Input: first line 'n m'. Next m lines: 'u v w' meaning a directed edge u->v of weight w.
Output: two integers on one line: the shortest distance, and the count of shortest paths mod 1e9+7.

Approach

Run Dijkstra from node 1 with a min-heap of (distance, node) pairs, but alongside dist[] also maintain cnt[] (number of shortest paths found so far). When popping a stale queue entry (its stored distance is worse than the current best for that node) skip it. When relaxing an edge (u -> v, w): if dist[u]+w gives a strictly smaller distance than the current dist[v], overwrite dist[v] and reset cnt[v] = cnt[u] (the old count is now irrelevant, it belonged to a longer path). If dist[u]+w exactly equals the current dist[v], this is an equally-short alternative path, so add cnt[u] into cnt[v] (mod 1e9+7). Because all weights are positive, vertices are finalized in non-decreasing order of distance, so by the time a vertex v is finalized, every path of that exact length that could contribute to cnt[v] has already been accounted for.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long MOD = 1000000007;
int main(){
    int n, m;
    cin >> n >> m;
    vector<vector<pair<int,long long>>> adj(n+1);
    for(int i=0;i<m;i++){
        int u,v; long long w;
        cin >> u >> v >> w;
        adj[u].push_back({v,w});
    }
    vector<long long> dist(n+1, LLONG_MAX);
    vector<long long> cnt(n+1, 0);
    dist[1]=0; cnt[1]=1;
    priority_queue<pair<long long,int>, vector<pair<long long,int>>, greater<>> pq;
    pq.push({0,1});
    while(!pq.empty()){
        auto [d,u] = pq.top(); pq.pop();
        if(d > dist[u]) continue; // stale entry
        for(auto [v,w] : adj[u]){
            long long nd = d + w;
            if(nd < dist[v]){
                dist[v] = nd;
                cnt[v] = cnt[u] % MOD;
                pq.push({nd, v});
            } else if(nd == dist[v]){
                cnt[v] = (cnt[v] + cnt[u]) % MOD;
            }
        }
    }
    cout << dist[n] << " " << cnt[n] << "\n";
}

Maximum Score Path with Runaway-Cycle Detection

Problem

A directed graph on n nodes has m directed edges, each with an integer weight that may be negative (think of it as a score gained by traversing that road). Find the maximum possible total score of a path from node 1 to node n. If there exists a positive-weight cycle that is both reachable from node 1 and can itself reach node n, the score can be made arbitrarily large; in that case print 'IMPOSSIBLE'.

Input: first line 'n m'. Next m lines: 'u v w' (edge u->v with weight w, possibly negative).
Output: the maximum score, or 'IMPOSSIBLE'.

Approach

This is Bellman-Ford adapted to maximize instead of minimize: relax every edge with dist[v] = max(dist[v], dist[u]+w) for n-1 rounds, which correctly computes the best score of any simple path. Then run one more full pass over all edges: any edge that can still improve its endpoint signals that endpoint lies on (or after) a cycle whose net weight is positive and that is still reachable from node 1 (otherwise dist[u] would never have been a finite, non-sentinel value at all). Mark such endpoints 'unbounded'. Since the runaway property must also propagate forward along further edges (a node reachable from an unbounded node inherits the unbounded property, because you can loop the cycle as many times as needed before continuing), repeat this propagation pass n times total, each time also treating 'unbounded[u] implies unbounded[v]' for every edge u->v. Finally, node n is reachable with unbounded score iff unbounded[n] is set; otherwise dist[n] is the answer.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long NEG_INF = LLONG_MIN / 2;
int main(){
    int n, m;
    cin >> n >> m;
    vector<array<long long,3>> edges(m); // u, v, w
    for(int i=0;i<m;i++){
        long long u,v,w; cin >> u >> v >> w;
        edges[i] = {u,v,w};
    }
    vector<long long> dist(n+1, NEG_INF);
    dist[1] = 0;
    // n-1 passes guarantee correct longest-path values in absence of positive cycles
    for(int i=0;i<n-1;i++){
        for(auto &e : edges){
            int u=e[0], v=e[1]; long long w=e[2];
            if(dist[u] > NEG_INF/2 && dist[u]+w > dist[v]) dist[v] = dist[u]+w;
        }
    }
    vector<char> unbounded(n+1, 0);
    // propagate: one more relaxation pass detects nodes still improvable (on/after a positive cycle);
    // repeat n times so the "unbounded" property propagates along any chain of edges of length < n
    for(int i=0;i<n;i++){
        for(auto &e : edges){
            int u=e[0], v=e[1]; long long w=e[2];
            if(dist[u] <= NEG_INF/2) continue;
            if(dist[u] + w > dist[v] || unbounded[u]){
                if(dist[u]+w > dist[v]) dist[v] = dist[u]+w;
                unbounded[v] = 1;
            }
        }
    }
    if(unbounded[n]) cout << "IMPOSSIBLE\n";
    else cout << dist[n] << "\n";
}

Best Distance After Halving One Edge

Problem

An undirected weighted graph has n vertices and m edges (all weights guaranteed even, so halved weights are integers), and two fixed vertices s and t. You may choose at most one edge and halve its weight (or choose none). Find the minimum possible distance from s to t after this single optional change.

Input: first line 'n m s t'. Next m lines: 'a b w' (undirected edge between a and b, weight w).
Output: a single integer, the minimum achievable distance from s to t.

Approach

First run Floyd-Warshall once on the unmodified graph to get all-pairs shortest distances d[i][j]. It can be shown that an optimal solution uses the halved edge at most once along the chosen path, so for every edge (a,b,w) the best distance achievable *if that edge is the one halved* is min( d[s][a] + w/2 + d[b][t], d[s][b] + w/2 + d[a][t] ) — go from s to one endpoint using ordinary shortest paths, cross the halved edge, then continue from the other endpoint to t using ordinary shortest paths. The overall answer is the minimum of the unmodified d[s][t] and this quantity taken over every edge.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long INF = LLONG_MAX/4;
int main(){
    int n, m; long long s, t;
    cin >> n >> m >> s >> t;
    vector<vector<long long>> d(n+1, vector<long long>(n+1, INF));
    for(int i=1;i<=n;i++) d[i][i]=0;
    vector<array<long long,3>> edges(m);
    for(int i=0;i<m;i++){
        long long a,b,w; cin >> a >> b >> w;
        edges[i]={a,b,w};
        d[a][b] = min(d[a][b], w);
        d[b][a] = min(d[b][a], w);
    }
    for(int k=1;k<=n;k++)
        for(int i=1;i<=n;i++)
            for(int j=1;j<=n;j++)
                if(d[i][k]+d[k][j] < d[i][j]) d[i][j] = d[i][k]+d[k][j];

    long long best = d[s][t];
    for(auto &e : edges){
        long long a=e[0], b=e[1], w=e[2];
        long long half = w/2; // weights are given even, so this is exact
        best = min(best, d[s][a] + half + d[b][t]);
        best = min(best, d[s][b] + half + d[a][t]);
    }
    cout << best << "\n";
}

Minimum Spanning Tree (Kruskal, Prim)

3 worked examples

A minimum spanning tree connects all vertices of a connected, weighted, undirected graph using exactly V-1 edges of minimum possible total weight. Both classic algorithms are greedy, and their correctness rests on two equivalent facts: the cut property (for any partition of the vertices into two non-empty sets, the minimum-weight edge crossing the cut belongs to *some* MST) and the cycle property (the maximum-weight edge on any cycle never belongs to *any* MST, unless there's a tie). Kruskal's algorithm sorts all edges by weight and greedily adds an edge if and only if its two endpoints are currently in different components, using a Disjoint Set Union (DSU) structure to test and merge components in near-constant amortized time; this is a direct application of the cycle property, since skipping an edge that would close a cycle is always safe. Prim's algorithm instead grows a single tree from an arbitrary start vertex, at each step adding the minimum-weight edge that connects the current tree to a vertex outside it — a direct application of the cut property, with the cut being (tree so far, everything else).

The choice between them is mostly about representation and secondary needs. Kruskal's is O(E log E) (dominated by the sort) and works naturally off an edge list, which makes it easy to extend — for example, feeding a single non-tree edge into the union-find *before* running the greedy pass over the rest is a clean way to compute 'the minimum spanning tree forced to include this particular edge' for many query edges. Prim's is more natural on a dense graph given as an adjacency matrix, where the O(V^2) array-scan version (repeatedly picking the closest unvisited vertex, no heap at all) beats Kruskal's sort for E close to V^2; on sparse graphs, a binary-heap version of Prim's runs in O((V+E) log V), about the same as Kruskal's.

Recognize it by

Any problem phrased as 'connect all these points/cities/computers with minimum total cost of cables/roads', or 'minimum cost to make the graph connected', is an MST problem. If the underlying graph is dense and given as a full distance/cost matrix (e.g., all pairwise Euclidean distances between points), prefer the O(V^2) array-based Prim's. If the graph is sparse and given as an edge list, or if you need to process edges individually (sort once, reuse the ordering for multiple queries), prefer Kruskal's with DSU.

Complexity

Kruskal's: O(E log E) for the sort plus near-O(E) for E α(V) DSU operations. Prim's: O(V^2) with a plain array (good for dense graphs), O((V+E) log V) with a binary heap (good for sparse graphs).

Minimum Spanning Tree Weight (Kruskal)

Problem

Given an undirected, connected, weighted graph with n vertices and m edges, find the total weight of a minimum spanning tree.

Input: first line 'n m'. Next m lines: 'a b w' (undirected edge between a and b with weight w).
Output: a single integer, the total MST weight (or 'IMPOSSIBLE' if the graph is not connected).

Approach

Sort all m edges by weight ascending. Initialize a DSU with each vertex in its own set. Walk the sorted edges in order; for each edge, if its two endpoints are in different DSU components, union them and add its weight to the running total. Stop early (or just keep going) until n-1 edges have been added. If fewer than n-1 edges were ever added, the graph was disconnected.

Solution
#include <bits/stdc++.h>
using namespace std;
struct DSU{
    vector<int> p, r;
    DSU(int n): p(n+1), r(n+1,0){ iota(p.begin(), p.end(), 0); }
    int find(int x){ return p[x]==x ? x : p[x]=find(p[x]); }
    bool unite(int a, int b){
        a=find(a); b=find(b);
        if(a==b) return false;
        if(r[a]<r[b]) swap(a,b);
        p[b]=a;
        if(r[a]==r[b]) r[a]++;
        return true;
    }
};
int main(){
    int n, m;
    cin >> n >> m;
    vector<array<long long,3>> edges(m);
    for(int i=0;i<m;i++){
        long long a,b,w; cin >> a >> b >> w;
        edges[i] = {w,a,b};
    }
    sort(edges.begin(), edges.end());
    DSU dsu(n);
    long long total = 0;
    int used = 0;
    for(auto &e : edges){
        long long w=e[0], a=e[1], b=e[2];
        if(dsu.unite(a,b)){
            total += w;
            used++;
        }
    }
    if(used == n-1) cout << total << "\n";
    else cout << "IMPOSSIBLE\n";
}

MST on a Dense Graph (Prim's, O(V^2))

Problem

Given an undirected, connected, weighted graph with n vertices and m edges (n is small enough that the graph may be dense), find the total weight of a minimum spanning tree.

Input: first line 'n m'. Next m lines: 'a b w'.
Output: a single integer, the total MST weight (or 'IMPOSSIBLE' if disconnected).

Approach

Build a dense adjacency matrix (INF where no direct edge exists, keeping the minimum weight on parallel edges). Maintain minEdge[v] = the cheapest edge weight connecting v to the tree built so far (initialized to infinity except the start vertex, which is 0), and a boolean inMST[] array. Repeat n times: scan all vertices with a plain linear loop to find the not-yet-included vertex with the smallest minEdge value, add it to the tree, add its minEdge value to the total, then relax minEdge[] for every other vertex using the newly added vertex's row of the matrix. This avoids any heap entirely, which is faster than Kruskal's sort when the graph is dense (E close to V^2).

Solution
#include <bits/stdc++.h>
using namespace std;
const long long INF = LLONG_MAX/4;
int main(){
    int n, m;
    cin >> n >> m;
    vector<vector<long long>> g(n+1, vector<long long>(n+1, INF));
    for(int i=0;i<m;i++){
        int a,b; long long w;
        cin >> a >> b >> w;
        g[a][b] = min(g[a][b], w);
        g[b][a] = min(g[b][a], w);
    }
    vector<long long> minEdge(n+1, INF);
    vector<char> inMST(n+1, 0);
    minEdge[1] = 0;
    long long total = 0;
    int count = 0;
    for(int iter=0; iter<n; iter++){
        int u = -1;
        for(int v=1; v<=n; v++){
            if(!inMST[v] && (u==-1 || minEdge[v] < minEdge[u])) u = v;
        }
        if(minEdge[u] == INF){ count = -1; break; } // unreachable -> not connected
        inMST[u] = 1;
        total += minEdge[u];
        count++;
        for(int v=1; v<=n; v++){
            if(!inMST[v] && g[u][v] < minEdge[v]) minEdge[v] = g[u][v];
        }
    }
    if(count == n) cout << total << "\n";
    else cout << "IMPOSSIBLE\n";
}

Minimum Spanning Tree Forced Through Each Edge

Problem

Given a connected, weighted, undirected graph with n vertices and m edges, for every edge in the input (in the order given), compute the minimum possible total weight of a spanning tree that is required to include that specific edge.

Input: first line 'n m'. Next m lines: 'a b w'.
Output: m integers on one line, the answer for each edge in input order.

Approach

Pre-sort the edge indices by weight once. For each query edge e = (a,b,w): start a fresh DSU, immediately union(a,b) and add w to the running total (forcing e into the tree first) — this is safe by the same cut/cycle-property argument that justifies Kruskal's greedy choice, just seeded with one mandatory edge instead of starting from nothing. Then continue Kruskal's algorithm as normal over the remaining edges in the pre-sorted order (skipping edge e itself), adding any edge that connects two different components, until n-1 edges are used. Repeating this independently for every query edge is O(m) DSU-Kruskal passes, i.e. O(m * (n + m α(n))), which is fine for modest n, m; a competitive-programming-hard version of this problem instead reuses one base MST plus binary lifting over the tree to answer each query in O(log n).

Solution
#include <bits/stdc++.h>
using namespace std;
struct DSU{
    vector<int> p, r;
    DSU(int n): p(n+1), r(n+1,0){ iota(p.begin(), p.end(), 0); }
    int find(int x){ return p[x]==x ? x : p[x]=find(p[x]); }
    bool unite(int a, int b){
        a=find(a); b=find(b);
        if(a==b) return false;
        if(r[a]<r[b]) swap(a,b);
        p[b]=a;
        if(r[a]==r[b]) r[a]++;
        return true;
    }
};
int main(){
    int n, m;
    cin >> n >> m;
    // store as (w, a, b) plus original index
    vector<array<long long,3>> edges(m);
    for(int i=0;i<m;i++){
        long long a,b,w; cin >> a >> b >> w;
        edges[i] = {w,a,b};
    }
    // sorted order of edge indices by weight, used for every query
    vector<int> order(m);
    iota(order.begin(), order.end(), 0);
    sort(order.begin(), order.end(), [&](int i, int j){ return edges[i][0] < edges[j][0]; });

    vector<long long> answers(m);
    for(int q=0; q<m; q++){
        DSU dsu(n);
        long long total = edges[q][0];
        dsu.unite((int)edges[q][1], (int)edges[q][2]);
        int used = 1;
        for(int idx : order){
            if(idx == q) continue;
            long long w=edges[idx][0], a=edges[idx][1], b=edges[idx][2];
            if(dsu.unite((int)a,(int)b)){
                total += w;
                used++;
            }
        }
        answers[q] = (used == n-1) ? total : -1; // -1 would mean graph disconnected without this edge helping
    }
    for(int i=0;i<m;i++){
        cout << answers[i] << (i+1<m ? ' ' : '\n');
    }
}

Topological Sort

3 worked examples

A topological order of a directed acyclic graph (DAG) is a linear ordering of its vertices such that for every directed edge u -> v, u appears before v. Such an ordering exists if and only if the graph has no directed cycle. Two standard algorithms compute it, and both double as cycle detectors. Kahn's algorithm is BFS-based: compute the in-degree of every vertex, put all in-degree-zero vertices in a queue (a vertex with in-degree zero has no unmet prerequisite, so it's always safe to place next), and repeatedly pop a vertex, append it to the output, and decrement the in-degree of each of its neighbors, pushing any neighbor whose in-degree just hit zero. If the total number of vertices ever output is less than V, the remaining vertices form at least one cycle (they can never reach in-degree zero because their prerequisites are all mutually blocking each other) and no topological order exists.

The DFS-based algorithm instead runs a standard DFS while 3-coloring vertices white (unvisited) / gray (currently on the recursion stack) / black (fully finished), and prepends each vertex to the output the moment it finishes (equivalently, appends to a list and reverses at the end). This works because a vertex only finishes after every vertex reachable from it has already finished, so in the reversed finish order every edge correctly points from an earlier vertex to a later one. A cycle is detected the instant DFS encounters an edge to a gray vertex — a 'back edge' to a vertex that is a live ancestor in the current recursion stack, as opposed to an edge to a black vertex (a 'cross' or 'forward' edge to an already-finished, unrelated part of the graph), which is completely normal and not a cycle.

Beyond producing an ordering, topological sort's most important use in competitive programming is as scaffolding for dynamic programming on a DAG: once vertices are linearized so that every edge goes from an earlier to a later position, any 'longest/shortest/count paths' recurrence over the DAG can be computed with one linear pass in that order, because by the time you process a vertex, every predecessor's DP value is already final.

Recognize it by

Problems about scheduling with prerequisites, build/compile order, course ordering, or any 'must happen before' directed constraint set are direct applications. If a problem instead asks for a longest/shortest path, or a count/number-of-ways, in a graph that is guaranteed (or provably must be) acyclic, that is a strong signal to topologically sort first and then run a simple DP pass over the order. If a problem asks you to detect whether a set of directed constraints is even satisfiable, that's exactly cycle detection via a failed topological sort.

Complexity

O(V+E) time and O(V) extra space for both Kahn's and the DFS-based algorithm.

Deterministic Course Ordering (Kahn's Algorithm)

Problem

There are n courses (1..n) and m prerequisite pairs 'u v' meaning course u must be taken before course v. Output a valid course order. If multiple valid orders exist, output the lexicographically smallest one. If no valid order exists (a cyclic prerequisite chain), print 'IMPOSSIBLE'.

Input: first line 'n m'. Next m lines: 'u v'.
Output: n space-separated course numbers forming a valid order (lexicographically smallest among all valid orders), or 'IMPOSSIBLE'.

Approach

Standard Kahn's algorithm, but using a min-heap instead of a plain queue: always expand the smallest-numbered available (in-degree zero) vertex first. This greedy tie-break is exactly what produces the lexicographically smallest topological order, because at every step you are choosing the smallest label among all currently legal next choices. If fewer than n vertices are ever popped, some vertices' in-degrees never reach zero, meaning a cycle exists among them.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, m;
    cin >> n >> m;
    vector<vector<int>> adj(n+1);
    vector<int> indeg(n+1, 0);
    for(int i=0;i<m;i++){
        int u,v; cin >> u >> v;
        adj[u].push_back(v);
        indeg[v]++;
    }
    priority_queue<int, vector<int>, greater<int>> pq; // smallest label first -> deterministic order
    for(int v=1; v<=n; v++) if(indeg[v]==0) pq.push(v);
    vector<int> order;
    while(!pq.empty()){
        int u = pq.top(); pq.pop();
        order.push_back(u);
        for(int v : adj[u]){
            if(--indeg[v]==0) pq.push(v);
        }
    }
    if((int)order.size() != n){
        cout << "IMPOSSIBLE\n";
    } else {
        for(int i=0;i<n;i++) cout << order[i] << (i+1<n?' ':'\n');
    }
}

Feasibility of a Build Order (DFS-based, Cycle Detection)

Problem

A build system has n targets (1..n) and m directed dependency edges 'u v' meaning target u must be built before target v. Determine whether a valid build order exists at all; if the dependencies are cyclic, print 'IMPOSSIBLE'.

Input: first line 'n m'. Next m lines: 'u v'.
Output: 'IMPOSSIBLE' if the dependency graph has a cycle; otherwise a valid build order (any one is accepted, here produced by DFS-based topological sort).

Approach

Run DFS from every unvisited vertex 1..n in order, 3-coloring each vertex white/gray/black. When exploring an edge to a vertex that is currently gray (still on the recursion stack, i.e. a live ancestor), a cycle has been found — this is the critical distinction from an edge to an already-black vertex, which is just a harmless cross edge to a finished subtree and must NOT be flagged as a cycle. On finishing a vertex (all its neighbors explored), push it onto a postorder list; reversing that list at the end gives a valid topological order whenever no cycle was found.

Solution
#include <bits/stdc++.h>
using namespace std;
int n, m;
vector<vector<int>> adj;
vector<int> color_; // 0 = white (unvisited), 1 = gray (on stack), 2 = black (done)
vector<int> postorder;
bool cyclic = false;

void dfs(int u){
    color_[u] = 1; // gray: currently in the recursion stack
    for(int v : adj[u]){
        if(cyclic) return;
        if(color_[v] == 1){
            cyclic = true; // back edge to an ancestor -> cycle
            return;
        }
        if(color_[v] == 0) dfs(v);
    }
    color_[u] = 2; // black: fully explored
    postorder.push_back(u);
}

int main(){
    cin >> n >> m;
    adj.assign(n+1, {});
    color_.assign(n+1, 0);
    for(int i=0;i<m;i++){
        int u,v; cin >> u >> v;
        adj[u].push_back(v);
    }
    for(int s=1; s<=n && !cyclic; s++){
        if(color_[s]==0) dfs(s);
    }
    if(cyclic){
        cout << "IMPOSSIBLE\n";
    } else {
        reverse(postorder.begin(), postorder.end());
        for(int i=0;i<n;i++) cout << postorder[i] << (i+1<n?' ':'\n');
    }
}

Longest Weighted Path in a DAG

Problem

Given a directed acyclic graph with n vertices and m weighted edges, and two vertices src and dst, find the length (maximum total edge weight) of the longest path from src to dst. If dst is unreachable from src, print 'UNREACHABLE'.

Input: first line 'n m src dst'. Next m lines: 'u v w' (edge u->v with weight w).
Output: the maximum total weight of a src -> dst path, or 'UNREACHABLE'.

Approach

Topologically sort the DAG with Kahn's algorithm (the vertex numbering is deliberately not already in topological order, to make clear the sort is doing real work). Initialize dist[src]=0 and every other dist[v] to -infinity. Sweep vertices in topological order; for each vertex u with a finite dist[u], relax every outgoing edge (u,v,w) with dist[v] = max(dist[v], dist[u]+w). Because the sweep order guarantees every predecessor of a vertex is processed before it, dist[v] is guaranteed final by the time v itself is processed.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long NEG_INF = LLONG_MIN/2;
int main(){
    int n, m, src, dst;
    cin >> n >> m >> src >> dst;
    vector<vector<pair<int,long long>>> adj(n+1);
    vector<int> indeg(n+1, 0);
    for(int i=0;i<m;i++){
        int u,v; long long w;
        cin >> u >> v >> w;
        adj[u].push_back({v,w});
        indeg[v]++;
    }
    queue<int> q;
    for(int v=1; v<=n; v++) if(indeg[v]==0) q.push(v);
    vector<int> topo;
    vector<int> indeg2 = indeg;
    while(!q.empty()){
        int u = q.front(); q.pop();
        topo.push_back(u);
        for(auto &pr : adj[u]){
            int v = pr.first;
            if(--indeg2[v]==0) q.push(v);
        }
    }
    vector<long long> dist(n+1, NEG_INF);
    dist[src] = 0;
    for(int u : topo){
        if(dist[u] == NEG_INF) continue;
        for(auto &pr : adj[u]){
            int v = pr.first; long long w = pr.second;
            if(dist[u] + w > dist[v]) dist[v] = dist[u] + w;
        }
    }
    if(dist[dst] == NEG_INF) cout << "UNREACHABLE\n";
    else cout << dist[dst] << "\n";
}

Strongly Connected Components (Tarjan's Algorithm)

2 worked examples

A strongly connected component (SCC) of a directed graph is a maximal set of vertices such that every vertex in the set can reach every other vertex in the set via directed edges. Tarjan's algorithm finds all SCCs in a single DFS pass using two values per vertex: disc[u], the order in which u was first visited, and low[u], defined as the smallest disc[] value reachable from u's DFS subtree using at most one 'back edge' to a vertex that is still active (i.e. on the explicit stack of visited-but-not-yet-finalized vertices). The algorithm maintains this explicit stack with an onStack[] boolean array; when DFS from u explores a neighbor v: if v is unvisited, recurse into it as a tree edge and fold low[v] into low[u]; if v is already visited AND currently on the stack, this is a back edge to a live ancestor (or to another vertex in the same still-forming SCC), so fold disc[v] (not low[v]) into low[u]; if v is visited but no longer on the stack, it belongs to an already-completed, different SCC, and must be ignored entirely for low-link purposes.

That third case — visited-but-off-stack — is the single most common source of bugs: forgetting the onStack check causes the algorithm to incorrectly merge unrelated, already-finished components. The termination condition low[u] == disc[u] identifies u as the root of its SCC: nothing in u's subtree can reach any vertex discovered before u, so the SCC is complete and can be popped off the stack down to and including u. Because every vertex is pushed once, popped once, and every edge examined once, the whole algorithm runs in O(V+E). SCCs are produced in reverse topological order of the condensation graph (the DAG formed by contracting each SCC to a single node) — a useful fact when an algorithm needs to process components in dependency order afterward. Kosaraju's algorithm is the classic alternative: DFS the original graph to get a finishing order, then DFS the *reverse* graph strictly in decreasing finishing order, and each resulting DFS tree is one SCC; it needs two full graph traversals instead of one but is conceptually simpler to reason about.

Recognize it by

Whenever a directed graph problem asks about mutual reachability, cycles that aren't simply 'any cycle' but 'the full set of vertices reachable both ways', or asks you to contract the graph into a DAG before applying a second algorithm (topological sort, longest path, counting sources/sinks), SCC decomposition is the right first step. It is also the standard tool underlying 2-SAT (build an implication graph, and a variable's assignment is infeasible exactly when x and not-x land in the same SCC).

Complexity

Tarjan's: O(V+E) time and space, single DFS pass. Kosaraju's: O(V+E) time and space, but requires two DFS passes (one on G, one on the transpose graph).

Finding All Strongly Connected Components

Problem

Given a directed graph with n vertices and m edges, find all of its strongly connected components.

Input: first line 'n m'. Next m lines: 'u v' (directed edge u -> v).
Output: first line the number of SCCs. Then one line per SCC, listing its member vertices in increasing order, with SCCs printed in the order Tarjan's algorithm completes them (reverse topological order of the condensation graph).

Approach

Run Tarjan's algorithm exactly as described in the theory: DFS from every unvisited vertex 1..n, tracking disc[]/low[]/onStack[] and an explicit stack. Whenever a vertex u satisfies low[u]==disc[u] after exploring all its outgoing edges, pop the stack down to and including u; that popped set is one complete SCC (sort it for a clean, deterministic printout). Because DFS explores neighbors in the order edges were given, and starts from vertex 1, the resulting sequence of completed SCCs is fully deterministic.

Solution
#include <bits/stdc++.h>
using namespace std;
int n, m, timer_ = 0;
vector<vector<int>> adj;
vector<int> disc, low;
vector<char> onStack;
vector<int> st;
vector<vector<int>> sccs;

void dfs(int u){
    disc[u] = low[u] = timer_++;
    st.push_back(u);
    onStack[u] = 1;
    for(int v : adj[u]){
        if(disc[v] == -1){
            dfs(v);
            low[u] = min(low[u], low[v]);
        } else if(onStack[v]){
            low[u] = min(low[u], disc[v]);
        }
    }
    if(low[u] == disc[u]){
        vector<int> comp;
        while(true){
            int w = st.back(); st.pop_back();
            onStack[w] = 0;
            comp.push_back(w);
            if(w == u) break;
        }
        sort(comp.begin(), comp.end());
        sccs.push_back(comp);
    }
}

int main(){
    cin >> n >> m;
    adj.assign(n+1, {});
    disc.assign(n+1, -1);
    low.assign(n+1, 0);
    onStack.assign(n+1, 0);
    for(int i=0;i<m;i++){
        int u,v; cin >> u >> v;
        adj[u].push_back(v);
    }
    for(int s=1;s<=n;s++) if(disc[s]==-1) dfs(s);

    cout << sccs.size() << "\n";
    for(auto &c : sccs){
        for(size_t i=0;i<c.size();i++) cout << c[i] << (i+1<c.size() ? ' ' : '\n');
    }
}

Minimum Roads to Reach Every City from the Capital

Problem

A country has n cities and m one-way roads, with city 'capital' as the capital. Find the minimum number of new one-way roads that must be added so that every city becomes reachable from the capital.

Input: first line 'n m capital'. Next m lines: 'u v' (one-way road u -> v).
Output: a single integer, the minimum number of roads to add.

Approach

Condense the graph into its SCCs using Tarjan's algorithm, assigning each vertex a component id. Build the condensation DAG's edges (deduplicated) and compute each component's in-degree within that DAG. Any component other than the capital's own component that has in-degree zero in the condensation DAG can only ever be reached by adding a brand-new direct road into it (nothing already reaches it), so the answer is exactly the count of such zero-in-degree components, excluding the capital's own component (which needs no incoming road since we start there).

Solution
#include <bits/stdc++.h>
using namespace std;
int n, m, timer_ = 0, capital;
vector<vector<int>> adj;
vector<int> disc, low, comp;
vector<char> onStack;
vector<int> st;
int numComp = 0;

void dfs(int u){
    disc[u] = low[u] = timer_++;
    st.push_back(u);
    onStack[u] = 1;
    for(int v : adj[u]){
        if(disc[v] == -1){
            dfs(v);
            low[u] = min(low[u], low[v]);
        } else if(onStack[v]){
            low[u] = min(low[u], disc[v]);
        }
    }
    if(low[u] == disc[u]){
        while(true){
            int w = st.back(); st.pop_back();
            onStack[w] = 0;
            comp[w] = numComp;
            if(w == u) break;
        }
        numComp++;
    }
}

int main(){
    cin >> n >> m >> capital;
    adj.assign(n+1, {});
    disc.assign(n+1, -1);
    low.assign(n+1, 0);
    onStack.assign(n+1, 0);
    comp.assign(n+1, -1);
    vector<pair<int,int>> edges(m);
    for(int i=0;i<m;i++){
        int u,v; cin >> u >> v;
        edges[i] = {u,v};
        adj[u].push_back(v);
    }
    for(int s=1;s<=n;s++) if(disc[s]==-1) dfs(s);

    vector<int> indeg(numComp, 0);
    set<pair<int,int>> condEdges;
    for(auto &e : edges){
        int cu = comp[e.first], cv = comp[e.second];
        if(cu != cv) condEdges.insert({cu,cv});
    }
    for(auto &e : condEdges) indeg[e.second]++;

    int capComp = comp[capital];
    int answer = 0;
    for(int c=0;c<numComp;c++){
        if(c != capComp && indeg[c]==0) answer++;
    }
    cout << answer << "\n";
}

Bridges and Articulation Points

3 worked examples

Bridges and articulation points describe the fragile parts of an undirected connected graph: a bridge is an edge whose removal disconnects the graph (increases the number of connected components), and an articulation point (cut vertex) is a vertex whose removal does the same. Both are found with a single DFS using the same disc[]/low[] machinery as Tarjan's SCC algorithm, but simpler, since undirected graphs need no explicit stack or onStack tracking — low[u] here just means 'the smallest disc[] value reachable from u's subtree using at most one back edge to an ancestor'. For a DFS tree edge (u, v) where v is a child of u, that edge is a bridge exactly when low[v] > disc[u]: nothing in v's subtree (including v itself) has any way back to u or to any of u's ancestors except through this one edge, so removing it truly severs the subtree. A non-root vertex u is an articulation point if it has some DFS-tree child v with low[v] >= disc[u] (note: >=, not >, since even reaching u itself, but not past u, is enough to make u the sole connector for that subtree). The DFS root is a special case: it is an articulation point if and only if it has two or more children in the DFS tree, since the root has no parent to disconnect from — its subtrees only ever connect to each other through the root itself.

A classic implementation bug is skipping the 'edge back to parent' using the parent's vertex id; if there are multiple parallel edges between u and its parent, that incorrectly treats a genuine back edge (through a *different* parallel edge) as the trivial parent edge and silently misses a back-connection, which can turn a real bridge into a false one. The robust fix is to track the *edge id* used to reach the parent and skip only that exact edge, not every edge to the parent vertex. Bridges and articulation points also compose naturally with a follow-up union-find pass: contracting every non-bridge edge (union its endpoints) and counting the resulting distinct components gives the graph's 2-edge-connected components — maximal subgraphs with no internal bridge — which form a tree once bridges are the only edges left between them.

Recognize it by

'Critical connections', 'find every edge/server whose failure disconnects the network', 'single point of failure', or any robustness/reliability framing on an undirected connected graph. If a problem asks about the structure that remains after removing all fragile edges (2-edge-connected components) or wants a bridge tree to run further algorithms on, this is also the starting point.

Complexity

O(V+E) time, one DFS pass; O(V) extra space for disc[]/low[] and the recursion stack.

Critical Connections in a Network

Problem

A network of n servers (1..n) is connected by m bidirectional links, forming a connected undirected graph. Find every 'critical connection': a link whose removal would disconnect the network (i.e. every bridge).

Input: first line 'n m'. Next m lines: 'a b' (an undirected link between a and b).
Output: first line the number of bridges. Then one line per bridge 'a b' (with a<b), sorted.

Approach

DFS from any vertex, tracking disc[]/low[] and, for each adjacency entry, the id of the edge used to reach it (so the traversal can skip exactly the edge it arrived on, not just any edge to the same parent vertex — important for correctness with multi-edges). For a tree edge (u,v), after the recursive call to v returns, check whether low[v] > disc[u]; if so, (u,v) is a bridge. For a non-tree edge to an already-visited vertex, fold in disc[] (not low[]) of that vertex, since it's a direct back edge.

Solution
#include <bits/stdc++.h>
using namespace std;
int n, m, timer_ = 0;
vector<vector<pair<int,int>>> adj; // (neighbor, edge id)
vector<int> disc, low;
vector<pair<int,int>> bridges;

void dfs(int u, int parentEdge){
    disc[u] = low[u] = timer_++;
    for(auto &[v, id] : adj[u]){
        if(id == parentEdge) continue; // don't walk back along the edge we arrived on
        if(disc[v] == -1){
            dfs(v, id);
            low[u] = min(low[u], low[v]);
            if(low[v] > disc[u]){
                bridges.push_back({min(u,v), max(u,v)});
            }
        } else {
            low[u] = min(low[u], disc[v]); // back edge: use disc[v], not low[v]
        }
    }
}

int main(){
    cin >> n >> m;
    adj.assign(n+1, {});
    disc.assign(n+1, -1);
    low.assign(n+1, 0);
    for(int i=0;i<m;i++){
        int u,v; cin >> u >> v;
        adj[u].push_back({v,i});
        adj[v].push_back({u,i});
    }
    for(int s=1;s<=n;s++) if(disc[s]==-1) dfs(s, -1);

    sort(bridges.begin(), bridges.end());
    cout << bridges.size() << "\n";
    for(auto &[a,b] : bridges) cout << a << " " << b << "\n";
}

Finding Articulation Points

Problem

Input: first line 'n m'. Next m lines: 'a b'.
Output: first line the number of articulation points. Then their labels in increasing order on the second line.

Approach

Run the same disc[]/low[] DFS, additionally counting DFS-tree children of the root. For a non-root vertex u with a DFS-tree child v, mark u as an articulation point if low[v] >= disc[u] (note the DFS may find this true for more than one child, but u should only be counted once). #include <bits/stdc++.h>
using namespace std;
int n, m, timer_ = 0;
vector<vector<pair<int,int>>> adj; // (neighbor, edge id)
vector<int> disc, low;
vector<char> isAP;

void dfs(int u, int parentEdge, bool isRoot){
    disc[u] = low[u] = timer_++;
    int children = 0;
    for(auto &[v, id] : adj[u]){
        if(id == parentEdge) continue;
        if(disc[v] == -1){

            dfs(v, id, false);
            low[u] = min(low[u], low[v]);

        adj[u].push_back({v,i});
        adj[v].push_back({u,i});

    for(int s=1;s<=n;s++) if(disc[s]==-1) dfs(s, -1, true);

    vector<int> result;
    for(int v=1;v<=n;v++) if(isAP[v]) result.push_back(v);
    cout << result.size() << "\n";
    for(size_t i=0;i<result.size();i++) cout << result[i] << (i+1<result.size()?' ':'\n');
}

Counting 2-Edge-Connected Components

Problem

Given a connected undirected graph with n vertices and m edges, find the number of 2-edge-connected components: the maximal groups of vertices you get by repeatedly contracting every non-bridge edge (equivalently, the pieces left over once every bridge is 'cut').

Input: first line 'n m'. Next m lines: 'a b'.
Output: a single integer, the number of 2-edge-connected components.

Approach

First find all bridges exactly as before (DFS with disc[]/low[], flagging bridge edges by their edge id rather than by endpoint pair, since a graph could in principle have a repeated (a,b) pair where only one copy is a bridge). Then build a fresh DSU over the n vertices and union the endpoints of every edge that is NOT a bridge. The number of distinct DSU roots among all n vertices is the answer: each 2-edge-connected component collapses to one root, and the only edges left uncontracted (the bridges) connect these roots in a tree structure.

Solution
#include <bits/stdc++.h>
using namespace std;
int n, m, timer_ = 0;
vector<vector<pair<int,int>>> adj; // (neighbor, edge id)
vector<int> disc, low;
vector<char> isBridge;
vector<pair<int,int>> edgeList;

void dfs(int u, int parentEdge){
    disc[u] = low[u] = timer_++;
    for(auto &[v, id] : adj[u]){
        if(id == parentEdge) continue;
        if(disc[v] == -1){
            dfs(v, id);
            low[u] = min(low[u], low[v]);
            if(low[v] > disc[u]) isBridge[id] = 1;
        } else {
            low[u] = min(low[u], disc[v]);
        }
    }
}

struct DSU{
    vector<int> p;
    DSU(int n): p(n+1){ iota(p.begin(), p.end(), 0); }
    int find(int x){ return p[x]==x ? x : p[x]=find(p[x]); }
    void unite(int a, int b){ a=find(a); b=find(b); if(a!=b) p[a]=b; }
};

int main(){
    cin >> n >> m;
    adj.assign(n+1, {});
    disc.assign(n+1, -1);
    low.assign(n+1, 0);
    isBridge.assign(m, 0);
    edgeList.resize(m);
    for(int i=0;i<m;i++){
        int u,v; cin >> u >> v;
        edgeList[i] = {u,v};
        adj[u].push_back({v,i});
        adj[v].push_back({u,i});
    }
    for(int s=1;s<=n;s++) if(disc[s]==-1) dfs(s, -1);

    DSU dsu(n);
    for(int i=0;i<m;i++){
        if(!isBridge[i]) dsu.unite(edgeList[i].first, edgeList[i].second);
    }
    set<int> roots;
    for(int v=1; v<=n; v++) roots.insert(dsu.find(v));
    cout << roots.size() << "\n";
}

Bipartite Check

2 worked examples

An undirected graph is bipartite if and only if its vertices can be split into two groups such that every edge connects vertices from different groups — equivalently, if and only if it contains no odd-length cycle. This is checked with a simple BFS or DFS 2-coloring: pick an uncolored vertex, color it 0, then color every neighbor the opposite color of its parent, propagating outward. If the traversal ever reaches an edge whose two endpoints already carry the same color, that edge (together with the two colored paths from the common ancestor to each endpoint) forms an odd cycle, and the graph is not bipartite. Because a graph may be disconnected, this coloring must be restarted from a fresh uncolored vertex for every remaining component; the answer is 'bipartite' only if no component ever produces a conflict.

Beyond a yes/no answer, the produced 2-coloring is itself useful: it is the starting point for bipartite matching algorithms (Hopcroft-Karp, Hungarian algorithm), and it can be used to force a canonical structure onto the graph — for example, consistently orienting every edge from the color-0 endpoint to the color-1 endpoint guarantees that no directed path of two or more edges can exist, since every color-1 vertex then has only incoming edges and every color-0 vertex only outgoing ones (any two consecutive edges would need to pass through a middle vertex with both an incoming and an outgoing edge, which the coloring forbids). Proving that such a valid orientation is even possible if and only if the graph is bipartite is usually the real content of such a problem — the coloring/construction itself is routine once that insight is in hand.

Recognize it by

'Can the elements be split into two groups with no relationship inside a group', 'is this graph 2-colorable', conflict/incompatibility graphs, or any problem hinting at an odd-cycle obstruction. It is also a mandatory feasibility pre-check before applying any bipartite-matching algorithm, and a common building block: whenever a construction needs 'no edge/path can go too far in one direction', check whether the underlying constraint graph is bipartite first.

Complexity

O(V+E) time and space — one BFS/DFS traversal with an added color array.

Bipartite Check on a Graph with Multiple Components

Problem

Given an undirected graph with n vertices and m edges (possibly disconnected), determine whether it is bipartite. If it is, output a valid 2-coloring.

Input: first line 'n m'. Next m lines: 'a b'.
Output: 'YES' followed by n space-separated 0/1 colors (one per vertex 1..n) if bipartite; otherwise just 'NO'.

Approach

For every vertex from 1 to n that is not yet colored, start a fresh BFS, coloring the start vertex 0 and every newly discovered neighbor the opposite of its parent's color. Whenever an already-colored neighbor is found with the same color as the current vertex, the graph is not bipartite; stop immediately. Because coloring restarts at every uncolored vertex, disconnected components are each independently and correctly 2-colored.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, m;
    cin >> n >> m;
    vector<vector<int>> adj(n+1);
    for(int i=0;i<m;i++){
        int u,v; cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);
    }
    vector<int> color(n+1, -1);
    bool ok = true;
    for(int s=1; s<=n && ok; s++){
        if(color[s] != -1) continue;
        color[s] = 0;
        queue<int> q; q.push(s);
        while(!q.empty() && ok){
            int u = q.front(); q.pop();
            for(int v : adj[u]){
                if(color[v] == -1){
                    color[v] = color[u]^1;
                    q.push(v);
                } else if(color[v] == color[u]){
                    ok = false; break;
                }
            }
        }
    }
    if(!ok){
        cout << "NO\n";
    } else {
        cout << "YES\n";
        for(int v=1; v<=n; v++) cout << color[v] << (v<n?' ':'\n');
    }
}

Orienting Edges to Forbid Long Directed Paths

Problem

Given a connected undirected graph with n vertices and m edges, orient every edge (choose a direction for it) so that the resulting directed graph contains no directed path of two or more edges. Determine if this is possible, and if so, output one valid orientation.

Input: first line 'n m'. Next m lines: 'a b'.

Approach

The key insight is that such an orientation exists if and only if the graph is bipartite: 2-color it, and orient every edge from its color-0 endpoint to its color-1 endpoint. Every vertex colored 1 then has only incoming edges and every vertex colored 0 only outgoing edges (both endpoints of any edge always differ in color by construction), so no vertex can be the middle of a length-2 directed path. If the graph is not bipartite (an odd cycle exists), no valid orientation can exist, because walking any odd cycle and orienting consistently around it is provably impossible without creating a length-2 directed path somewhere.

2-SAT

2 worked examples

2-SAT (2-satisfiability) decides whether n boolean variables can be assigned values so that a conjunction of m clauses, each an OR of exactly two literals (a literal being a variable or its negation), is simultaneously satisfied. Unlike general k-SAT for k >= 3 (NP-complete), 2-SAT is solvable in linear time because a clause (a OR b) is logically equivalent to two implications: (NOT a) IMPLIES b, and (NOT b) IMPLIES a. Building a directed 'implication graph' with two nodes per variable (one for the literal being true, one for it being false) and one directed edge per implication turns satisfiability into a reachability question: the formula is satisfiable if and only if, for every variable x, x-is-true and x-is-false do not lie in the same strongly connected component (SCC) of the implication graph. If they did, the graph would prove x implies NOT x and NOT x implies x, forcing a contradiction no matter which value is chosen.

When the formula is satisfiable, a valid assignment falls out of the SCC condensation for free: assign each variable the value corresponding to whichever of its two literal-nodes lies in the SCC that comes LATER in the condensation's reverse-topological numbering produced by Kosaraju's or Tarjan's algorithm (equivalently, using the standard convention where SCC ids are assigned in decreasing order along edges, pick the literal with the larger SCC id). This works because implications only ever point 'forward' toward consequences, so choosing the literal that is a logical consequence of nothing already-forced (i.e. sits later/more 'downstream' in the DAG of SCCs) never triggers a chain that contradicts an earlier choice; it can be proven this assignment satisfies every implication edge simultaneously.

The implementation pattern is always: (1) create nodes 2*i (variable i literal 'true') and 2*i+1 (literal 'false') -- or any consistent pairing, (2) for every clause (lit_a OR lit_b), add edges NOT(lit_a) -> lit_b and NOT(lit_b) -> lit_a, (3) run an SCC algorithm (Tarjan's is a single DFS and is the standard competitive-programming choice), (4) check comp[true_i] != comp[false_i] for every i, (5) read off the assignment from the SCC ordering. The hard part of most 2-SAT problems is step (2) in disguise: recognizing that a real-world constraint ('these two people must not both attend', 'exactly one of these two switches flips this door', 'these two intervals must not both be chosen') is secretly a 2-literal clause, then building O(n) or O(n log n) implication edges instead of an accidental O(n^2) blow-up.

Beyond plain boolean satisfiability, 2-SAT generalizes to 'AT MOST ONE of these k variables is true' (via O(k) auxiliary variables chained together) and to constraints like 'these two intervals must be disjoint' (each interval gets a boolean choosing one of two non-overlapping placements, with implications forbidding the overlapping combinations) -- both are common building blocks in harder problems layered on top of the base algorithm.

Recognize it by

You need to decide TRUE/FALSE for each of n boolean variables (or make a binary choice for each of n items) subject to a set of pairwise constraints of the form 'at least one of these two conditions must hold' (equivalently, 'these two specific choices cannot both be violated') -- especially when constraints are phrased as implications ('if A picks state x then B must pick state y') or forbidden pairs ('A and B cannot both be true' / 'at least one of A, B must be true'). If the constraint naturally decomposes into 2-literal clauses and n, m are too large for brute-force 2^n search, it's 2-SAT.

Complexity

O(n + m) time and space, where n is the number of variables and m is the number of clauses (each clause contributes O(1) implication edges), since it reduces to one or two linear-time DFS passes for SCC computation.

Giant Pizza (canonical 2-SAT satisfiability + reconstruction)

Problem

A group of n friends is ordering a pizza with m possible toppings. Each friend gives exactly one opinion of the form '+x' (wants topping x on the pizza) or '-x' (does not want topping x), and each of n input lines actually lists TWO such opinions (from two different friends' requests) that must be treated as a single requirement: at least one of the two stated opinions must be satisfied by the final topping choice. For each of the m toppings you must decide whether it is included (+) or excluded (-) so that every one of the n given two-opinion requirements has at least one opinion satisfied, or determine this is impossible.

Input: two integers n and m (number of requirements and number of toppings) on the first line. Then n lines, each with two tokens of the form '+k' or '-k' (1 <= k <= m), meaning that requirement is satisfied if topping k is included ('+k') or excluded ('-k').
Output: if no valid choice of toppings exists, print IMPOSSIBLE. Otherwise print m tokens ('+' or '-') separated by spaces, one per topping in order 1..m, describing a valid choice.

Approach

This is a direct 2-SAT instance: each topping k is a boolean variable (true = included), and each input line '+a -b' (or any combination of signs) is exactly a clause (lit_a OR lit_b) where lit_a is the literal 'topping a included' if the token is '+a', or 'topping a excluded' (i.e. NOT topping a) if the token is '-a'.

Build the implication graph with 2*m nodes: node 2*i represents the literal 'topping (i+1) is TRUE', node 2*i+1 represents 'topping (i+1) is FALSE' (0-indexed internally). For a clause (lit_a OR lit_b), add edges NOT(lit_a) -> lit_b and NOT(lit_b) -> lit_a (if lit_a is violated, lit_b is forced, and symmetrically) -- this is exactly the general clause-to-implication translation, so a single addClause(a, negated_a, b, negated_b) routine handles every sign combination uniformly, whether the two opinions in a line are from the same variable (a forced/unit constraint when a == b) or different ones.

Run a DFS-based SCC computation (Kosaraju's algorithm: one DFS on the graph recording finish order, one DFS on the transposed graph processing nodes in reverse finish order to assign component ids). For every topping i, if comp[true-node] == comp[false-node], the instance is contradictory -> IMPOSSIBLE. Otherwise assign topping i = TRUE if comp[true-node] > comp[false-node] (the literal in the SCC that is 'more downstream' in the condensation order), else FALSE. This runs in O(n + m) and is verified below on a 4-clause, 4-topping instance with two independent satisfying assignments, confirming the printed assignment actually satisfies all four clauses by hand.

Solution
#include <bits/stdc++.h>
using namespace std;

int n; // number of variables (toppings)
vector<vector<int>> adj, radj;
vector<bool> used;
vector<int> order_, comp;

void addImp(int u, int v) {
    adj[u].push_back(v);
    radj[v].push_back(u);
}
// clause (lit_a OR lit_b): a,b are variable indices (0-indexed), na/nb true means negated
void addClause(int a, bool na, int b, bool nb) {
    int A = 2*a ^ (na?1:0);   // node for literal a (na=false-> "a true" node)
    int B = 2*b ^ (nb?1:0);
    int notA = A ^ 1;
    int notB = B ^ 1;
    addImp(notA, B);
    addImp(notB, A);
}
void dfs1(int v) {
    used[v] = true;
    for (int u : adj[v]) if (!used[u]) dfs1(u);
    order_.push_back(v);
}
void dfs2(int v, int cl) {
    comp[v] = cl;
    for (int u : radj[v]) if (comp[u] == -1) dfs2(u, cl);
}

int main(){
    int m; // number of opinions/persons
    cin >> n >> m;
    int N = 2*n;
    adj.assign(N, {}); radj.assign(N, {});
    for (int i = 0; i < m; i++) {
        string t1, t2;
        cin >> t1 >> t2;
        bool na = (t1[0]=='-');
        int a = stoi(t1.substr(1)) - 1;
        bool nb = (t2[0]=='-');
        int b = stoi(t2.substr(1)) - 1;
        addClause(a, na, b, nb);
    }
    used.assign(N, false);
    for (int i = 0; i < N; i++) if (!used[i]) dfs1(i);
    comp.assign(N, -1);
    int j = 0;
    for (int i = 0; i < N; i++) {
        int v = order_[N-i-1];
        if (comp[v] == -1) dfs2(v, j++);
    }
    vector<int> val(n);
    bool ok = true;
    for (int i = 0; i < n; i++) {
        if (comp[2*i] == comp[2*i+1]) { ok = false; break; }
        val[i] = (comp[2*i] > comp[2*i+1]) ? 1 : 0; // node 2*i = "true" literal
    }
    if (!ok) { cout << "IMPOSSIBLE" << endl; return 0; }
    for (int i = 0; i < n; i++) cout << (val[i] ? '+' : '-') << (i+1<n? ' ' : '\n');
}

The Door Problem (modeling XOR/equality constraints as 2-SAT clauses)

Problem

There are n switches (numbered 1..n) and m doors. Every switch starts OFF; you choose independently, for each switch, whether to turn it ON or leave it OFF. Each door i has a given initial state s_i (0 = closed, 1 = open) and is wired to either one or two switches: if wired to a single switch x, turning x ON toggles the door's state once; if wired to two switches x and y, the door's final state is toggled once for every one of x, y that ends up ON. You must find an ON/OFF assignment for all switches so that EVERY door ends up open (final state 1), or report it is impossible.

Input: n and m on the first line. Then m lines, each describing a door: s (0 or 1), k (1 or 2, the number of switches wired to it), followed by k switch indices (1-indexed).
Output: if no assignment makes every door open, print NO. Otherwise print YES on one line, then a single line of n characters (1 = switch on, 0 = switch off).

Approach

For a door wired to exactly one switch x, the final state is s XOR val(x); requiring this to equal 1 forces val(x) to the fixed value (1 XOR s), i.e. a unit constraint -- encoded as the degenerate clause (x OR x) if x must be true, or (NOT x OR NOT x) if x must be false.

For a door wired to two switches x, y, the final state is s XOR val(x) XOR val(y). If s == 0, we need val(x) XOR val(y) = 1 (the two switches must differ), which is exactly the pair of clauses (x OR y) AND (NOT x OR NOT y) -- ruling out both-false and both-true. If s == 1, we need val(x) XOR val(y) = 0 (the two switches must agree), which is (x OR NOT y) AND (NOT x OR y) -- ruling out the two disagreeing combinations. Every one of these is a standard 2-literal clause, so the same addClause(a, negA, b, negB) implication-graph routine used for general 2-SAT handles all cases uniformly.

After building all clauses from all m doors, run the same SCC-based satisfiability check as in a plain 2-SAT solver. If some switch's true/false literals collapse into the same SCC, print NO. Otherwise reconstruct the assignment from the SCC ordering and print it. The worked example below is deliberately built so the constraints fully DETERMINE a unique switch assignment (door 1 forces switch 1 ON; door 2, wired to switches 1 and 2 with s=1, forces switch 2 to match switch 1, i.e. ON; door 3, wired to switches 2 and 3 with s=0, forces switch 3 to differ from switch 2, i.e. OFF) -- this was verified by hand before running the solver, and the program's output matches the hand-derived assignment exactly, then independently re-verified by plugging the assignment back into every door's XOR equation.

    addImp(notB, A);

                addClause(x, false, y, true);
                addClause(x, true, y, false);

    comp.assign(N, -1);

    }
    if (!ok) { cout << "NO" << endl; return 0; }
    cout << "YES" << endl;
    for (int i = 0; i < n; i++) cout << val[i];
    cout << endl;

Euler Path / Euler Circuit (Hierholzer's Algorithm)

2 worked examples

An Euler circuit is a closed walk that uses every edge of a graph exactly once and returns to its starting vertex; an Euler path is the open-walk version (starts and ends at different vertices). For an UNDIRECTED graph, an Euler circuit exists if and only if every vertex has even degree and all edges lie in a single connected component (isolated vertices with no edges are ignored); an Euler path (but not circuit) exists if and only if exactly two vertices have odd degree (the path must start and end at those two). For a DIRECTED graph, an Euler circuit exists iff in-degree equals out-degree at every vertex and the graph is connected (ignoring direction, restricted to edge-bearing vertices); an Euler path exists iff at most one vertex has out-degree = in-degree + 1 (a valid start) and at most one has in-degree = out-degree + 1 (a valid end), with all other vertices balanced.

Hierholzer's algorithm constructs the actual circuit/path in O(V + E) once feasibility is confirmed. The core idea: start at a valid vertex and greedily walk along unused edges until you get stuck (which, given the degree conditions, can only happen back at the start vertex for a circuit, or at the required end vertex for a path) -- this produces some closed sub-tour. Then, since every vertex on that sub-tour still has all its OTHER incident edges unused in balanced pairs, splice in additional closed sub-tours at any vertex along the current tour that still has unused edges, repeating until no unused edges remain anywhere on the tour. The famous, notoriously bug-prone part is implementing the 'splice' efficiently and correctly: a naive recursive implementation that walks forward, recurses into a stuck detour, and pushes the current vertex to the answer list AFTER the recursive call returns is correct in principle, but it is easy to accidentally scan an adjacency list from the beginning on every visit (making it O(V*E)) or to consume/skip edges incorrectly across recursive calls, silently corrupting the traversal. It also risks stack overflow on graphs with long chains, since one recursive call is made per edge.

The robust, competitive-programming-standard fix is to make the algorithm ITERATIVE using an explicit stack, combined with a per-vertex 'next edge pointer' (not a boolean-searched adjacency scan): while the top of the stack has an unused outgoing edge (found by advancing that vertex's pointer past already-used edges, never resetting it), push the edge's endpoint onto the stack and mark the edge used; when the top of the stack has no unused edges left, pop it and append it to the answer list. Reversing the final answer list gives a valid Euler circuit/path. This pointer-advance trick guarantees each edge is examined O(1) amortized times in total (the pointer only moves forward, never resets), giving true O(V + E), and the explicit stack avoids both the recursion-depth blowup and the classic bug where a recursive call's edge-consumption state leaks incorrectly into its caller's remaining iteration.

A subtlety for multigraphs (parallel edges, self-loops): edges must be tracked by a unique id (not just by endpoint), since 'the same neighbor' can appear via multiple distinct edges that must each be used exactly once; self-loops toggle the same vertex's degree by 2 and are trivially traversed as one edge from a vertex back to itself. Many real problems first require detecting or fixing infeasibility (adding the minimum edges to make all degrees even, or matching a directed graph's imbalanced vertices) before Hierholzer's algorithm can even be applied.

Recognize it by

The problem asks you to use every edge of a graph EXACTLY ONCE (not every vertex, which would be a Hamiltonian path/TSP) and produce (or count, or determine feasibility of) such a route -- phrases like 'route that crosses every bridge/road/street exactly once', 'sequence using every domino/ticket/relation exactly once', or 'reconstruct one long string from overlapping fixed-length fragments' (which becomes an Euler path over a de Bruijn-style graph of overlaps) are strong signals.

Complexity

O(V + E) time and space for feasibility checking (degree count + connectivity via BFS/DFS) and for constructing the circuit/path via iterative Hierholzer's algorithm.

Mail Delivery (undirected Euler circuit via iterative Hierholzer's)

Problem

A city has n buildings and m streets (the street graph may contain multiple streets between the same pair of buildings, and a street from a building to itself). Starting and ending at building 1, find a route that uses every street exactly once, or report that no such route exists.

Input: n and m on the first line, then m lines each with two integers a b (a street between buildings a and b; a == b is allowed for a self-loop street, and the same pair may repeat).
Output: if no Euler circuit exists, print IMPOSSIBLE. Otherwise print the m+1 buildings visited in order (starting and ending at building 1), space-separated.

Approach

First check feasibility: an undirected Euler circuit exists iff every vertex has even degree and every edge-bearing vertex is reachable from any other (single connected component among vertices with degree > 0) -- verified here with one BFS.

Then run Hierholzer's algorithm ITERATIVELY to avoid both the classic recursion-based edge-consumption bug and stack-overflow risk on long chains: maintain, for every vertex v, a pointer ptr[v] into its adjacency list that only ever advances forward (skipping edges already marked used, and NEVER resetting once advanced), plus a global usedEdge[] array indexed by a unique edge id (essential for multigraphs, since two edges between the same pair of vertices are NOT interchangeable -- each must be consumed exactly once). Push the start vertex onto an explicit stack; while the stack is non-empty, look at its top vertex v: advance ptr[v] past used edges, and if an unused edge to some 'to' remains, mark it used and push 'to'; if no unused edge remains at v, pop v and append it to the answer list. Reversing the final answer list yields the Euler circuit in the correct visiting order.

This was hand-traced on the sample below before running: with edges 1-2 (id0), 2-3 (id1), 3-1 (id2), the traversal pushes 1,2,3,1 (using each edge once), then pops back 1,3,2,1 as no vertex has remaining unused edges, and reversing gives the final route 1 2 3 1 -- confirmed to match the program's actual output. Additional runs against multigraphs with a self-loop and repeated edges (not shown in the final example, but tested during development) also produced valid Euler circuits, confirming the pointer-based approach correctly handles multi-edges.

        }

        }

    st.push_back(1);
    while (!st.empty()) {
        int v = st.back();
        // advance ptr past used edges
        while (ptr[v] < (int)adj[v].size() && usedEdge[adj[v][ptr[v]].second]) ptr[v]++;
        if (ptr[v] == (int)adj[v].size()) {
            circuit.push_back(v);
            st.pop_back();
        } else {
            auto [to, id] = adj[v][ptr[v]];
            ptr[v]++;
            usedEdge[id] = true;
            st.push_back(to);
        }
    }
    reverse(circuit.begin(), circuit.end());
    if ((int)circuit.size() != m + 1) { cout << "IMPOSSIBLE" << endl; return 0; }
    for (int i = 0; i < (int)circuit.size(); i++) cout << circuit[i] << (i+1<(int)circuit.size()?' ':'\n');
}

Reconstruct Itinerary (directed Euler path, lexicographically smallest)

Problem

You are given a list of m airline tickets, each a pair [from, to] of three-letter airport codes, representing a directed edge from 'from' to 'to'. All tickets must be used exactly once, the itinerary must begin at 'JFK', and it is guaranteed at least one valid itinerary using every ticket exists. If multiple valid itineraries exist, return the lexicographically smallest one (comparing the sequence of airport codes as an ordered list of strings).

Input: m, then m lines each with two space-separated airport codes (from, to).
Output: the m+1 airports of the lexicographically smallest valid itinerary, space-separated.

Approach

This is a directed Euler PATH problem (start fixed at JFK, use every edge/ticket exactly once) with an added lexicographic-smallest requirement, solved by a greedy variant of iterative Hierholzer's algorithm: store each airport's outgoing destinations in a sorted multiset (so the smallest unused destination is always at the front), then run the same 'push while edges remain, pop-and-record when stuck' iterative loop as in the undirected case, but always advancing along the CURRENTLY smallest remaining outgoing edge from the top of the stack (erasing it from the multiset immediately, which is safe because a multiset erase-by-iterator does not need index bookkeeping).

The reason greedily taking the smallest edge still produces a globally valid (and lexicographically minimal) Euler path -- rather than getting stuck early and needing backtracking -- is a classical fact about Hierholzer-style construction: any maximal walk that gets stuck can only get stuck back at a vertex whose in/out-degree imbalance forces it to be the path's endpoint (or, for interior vertices, all their edges have necessarily been exhausted in pairs), so the 'stuck' vertex is appended to the answer and the algorithm backtracks naturally through the stack, splicing in the remaining unused edges from earlier vertices on the stack -- exactly like the undirected circuit case, but directed. Taking the lexicographically smallest available edge at every step, combined with this stack-based backtracking (not a naive greedy walk with no backtracking, which CAN get stuck with unused edges remaining), is what guarantees both correctness and lexicographic minimality.

Hand-traced and cross-checked against the two official examples for this exact problem (LeetCode 332): tickets forming a JFK-A-JFK-B-JFK-C fan produce 'JFK A JFK B JFK C' (verified below), and the second official example's 5-ticket set among JFK/SFO/ATL correctly reproduces 'JFK ATL JFK SFO ATL SFO' -- both confirmed to match this program's actual output exactly.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int m;
    cin >> m;
    map<string, multiset<string>> adj;
    map<string, int> outDeg, inDeg;
    for (int i = 0; i < m; i++) {
        string a, b;
        cin >> a >> b;
        adj[a].insert(b);
        outDeg[a]++; inDeg[b]++;
    }
    string start = "JFK";
    // iterative Hierholzer's algorithm (directed), always taking the
    // lexicographically smallest unused outgoing edge (multiset keeps sorted order)
    vector<string> stack_;
    vector<string> route;
    stack_.push_back(start);
    while (!stack_.empty()) {
        string v = stack_.back();
        auto it = adj.find(v);
        if (it != adj.end() && !it->second.empty()) {
            auto first = it->second.begin();
            string u = *first;
            it->second.erase(first);
            stack_.push_back(u);
        } else {
            route.push_back(v);
            stack_.pop_back();
        }
    }
    reverse(route.begin(), route.end());
    if ((int)route.size() != m + 1) { cout << "NO VALID ITINERARY" << endl; return 0; }
    for (int i = 0; i < (int)route.size(); i++) cout << route[i] << (i+1<(int)route.size()?' ':'\n');
}

0/1 BFS & Multi-Source BFS

2 worked examples

0/1 BFS solves single-source shortest paths on graphs where every edge weight is either 0 or 1, in O(V + E) -- faster than Dijkstra's O((V+E) log V) and without needing a priority queue. The key insight is that a plain BFS already computes shortest paths when all edges have weight 1 because a FIFO queue processes vertices in strictly increasing order of distance; 0/1 BFS generalizes this using a DEQUE instead of a queue: when relaxing an edge of weight 0, push the neighbor to the FRONT of the deque (it has the same tentative distance as the current vertex, so it should be processed before vertices already queued with larger distances); when relaxing an edge of weight 1, push the neighbor to the BACK (it has one more than the current distance). This maintains the deque as (at most) two contiguous blocks of tentative distances d and d+1 at all times, which is exactly what lets plain popping from the front still process vertices in non-decreasing distance order -- giving Dijkstra-correct results with BFS-level cost. As with Dijkstra, you should allow a vertex to be pushed multiple times and simply skip processing it again once popped with its final (already-finalized, smaller) distance recorded, rather than trying to prevent duplicates up front.

The pattern shows up constantly in disguise: grid problems where moving in your 'preferred'/marked direction is free but any other move costs 1 (0/1 BFS immediately), problems that reduce to a minimum vertex/edge cut in a planar graph via the planar dual (existing cut-friendly edges cost 0, edges requiring new cuts cost 1), and problems requiring a potential/labeling function consistent with edge constraints (extracting per-node 'levels' via 0/1 BFS, then deriving other quantities from the level differences).

Multi-source BFS is a different but related idea: instead of starting a single-source BFS from one vertex, you initialize the BFS queue with an ENTIRE SET of sources simultaneously, all at distance 0. This correctly computes, for every vertex, the shortest distance to the NEAREST of any of the sources -- as if a single super-source were connected to every real source by a free (weight 0) edge. It is critically NOT the same as running |sources| separate single-source BFS passes and taking a minimum (which would cost O(sources * (V+E)) instead of O(V+E)); pushing all sources into the queue at once before the first pop is what makes the shared frontier expand outward correctly in one linear pass. A related but distinct trick, used when you need the distance FROM every vertex TO the nearest member of some target set (rather than from a fixed set outward), is to run the multi-source BFS on the REVERSED graph starting from the target set -- since distance from u to v in a graph equals distance from v to u in its reverse, this converts an otherwise expensive 'per-query single-target BFS' into one linear multi-source pass.

Recognize it by

0/1 BFS: edge weights are restricted to exactly two distinct values (commonly 0 and 1, or reducible to that by scaling), especially in grid problems phrased as 'moving this way is free, any other move costs one unit' or 'this cell is already usable, converting a new one costs one unit'. Multi-source BFS: you need shortest distances from ANY of several simultaneous starting points to every other node (or vice versa, via a reversed graph), rather than from one fixed start -- signaled by phrasing like 'multiple fires/infections/sources spread simultaneously' or 'distance to the nearest of these marked cells'.

Complexity

O(V + E) time and space for both 0/1 BFS (using a deque) and multi-source BFS (using a plain queue seeded with all sources at distance 0), versus O((V+E) log V) for a general Dijkstra or O(k * (V+E)) for k naive single-source BFS runs.

Minimum Obstacle Removal to Reach Corner (0/1 BFS on a grid)

Problem

You are given an R x C grid where each cell is either 0 (empty) or 1 (an obstacle). Starting at the top-left cell (0,0) and moving to an orthogonally adjacent cell each step, find the minimum number of obstacles you must remove to reach the bottom-right cell (R-1, C-1). You may move into a 0-cell for free; moving into a 1-cell costs 1 (removing that obstacle), and the starting cell's own obstacle status also counts if it is a 1.

Input: R and C, then the R x C grid of 0s and 1s.
Output: the minimum number of obstacles removed.

Approach

Model the grid as a graph where moving onto a 0-cell costs 0 and moving onto a 1-cell costs 1 -- exactly the 0/1 BFS setting. Initialize dist[0][0] to 1 if the start cell itself is an obstacle, else 0 (since 'entering' the start cell would have cost that much), and push it onto a deque.

Repeatedly pop the front of the deque and relax its up-to-4 neighbors: if moving into a neighbor cell of value 0, the edge weight is 0, so if it improves the neighbor's distance, push the neighbor to the FRONT of the deque (same tentative distance tier as the current cell); if the neighbor is a 1-cell, the edge weight is 1, so on improvement push it to the BACK of the deque (next tier). Because the deque always holds at most two contiguous distance tiers in order, popping from the front still processes cells in non-decreasing distance order, so the first time a cell is popped its distance is final -- allowing a stale/duplicate pop to simply be skip-relaxed again harmlessly (or checked against a visited flag). The answer is dist[R-1][C-1]. Verified against the official LeetCode example grid [[0,1,1],[1,1,0],[1,1,0]], which has known answer 2, and the program reproduces exactly 2.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int R, C;
    cin >> R >> C;
    vector<vector<int>> g(R, vector<int>(C));
    for (auto &row : g) for (auto &x : row) cin >> x;
    vector<vector<int>> dist(R, vector<int>(C, INT_MAX));
    deque<pair<int,int>> dq;
    dist[0][0] = (g[0][0] == 1) ? 1 : 0;
    dq.push_back({0,0});
    int dr[4] = {-1,1,0,0}, dc[4] = {0,0,-1,1};
    while (!dq.empty()) {
        auto [r, c] = dq.front(); dq.pop_front();
        for (int k = 0; k < 4; k++) {
            int nr = r+dr[k], nc = c+dc[k];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            int w = (g[nr][nc] == 1) ? 1 : 0; // cost 1 to move into an obstacle cell, 0 otherwise
            if (dist[r][c] + w < dist[nr][nc]) {
                dist[nr][nc] = dist[r][c] + w;
                if (w == 0) dq.push_front({nr, nc});
                else dq.push_back({nr, nc});
            }
        }
    }
    cout << dist[R-1][C-1] << endl;
}

Nearest Opposite Parity (multi-source BFS on a reversed jump graph)

Problem

You are given an array a[1..n] of positive integers. From index i you may jump to index i-a[i] or i+a[i], provided the resulting index stays within [1, n]. For every starting index i, find the minimum number of jumps required to reach SOME index j (not necessarily distinct from i) such that a[j] has the OPPOSITE PARITY of a[i] (one is even, the other odd). If no such index is reachable from i, report -1.

Input: n, then a[1..n].
Output: n integers, the answer for each starting index 1..n, space-separated.

Approach

A naive solution runs a separate BFS from every index looking for the nearest opposite-parity node, costing O(n^2) in the worst case. The key trick is to flip the question around: instead of asking 'from i, how far to the nearest odd-valued node' for every i separately, ask 'what is the distance, in the REVERSED jump graph, from EVERY odd-valued node simultaneously to each vertex' -- and by the general fact that distance from u to v equals distance from v to u in the reverse graph, this reversed-graph multi-source BFS started from all odd-valued nodes at once directly gives, for every vertex i, its distance TO the nearest odd-valued node in the ORIGINAL graph -- computed in one O(n) pass instead of O(n) separate BFS runs.

Concretely: build the original directed graph with edges i -> i-a[i] and i -> i+a[i] (when in range), then build its reverse (swap each edge's direction). Run one multi-source BFS on the reverse graph seeded with distance 0 at every index j where a[j] is odd; the resulting dist[] array gives, for each i, the shortest number of jumps from i to some odd-valued node in the original graph. Symmetrically run a second multi-source BFS seeded at every even-valued index to get distances to the nearest even-valued node. The final answer for index i is the 'distance to nearest odd' array if a[i] is even, or the 'distance to nearest even' array if a[i] is odd (each array's own -1/unreached sentinel carries through unchanged).

Hand-verified on a=[1,2,3,4]: from index 1 (odd) you can jump to index 2 (even) in 1 step, so answer 1; index 2 (even) can only jump to index 4 (also even, a dead end beyond that), never reaching an odd value, so answer -1; index 3 (odd) has no valid jump at all (3±3 both out of range), so answer -1; index 4 (even) also has no valid jump (4±4 both out of range), so answer -1 -- giving '1 -1 -1 -1', confirmed both by independent hand reasoning about each index's reachable set and by the program's actual output.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    cin >> n;
    vector<int> a(n+1);
    for (int i = 1; i <= n; i++) cin >> a[i];

    // reversed jump graph: original edge i -> i-a[i] and i -> i+a[i]
    // (when in [1,n]); store the reverse so we can multi-source BFS from a
    // whole parity class and get, for every node, its distance TO that class
    // in the ORIGINAL graph.
    vector<vector<int>> radj(n+1);
    for (int i = 1; i <= n; i++) {
        int lo = i - a[i], hi = i + a[i];
        if (lo >= 1 && lo <= n) radj[lo].push_back(i);
        if (hi >= 1 && hi <= n) radj[hi].push_back(i);
    }

    auto multiSourceDist = [&](int wantParity) {
        vector<int> dist(n+1, -1);
        queue<int> q;
        for (int i = 1; i <= n; i++) {
            if (a[i] % 2 == wantParity) { dist[i] = 0; q.push(i); }
        }
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v : radj[u]) {
                if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); }
            }
        }
        return dist;
    };

    vector<int> distToOdd = multiSourceDist(1);
    vector<int> distToEven = multiSourceDist(0);

    for (int i = 1; i <= n; i++) {
        int ans = (a[i] % 2 == 0) ? distToOdd[i] : distToEven[i];
        cout << ans << (i < n ? ' ' : '\n');
    }
}

Functional Graphs & Cycle Detection

2 worked examples

A functional graph is a directed graph in which every vertex has exactly out-degree 1 (each node points to exactly one 'successor'), typically arising from a deterministic transition function next(v) applied to n items (teleporters with one destination each, an array where a[i] tells you the next index, a permutation, or a rooted tree's parent pointers, where 'next' means 'move to parent'). Because every vertex has exactly one outgoing edge, following next() repeatedly from ANY starting vertex must eventually revisit a vertex (there are only n vertices, so within n+1 steps some vertex repeats), and once a vertex repeats, the walk is trapped forever cycling through the same sequence. This means every functional graph decomposes, per weakly-connected component, into exactly one cycle with trees hanging off its nodes (their edges pointing inward toward the cycle) -- often visualized as a 'rho' (greek letter p) shape: a tail leading into a loop.

Detecting each vertex's cycle (and the length of its tail before entering the cycle) is done in O(n) total with a single pass: walk forward from each unvisited vertex, marking every vertex touched as 'in-progress' and recording its position in the current walk; if the walk reaches a vertex that is already 'in-progress' IN THE SAME WALK, everything from that vertex's recorded position onward is the cycle, and everything before it is tail; if the walk instead reaches a vertex marked 'done' from a previous walk, the current walk simply merges into an already-fully-classified structure with no new cycle. Marking every vertex 'done' once its walk finishes guarantees each vertex is traversed at most a constant number of times across all walks combined, giving true O(n) rather than O(n^2).

Many problems need not just cycle detection but fast ANSWERING of 'where do you end up after k steps from vertex v', for potentially huge k (up to 10^9 or 10^18) and many queries. BINARY LIFTING precomputes, for each vertex v and each power of two j, the vertex reached after exactly 2^j steps from v: up[0][v] = next(v), and up[j][v] = up[j-1][up[j-1][v]] (apply the 2^(j-1)-step jump twice). This table has O(n log(max k)) entries and O(n log(max k)) construction time. To answer a query (v, k), decompose k into its binary representation and apply the corresponding jumps up[j][v] for every set bit j of k, in increasing order of j, updating v after each jump -- O(log k) per query. This is exactly the 'sparse ancestor table' technique also used for LCA and k-th ancestor queries on trees (a tree's parent-pointer structure is itself a functional graph, so kth-ancestor and functional-graph successor queries are the same technique). The table can be extended to aggregate additional information along each jump (sum of edge weights, minimum edge weight, etc.) by storing, alongside up[j][v], the combined statistic for that 2^j-step block and combining both halves' statistics when composing two jumps -- exactly analogous to a sparse table for range queries.

Recognize it by

Every node/item has EXACTLY ONE designated 'next' or 'successor' (a teleporter, a single next-array entry, a permutation, or a tree's parent pointer used for ancestor queries) -- as opposed to a general graph where nodes can have multiple or zero outgoing edges. Signals include: 'find where you end up after k steps/jumps/teleports', 'find the cycle a repeated process falls into', or '(kth) ancestor of a node' when the graph is secretly a rooted tree's parent-pointer structure.

Complexity

O(n) for one-pass cycle/tail decomposition; O(n log K) preprocessing and O(log K) per query for binary lifting, where K is the maximum number of steps that must be supported.

Mouse Hunt (pure cycle detection: minimum-cost cycle traps)

Problem

There are n rooms; room i has exactly one exit leading deterministically to room nxt[i] (so the room-transition structure is a functional graph), and placing a trap in room i costs cost[i]. A mouse starts in some UNKNOWN room and moves to nxt[current room] every second forever. Choose a set of rooms to trap, of minimum total cost, such that no matter which room the mouse starts in, it is guaranteed to eventually enter a trapped room.

Input: n, then n integers nxt[1..n] (1-indexed room the mouse moves to from room i), then n integers cost[1..n].
Output: the minimum total cost of a guaranteed-catch trap set.

Approach

Since every room has out-degree 1, this is a functional graph, and the key structural fact is that no matter which room the mouse starts in, it eventually enters a cycle (every 'tail' inevitably flows into some cycle). So trapping is only ever NECESSARY on cycle nodes: a mouse starting on a pure tail will walk into whatever cycle its tail leads to and get caught there, so trapping tail nodes is never required, and trapping a cheapest node PER CYCLE is both necessary (some node on every cycle must be trapped, or a mouse starting there loops forever uncaught) and sufficient (once one node on a cycle is trapped, any mouse entering that cycle eventually reaches the trap). So the answer is exactly the sum, over every distinct cycle in the functional graph, of the minimum cost[] among that cycle's nodes.

Find all cycles with one O(n) pass: for every unvisited start vertex, walk forward recording each visited vertex's position in a local path list and marking it 'in-progress'; if the walk reaches a vertex already 'in-progress' in the SAME walk, the sub-list from that vertex's recorded position to the end of the path is exactly one cycle -- take its minimum cost and add to the running answer; if the walk instead reaches an already-'done' vertex from an earlier walk, no new cycle is found (the tail simply merges into previously discovered structure). Mark every node in the finished path 'done' so each node is processed O(1) times overall. Verified by hand on the sample: rooms 1->2->3->1 form a 3-cycle with costs 10,20,5 (minimum 5), rooms 4->3 and 5->4 are tails feeding into that same cycle and contribute nothing extra, giving total answer 5 -- matching the program's actual output, and cross-checked again on a second input with two disjoint 2-cycles (minimums 3 and 1, summing to 4), which the program also reproduced exactly.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    cin >> n;
    vector<int> nxt(n+1), cost(n+1);
    for (int i = 1; i <= n; i++) cin >> nxt[i];
    for (int i = 1; i <= n; i++) cin >> cost[i];

    vector<int> state(n+1, 0); // 0 = unvisited, 1 = in-progress, 2 = done
    long long answer = 0;

    for (int start = 1; start <= n; start++) {
        if (state[start] != 0) continue;
        vector<int> path;
        unordered_map<int,int> posInPath;
        int v = start;
        while (state[v] == 0) {
            state[v] = 1;
            posInPath[v] = (int)path.size();
            path.push_back(v);
            v = nxt[v];
        }
        if (state[v] == 1) {
            // v lies on the current path -> path[posInPath[v] .. end] is a cycle
            int idx = posInPath[v];
            long long minCost = LLONG_MAX;
            for (int k = idx; k < (int)path.size(); k++) minCost = min(minCost, (long long)cost[path[k]]);
            answer += minCost;
        }
        for (int u : path) state[u] = 2;
    }
    cout << answer << endl;
}

Planets Queries I (binary lifting: k-th successor in a functional graph)

Problem

There are n planets; planet i has exactly one teleporter leading to planet nxt[i]. Answer q independent queries, each giving a starting planet x and a (potentially huge) number of teleporter uses k: determine which planet you end up on after using the teleporter exactly k times starting from planet x.

Input: n, then n integers nxt[1..n] (1-indexed destination planet of planet i's teleporter). Then q, followed by q lines each with x and k (k can be as large as about 2^31 - 1 in this worked example, and the technique scales to much larger k by widening the table).
Output: q lines, each the resulting planet for that query.

Approach

This is the direct textbook application of binary lifting on a functional graph. Precompute a sparse table up[j][v] = the planet reached after exactly 2^j teleports starting from v, for j = 0..LOG-1 (LOG chosen so 2^LOG exceeds the maximum possible k): base case up[0][v] = nxt[v] (one teleport), and up[j][v] = up[j-1][ up[j-1][v] ] (take a 2^(j-1)-teleport jump, then take the same size jump again, composing to a 2^j-teleport jump).

For each query (x, k), decompose k in binary and apply exactly the jumps corresponding to k's set bits, from the least significant bit upward, updating the current planet after each applied jump: for each bit position j where k has a 1, set x = up[j][x]. After processing all LOG bit positions, x holds the planet reached after exactly k teleports. Each query costs O(log k) instead of O(k), which is essential once k is too large to simulate step by step.

Verified by hand on a 4-planet cycle 1->2->3->4->1: query (1, 5) walks 1,2,3,4,1,2 (5 teleports) landing on 2; query (3, 2) walks 3,4,1 (2 teleports) landing on 1; query (2, 0) performs zero teleports and stays at 2 -- all three confirmed by direct step-by-step simulation and matching the program's actual binary-lifting output exactly.

Solution
#include <bits/stdc++.h>
using namespace std;

const int LOG = 32; // enough for k up to ~2^32-1

int main(){
    int n;
    cin >> n;
    vector<vector<int>> up(LOG, vector<int>(n+1));
    for (int i = 1; i <= n; i++) cin >> up[0][i];
    for (int j = 1; j < LOG; j++)
        for (int i = 1; i <= n; i++)
            up[j][i] = up[j-1][up[j-1][i]];

    int q;
    cin >> q;
    while (q--) {
        int x; long long k;
        cin >> x >> k;
        for (int j = 0; j < LOG; j++) {
            if (k & (1LL << j)) x = up[j][x];
        }
        cout << x << "\n";
    }
}
