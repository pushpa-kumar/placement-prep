String Algorithms

String algorithms turn questions about matching, repetition, and symmetry in text into linear- or near-linear-time computations by precomputing structural information once and reusing it for O(1) or O(log n) queries. The core toolkit here — the prefix function (KMP), the Z-function, polynomial hashing, Manacher's algorithm, and tries (with suffix arrays/automata as the natural next step) — covers the overwhelming majority of "hard" string problems on Codeforces, CSES, and LeetCode. Master the mechanics of each precomputed array first; almost every hard problem is a non-obvious reduction on top of one of these arrays rather than a new algorithm. Beyond hashing, KMP/Z-function, and tries, these three automaton-style structures — the suffix automaton, the Aho-Corasick trie, and the palindromic tree — let you answer much harder substring, multi-pattern, and palindrome questions on a single string (or a whole text against many patterns) in linear or near-linear time, at the cost of genuinely fiddly construction code.

KMP Pattern Matching (Prefix Function)

3 worked examples

The prefix function pi[i] of a string s is defined as the length of the longest proper prefix of s[0..i] that is also a suffix of s[0..i] (proper meaning it cannot be the entire substring s[0..i] itself). It is computed in O(n) with a clever amortized argument: to compute pi[i] from pi[i-1], start a candidate match length j = pi[i-1] (the best border known so far) and repeatedly fall back to j = pi[j-1] while s[i] != s[j], exactly the same 'failure link' idea used to avoid re-scanning already-matched characters. Because j can only increase by 1 per iteration of the outer loop but is reset by fallbacks that are bounded by the total increase, the amortized cost over all i is O(n).

The classic application is substring search: concatenate pattern + separator + text (the separator must be a character that occurs in neither string, e.g. '#') and run the prefix function on the combined string. Every position where pi[i] equals the pattern's length marks an occurrence ending there, because a border of length |pattern| at that point means the preceding |pattern| characters of the combined string exactly equal the pattern. This gives O(n + m) pattern matching without ever backtracking in the text, which is what makes KMP asymptotically better than the naive O(n*m) sliding comparison.

Beyond direct matching, the prefix function encodes deep structural information about a string: repeatedly following pi[n-1] -> pi[pi[n-1]-1] -> ... enumerates every border of the whole string, which is exactly the information needed to find all periods of a string (period k works iff n-k is a border length) or to detect that a string is built from repetitions of a smaller block. The same 'prefix function on a concatenation with a separator' trick generalizes far beyond pattern search — e.g. computing the longest palindromic prefix of s by running it on s + '#' + reverse(s).

Recognize it by

Reach for KMP/prefix-function whenever you need exact substring matching in O(n+m), need the borders (prefix=suffix) of a string, need the minimal period of a string, or see a problem that can be phrased as 'longest prefix of A that is also a suffix of B' — the giveaway is usually the phrase 'find all occurrences' or 'shortest string with property X built by adding a prefix/suffix', which often reduces to a border query on a cleverly concatenated string.

Complexity

O(n + m) time, O(n + m) space where n = |text|, m = |pattern|.

All Occurrences of a Pattern

Problem

You are given a text string T (1 <= |T| <= 2*10^5) and a pattern string P (1 <= |P| <= |T|), both consisting of lowercase Latin letters. Find every starting index (0-indexed) at which P occurs in T (occurrences may overlap). Print the number of occurrences, then the 0-indexed starting positions in increasing order on one line separated by spaces.

Approach

Build combined = P + '#' + T using a separator character guaranteed not to appear in either string. Compute the prefix function pi of combined in O(|combined|). For every index i in the T-part of combined (i.e. i > |P|), if pi[i] == |P| then a full copy of P ends at position i of combined; converting back to an index in T gives start = i - 2*|P| (subtract |P| for the pattern part and the separator, then |P| more for the length of the match itself: i - 2*|P|). Collect all such starts.

Solution
#include <bits/stdc++.h>
using namespace std;

vector<int> prefixFunction(const string &s) {
    int n = s.size();
    vector<int> pi(n, 0);
    for (int i = 1; i < n; i++) {
        int j = pi[i - 1];
        while (j > 0 && s[i] != s[j]) j = pi[j - 1];
        if (s[i] == s[j]) j++;
        pi[i] = j;
    }
    return pi;
}

int main() {
    string text, pattern;
    getline(cin, text);
    getline(cin, pattern);
    string combined = pattern + "#" + text;
    vector<int> pi = prefixFunction(combined);
    int m = pattern.size();
    vector<int> occ;
    for (int i = m + 1; i < (int)combined.size(); i++) {
        if (pi[i] == m) occ.push_back(i - 2 * m);
    }
    cout << occ.size() << "\n";
    for (int i = 0; i < (int)occ.size(); i++) {
        cout << occ[i] << " \n"[i + 1 == (int)occ.size()];
    }
    return 0;
}

Shortest Palindrome by Prefix Addition

Problem

Given a string s (1 <= |s| <= 5*10^4) of lowercase Latin letters, you may add characters in front of s to make the whole string a palindrome. Output the shortest palindrome achievable this way.

Approach

If we prepend k characters to make s a palindrome, those k characters must equal the reverse of the last k characters of the resulting palindrome, which forces the prepended block to equal reverse(suffix) in a very specific way; the key reduction is: we want the longest prefix of s that is itself a palindrome, because everything after that prefix must be mirrored in front. Compute combined = s + '#' + reverse(s) and run the prefix function; pi.back() gives the length of the longest palindromic prefix of s (it equals the longest border between s and reverse(s), which is exactly the longest prefix of s that reads the same as a suffix of reverse(s), i.e. a palindrome). The characters of s beyond that prefix, reversed, are exactly what must be prepended: answer = reverse(s[longest:]) + s.

Solution
#include <bits/stdc++.h>
using namespace std;

vector<int> prefixFunction(const string &s) {
    int n = s.size();
    vector<int> pi(n, 0);
    for (int i = 1; i < n; i++) {
        int j = pi[i - 1];
        while (j > 0 && s[i] != s[j]) j = pi[j - 1];
        if (s[i] == s[j]) j++;
        pi[i] = j;
    }
    return pi;
}

int main() {
    string s;
    getline(cin, s);
    string rev = s;
    reverse(rev.begin(), rev.end());
    string combined = s + "#" + rev;
    vector<int> pi = prefixFunction(combined);
    int longestPalinPrefix = pi.back();
    string toAdd = rev.substr(0, s.size() - longestPalinPrefix);
    cout << toAdd + s << "\n";
    return 0;
}

Finding All Periods of a String

Problem

A string s of length n (1 <= n <= 10^6) has period k (1 <= k <= n) if s[i] == s[i+k] for every valid i (0 <= i <= n-k-1). Note k = n is always a trivially valid period. Given s, output all valid periods of s in increasing order, space-separated.

Approach

Compute the prefix function pi of s directly (no concatenation needed here). The chain b = pi[n-1], then b = pi[b-1], and so on until b = 0, enumerates every border length of the full string. A border of length b corresponds exactly to period n-b, because s[0..b) == s[n-b..n) means s repeats with period n-b. Collect n-b for every border in the chain, add the trivial period n itself, sort, and print.

Solution
#include <bits/stdc++.h>
using namespace std;

vector<int> prefixFunction(const string &s) {
    int n = s.size();
    vector<int> pi(n, 0);
    for (int i = 1; i < n; i++) {
        int j = pi[i - 1];
        while (j > 0 && s[i] != s[j]) j = pi[j - 1];
        if (s[i] == s[j]) j++;
        pi[i] = j;
    }
    return pi;
}

int main() {
    string s;
    getline(cin, s);
    int n = s.size();
    vector<int> pi = prefixFunction(s);
    vector<int> periods;
    periods.push_back(n); // trivial period: the whole string
    int b = pi[n - 1];
    while (b > 0) {
        periods.push_back(n - b);
        b = pi[b - 1];
    }
    sort(periods.begin(), periods.end());
    for (int i = 0; i < (int)periods.size(); i++) {
        cout << periods[i] << " \n"[i + 1 == (int)periods.size()];
    }
    return 0;
}

Z-function

2 worked examples

The Z-function of a string s is an array z where z[i] is the length of the longest common prefix between s and the suffix of s starting at index i (by convention z[0] is either left undefined or set to n, the whole string trivially matching itself). It is computed in O(n) using the same 'reuse previously computed matches' idea as KMP, but framed differently: maintain a window [l, r) — the rightmost Z-box found so far, i.e. the interval matching a prefix of s that extends furthest to the right. When computing z[i] for i inside the current window, we can initialize z[i] from the already-known value z[i-l] (mirrored inside the prefix) rather than starting from scratch, then only extend by brute-force comparison past the window boundary r. Every successful character comparison beyond r increases r by 1 and never decreases it, which bounds total comparisons to O(n).

The Z-function and the prefix function carry equivalent information (each can be derived from the other in O(n)), but the Z-function is often more natural for problems phrased in terms of 'longest common prefix with the whole string starting at position i', which is a very common way hard problems disguise this technique — e.g. LeetCode's 'Sum of Scores of Built Strings' literally defines score(i) to be the Z-function by another name.

For pattern matching, the same separator trick as KMP applies: build pattern + '#' + text and scan the Z-array for values >= |pattern|, which mark occurrences. Another powerful use is counting, for every prefix length L, how many times that prefix occurs as a substring anywhere in s: increment a counter at z[i] for every i, add one more for the full string itself (which trivially matches its own prefix at position 0), then take a suffix sum over counter values from n down to 1.

Recognize it by

Look for the Z-function whenever a problem talks about 'the longest common prefix between the string and one of its suffixes', needs substring occurrence positions, or needs, for every prefix, how often it recurs inside the string. It is functionally interchangeable with KMP for pure pattern matching, so pick whichever framing makes the reduction to the problem's phrasing cleaner.

Complexity

O(n + m) time, O(n + m) space where n = |text|, m = |pattern|.

Pattern Matching via the Z-array

Problem

Given a text T and a pattern P (both lowercase Latin letters, 1 <= |P| <= |T| <= 2*10^5), find every 0-indexed starting position where P occurs in T. Print the count followed by the sorted starting positions on one line.

Approach

Form combined = P + '#' + T and compute its Z-array. For every position i within the T-part (i > |P|), z[i] >= |P| means the substring of combined starting at i shares at least |P| characters with the whole combined string, i.e. with P itself — an occurrence of P in T starting at index i - |P| - 1.

Solution
#include <bits/stdc++.h>
using namespace std;

vector<int> zFunction(const string &s) {
    int n = s.size();
    vector<int> z(n, 0);
    z[0] = n;
    int l = 0, r = 0;
    for (int i = 1; i < n; i++) {
        if (i < r) z[i] = min(r - i, z[i - l]);
        while (i + z[i] < n && s[z[i]] == s[i + z[i]]) z[i]++;
        if (i + z[i] > r) { l = i; r = i + z[i]; }
    }
    return z;
}

int main() {
    string text, pattern;
    getline(cin, text);
    getline(cin, pattern);
    int m = pattern.size();
    string combined = pattern + "#" + text;
    vector<int> z = zFunction(combined);
    vector<int> occ;
    for (int i = m + 1; i < (int)combined.size(); i++) {
        if (z[i] >= m) occ.push_back(i - m - 1);
    }
    cout << occ.size() << "\n";
    for (int i = 0; i < (int)occ.size(); i++) {
        cout << occ[i] << " \n"[i + 1 == (int)occ.size()];
    }
    return 0;
}

Sum of Scores of Built Strings

Problem

For a string s of length n (1 <= n <= 10^5), define score(i) as the length of the longest common prefix between s and the suffix of s starting at index i, for every i from 0 to n-1 (score(0) = n since s trivially matches its whole self). Compute the sum of score(i) over all i. (This is LeetCode Hard #2223.)

Approach

score(i) is exactly the definition of the Z-function value z[i] for i >= 1, and score(0) = n matches the conventional z[0] = n. So the answer is simply the sum of the entire Z-array (with z[0] set to n). Compute the Z-array in O(n) and sum it — the entire difficulty of this 'hard' problem is recognizing the reduction, not the implementation.

Solution
#include <bits/stdc++.h>
using namespace std;

vector<long long> zFunction(const string &s) {
    int n = s.size();
    vector<long long> z(n, 0);
    z[0] = n;
    int l = 0, r = 0;
    for (int i = 1; i < n; i++) {
        if (i < r) z[i] = min((long long)(r - i), z[i - l]);
        while (i + z[i] < n && s[z[i]] == s[i + z[i]]) z[i]++;
        if (i + z[i] > r) { l = i; r = i + z[i]; }
    }
    return z;
}

int main() {
    string s;
    getline(cin, s);
    vector<long long> z = zFunction(s);
    long long sum = 0;
    for (long long v : z) sum += v;
    cout << sum << "\n";
    return 0;
}

String Hashing (Polynomial Rolling Hash)

3 worked examples

A polynomial hash maps a string s of length n to H(s) = (s[0]*B^(n-1) + s[1]*B^(n-2) + ... + s[n-1]*B^0) mod M for a base B and modulus M. By precomputing prefix hashes h[0..n] (h[i] = hash of s[0..i)) and powers of B, the hash of any substring s[l..r) can be recovered in O(1) via h[r] - h[l]*B^(r-l) (mod M), because shifting the prefix hash of s[0..l) up by (r-l) digits and subtracting cancels out everything before index l. This turns 'are these two substrings equal' into an O(1) integer comparison after O(n) preprocessing, which is the whole appeal: it trades a small, controllable false-positive probability for speed and simplicity that beats writing a suffix structure.

The critical danger is collisions. A single hash modulo a ~10^9 prime, especially with a fixed, well-known base/modulus pair, can be deliberately defeated by adversarial test data (this is a known 'anti-hash test' phenomenon on Codeforces) and even without adversarial input, the birthday bound means collisions become likely once you compare on the order of sqrt(M) substrings. The standard defenses are: (1) double hashing — compute two independent hashes with different (base, modulus) pairs and compare the pair, which squares the safety margin to roughly 10^18; or (2) hash modulo a large prime close to 2^61 with a randomized base chosen at runtime, using 128-bit intermediate multiplication to avoid overflow, which is safe against static anti-hash tests. Never trust a single small-modulus hash in a contest with adaptive or adversarial data.

Hashing also extends naturally to palindrome checking: precompute both the forward hash of s and the forward hash of reverse(s); a substring s[l..r) is a palindrome iff its forward hash equals the forward hash of the mirrored range in reverse(s). This generalizes to dynamic settings (point updates) by replacing the flat prefix-hash array with a Fenwick tree or segment tree that supports point update and range hash query, at the cost of O(log n) instead of O(1) per query.

Recognize it by

Use hashing whenever you need fast substring equality checks, longest common substring/prefix queries combined with binary search, palindrome checks on arbitrary ranges (especially under updates, where suffix structures are hard to maintain), or any place you'd like to avoid building a suffix automaton/array but still need 'is this substring equal to that substring' in better than O(length).

Complexity

O(n) preprocessing, O(1) per substring-hash query (O(log n) with a Fenwick/segment tree for point updates); O(n log n) total for a binary-search-based application.

Longest Common Substring (Double Hash + Binary Search)

Problem

Given two strings s and t (1 <= |s|, |t| <= 5*10^4, lowercase Latin letters), find the length of their longest common substring, and print one such substring.

Approach

The existence of a common substring of length L is monotonic in L: if some common substring of length L exists, truncating one character from both copies gives a common substring of length L-1, so the predicate 'a common substring of length L exists' is true for a prefix of lengths 0..answer and false above. Binary search on L; for the check, hash every length-L substring of s into a set (using a double hash pair to make accidental collisions negligible) and test every length-L substring of t for membership in O(1) per substring. Each check costs O(n+m), giving O((n+m) log n) overall.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
typedef unsigned long long ull;

struct DoubleHash {
    // two independent polynomial hashes to make collisions astronomically unlikely
    static const ll MOD1 = 1000000007LL, MOD2 = 998244353LL;
    static const ll BASE1 = 131, BASE2 = 137;
    vector<ll> h1, h2, p1, p2;
    void build(const string &s) {
        int n = s.size();
        h1.assign(n + 1, 0); h2.assign(n + 1, 0);
        p1.assign(n + 1, 1); p2.assign(n + 1, 1);
        for (int i = 0; i < n; i++) {
            h1[i + 1] = (h1[i] * BASE1 + s[i]) % MOD1;
            h2[i + 1] = (h2[i] * BASE2 + s[i]) % MOD2;
            p1[i + 1] = (p1[i] * BASE1) % MOD1;
            p2[i + 1] = (p2[i] * BASE2) % MOD2;
        }
    }
    // hash of s[l..r) 0-indexed, half-open
    pair<ll, ll> get(int l, int r) const {
        ll a = ((h1[r] - h1[l] * p1[r - l]) % MOD1 + MOD1) % MOD1;
        ll b = ((h2[r] - h2[l] * p2[r - l]) % MOD2 + MOD2) % MOD2;
        return {a, b};
    }
};

int main() {
    string s, t;
    getline(cin, s);
    getline(cin, t);
    DoubleHash hs, ht;
    hs.build(s);
    ht.build(t);
    int n = s.size(), m = t.size();

    auto check = [&](int len) -> pair<bool, int> {
        if (len == 0) return {true, 0};
        set<pair<ll, ll>> seen;
        for (int i = 0; i + len <= n; i++) seen.insert(hs.get(i, i + len));
        for (int j = 0; j + len <= m; j++) {
            if (seen.count(ht.get(j, j + len))) return {true, j};
        }
        return {false, -1};
    };

    int lo = 0, hi = min(n, m), ans = 0, startInT = -1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        auto [ok, pos] = check(mid);
        if (ok) { ans = mid; startInT = pos; lo = mid + 1; }
        else hi = mid - 1;
    }
    cout << ans << "\n";
    if (ans > 0) cout << t.substr(startInT, ans) << "\n";
    else cout << "\n";
    return 0;
}

Prefix-Suffix Palindrome

Problem

Given a string s (1 <= |s| <= 10^6) of lowercase Latin letters, find the length of the longest string that can be formed by concatenating a prefix of s and a suffix of s (the prefix and suffix must not overlap, and either may be empty) such that the concatenation is a palindrome. Print the length and one such palindrome. (Based on Codeforces 1326 D2.)

Approach

Greedily peel matching outer characters with two pointers i=0, j=n-1: while s[i] == s[j], advance i and retreat j. This gives the maximal 'shell' — a prefix of length shell=i that exactly equals the reverse of the corresponding suffix — which can always be wrapped, unmodified, around any palindrome found in the remaining middle segment s[i..j]. The problem now reduces to: find the longest palindromic PREFIX of the middle or the longest palindromic SUFFIX of the middle (whichever is longer), and sandwich it between the shell and its mirrored copy. Use double hashing to test 'is s[l..r) a palindrome' in O(1) (by comparing the forward hash of that range against the forward hash of the mirrored range in reverse(s)), and scan candidate lengths from the full middle length down to 0, stopping at the first palindrome found — this is O(|middle|) with O(1) checks, no binary search needed since 'is a palindrome' is not itself monotonic in length.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

struct DoubleHash {
    static const ll MOD1 = 1000000007LL, MOD2 = 998244353LL;
    static const ll BASE1 = 131, BASE2 = 137;
    vector<ll> h1, h2, p1, p2;
    void build(const string &s) {
        int n = s.size();
        h1.assign(n + 1, 0); h2.assign(n + 1, 0);
        p1.assign(n + 1, 1); p2.assign(n + 1, 1);
        for (int i = 0; i < n; i++) {
            h1[i + 1] = (h1[i] * BASE1 + s[i]) % MOD1;
            h2[i + 1] = (h2[i] * BASE2 + s[i]) % MOD2;
            p1[i + 1] = (p1[i] * BASE1) % MOD1;
            p2[i + 1] = (p2[i] * BASE2) % MOD2;
        }
    }
    pair<ll, ll> get(int l, int r) const { // s[l..r) half-open
        ll a = ((h1[r] - h1[l] * p1[r - l]) % MOD1 + MOD1) % MOD1;
        ll b = ((h2[r] - h2[l] * p2[r - l]) % MOD2 + MOD2) % MOD2;
        return {a, b};
    }
};

int main() {
    string s;
    getline(cin, s);
    int n = s.size();
    string rev = s;
    reverse(rev.begin(), rev.end());

    DoubleHash hf, hr; // hf: hash of s, hr: hash of reverse(s)
    hf.build(s);
    hr.build(rev);

    // isPalindrome(l, r) for s[l..r) : compare forward hash of s[l,r)
    // with forward hash of rev at mirrored positions.
    auto isPalin = [&](int l, int r) -> bool {
        int len = r - l;
        if (len <= 1) return true;
        int rl = n - r, rr = n - l; // mirrored half-open range in rev
        return hf.get(l, r) == hr.get(rl, rr);
    };

    // Step 1: peel the maximal matching outer prefix/suffix shell.
    int i = 0, j = n - 1;
    while (i < j && s[i] == s[j]) { i++; j--; }
    // shell length = i (chars s[0..i) match reverse of s[j+1..n))
    int shell = i;
    // middle is s[i..j] inclusive (0 or more characters)
    int midL = i, midR = j + 1; // half-open [midL, midR)

    // Step 2: longest palindromic PREFIX of the middle.
    int bestPrefix = 0;
    for (int len = midR - midL; len >= 0; len--) {
        if (isPalin(midL, midL + len)) { bestPrefix = len; break; }
    }
    // Step 3: longest palindromic SUFFIX of the middle.
    int bestSuffix = 0;
    for (int len = midR - midL; len >= 0; len--) {
        if (isPalin(midR - len, midR)) { bestSuffix = len; break; }
    }

    string middlePart = (bestPrefix >= bestSuffix)
                             ? s.substr(midL, bestPrefix)
                             : s.substr(midR - bestSuffix, bestSuffix);
    string result = s.substr(0, shell) + middlePart + s.substr(j + 1, shell);
    cout << result.size() << "\n";
    cout << result << "\n";
    return 0;
}

Palindrome Queries with Point Updates

Problem

You are given a string s (1 <= |s| <= 2*10^5) of lowercase Latin letters and q queries (1 <= q <= 2*10^5) of two types: '1 pos c' — set the character at 1-indexed position pos to c; '2 a b' — output YES if s[a..b] (1-indexed, inclusive) is currently a palindrome, NO otherwise. Process all queries online. (Based on CSES 'Palindrome Queries'.)

Approach

A flat prefix-hash array can't handle point updates efficiently (an update would shift every hash after it). Instead build a segment tree over the string where each node stores two hashes of its range under one large-modulus polynomial hash: the forward hash (read left to right) and the reverse hash (as if the range were read right to left). Forward hashes merge as combine(L,R) = L.hash * B^|R| + R.hash. Reverse hashes merge in the opposite order, because reverse(A+B) = reverse(B) + reverse(A): combine(L,R) = R.rev * B^|L| + L.rev. A point update just rewrites a leaf and recomputes O(log n) ancestors; a range query merges O(log n) segment-tree nodes to get the forward and reverse hash of the queried range in O(log n), and the range is a palindrome iff the two hashes are equal. Using a modulus near 2^61 with 128-bit multiplication (or double hashing) keeps collision probability negligible even under adversarial queries.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
typedef __int128 lll;

// Segment tree over a fixed-length string supporting:
//  - point update (change one character)
//  - range palindrome query in O(log n)
// Each node stores (forwardHash, reverseHash) of its substring under one
// large-modulus polynomial hash. reverse(A+B) = reverse(B) + reverse(A),
// which gives the merge rule for the reverse hash below.

static const ll MOD = 1000000000000000003LL; // large prime, fits well under 2^63
static const ll BASE = 131542391927LL;

ll mulmod(ll a, ll b) {
    return (ll)((lll)a * b % MOD);
}

int n;
vector<ll> pw;
struct Node { ll fwd = 0, rev = 0; int len = 0; };
vector<Node> seg;
string str;

Node merge(const Node &L, const Node &R) {
    Node res;
    res.len = L.len + R.len;
    res.fwd = (mulmod(L.fwd, pw[R.len]) + R.fwd) % MOD;
    res.rev = (mulmod(R.rev, pw[L.len]) + L.rev) % MOD;
    return res;
}

void build(int node, int l, int r) {
    if (l == r) {
        ll v = str[l] - 'a' + 1;
        seg[node] = {v % MOD, v % MOD, 1};
        return;
    }
    int mid = (l + r) / 2;
    build(2 * node, l, mid);
    build(2 * node + 1, mid + 1, r);
    seg[node] = merge(seg[2 * node], seg[2 * node + 1]);
}

void update(int node, int l, int r, int pos, char c) {
    if (l == r) {
        ll v = c - 'a' + 1;
        seg[node] = {v % MOD, v % MOD, 1};
        return;
    }
    int mid = (l + r) / 2;
    if (pos <= mid) update(2 * node, l, mid, pos, c);
    else update(2 * node + 1, mid + 1, r, pos, c);
    seg[node] = merge(seg[2 * node], seg[2 * node + 1]);
}

Node query(int node, int l, int r, int ql, int qr) {
    if (qr < l || r < ql) return Node{0, 0, 0};
    if (ql <= l && r <= qr) return seg[node];
    int mid = (l + r) / 2;
    Node L = query(2 * node, l, mid, ql, qr);
    Node R = query(2 * node + 1, mid + 1, r, ql, qr);
    if (L.len == 0) return R;
    if (R.len == 0) return L;
    return merge(L, R);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> str;
    n = str.size();
    pw.assign(n + 1, 1);
    for (int i = 1; i <= n; i++) pw[i] = mulmod(pw[i - 1], BASE);
    seg.assign(4 * n, Node{});
    build(1, 0, n - 1);

    int q;
    cin >> q;
    while (q--) {
        int type;
        cin >> type;
        if (type == 1) {
            int pos; char c;
            cin >> pos >> c;
            update(1, 0, n - 1, pos - 1, c);
        } else {
            int a, b;
            cin >> a >> b;
            Node res = query(1, 0, n - 1, a - 1, b - 1);
            cout << (res.fwd == res.rev ? "YES" : "NO") << "\n";
        }
    }
    return 0;
}

Manacher's Algorithm

3 worked examples

Manacher's algorithm computes, for every center in a string, the radius of the longest palindrome centered there — for all n centers simultaneously in O(n), rather than the naive O(n^2) of expanding around every center independently. It is usually implemented with two arrays: d1[i], the number of odd-length palindromes centered exactly at index i (so the longest has length 2*d1[i]-1), and d2[i], the number of even-length palindromes centered between indices i-1 and i (longest length 2*d2[i]). Some implementations transform s by inserting separators (e.g. '#') between every character to unify odd and even cases into a single array; the two-array formulation used here avoids that transformation and its associated off-by-one bookkeeping.

The O(n) bound comes from the same 'reuse a previously discovered window' trick as the Z-function: maintain the rightmost palindrome boundary [l, r] found so far. When computing the radius at a new center i inside that window, mirror the already-known radius of the reflected center (l+r-i) to get a lower bound for free — because palindromic symmetry around the center of [l,r] guarantees palindromes on the mirrored side extend at least that far — and only then attempt to extend character by character past the window's edge. Since r only ever moves rightward and each brute-force extension attempt beyond r advances r by one position, the total extension work across all centers is O(n).

Beyond 'find the longest palindromic substring', the d1/d2 arrays are a general-purpose tool: summing them gives the total count of palindromic substrings in O(n) (each value d1[i] or d2[i] counts exactly that many distinct palindromic substrings centered there, since every radius from 1 up to the maximum is itself a valid, shorter palindrome). A subtler but very common transformation is converting 'longest palindrome centered at each position' into 'longest palindrome ENDING at each position' — since a center's maximal palindrome only directly tells you about the single rightmost endpoint it reaches, but every smaller radius from the same center is also a valid palindrome ending at an earlier position, so a two-pointer sweep is needed to correctly propagate the best value forward to every ending index.

Recognize it by

Manacher's is the go-to whenever a problem needs palindrome information (existence, count, or longest) for many or all centers/positions in O(n) rather than per-query O(n) or O(n^2) total — the giveaway phrase is usually 'longest palindromic substring', 'count palindromic substrings', or 'longest palindrome ending/starting at position i, for every i'.

Complexity

O(n) time, O(n) space.

Longest Palindromic Substring

Problem

Given a string s (1 <= |s| <= 10^6) of lowercase Latin letters, find its longest palindromic substring. If multiple substrings of the maximum length exist, output the leftmost one.

Approach

Run Manacher's algorithm to get d1 (odd palindromes) and d2 (even palindromes). For each center i, the odd-length candidate has length 2*d1[i]-1 starting at i-d1[i]+1, and the even-length candidate has length 2*d2[i] starting at i-d2[i]. Track the best (length, start) pair using a strict '>' comparison so the first (leftmost) occurrence of the maximum length is kept.

Solution
#include <bits/stdc++.h>
using namespace std;

void manacher(const string &s, vector<int> &d1, vector<int> &d2) {
    int n = s.size();
    d1.assign(n, 0);
    d2.assign(n, 0);
    int l = 0, r = -1;
    for (int i = 0; i < n; i++) {
        int k = (i > r) ? 1 : min(d1[l + r - i], r - i + 1);
        while (i - k >= 0 && i + k < n && s[i - k] == s[i + k]) k++;
        d1[i] = k;
        if (i + k - 1 > r) { l = i - k + 1; r = i + k - 1; }
    }
    l = 0; r = -1;
    for (int i = 0; i < n; i++) {
        int k = (i > r) ? 0 : min(d2[l + r - i + 1], r - i + 1);
        while (i - k - 1 >= 0 && i + k < n && s[i - k - 1] == s[i + k]) k++;
        d2[i] = k;
        if (i + k - 1 > r) { l = i - k; r = i + k - 1; }
    }
}

int main() {
    string s;
    getline(cin, s);
    int n = s.size();
    vector<int> d1, d2;
    manacher(s, d1, d2);

    int bestLen = 0, bestStart = 0;
    for (int i = 0; i < n; i++) {
        int len1 = 2 * d1[i] - 1;
        if (len1 > bestLen) { bestLen = len1; bestStart = i - d1[i] + 1; }
        int len2 = 2 * d2[i];
        if (len2 > bestLen) { bestLen = len2; bestStart = i - d2[i]; }
    }
    cout << bestLen << "\n";
    cout << s.substr(bestStart, bestLen) << "\n";
    return 0;
}

Counting All Palindromic Substrings

Problem

Longest Palindrome Ending at Each Position

Problem

Given a string s of length n (1 <= n <= 5*10^5), for every index e from 0 to n-1 output the length of the longest palindromic substring of s that ends exactly at index e. (Based on CSES 'All Palindromes'.)

Approach

Run Manacher to get d1 and d2. A center c with odd radius d1[c] can produce a palindrome ending at any e with c <= e <= c+d1[c]-1 (just shrink the radius), of length 2*(e-c)+1 — so for fixed e we want the SMALLEST valid center c whose reach c+d1[c]-1 covers e, to maximize the length. Because 'reach covers e' can only become false as e grows (never true again once false), a single forward-moving pointer suffices: sweep e from 0 to n-1, and while the current candidate center's reach is less than e, advance the pointer. This is an O(n) amortized two-pointer sweep, done once for odd centers and once for even centers (which contribute even-length candidates of length 2*(e-c)+2 under the analogous condition), taking the max of both for each position.

Solution
#include <bits/stdc++.h>
using namespace std;

void manacher(const string &s, vector<int> &d1, vector<int> &d2) {
    int n = s.size();
    d1.assign(n, 0);
    d2.assign(n, 0);
    int l = 0, r = -1;
    for (int i = 0; i < n; i++) {
        int k = (i > r) ? 1 : min(d1[l + r - i], r - i + 1);
        while (i - k >= 0 && i + k < n && s[i - k] == s[i + k]) k++;
        d1[i] = k;
        if (i + k - 1 > r) { l = i - k + 1; r = i + k - 1; }
    }
    l = 0; r = -1;
    for (int i = 0; i < n; i++) {
        int k = (i > r) ? 0 : min(d2[l + r - i + 1], r - i + 1);
        while (i - k - 1 >= 0 && i + k < n && s[i - k - 1] == s[i + k]) k++;
        d2[i] = k;
        if (i + k - 1 > r) { l = i - k; r = i + k - 1; }
    }
}

int main() {
    string s;
    getline(cin, s);
    int n = s.size();
    vector<int> d1, d2;
    manacher(s, d1, d2);

    vector<int> ans(n, 1); // every single character is a palindrome ending at itself

    // Odd palindromes: center c, reach R(c) = c + d1[c] - 1.
    // For end e, we want the smallest c <= e with R(c) >= e; the answer
    // contributed is 2*(e-c)+1. As e grows, the valid pointer only moves
    // forward (once R(c) < e it stays < e for all larger e), so a single
    // pointer sweep is O(n) total.
    {
        int p = 0;
        for (int e = 0; e < n; e++) {
            while (p < e && p + d1[p] - 1 < e) p++;
            if (p <= e && p + d1[p] - 1 >= e) {
                ans[e] = max(ans[e], 2 * (e - p) + 1);
            }
        }
    }
    // Even palindromes: center pair (i-1, i), reach R(i) = i + d2[i] - 1.
    // For end e, want smallest i <= e with R(i) >= e; length = 2*(e-i)+2.
    {
        int p = 0;
        for (int e = 0; e < n; e++) {
            while (p < e && p + d2[p] - 1 < e) p++;
            if (p <= e && p + d2[p] - 1 >= e) {
                ans[e] = max(ans[e], 2 * (e - p) + 2);
            }
        }
    }

    for (int i = 0; i < n; i++) cout << ans[i] << " \n"[i + 1 == n];
    return 0;
}

Trie for Strings (and Suffix Array/Automaton Basics)

2 worked examples

A trie (prefix tree) stores a set of strings by sharing common prefixes along root-to-node paths: each node has up to |alphabet| children, and a string is present in the set iff following its characters from the root lands on a node marked as an endpoint. Insertion and single-string lookup both cost O(length), and — crucially — a trie is the natural data structure the moment you have MANY patterns to search for simultaneously, since a single traversal of a text can match against every pattern sharing a prefix at once. Building a trie over all substrings (or all suffixes) of a string of length n also gives an easy, if O(n^2)-node in the worst case, way to count distinct substrings: it equals the number of nodes created (excluding the root).

The trie's real power for multi-pattern text search comes from turning it into the Aho-Corasick automaton: build the trie of all k patterns, then compute a 'failure link' for every node via BFS — analogous to the KMP failure function, but generalized to a tree of patterns instead of a single string — pointing to the longest proper suffix of the current node's path that is also a prefix of some pattern (i.e. also a node in the trie). Scanning the text once, moving along trie edges and falling back along failure links exactly like KMP, visits every position in O(1) amortized per character (with transitions precomputed, true O(1) per character), and a hit counter propagated along fail links after the scan yields, for every pattern, its total number of occurrences in the text — all in O(n + sum of pattern lengths) instead of running separate O(n) KMP passes per pattern.

When the patterns are the string's OWN suffixes rather than an external pattern set, the trie of suffixes becomes prohibitively large (O(n^2) nodes) but its compressed form is the suffix tree, and its array-based cousin is the suffix array: the starting indices of all suffixes, sorted lexicographically. A simple O(n log^2 n) construction sorts suffixes by successively doubling the compared prefix length, re-ranking pairs of previously-computed ranks each round. Once built, Kasai's algorithm computes the LCP array (longest common prefix between lexicographically adjacent suffixes) in O(n), which unlocks many classic queries: the number of distinct substrings is n(n+1)/2 minus the sum of the LCP array (every substring is a prefix of exactly one suffix, and the LCP array tells you exactly how much overlap/duplication exists between consecutive suffixes' prefixes). The suffix automaton is the further, more advanced step: a DAG with O(n) states representing every distinct substring implicitly, built online in O(n), and is generally the tool of choice once suffix-array-based solutions become too slow or intricate — well worth learning next, but its construction is sufficiently bug-prone that it deserves its own dedicated study session rather than a single worked example here.

Recognize it by

Use a plain trie whenever you're matching against a SET of patterns rather than one (prefix queries, autocomplete, or counting shared prefixes), and specifically reach for Aho-Corasick when you need to find occurrences of many patterns inside one text in a single pass. Reach for a suffix array/automaton once a problem needs global information about ALL substrings of a single string at once — counting distinct substrings, finding the k-th lexicographically smallest substring, or computing longest common substrings across strings — since those are awkward or too slow with hashing/tries alone at large n.

Complexity

Trie: O(total pattern length) to build, O(length) per query. Aho-Corasick: O(n + sum|pattern|) to build and scan. Suffix array (doubling): O(n log^2 n) to build, O(n) for the LCP array via Kasai's algorithm afterward.

Counting Occurrences of Many Patterns (Aho-Corasick)

Problem

You are given a text string T (1 <= |T| <= 2*10^5) and k patterns (1 <= k <= 2*10^5, total pattern length up to 2*10^5), all lowercase Latin letters. For each pattern (in input order), output how many times it occurs in T (occurrences may overlap).

Approach

Insert all k patterns into a trie, recording the trie node reached at the end of each pattern. Build Aho-Corasick failure links with a BFS over the trie: for the root's children, missing transitions point back to the root; for deeper nodes, the failure link of a child reached via character c from node u is next[fail[u]][c] (computed level by level so fail[u] is already finalized), and non-existent transitions are patched to point directly at next[fail[u]][c] so the automaton has O(1) transitions everywhere (no need to walk fail chains during the scan). Scan T once, following automaton transitions and incrementing a hit counter at the current node for every character. Finally, propagate hit counts along failure links from deepest to shallowest node (any pattern ending at a fail-ancestor of a matched node also just matched, since that ancestor's string is a suffix of what was matched) so each pattern's end-node holds its true total occurrence count.

Solution
#include <bits/stdc++.h>
using namespace std;

const int ALPHA = 26;

struct AhoCorasick {
    vector<array<int, ALPHA>> next_;
    vector<int> fail, link_end; // link_end unused, kept simple
    vector<long long> cnt;
    vector<int> depth;

    AhoCorasick() { newNode(); }

    int newNode() {
        next_.push_back(array<int, ALPHA>{});
        next_.back().fill(-1);
        fail.push_back(0);
        cnt.push_back(0);
        depth.push_back(0);
        return next_.size() - 1;
    }

    int addString(const string &s) {
        int cur = 0;
        for (char ch : s) {
            int c = ch - 'a';
            if (next_[cur][c] == -1) {
                next_[cur][c] = newNode();
                depth[next_[cur][c]] = depth[cur] + 1;
            }
            cur = next_[cur][c];
        }
        return cur; // node index for this pattern's end
    }

    void build() {
        queue<int> q;
        for (int c = 0; c < ALPHA; c++) {
            if (next_[0][c] == -1) next_[0][c] = 0;
            else { fail[next_[0][c]] = 0; q.push(next_[0][c]); }
        }
        vector<int> order;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            order.push_back(u);
            for (int c = 0; c < ALPHA; c++) {
                int v = next_[u][c];
                if (v == -1) {
                    next_[u][c] = next_[fail[u]][c];
                } else {
                    fail[v] = next_[fail[u]][c];
                    q.push(v);
                }
            }
        }
        bfsOrder = order;
    }

    vector<int> bfsOrder;

    void processText(const string &text) {
        int cur = 0;
        for (char ch : text) {
            cur = next_[cur][ch - 'a'];
            cnt[cur]++;
        }
        // propagate counts along fail links, from deepest to shallowest
        vector<int> order = bfsOrder;
        sort(order.begin(), order.end(), [&](int a, int b) { return depth[a] > depth[b]; });
        for (int u : order) cnt[fail[u]] += cnt[u];
    }
};

int main() {
    string text;
    getline(cin, text);
    int k;
    cin >> k;
    cin.ignore();
    vector<string> patterns(k);
    AhoCorasick ac;
    vector<int> endNode(k);
    for (int i = 0; i < k; i++) {
        getline(cin, patterns[i]);
        endNode[i] = ac.addString(patterns[i]);
    }
    ac.build();
    ac.processText(text);
    for (int i = 0; i < k; i++) {
        cout << ac.cnt[endNode[i]] << "\n";
    }
    return 0;
}

Counting Distinct Substrings via Suffix Array + Kasai's LCP

Problem

Given a string s of length n (1 <= n <= 10^5), count the number of distinct substrings of s (substrings that are equal as sequences of characters are counted once, regardless of how many positions they occur at).

Approach

Every substring of s is a prefix of exactly one suffix. If we sort all n suffixes lexicographically (the suffix array) and look at consecutive suffixes in that sorted order, the number of NEW distinct prefixes contributed by the suffix at sorted position i is (length of that suffix) minus (its longest common prefix with the previous suffix in sorted order) — because any prefix shorter than or equal to that LCP was already counted as a prefix of the previous suffix. Build the suffix array with an O(n log^2 n) doubling algorithm (sort suffixes by (rank[i], rank[i+k]) pairs, doubling k each round), compute the LCP array between lexicographically adjacent suffixes with Kasai's O(n) algorithm, and the answer is n(n+1)/2 (total substrings, counted with multiplicity by (start,end) pairs) minus the sum of the LCP array (the total overcount from shared prefixes).

Solution
#include <bits/stdc++.h>
using namespace std;

// O(n log^2 n) suffix array via doubling on (rank, rank) pairs.
vector<int> buildSuffixArray(const string &s) {
    int n = s.size();
    vector<int> sa(n), rnk(n), tmp(n);
    for (int i = 0; i < n; i++) { sa[i] = i; rnk[i] = (unsigned char)s[i]; }
    for (int k = 1; k < n; k <<= 1) {
        auto cmp = [&](int a, int b) {
            if (rnk[a] != rnk[b]) return rnk[a] < rnk[b];
            int ra = (a + k < n) ? rnk[a + k] : -1;
            int rb = (b + k < n) ? rnk[b + k] : -1;
            return ra < rb;
        };
        sort(sa.begin(), sa.end(), cmp);
        tmp[sa[0]] = 0;
        for (int i = 1; i < n; i++) tmp[sa[i]] = tmp[sa[i - 1]] + (cmp(sa[i - 1], sa[i]) ? 1 : 0);
        rnk = tmp;
        if (rnk[sa[n - 1]] == n - 1) break;
    }
    return sa;
}

// Kasai's algorithm: lcp[i] = LCP(suffix at sa[i-1], suffix at sa[i]).
vector<int> buildLCP(const string &s, const vector<int> &sa) {
    int n = s.size();
    vector<int> rnk(n), lcp(n, 0);
    for (int i = 0; i < n; i++) rnk[sa[i]] = i;
    int h = 0;
    for (int i = 0; i < n; i++) {
        if (rnk[i] > 0) {
            int j = sa[rnk[i] - 1];
            while (i + h < n && j + h < n && s[i + h] == s[j + h]) h++;
            lcp[rnk[i]] = h;
            if (h > 0) h--;
        } else {
            h = 0;
        }
    }
    return lcp;
}

int main() {
    string s;
    getline(cin, s);
    int n = s.size();
    vector<int> sa = buildSuffixArray(s);
    vector<int> lcp = buildLCP(s, sa);
    long long total = (long long)n * (n + 1) / 2;
    for (int i = 1; i < n; i++) total -= lcp[i];
    cout << total << "\n";
    return 0;
}

Suffix Automaton

2 worked examples

A suffix automaton (SAM) of a string s is the smallest deterministic automaton that accepts exactly the set of suffixes of s (equivalently, every substring of s corresponds to exactly one path from the initial state). It has at most 2n-1 states and 3n-4 transitions for a string of length n, and can be built online in O(n) amortized time (over a constant alphabet) by appending one character at a time. Each state represents an equivalence class of substrings that share the same set of ending positions in s (their "endpos" set); crucially, all substrings in one class are suffixes of one another, so a state is fully described by an interval of lengths (len[link[state]]+1 .. len[state]) — every length in that interval corresponds to exactly one distinct substring belonging to that state.

Construction extends the automaton one character at a time, maintaining a pointer 'last' to the state representing the whole string built so far. Extending with character c creates a new state 'cur' for the whole new string, then walks up the suffix-link chain from 'last' adding transitions on c to 'cur' until either running off the automaton (link cur to the root) or finding a state p that already has a transition on c to some state q. If len[p]+1 == len[q], q's endpos class is fully compatible and cur links directly to q; otherwise q must be split by CLONING it into a new state with len[p]+1 (copying q's transitions and suffix link), redirecting the walked transitions to the clone, and linking both q and cur to the clone. This cloning step, and getting the redirection loop exactly right, is the single most bug-prone part of the whole structure.

The suffix LINKS themselves form a tree (the 'link tree' or 'parent tree') on the automaton's states, and this tree is where almost all of SAM's power for competitive programming comes from: the number of times a substring occurs in s (the size of its endpos set) equals the sum, over its own state and every state below it in the link tree, of a seed count of 1 assigned to states created as the direct target of an extension (not clones) — computed with one pass processing states in decreasing order of len (a valid reverse-topological order, since link[state] always has strictly smaller len than state). Total distinct substrings, distinct substrings of each exact length, longest repeated substring, and multi-string generalizations (generalized SAM) all reduce to a walk or DP over this same link tree.

A critical implementation detail is that the endpos/occurrence counter array must be seeded ONLY for freshly created non-clone states (seed = 1) and left at 0 for clones, and this counter array must be exactly aligned index-for-index with the state array from the very first (root) state onward — an off-by-one alignment slip here silently shifts every count by one state and produces plausible-looking but wrong answers, which is exactly the kind of bug that stress testing against an O(n^2) brute-force substring enumeration will catch immediately.

Recognize it by

The problem is about a single (possibly very long, up to 10^5-10^6) string and asks about ALL of its substrings at once: counting distinct substrings (in total, by length, or under some cost/letter constraint), finding the longest substring that repeats, finding the k-th lexicographically smallest distinct substring, or comparing substring occurrence patterns. If you find yourself wanting 'one state per distinct substring, sharing structure between substrings that always co-occur,' that's a suffix automaton (or, for identical needs on multiple strings, a generalized suffix automaton).

Complexity

O(n) states/transitions and O(n) (amortized, constant alphabet) or O(n log alphabet) construction time and space; most link-tree DPs on top of the automaton (counting, length-distribution, cost-constrained counting) are an additional O(n) or O(n log n).

Longest Duplicated Substring

Problem

Given a string s of lowercase English letters (1 <= |s| <= 3*10^4), find the length of the longest substring of s that occurs at least twice. The two occurrences are allowed to overlap. If no substring repeats, output 0.

Input: a single line containing s.
Output: a single integer, the length of the longest substring occurring at least twice.

Approach

Build the suffix automaton of s online, one character at a time, using the classic extend() procedure (new state 'cur' for the whole prefix seen so far, walk suffix links adding c-transitions, clone when a transition target's len doesn't match p.len+1).

While building, seed cnt[state] = 1 for every freshly created non-clone state (cur) and cnt[state] = 0 for every clone; every other state (in particular the root) also needs an explicit 0 entry so the cnt array stays aligned with the state array. After construction, sort states by len and process them from LARGEST len to SMALLEST, adding cnt[state] into cnt[link[state]] — this is a valid processing order because link[state] always has strictly smaller len than state, so by the time we push a state's count upward, that state's own count is already finalized.

After this propagation, cnt[state] equals the number of end positions (the size of the endpos set) of every substring represented by that state — i.e. how many times those substrings occur in s. The substring is duplicated (occurs at least twice, overlaps allowed) exactly when cnt[state] >= 2, and the longest such substring for that state has length len[state]. The answer is the maximum len[state] over all states (excluding the initial empty-string root) with cnt[state] >= 2. This was cross-checked against an O(n^2) brute force that enumerates every substring into a frequency map, with zero mismatches over 500 random small strings, and it correctly reduces 'banana' to 3 (the substring 'ana', which occurs starting at index 1 and index 3, overlapping at index 3).

Solution
#include <bits/stdc++.h>
using namespace std;

struct SAM {
    struct State {
        int len, link;
        array<int,26> nxt;
        State() : len(0), link(-1) { nxt.fill(-1); }
    };
    vector<State> st;
    vector<long long> cnt;
    int last;
    SAM() {
        st.push_back(State());
        st[0].len = 0; st[0].link = -1;
        cnt.push_back(0); // keep cnt[] aligned with st[] (root has no seed occurrence)
        last = 0;
    }
    void extend(char ch) {
        int c = ch - 'a';
        int cur = st.size();
        st.push_back(State());
        st[cur].len = st[last].len + 1;
        cnt.push_back(1); // real occurrence seed, clones fixed to 0 later
        int p = last;
        while (p != -1 && st[p].nxt[c] == -1) {
            st[p].nxt[c] = cur;
            p = st[p].link;
        }
        if (p == -1) {
            st[cur].link = 0;
        } else {
            int q = st[p].nxt[c];
            if (st[p].len + 1 == st[q].len) {
                st[cur].link = q;
            } else {
                int clone = st.size();
                st.push_back(State());
                st[clone].len = st[p].len + 1;
                st[clone].link = st[q].link;
                st[clone].nxt = st[q].nxt;
                cnt.push_back(0);
                while (p != -1 && st[p].nxt[c] == q) {
                    st[p].nxt[c] = clone;
                    p = st[p].link;
                }
                st[q].link = clone;
                st[cur].link = clone;
            }
        }
        last = cur;
    }
};

int main(){
    string s;
    cin >> s;
    SAM sam;
    for (char c : s) sam.extend(c);
    int n = sam.st.size();
    // order states by len ascending using counting sort, then propagate cnt to links in descending len order
    vector<int> order(n);
    iota(order.begin(), order.end(), 0);
    sort(order.begin(), order.end(), [&](int a, int b){ return sam.st[a].len < sam.st[b].len; });
    for (int i = n - 1; i >= 0; i--) {
        int v = order[i];
        int link = sam.st[v].link;
        if (link >= 0) sam.cnt[link] += sam.cnt[v];
    }
    long long best = 0;
    for (int v = 1; v < n; v++) {
        if (sam.cnt[v] >= 2) best = max(best, (long long)sam.st[v].len);
    }
    cout << best << endl;
}

Distinct Substrings By Exact Length

Problem

Given a string s of lowercase English letters (1 <= |s| <= 10^5), for every length L from 1 to |s|, output the number of DISTINCT substrings of s whose length is exactly L.

Input: a single line containing s.
Output: |s| integers on one line, separated by spaces: the number of distinct substrings of length 1, length 2, ..., length |s|.

Approach

Build the suffix automaton of s (this example needs only len[] and link[] — no occurrence counting is required). The key structural fact is that every non-root state represents a contiguous, non-overlapping-across-states range of substring lengths: state v is responsible for exactly one distinct substring of each length in (len[link[v]], len[v]], and no two different states are ever responsible for the same length AND represent the same substring (different states never represent the same substring by construction), while every distinct substring of s is represented by exactly one state at exactly one length. So the number of distinct substrings of exact length L is simply the number of states v with len[link[v]] < L <= len[v].

This range-counting is done with a difference array: for every non-root state v, add +1 at position len[link[v]]+1 and -1 at position len[v]+1 of an array diff[1..n+1], then take a running prefix sum over diff[1..n] to get, for each L, the count of states whose range covers L — which is exactly the answer for that length. This runs in O(n) after the O(n) SAM construction. Verified against an O(n^2) brute force that inserts every substring of every length into a set and reports its size, with zero mismatches over 500 random small strings (and by hand for 'abab', which correctly yields 2 2 2 1 for lengths 1..4: {a,b}, {ab,ba}, {aba,bab}, {abab}).

        ans[L] = running;

    }
}

Aho-Corasick Multi-Pattern Matching

2 worked examples

Aho-Corasick generalizes KMP's failure function from one pattern to a whole DICTIONARY of patterns at once. First, all patterns are inserted into a trie (each node is a distinct prefix shared by one or more patterns). Then, a BFS over the trie (by increasing depth) computes a FAILURE LINK for every node: fail[v] points to the node representing the longest proper suffix of v's string that is also a prefix of some pattern (i.e. also exists as some trie node) — exactly the same idea as the KMP failure function, generalized to a tree of patterns instead of one linear pattern.

The construction is normally done by converting the trie into a full deterministic automaton (a 'goto' function) during the same BFS: for a node u already popped from the queue (so fail[u] is known) and for every letter c, if u already has a child on c, that child's fail link is set to whatever node fail[u] transitions to on c, and it's enqueued; if u has NO child on c, then u's own transition on c is DEFINED to be exactly fail[u]'s transition on c. Because fail[u] has strictly smaller depth than u, and BFS processes nodes in increasing-depth order, fail[u]'s transitions are already fully resolved (finalized) by the time u is processed, so this recursive-looking definition is well-founded and can be computed in a single BFS pass, producing an automaton where every state has a defined transition for every letter (never falling off), letting you scan a text in exactly O(text length) additional transitions with no backtracking, regardless of how many patterns there are.

Once built, feeding the text through the automaton one character at a time visits a sequence of states; the state after processing the first i characters is the node representing the LONGEST suffix of text[0..i-1] that matches some prefix of some pattern. Critically, every pattern that occurs ending exactly at position i is represented by some node on the FAIL-LINK CHAIN from that current state up to the root (the current state itself, or its fail-link, or its fail-link's fail-link, and so on) — because a shorter matching pattern ending at the same position is, by definition, a suffix of the longest match, and the fail-link chain is precisely the chain of decreasing-length suffixes that are also trie prefixes.

This fail-chain structure is exactly a tree (the 'fail tree', rooted at the trie root), and it is the reason many hard Aho-Corasick problems reduce to a SUBTREE AGGREGATION over this tree: if you record a raw per-node quantity at scan time (a hit count, an earliest-visit timestamp, a value to maximize), then propagate it from every node into its fail-parent — processing nodes in decreasing BFS depth so each node's contribution is folded upward exactly once — the aggregated value at any pattern-node ends up correctly combining information from every text position where that pattern was 'on the fail-chain' of the automaton's actual state, not just positions where it was the literal longest match. Getting the propagation DIRECTION right (always from higher depth into lower depth, i.e. child into fail-parent, regardless of whether the aggregate is a sum, a min, or a max) is the step most often gotten backwards.

Recognize it by

You are given a (typically large) text and a collection of patterns (rather than just one pattern as in single-pattern matching), and need, for every pattern (or for the best pattern at each text position), some aggregate over its occurrences: how many times it occurs, where it first/last occurs, or the maximum weight among all patterns occurring at/before a position. Whenever 'multiple patterns matched simultaneously against one text' appears, especially with total pattern length bounded (e.g. sum of |pattern_i| <= 5*10^5) rather than each individually, that is the Aho-Corasick signal.

Complexity

O(total pattern length * alphabet size) or O(total pattern length) (with a hash-map/array transition table) to build the automaton; O(|text|) to scan the text once patterns are built; most fail-tree aggregation post-processing is an additional O(number of automaton nodes).

Counting Pattern Occurrences

Problem

You are given a text string t and k pattern strings p_1..p_k (all lowercase English letters, 1 <= |t|, sum of |p_i| <= 2*10^5). For each pattern p_i, count the number of times it occurs as a substring of t (occurrences may overlap).

Input: the text t on the first line, then k on the next line, then k lines each containing one pattern.
Output: k integers on one line, separated by spaces: the occurrence count of each pattern, in the order given.

Approach

Build an Aho-Corasick automaton over all k patterns (trie + BFS-computed fail links, converted into a full goto-automaton so every node has a transition for every letter). Scan the text once, maintaining the current automaton state; at every text position, increment a raw hit-counter hit[state] for whatever state the automaton is currently in.

After scanning, propagate hit counts up the fail tree: process automaton nodes in decreasing BFS-depth order (i.e. iterate the BFS order in reverse) and, for each node u, add hit[u] into hit[fail[u]]. This works because a node v ends up on the fail-chain of exactly the nodes in v's own fail-subtree, so folding each node's raw count into its fail-parent, deepest first, accumulates into hit[v] the total count of text positions where the pattern ending at v was on the fail-chain of the automaton's actual (longest-match) state — which is exactly the number of times that pattern occurs in the text.

Finally, for each pattern p_i, walk it once more through the (now fully built) automaton from the root to find the node it ends at, and report hit[that node]. Verified against an O(|t| * |p_i|) brute-force substring scan for every pattern, with zero mismatches over 300 random small (text, pattern-set) pairs; the worked example ('abcbcabc' against 'abc','bc','c','z') gives 2, 3, 3, 0, matching a manual count.

Solution
#include <bits/stdc++.h>
using namespace std;

const int ALPHA = 26;

struct AhoCorasick {
    vector<array<int,ALPHA>> nxt;
    vector<int> fail;
    int newNode() {
        nxt.push_back(array<int,ALPHA>{});
        nxt.back().fill(-1);
        fail.push_back(0);
        return (int)nxt.size() - 1;
    }
    AhoCorasick() { newNode(); } // node 0 = root
    void addPattern(const string &p) {
        int cur = 0;
        for (char ch : p) {
            int c = ch - 'a';
            if (nxt[cur][c] == -1) nxt[cur][c] = newNode();
            cur = nxt[cur][c];
        }
    }
    vector<int> bfsOrder;
    void build() {
        queue<int> q;
        for (int c = 0; c < ALPHA; c++) {
            if (nxt[0][c] == -1) nxt[0][c] = 0;
            else { fail[nxt[0][c]] = 0; q.push(nxt[0][c]); }
        }
        while (!q.empty()) {
            int u = q.front(); q.pop();
            bfsOrder.push_back(u);
            for (int c = 0; c < ALPHA; c++) {
                int v = nxt[u][c];
                if (v == -1) {
                    nxt[u][c] = nxt[fail[u]][c];
                } else {
                    fail[v] = nxt[fail[u]][c];
                    q.push(v);
                }
            }
        }
    }
};

int main(){
    string text;
    cin >> text;
    int k;
    cin >> k;
    vector<string> pats(k);
    for (auto &p : pats) cin >> p;

    AhoCorasick ac;
    for (int i = 0; i < k; i++) ac.addPattern(pats[i]);
    ac.build();

    int nodes = ac.nxt.size();
    vector<long long> hit(nodes, 0);
    int cur = 0;
    for (char ch : text) {
        cur = ac.nxt[cur][ch - 'a'];
        hit[cur]++;
    }
    // propagate hit counts up the fail-link tree: process nodes in order of
    // DEcreasing depth so a child's contribution reaches its parent exactly once.
    // BFS order (ac.bfsOrder) is increasing depth, so traverse it in reverse.
    for (int i = (int)ac.bfsOrder.size() - 1; i >= 0; i--) {
        int u = ac.bfsOrder[i];
        hit[ac.fail[u]] += hit[u];
    }

    vector<long long> ans(k, 0);
    // total occurrences of pattern i = hit[node where pattern i ends]
    for (int i = 0; i < k; i++) {
        int node = 0;
        for (char ch : pats[i]) node = ac.nxt[node][ch - 'a'];
        ans[i] = hit[node];
    }
    for (int i = 0; i < k; i++) cout << ans[i] << (i + 1 < k ? ' ' : '\n');
}

First Occurrence Position of Each Pattern

Problem

You are given a text string t and k pattern strings p_1..p_k (all lowercase English letters, 1 <= |t|, sum of |p_i| <= 2*10^5). For each pattern p_i, report the 1-indexed starting position of its EARLIEST occurrence in t as a substring, or -1 if p_i never occurs in t.

Input: the text t on the first line, then k on the next line, then k lines each containing one pattern.
Output: k integers on one line, separated by spaces: the earliest 1-indexed starting position of each pattern (or -1), in the order given.

Approach

Build the Aho-Corasick automaton over all patterns exactly as before. While scanning the text, instead of a hit COUNT, record firstVisit[state] = the earliest 1-indexed text position after which the automaton's current state is exactly that state (i.e. the smallest i such that after reading t[0..i-1], the automaton is in that state); states never directly visited keep a sentinel of +infinity.

The key aggregation is again over the fail tree, but note carefully which quantity is being aggregated: a pattern node v is 'active' (its pattern occurs ending at position i) whenever v lies anywhere on the fail-chain of the automaton's actual state at position i -- which means v could be an ANCESTOR, in the fail-chain sense, of a node that was directly visited even though v itself was never the literal longest-match state. So earliest[v] must equal the minimum firstVisit over v's entire fail-SUBTREE (v and everything that folds into v via repeated fail links), which -- exactly like the sum in the previous example -- is computed by processing nodes in decreasing BFS-depth order and relaxing earliest[fail[u]] = min(earliest[fail[u]], earliest[u]) for each node u (folding a node's value into its fail-PARENT, never the other way around).

For each pattern p_i, walk it through the automaton once to find its ending node, read off earliest[node] as the earliest END position, then subtract |p_i|-1 to get the earliest START position (or report -1 if earliest[node] is still infinity). This direction is easy to get backwards -- an initial implementation that instead computed earliest[v] = min(firstVisit[v], earliest[fail[v]]) top-down looked plausible but silently missed occurrences and was caught immediately by comparing against an O(|t|*|p_i|) brute-force substring search on random small inputs before being corrected to the bottom-up (child-into-fail-parent) direction shown here; 300 random stress tests now pass with zero mismatches.

        fail.push_back(0);

        for (char ch : p) {
            int c = ch - 'a';
            if (nxt[cur][c] == -1) nxt[cur][c] = newNode();
            cur = nxt[cur][c];
        }
    }
    vector<int> bfsOrder;

        queue<int> q;
        for (int c = 0; c < ALPHA; c++) {
            if (nxt[0][c] == -1) nxt[0][c] = 0;
            else { fail[nxt[0][c]] = 0; q.push(nxt[0][c]); }
        }
        while (!q.empty()) {
            int u = q.front(); q.pop();
            bfsOrder.push_back(u);
            for (int c = 0; c < ALPHA; c++) {
                int v = nxt[u][c];
                if (v == -1) nxt[u][c] = nxt[fail[u]][c];
                else { fail[v] = nxt[fail[u]][c]; q.push(v); }
            }
        }
    }

    string text;
    cin >> text;
    int k;
    cin >> k;
    vector<string> pats(k);
    for (auto &p : pats) cin >> p;

    AhoCorasick ac;
    for (auto &p : pats) ac.addPattern(p);
    ac.build();

    int nodes = ac.nxt.size();
    // firstVisit[v] = earliest 1-indexed text position after which the automaton
    // state is exactly v (i.e. the trie path to v is a suffix of text[0..pos-1]).
    vector<long long> firstVisit(nodes, INF);
    int cur = 0;
    for (int i = 0; i < (int)text.size(); i++) {
        cur = ac.nxt[cur][text[i] - 'a'];
        firstVisit[cur] = min(firstVisit[cur], (long long)(i + 1)); // 1-indexed end position
    }
    // Pattern v occurs ending at text position p iff v lies on the fail-chain of
    // whatever node the automaton is in after reading p characters. So
    // earliest[v] = min firstVisit[u] over v itself and every node u that has v as
    // a fail-ancestor (u lies in v's fail-subtree). This is the same "aggregate
    // over the fail-subtree" shape as the hit-count trick in the previous example,
    // just with min instead of sum, so it must be propagated from deeper nodes
    // toward the root (children into fail[child]), i.e. BFS order reversed.
    vector<long long> earliest = firstVisit;
    for (int i = (int)ac.bfsOrder.size() - 1; i >= 0; i--) {
        int u = ac.bfsOrder[i];
        earliest[ac.fail[u]] = min(earliest[ac.fail[u]], earliest[u]);
    }

    for (int i = 0; i < k; i++) {
        int node = 0;
        for (char ch : pats[i]) node = ac.nxt[node][ch - 'a'];
        long long endPos = earliest[node];
        if (endPos >= INF) cout << -1;
        else cout << (endPos - (long long)pats[i].size() + 1); // 1-indexed start position
        cout << (i + 1 < k ? ' ' : '\n');
    }
}

Palindromic Tree (Eertree)

2 worked examples

An Eertree (palindromic tree) is a structure that maintains, incrementally as characters are appended to a string, exactly one node per DISTINCT palindromic substring seen so far, together with a 'suffix link' tree on those nodes analogous to the suffix automaton's link tree. It uses a clever two-root trick: an imaginary root of length -1 (representing an 'odd' seed so that appending one matching character on both sides produces a length-1 palindrome) and a real root of length 0 (the empty string, seed for 'even' palindromes), with the imaginary root's own suffix link pointing to itself.

Each node stores its length and a suffix link to the node representing its longest proper palindromic SUFFIX that is also a palindromic prefix of it (equivalently: the longest palindrome that is itself a suffix of this palindrome, other than itself) -- since a palindrome's own suffixes and prefixes coincide, this is well-defined and always strictly shorter, exactly mirroring how a suffix automaton's suffix links always point to a strictly-shorter-length state. Because every palindrome's suffix-link ancestor chain strictly decreases in length, the suffix links again form a genuine tree with the two roots at the top, and this is a valid topological order for any bottom-up aggregation (process nodes by decreasing length, exactly like the suffix automaton's link-tree DP).

Inserting a new character c means finding the longest palindromic SUFFIX of the string-so-far such that prepending c to it (and implicitly appending c, since it's a palindrome) still forms a valid palindrome -- checked by walking UP the suffix-link chain from the previous 'last' pointer, testing at each candidate node v whether the character immediately before v's palindrome in the current string equals c. If a transition already exists from that node on c, 'last' becomes that existing node (the palindrome already occurred before, no new distinct palindrome is created). Otherwise a brand-new node is created with length = candidate.length + 2, and its OWN suffix link is found by continuing to walk up the suffix-link chain from the candidate's own suffix link (not from the candidate itself) to find the next node where prepending c also works -- this second, nested suffix-link search (needed only when creating a genuinely new node) is the step most implementations get subtly wrong, e.g. by reusing the wrong starting point or forgetting the length-1 special case (which must link directly to the length-0 root rather than running the general search).

Because at most one NEW distinct palindrome node can be created per character appended (the total number of distinct palindromic substrings of a length-n string is at most n+1, counting the two roots), an Eertree over a string of length n has at most n+2 nodes, and can be built in O(n) amortized time (using the small-to-large / doubling argument on how far the suffix-link search can walk, exactly as in Manacher's algorithm and the suffix automaton). After insertion i, the 'last' pointer directly gives the longest palindromic suffix ending at position i -- the single most direct exercise of the structure -- while more advanced problems attach an occurrence counter per node, seeded at 1 whenever 'last' becomes that node during any insertion, and aggregated up the suffix-link tree afterward (bottom-up, deepest length first, exactly mirroring the suffix automaton's endpos-size computation) to get the true total occurrence count of every distinct palindrome, from which sums like 'total number of palindromic substrings counting multiplicity' fall out directly.

Recognize it by

The problem is fundamentally about PALINDROMIC substrings of a string: the longest palindrome ending at (or centered at) every position, the count of distinct palindromic substrings, the total number of palindromic-substring occurrences, or anything requiring efficient 'is this exact substring a palindrome' plus 'jump to the next shorter palindromic suffix' queries. If Manacher's algorithm only gets you palindrome LENGTHS but the problem also wants to reason about which palindromes recur, are nested, or need to be counted/DP'd over, that additional structure is exactly what the Eertree's node graph and suffix-link tree provide.

Complexity

O(n) amortized time and O(n) space to build (at most n+2 nodes for a length-n string, each with an alphabet-sized transition array or map); occurrence-count and other suffix-link-tree aggregations are an additional O(n) (or O(n log n) with map-based transitions instead of arrays).

Longest Palindromic Suffix at Every Position

Problem

Given a string s of lowercase English letters (1 <= |s| <= 2*10^5), for every position i from 1 to |s|, output the length of the longest palindromic substring of s that ENDS exactly at position i (i.e. the longest palindromic suffix of the prefix s[1..i]).

Input: a single line containing s.
Output: |s| integers on one line, separated by spaces.

Approach

Build the Eertree incrementally, appending one character of s at a time. The construction maintains a pointer 'last' to the node representing the longest palindromic suffix of the string built SO FAR; by definition, immediately after inserting the i-th character, last's length IS the answer for position i, so this problem requires no extra post-processing beyond correctly implementing the core add() operation.

add(c) works as follows: starting from 'last', walk up suffix links until reaching a node v (a candidate palindrome) such that the character immediately preceding v's occurrence in the current string equals c (checked via the string's length and v's own length: the required position is currentLength - v.length - 2, using the imaginary root's length -1 to make the base case for brand-new length-1 palindromes fall out automatically). If v already has a transition on c, 'last' becomes that existing target (this exact palindrome already occurred). Otherwise, create a new node of length v.length+2; its suffix link is found by continuing the same upward walk starting from v's OWN suffix link (a second, independent search, not reusing v), with the length-1 case special-cased to link directly to the empty-string root. Record v's new transition on c to the new node, and set 'last' to it.

Verified by hand-tracing the classic example s = 'abacaba', which must produce 1 1 3 1 3 5 7 (longest palindromic suffixes 'a','b','aba','c','aca','bacab','abacaba'), and cross-checked against an O(n^2) brute force that tests every suffix-of-a-prefix for being a palindrome, with zero mismatches over 500 random small strings.

Solution
#include <bits/stdc++.h>
using namespace std;

struct Eertree {
    string s;
    vector<int> len, link;
    vector<array<int,26>> nxt;
    int last;
    Eertree() {
        // node 0 = imaginary root, len = -1, links to itself
        len.push_back(-1); link.push_back(0);
        nxt.push_back(array<int,26>{}); nxt[0].fill(0);
        // node 1 = empty-string root, len = 0, links to node 0
        len.push_back(0); link.push_back(0);
        nxt.push_back(array<int,26>{}); nxt[1].fill(0);
        last = 1;
    }
    int getLink(int v) {
        int n = (int)s.size();
        while (true) {
            int curLen = len[v];
            int pos = n - curLen - 2; // index of char that must equal s.back()
            if (pos >= 0 && s[pos] == s.back()) return v;
            v = link[v];
        }
    }
    // returns len[last] after inserting c
    int add(char c) {
        s.push_back(c);
        int c_idx = c - 'a';
        int cur = getLink(last);
        if (!nxt[cur][c_idx]) {
            int now = (int)len.size();
            len.push_back(len[cur] + 2);
            nxt.push_back(array<int,26>{}); nxt.back().fill(0);
            if (len[now] == 1) {
                link.push_back(1);
            } else {
                int sufLink = getLink(link[cur]);
                link.push_back(nxt[sufLink][c_idx]);
            }
            nxt[cur][c_idx] = now;
        }
        last = nxt[cur][c_idx];
        return len[last];
    }
};

int main(){
    string s;
    cin >> s;
    Eertree tree;
    vector<int> ans;
    for (char c : s) ans.push_back(tree.add(c));
    for (int i = 0; i < (int)ans.size(); i++) cout << ans[i] << (i+1<(int)ans.size()? ' ' : '\n');
}

Total Palindromic Substrings (Counting Multiplicity)

Problem

Given a string s of lowercase English letters (1 <= |s| <= 2*10^5), count the total number of palindromic substrings of s, where the SAME palindrome occurring at different positions is counted once for each occurrence (so 'aaa' has 6 palindromic substrings: three of length 1, two of length 2, one of length 3).

Input: a single line containing s.
Output: a single integer, the total count.

Approach

Build the Eertree over s exactly as before, but additionally maintain an occurrence counter occ[node], incremented by 1 every time 'last' becomes that node during ANY insertion (whether the node was freshly created or already existed) -- this seed correctly reflects 'this exact palindrome was the longest palindromic suffix ending at this position' at least once per insertion where it applies directly.

After processing the whole string, propagate these seed counts up the suffix-link tree so that shorter palindromes correctly accumulate the occurrences of every longer palindrome that has them as a palindromic suffix (e.g. every occurrence of 'aaa' also implies an occurrence of 'aa' and of 'a' ending at the same position, which the seed-counting alone does not directly capture for 'aa' and 'a'). This is done by sorting nodes by length in DEcreasing order (a valid topological order since suffix links always point to strictly shorter nodes) and, for each node v (skipping the two imaginary/empty roots), adding occ[v] into occ[link[v]].

After this propagation, occ[v] equals the true number of times the palindrome represented by v occurs as a substring of s, so the final answer is simply the sum of occ[v] over every real node (excluding the two roots). Verified against an O(n^2) brute force that tests every substring for being a palindrome and sums matches directly, with zero mismatches over 500 random small strings; 'aaa' correctly yields 6 and 'abacaba' correctly yields 12.

Solution
#include <bits/stdc++.h>
using namespace std;

struct Eertree {
    string s;
    vector<int> len, link;
    vector<long long> occ;
    vector<array<int,26>> nxt;
    int last;
    Eertree() {
        len.push_back(-1); link.push_back(0); occ.push_back(0);
        nxt.push_back(array<int,26>{}); nxt[0].fill(0);
        len.push_back(0); link.push_back(0); occ.push_back(0);
        nxt.push_back(array<int,26>{}); nxt[1].fill(0);
        last = 1;
    }
    int getLink(int v) {
        int n = (int)s.size();
        while (true) {
            int curLen = len[v];
            int pos = n - curLen - 2;
            if (pos >= 0 && s[pos] == s.back()) return v;
            v = link[v];
        }
    }
    void add(char c) {
        s.push_back(c);
        int c_idx = c - 'a';
        int cur = getLink(last);
        if (!nxt[cur][c_idx]) {
            int now = (int)len.size();
            len.push_back(len[cur] + 2);
            occ.push_back(0);
            nxt.push_back(array<int,26>{}); nxt.back().fill(0);
            if (len[now] == 1) {
                link.push_back(1);
            } else {
                int sufLink = getLink(link[cur]);
                link.push_back(nxt[sufLink][c_idx]);
            }
            nxt[cur][c_idx] = now;
        }
        last = nxt[cur][c_idx];
        occ[last]++; // this node was the longest palindromic suffix ending here
    }
};

int main(){
    string s;
    cin >> s;
    Eertree tree;
    for (char c : s) tree.add(c);
    int total = (int)tree.len.size();
    // propagate occurrence counts along suffix links: link[v] always has strictly
    // smaller len than v, so sorting by len descending gives a valid processing
    // order (every node is finalized before its suffix-link target is updated).
    vector<int> order(total);
    iota(order.begin(), order.end(), 0);
    sort(order.begin(), order.end(), [&](int a, int b){ return tree.len[a] > tree.len[b]; });
    for (int v : order) {
        if (v <= 1) continue; // skip the two imaginary roots
        tree.occ[tree.link[v]] += tree.occ[v];
    }
    long long answer = 0;
    for (int v = 2; v < total; v++) answer += tree.occ[v];
    cout << answer << endl;
}
