Dynamic Programming

Dynamic programming (DP) solves problems that exhibit optimal substructure (an optimal solution can be built from optimal solutions to subproblems) and overlapping subproblems (the same subproblem recurs many times during a naive recursive solution). Instead of recomputing shared subproblems exponentially many times, DP either memoizes them (caches results of a top-down recursion) or tabulates them (fills a bottom-up table in an order that respects dependencies), reducing runtime from exponential to polynomial. The entire skill of DP is: define a state precisely enough that it captures everything future decisions depend on, write a correct recurrence (transition) between states, and get the base cases and evaluation order right — everything below is a set of recognizable patterns for doing that. Beyond the core patterns, these techniques extend DP to specific structures (bitmasks, trees, digit positions, DAGs, adversarial games, randomness) and to optimizing the DP transition itself so an O(n^2) or O(n^3) recurrence runs in O(n log n) or O(n).

DP Fundamentals

2 worked examples

Every DP solution rests on three ingredients: a **state** (a tuple of parameters that fully describes a subproblem), a **transition/recurrence** (how a state's answer is computed from smaller/earlier states), and **base cases** (the smallest subproblems solved directly, without recursion). A recursive brute force becomes DP the moment you notice the recursion tree revisits identical (state) calls repeatedly — overlapping subproblems. Two implementation strategies compute the same recurrence: memoization (top-down) writes the recursion exactly as you'd think of it recursively, and wraps it in a cache (array or hash map) so each distinct state is computed once; tabulation (bottom-up) instead iterates over states in an order guaranteeing every state's dependencies are already filled in, storing answers in a table (usually an array).

Memoization is easier to derive correctly (you write the natural recursion and add a cache check at the top and a cache write before every return) and it only computes states that are actually reachable from the initial call, which matters when the full state space is large but the reachable subset is small. Tabulation is usually faster in practice (no recursion/function-call overhead, better cache locality) and makes space optimization straightforward — if dp[i] only depends on dp[i-1] and dp[i-2], you can drop the array to O(1) rolling variables, something far more awkward to see through a memoized recursion. The two are mechanically interchangeable: any tabulated DP can be rewritten top-down and vice versa, so in practice you pick whichever is easier to reason about for the recurrence at hand, then switch to the other if you hit its weaknesses (stack depth for memoization on deep recursion, unreachable-state waste for tabulation).

A state definition is correct if and only if it satisfies the **Markov / optimal-substructure property**: the best way to complete a state depends only on the state itself, not on how you arrived there. If two different histories reach 'the same' state but require different future decisions, the state is under-specified and must be enlarged (this is exactly what upgrades naive greedy attempts into DP with extra dimensions).

Recognize it by

Suspect DP when a problem asks for an optimum (min/max), a count of ways, or a yes/no feasibility over a search space that is exponential if you tried all possibilities directly, AND you can describe a smaller version of the same problem that a full solution decomposes into (i.e., 'the answer for n depends on the answer for some smaller n''). If greedy 'obviously' fails on some case, or brute-force recursion clearly repeats identical subcalls, that's a strong DP signal.

Complexity

Complexity is (number of distinct states) x (work per transition). Memoization and tabulation have identical asymptotic complexity for the same recurrence; tabulation usually has a smaller constant factor and enables O(states) -> O(1)-per-layer space optimization via rolling arrays when the recurrence only reaches back a bounded number of previous layers.

Coin Change — Minimum Coins (Bottom-Up Tabulation)

Problem

You are given n coin denominations and a target amount. Determine the minimum number of coins (unlimited supply of each denomination) needed to make exactly that amount, or report -1 if it is impossible.
Constraints: 1 <= n <= 100, 1 <= coin value <= 10^4, 0 <= amount <= 10^4.

Approach

Define dp[x] = minimum coins to make amount x, with dp[0] = 0 as the base case (zero coins needed for zero amount). For every amount x from 1 up to the target, and for every coin c <= x, dp[x] = min(dp[x], dp[x - c] + 1) — you are trying 'what if the last coin used was c', and the rest (x - c) is a strictly smaller subproblem already solved because we iterate x in increasing order (bottom-up tabulation). Initialize all dp entries to infinity except dp[0]; if dp[amount] is still infinity at the end, it is unreachable, so print -1. This is the unbounded-knapsack recurrence (each coin may be reused, which is exactly why the inner loop iterates coins for a fixed x rather than the other way around with a descending sweep, the way bounded 0/1 knapsack requires).

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; long long amount;
    cin >> n >> amount;
    vector<long long> coins(n);
    for (auto &c : coins) cin >> c;
    const long long INF = LLONG_MAX / 2;
    vector<long long> dp(amount + 1, INF);
    dp[0] = 0;
    for (long long x = 1; x <= amount; x++) {
        for (long long c : coins) {
            if (c <= x && dp[x - c] + 1 < dp[x]) dp[x] = dp[x - c] + 1;
        }
    }
    if (dp[amount] >= INF) cout << -1 << endl;
    else cout << dp[amount] << endl;
    return 0;
}

Longest Increasing Subsequence Length (Top-Down Memoization)

Problem

Given an array of n integers, find the length of the longest strictly increasing subsequence (elements need not be contiguous).
Constraints: 1 <= n <= 2500.

Approach

Define lis(i) = length of the longest strictly increasing subsequence that ends exactly at index i. The recurrence is lis(i) = 1 + max(lis(j)) over all j < i with a[j] < a[i], or just 1 if no such j exists (the subsequence containing only a[i]). Written as a plain recursive function this naturally calls lis(j) for every j < i, and the same lis(j) gets requested again for every larger i — classic overlapping subproblems — so we memoize with an array memo[i] initialized to -1 (uncomputed). The final answer is max(lis(i)) over all i, since the longest increasing subsequence can end anywhere. This is the O(n^2) DP (as opposed to the O(n log n) patience-sorting method), presented top-down to contrast with the bottom-up tabulation used in the coin-change example above — note it computes lis(i) purely from smaller indices, so the memoized recursion never needs to worry about cyclic dependencies.

Solution
#include <bits/stdc++.h>
using namespace std;
int n;
vector<int> a;
vector<int> memo;
int lis(int i){
    if (memo[i] != -1) return memo[i];
    int best = 1;
    for (int j = 0; j < i; j++){
        if (a[j] < a[i]) best = max(best, 1 + lis(j));
    }
    return memo[i] = best;
}
int main(){
    cin >> n;
    a.resize(n);
    for (auto &x : a) cin >> x;
    memo.assign(n, -1);
    int ans = 0;
    for (int i = 0; i < n; i++) ans = max(ans, lis(i));
    cout << ans << endl;
    return 0;
}

Linear/1D DP

3 worked examples

Linear DP indexes the state by a single position (usually 'considering the first i elements' or 'the subsequence ending at i') and the transition looks back at a bounded or unbounded number of earlier positions. The hallmark is a state array dp[i] (possibly with a small number of extra dimensions bolted on for auxiliary constraints — how many items used, how much capacity spent, etc.) where the recurrence dp[i] = f(dp[i-1], dp[i-2], ..., dp[0]) is evaluated left to right (or right to left).

Two recurring sub-patterns dominate this category. First, 'take or skip' recurrences (house-robber style) where dp[i] = max(dp[i-1], dp[i-2] + value[i]) — the decision at each position is binary and only depends on a fixed lookback window, so these are O(n) and trivially space-optimizable to O(1). Second, 'best subsequence ending here' recurrences (LIS-style) where dp[i] depends on ALL previous j < i satisfying some compatibility predicate, giving a naive O(n^2); when the predicate is monotonic (strictly increasing values, or non-overlapping time intervals), the search over j can be accelerated to O(log n) with binary search, a Fenwick/BIT tree, or a monotonic structure that tracks the best dp value seen so far for each possible 'key'.

A third, more advanced sub-pattern compresses an exponential search over subsets/orderings into a linear DP by using a bitmask as part of the state (dp[mask] or dp[mask][last]) — this only scales to n around 15-22 since the state space is 2^n, but it turns NP-hard-looking combinatorial search (visit every city / person / row exactly once) into a polynomial-in-2^n DP, which is the standard trick for small-n exact combinatorial optimization.

Recognize it by

Look for: 'array/sequence, choose a subsequence or a schedule of non-overlapping items to optimize a sum', 'longest / shortest chain where each element can only follow certain predecessors', or 'n is tiny (<=20) and the problem talks about visiting every item/city/person exactly once' (bitmask DP). The state is naturally 1D (plus maybe a bounded number of extra scalar dimensions), and the recurrence looks backward along the sequence, not across two independent dimensions like a grid.

Complexity

Take-or-skip DP: O(n) time, O(1) space after rolling-array optimization. Naive 'ending at i' DP: O(n^2) time, O(n) space; with binary search / BIT acceleration: O(n log n) time. Bitmask DP over subsets: O(2^n * n) or O(2^n * n^2) time, O(2^n) space — only tractable for n up to about 20.

Maximum Profit in Job Scheduling (Weighted Interval Scheduling)

Problem

You are given n jobs, each with a start time, end time, and profit. A job occupies [start, end]; two jobs may be scheduled together only if one ends at or before the other starts (touching endpoints are allowed). Choose a subset of non-overlapping jobs maximizing total profit.
Constraints: 1 <= n <= 5*10^4, 1 <= start < end <= 10^9, 1 <= profit <= 10^4.

Approach

Sort jobs by end time. Let dp[i] = the maximum profit achievable using only the first i jobs in this sorted order (job i itself is optional). For the i-th job (1-indexed after sorting) with (s, e, p): either skip it, giving dp[i-1], or take it, giving p plus the best profit obtainable from jobs that finish at or before s. Because jobs are sorted by end time, 'jobs finishing at or before s' is a prefix of the sorted list, so its boundary can be located with binary search (upper_bound on the array of sorted end times) rather than a linear scan, giving dp[i] = max(dp[i-1], dp[k] + p) where k is the count of earlier jobs ending at or before s. dp[0] = 0 is the base case (no jobs used). The final answer is dp[n].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<long long> s(n), e(n), p(n);
    for (auto &x : s) cin >> x;
    for (auto &x : e) cin >> x;
    for (auto &x : p) cin >> x;
    vector<int> idx(n);
    iota(idx.begin(), idx.end(), 0);
    sort(idx.begin(), idx.end(), [&](int a, int b){ return e[a] < e[b]; });
    vector<long long> endsSorted(n);
    for (int i = 0; i < n; i++) endsSorted[i] = e[idx[i]];
    vector<long long> dp(n + 1, 0);
    for (int i = 1; i <= n; i++){
        int job = idx[i - 1];
        int pos = upper_bound(endsSorted.begin(), endsSorted.begin() + (i - 1), s[job]) - endsSorted.begin();
        dp[i] = max(dp[i - 1], dp[pos] + p[job]);
    }
    cout << dp[n] << endl;
    return 0;
}

Super Egg Drop

Problem

You are given k identical eggs and a building with n floors. An egg breaks if dropped from at or above some unknown critical floor f (0 <= f <= n; f = 0 means even floor 1 breaks it), and survives if dropped below f. A broken egg cannot be reused; a surviving egg can be reused. Determine the minimum number of moves needed, in the worst case, to determine f exactly.
Constraints: 1 <= k <= 100, 1 <= n <= 10^4.

Approach

The natural DP dp[moves][eggs] = 'worst-case floors resolvable' would need an inner search over which floor to drop from first, giving O(k n^2) or O(k n log n) — workable but not the cleanest. The key reformulation: instead of asking 'how many moves to solve n floors with k eggs', ask f(t, k) = 'the maximum number of floors distinguishable using at most t moves and k eggs'. Dropping an egg from some floor either breaks it (reducing to f(t-1, k-1) floors above) or survives (reducing to f(t-1, k) floors below), plus the floor you just tested itself, so f(t, k) = f(t-1, k-1) + f(t-1, k) + 1, with base cases f(t, 0) = 0 and f(0, k) = 0. This DP is monotone increasing in t, so the answer is the smallest t with f(t, k) >= n — found by simply incrementing t and filling one new row of the table at a time until the threshold is reached. Because f(t, 1) = t, t never needs to exceed n, bounding the loop.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int k, n;
    cin >> k >> n;
    vector<vector<long long>> f(n + 1, vector<long long>(k + 1, 0));
    int t = 0;
    while (f[t][k] < n){
        t++;
        for (int j = 1; j <= k; j++){
            f[t][j] = f[t - 1][j - 1] + f[t - 1][j] + 1;
        }
    }
    cout << t << endl;
    return 0;
}

Russian Doll Envelopes (2D LIS)

Problem

Given n envelopes as (width, height) pairs, find the maximum number that can be nested inside one another, where envelope A fits inside envelope B only if both A.width < B.width and A.height < B.height (strict on both dimensions).
Constraints: 1 <= n <= 10^5, 1 <= width, height <= 10^5.

Approach

Sort envelopes by width ascending; to correctly forbid nesting two envelopes of equal width inside each other, break width ties by sorting height descending. After this sort, the problem reduces exactly to finding the length of the longest strictly increasing subsequence of the height sequence: because widths are non-decreasing left to right and equal-width groups have their heights in decreasing order, any strictly increasing run of heights automatically comes from strictly increasing widths too (equal-width envelopes can never both appear in an increasing height run, since within a tie group heights only decrease). Solve this reduced LIS with the O(n log n) patience-sorting technique: maintain an array 'tails' where tails[len-1] is the smallest possible tail value of an increasing subsequence of length len; for each height, binary search (lower_bound) for where it belongs and either extend or replace.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<pair<int,int>> env(n);
    for (auto &p : env) cin >> p.first >> p.second;
    sort(env.begin(), env.end(), [](const pair<int,int>&a, const pair<int,int>&b){
        if (a.first != b.first) return a.first < b.first;
        return a.second > b.second;
    });
    vector<int> tails;
    for (auto &p : env){
        int h = p.second;
        auto it = lower_bound(tails.begin(), tails.end(), h);
        if (it == tails.end()) tails.push_back(h);
        else *it = h;
    }
    cout << tails.size() << endl;
    return 0;
}

2D Grid DP

3 worked examples

Grid DP states are indexed by a cell position (r, c), with the recurrence moving in the grid's allowed directions (usually right/down for monotone-path problems). The default pattern — count paths, or find min/max cost path from top-left to bottom-right — sets dp[r][c] = f(dp[r-1][c], dp[r][c-1]) and fills the table in reading order (row by row, left to right), since both dependencies come from earlier rows/columns.

A subtler but common twist is that the natural forward direction of the DP produces an ill-defined state. Dungeon Game is the canonical example: if you try to track 'maximum health after reaching (r,c)' forward from the top-left, the greedy-looking 'maximize health so far' choice at each step is not actually optimal, because a path that arrives with more health now might need more health later for a bad room ahead — the state needs future information the forward direction doesn't have yet. The fix is to run the DP backward from the destination, where dp[r][c] = 'minimum health needed upon entering (r,c) to survive optimally from here to the end' — now the recurrence only needs already-solved future cells, and it's well-defined.

When a problem needs multiple simultaneous agents traversing the grid (two robots, or one round trip modeled as two forward walkers), the state grows to include every agent's position, constrained so all agents take the same number of steps at once — e.g. dp[step][r1][c1... but c2 derivable][col2] for two robots moving down together. This keeps the DP polynomial (state space is roughly rows * cols^(number of agents)) instead of exponential, as long as the number of agents stays small (2, occasionally 3).

Recognize it by

Any problem phrased over a 2D grid/matrix with directional movement (right/down, or 4-directional with a visiting constraint) that asks for a count, min/max cost, or feasibility of a path is grid DP. If the state 'as read forward' would need to know something about the future (a min-health / survivability constraint), that's the signal to reverse the DP direction. If multiple tokens/robots move through the grid at once, that's the signal to add extra position dimensions to the state (multi-agent grid DP).

Complexity

Single-agent monotone-path DP: O(rows * cols) time and space, often O(cols) with a rolling row. Two-agent DP (state = row, col1, col2): O(rows * cols^2) time and space. Hamiltonian-path-style grid problems requiring 4-directional movement that visits every cell exactly once generally need bitmask-augmented search, O(2^(rows*cols) * rows*cols) in the worst case, only tractable when rows*cols is small (<= ~20).

Dungeon Game (Reverse-Direction Grid DP)

Problem

A knight starts at the top-left cell of an m x n dungeon and must reach the bottom-right cell, moving only right or down at each step. Each cell has an integer value: negative means the knight loses that much health entering it, positive means the knight gains that much health. The knight's health must remain strictly above 0 at every point along the path (including the very first cell). Find the minimum initial health needed to guarantee survival to the end.
Constraints: 1 <= m, n <= 200, -1000 <= cell value <= 1000.

Approach

Define dp[r][c] as the minimum health required upon ENTERING cell (r,c) so that the knight can survive optimally all the way to the bottom-right corner. This must be computed backward, starting from the destination: dp[m-1][n-1] = max(1, 1 - grid[m-1][n-1]) (need at least 1 health after applying that cell's effect, and at least 1 overall). For any other cell, the knight will move to whichever of the right/down neighbor needs less incoming health, so dp[r][c] = max(1, min(dp[r+1][c], dp[r][c+1]) - grid[r][c]) (cells on the last row/column only have one neighbor). The answer is dp[0][0]. Computing forward from the start does not work because 'maximum health accumulated so far' is not a valid state — a path arriving with more current health can still be worse overall if it is about to walk into a large negative cell that a different, lower-health path would have avoided.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int m, n; cin >> m >> n;
    vector<vector<long long>> g(m, vector<long long>(n));
    for (auto &row : g) for (auto &x : row) cin >> x;
    vector<vector<long long>> dp(m, vector<long long>(n));
    for (int i = m - 1; i >= 0; i--){
        for (int j = n - 1; j >= 0; j--){
            if (i == m - 1 && j == n - 1){
                dp[i][j] = max(1LL, 1 - g[i][j]);
            } else if (i == m - 1){
                dp[i][j] = max(1LL, dp[i][j + 1] - g[i][j]);
            } else if (j == n - 1){
                dp[i][j] = max(1LL, dp[i + 1][j] - g[i][j]);
            } else {
                dp[i][j] = max(1LL, min(dp[i + 1][j], dp[i][j + 1]) - g[i][j]);
            }
        }
    }
    cout << dp[0][0] << endl;
    return 0;
}

Cherry Pickup II (Two Robots, Multi-Agent Grid DP)

Problem

Given a grid with rows rows and cols columns of non-negative cherry counts, robot 1 starts at the top-left cell (0,0) and robot 2 starts at the top-right cell (0, cols-1). Every step, both robots move simultaneously to the next row, each independently choosing to shift one column left, stay, or shift one column right (staying in bounds). Both robots collect the cherries on the cells they land on; if both robots land on the same cell, its cherries are only collected once. Maximize the total cherries collected after both robots reach the last row.
Constraints: 2 <= rows, cols <= 70.

Approach

State: dp[r][c1][c2] = maximum cherries collectible from row r onward, given robot 1 is at column c1 and robot 2 is at column c2 in row r. Base case, the last row: dp[rows-1][c1][c2] = grid[rows-1][c1] + (c1 != c2 ? grid[rows-1][c2] : 0). For earlier rows, both robots simultaneously choose one of 3 moves each (9 combinations), so dp[r][c1][c2] = grid[r][c1] + (c1 != c2 ? grid[r][c2] : 0) + max over the 9 valid (c1+d1, c2+d2) combinations of dp[r+1][c1+d1][c2+d2], with d1, d2 in {-1,0,1} and bounds-checked. This is filled bottom-up from the last row upward. The answer is dp[0][0][cols-1], the robots' starting positions.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int rows, cols; cin >> rows >> cols;
    vector<vector<int>> g(rows, vector<int>(cols));
    for (auto &row : g) for (auto &x : row) cin >> x;
    vector<vector<vector<int>>> dp(rows, vector<vector<int>>(cols, vector<int>(cols, 0)));
    for (int r = rows - 1; r >= 0; r--){
        for (int c1 = 0; c1 < cols; c1++){
            for (int c2 = 0; c2 < cols; c2++){
                int cherries = g[r][c1] + (c1 != c2 ? g[r][c2] : 0);
                if (r == rows - 1){
                    dp[r][c1][c2] = cherries;
                } else {
                    int best = 0;
                    for (int d1 = -1; d1 <= 1; d1++){
                        for (int d2 = -1; d2 <= 1; d2++){
                            int nc1 = c1 + d1, nc2 = c2 + d2;
                            if (nc1 < 0 || nc1 >= cols || nc2 < 0 || nc2 >= cols) continue;
                            best = max(best, dp[r + 1][nc1][nc2]);
                        }
                    }
                    dp[r][c1][c2] = cherries + best;
                }
            }
        }
    }
    cout << dp[0][0][cols - 1] << endl;
    return 0;
}

Unique Paths III (Hamiltonian Path Counting via Bitmask DP)

Problem

Given an m x n grid where each cell is 1 (the single start), 2 (the single end), 0 (walkable empty), or -1 (obstacle), count the number of distinct paths from start to end that move up/down/left/right and visit every non-obstacle cell exactly once (including start and end).
Constraints: 1 <= m, n <= 20, m*n <= 20 (small enough for a bitmask state).

Approach

Because the total number of non-obstacle cells is at most 20, the set of already-visited cells fits in a bitmask. Define a search dfs(r, c, mask) = number of ways to complete the tour to the end cell, given the current position is (r,c) and mask records every cell visited so far (including (r,c) itself). If (r,c) is the end cell, the path is only valid if mask has visited every free cell (popcount(mask) == total free cells) — return 1 if so, else 0. Otherwise, try all 4 neighbors that are in bounds, not an obstacle, and not already set in mask, recursing with the bit for that neighbor added. Crucially, the future count from (r,c,mask) depends only on the current position and which cells remain available — not on the order in which they were visited — so (r,c,mask) can be safely memoized, turning an otherwise exponential backtracking search into a bitmask DP over at most (m*n) * 2^(m*n) states.

Solution
#include <bits/stdc++.h>
using namespace std;
int m, n;
vector<vector<int>> g;
int endR, endC, totalFree;
unordered_map<long long, long long> memo;
long long dfs(int r, int c, int mask){
    if (r == endR && c == endC){
        return (__builtin_popcount((unsigned)mask) == totalFree) ? 1 : 0;
    }
    long long key = ((long long)(r * n + c) << 24) | (long long)mask;
    auto it = memo.find(key);
    if (it != memo.end()) return it->second;
    long long ways = 0;
    int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};
    for (int d = 0; d < 4; d++){
        int nr = r + dr[d], nc = c + dc[d];
        if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
        if (g[nr][nc] == -1) continue;
        int bit = nr * n + nc;
        if (mask & (1 << bit)) continue;
        ways += dfs(nr, nc, mask | (1 << bit));
    }
    memo[key] = ways;
    return ways;
}
int main(){
    cin >> m >> n;
    g.assign(m, vector<int>(n));
    int startR = 0, startC = 0;
    totalFree = 0;
    for (int i = 0; i < m; i++) for (int j = 0; j < n; j++){
        cin >> g[i][j];
        if (g[i][j] == 1) { startR = i; startC = j; }

    return 0;

Knapsack Family

3 worked examples

All knapsack problems share a state of the form dp[items considered][resource used] = best value achievable, and the defining choice at each item is binary: take it or don't. The crucial implementation detail is whether an item can be reused: for 0/1 knapsack (each item at most once), the resource dimension must be iterated in DECREASING order when updating in place (or a fresh row per item must be used), so that an item's own contribution isn't accidentally applied twice; for unbounded knapsack (unlimited copies of each item, as in Coin Change), the resource dimension is iterated in INCREASING order, deliberately allowing dp[x-w] to already reflect having used this same item.

Beyond the textbook 'maximize value subject to a weight limit' framing, the real skill tested in hard knapsack problems is recognizing which quantity should be the tracked resource dimension when it is not obviously a weight. Sometimes it's a count of items used (Profitable Schemes: members used x profit achieved, with the profit axis clamped at the target so the state space stays polynomial). Sometimes the natural target isn't a sum you can pin down in advance but a running SIGNED DIFFERENCE between two groups (Tallest Billboard: index by height-difference, often via a hash map since the difference can be negative or sparse). Sometimes what you're really doing is bin-packing in disguise, where the 'capacity' resets across multiple knapsacks (bins/rides) and the cleanest state is a bitmask over which items are already packed, together with how much room is left in the current bin (Elevator Rides) — this only scales to item counts of about 20 or fewer, since it's the subset-based, not sum-based, formulation.

Counting variants (how many subsets achieve exactly/at least some target) use the exact same take-or-skip recurrence structure, just summing counts instead of taking a max, and commonly require a modulus and care around double-counting symmetric solutions (e.g. a set and its complement being the 'same' partition).

Recognize it by

Suspect knapsack whenever a problem gives a list of items each with one or more costs and asks you to choose a subset under a budget/limit to optimize (or count subsets achieving) some target. If items are reusable, it's unbounded knapsack; if each is used at most once, 0/1. If the 'capacity' resets across multiple containers (rides, trucks, days), think bin-packing via bitmask DP over small n. If the natural resource axis isn't a plain sum but a difference or a count that needs capping, that's a sign the state needs a non-obvious second dimension.

Complexity

0/1 and unbounded knapsack: O(n * capacity) time, O(capacity) space with a 1D rolling array (2D-looking value/weight problems become O(n * dim1 * dim2)). Bitmask bin-packing DP: O(2^n * n) time and O(2^n) space, only tractable for n <= ~20. Difference-indexed knapsack (hash-map state): O(n * distinct-difference-values) rather than O(n * sum), which is the whole point when sums are too large to index directly but differences are sparse.

Two Sets II — Count Equal-Sum Partitions (Subset-Sum Counting)

Problem

Given n, count the number of ways to partition the set {1, 2, ..., n} into two subsets with equal sums, modulo 10^9+7. (If the total sum of 1..n is odd, the answer is 0.)
Constraints: 1 <= n <= 500.

Approach

Let S = n(n+1)/2. If S is odd, no equal split exists, so the answer is 0. Otherwise the target for one side is T = S/2, and we need the number of subsets of {1,...,n} summing exactly to T — a classic 0/1 knapsack counting DP: dp[0] = 1 (the empty subset sums to 0), and for each value i from 1 to n, iterate the sum s from T DOWN to i, doing dp[s] += dp[s-i] (decreasing order is essential so each i is only used once per subset). After processing all n values, dp[T] counts every subset summing to T; each such subset A and its complement (which also sums to T, since the total is 2T) form the same unordered partition into two sets, and A can never equal its own complement (they're disjoint and both non-empty for n >= 1), so dividing dp[T] by 2 (via the modular inverse of 2, since the modulus is an odd prime) gives the number of unordered partitions.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long MOD = 1000000007;
int main(){
    long long n; cin >> n;
    long long S = n * (n + 1) / 2;
    if (S % 2 == 1){ cout << 0 << endl; return 0; }
    long long target = S / 2;
    vector<long long> dp(target + 1, 0);
    dp[0] = 1;
    for (long long i = 1; i <= n; i++){
        for (long long s = target; s >= i; s--){
            dp[s] = (dp[s] + dp[s - i]) % MOD;
        }
    }
    long long inv2 = (MOD + 1) / 2;
    long long ans = dp[target] * inv2 % MOD;
    cout << ans << endl;
    return 0;
}

Elevator Rides (Bitmask Bin-Packing DP)

Problem

There are n people with given weights and an elevator with a maximum weight capacity x (every person's weight individually fits, weight[i] <= x). Find the minimum number of elevator rides needed to move every person up, where each ride carries any subset of the remaining people whose total weight does not exceed x.
Constraints: 1 <= n <= 20.

Approach

This is bin-packing: minimize the number of bins (rides) of capacity x. With n <= 20, track a bitmask of which people have already been transported. For each mask, store the Pareto-optimal pair (rides used so far, capacity remaining in the current/last ride), preferring fewer rides, and among equal ride counts, more remaining capacity. Base case dp[empty mask] = (1 ride started, x capacity available, nobody boarded yet). To compute dp[mask], pick any person i in mask, look at dp[mask without i] = (r, cap): if person i's weight fits in the remaining capacity cap, they join the current ride, giving (r, cap - weight[i]); otherwise they need a new ride, giving (r+1, x - weight[i]). Take the best candidate over all choices of i (any valid i gives a correct, though not necessarily optimal, decomposition order, and trying every i and keeping the best guarantees optimality). The answer is the ride count of dp[full mask].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; long long x;
    cin >> n >> x;
    vector<long long> w(n);
    for (auto &v : w) cin >> v;
    int full = 1 << n;
    vector<int> rides(full);
    vector<long long> cap(full);
    rides[0] = 1; cap[0] = x;
    for (int mask = 1; mask < full; mask++){
        int bestRides = INT_MAX; long long bestCap = -1;
        for (int i = 0; i < n; i++){
            if (!(mask & (1 << i))) continue;
            int prev = mask ^ (1 << i);
            int pr = rides[prev]; long long pc = cap[prev];
            int nr; long long nc;
            if (w[i] <= pc){ nr = pr; nc = pc - w[i]; }
            else { nr = pr + 1; nc = x - w[i]; }
            if (nr < bestRides || (nr == bestRides && nc > bestCap)){
                bestRides = nr; bestCap = nc;
            }
        }
        rides[mask] = bestRides; cap[mask] = bestCap;
    }
    cout << rides[full - 1] << endl;
    return 0;
}

Profitable Schemes (2D Bounded Knapsack with Clamped Profit)

Problem

You have G members available. There are n given 'crimes', each requiring group[i] members to execute and yielding profit[i]. A profitable scheme is a subset of crimes whose total member requirement is at most G and whose total profit is at least P. Count the number of profitable schemes, modulo 10^9+7 (the empty scheme counts if P = 0).
Constraints: 1 <= n <= 100, 0 <= G <= 100, 0 <= P <= 100.

Approach

This is a 2D 0/1 knapsack: the two resource axes are members used (bounded by G) and profit achieved (bounded below by P, but since profits beyond P are all equally 'sufficient', clamp the tracked profit at min(actual, P) to keep this axis's size at P+1 instead of unboundedly large). Let dp[j][k] = number of subsets of crimes considered so far that use exactly j members and achieve clamped profit exactly k. Base case dp[0][0] = 1 (the empty subset). For each crime (g, p), update in 0/1-knapsack fashion by iterating j from G down to g (so each crime is only counted once per subset), and for every k from 0 to P, add dp[j-g][k] into dp[j][min(P, k+p)]. After processing all crimes, the answer is the sum of dp[j][P] over every j from 0 to G — every subset whose clamped profit reached exactly P has real profit >= P.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long MOD = 1000000007;
int main(){
    int n; long long G, P;
    cin >> n >> G >> P;
    vector<long long> grp(n), prof(n);
    for (auto &v : grp) cin >> v;
    for (auto &v : prof) cin >> v;
    vector<vector<long long>> dp(G + 1, vector<long long>(P + 1, 0));
    dp[0][0] = 1;
    for (int c = 0; c < n; c++){
        long long g = grp[c], p = prof[c];
        for (long long j = G; j >= g; j--){
            for (long long k = 0; k <= P; k++){
                long long np = min(P, k + p);
                dp[j][np] = (dp[j][np] + dp[j - g][k]) % MOD;
            }
        }
    }
    long long ans = 0;
    for (long long j = 0; j <= G; j++) ans = (ans + dp[j][P]) % MOD;
    cout << ans << endl;
    return 0;
}

Interval DP

3 worked examples

Interval DP states are indexed by a contiguous range [l, r] of a sequence, with dp[l][r] representing the best (or only) way to fully resolve that entire subrange. The recurrence almost always tries every way to split or finish the interval at a 'pivot' k, combining the answers for the two resulting pieces: dp[l][r] = opt_k( dp[l][k] + dp[k+1][r] + cost(l,k,r) ) or similar. Filling order is always by increasing interval LENGTH (start with length-1 or length-2 base cases, then length-3, etc.), never by increasing l or r alone, because dp[l][r] depends on strictly shorter sub-intervals nested inside it.

The single most important insight to internalize is 'think about the LAST event, not the first, within the interval'. In Burst Balloons, trying to fix which balloon is burst FIRST inside [l, r] is a dead end, because after bursting it the two resulting sub-ranges are no longer independent (a balloon that used to be adjacent to something outside [l,r] now might not be). Fixing which balloon is burst LAST inside (l, r), however, means both of its neighbors at that moment are guaranteed to be exactly the boundary balloons l and r (everything else inside is already gone), which is why sentinel 1s are padded at both ends and dp[l][r] represents 'the best score for clearing everything strictly between l and r, with l and r themselves surviving until last'.

A second variant is the MINIMAX interval game: two players alternately take from the ends of a sequence, each maximizing their own score. Here dp[l][r] is 'the best score the player to move can guarantee from the remaining subarray [l,r]', and the recurrence must account for the opponent also playing optimally afterward — typically expressed as dp[l][r] = max(a[l] + (sum(l+1,r) - dp[l+1][r]), a[r] + (sum(l,r-1) - dp[l,r-1])), where 'total remaining minus what the opponent optimally takes' gives what's left for you across all your own future turns. A third variant generalizes the split to more than two pieces (merging k consecutive piles, or 2D rectangle cuts), adding an extra dimension for how many pieces are currently grouped, but the length-order evaluation and pivot-search structure stay the same.

Recognize it by

Interval DP shows up whenever a problem repeatedly removes, merges, or partitions a contiguous range of a sequence (or matched bracket/palindrome structure) and asks for an optimal (min cost / max value) way to fully process it, especially when doing an operation on part of the range changes what's adjacent to what outside it (signaling 'think about what happens last', not first). Two-player alternating-turn games on an array's ends are a distinct, recognizable minimax sub-flavor of the same [l,r] state shape.

Complexity

Standard interval DP (pivot search over 2 pieces): O(n^2) states x O(n) pivot search = O(n^3) time, O(n^2) space. Minimax array-game DP: O(n^2) time and space with no extra pivot search (only 2 choices per state). k-way merge / 2D rectangle-cut generalizations: an extra dimension (number of groups, or a second side length) multiplies the state count, typically giving O(n^3 k) or O(a^2 b^2) time.

Burst Balloons (Think About the Last Balloon, Not the First)

Problem

Given n balloons in a row with positive integer values, repeatedly burst one balloon; bursting balloon i earns value[left] * value[i] * value[right], where left and right are the balloons currently adjacent to i (or 1 if i is at either current end). Maximize the total coins collected after bursting all balloons.
Constraints: 1 <= n <= 500, 0 <= value <= 100.

Approach

Pad the array with a sentinel value 1 at both ends: a[0] = 1, a[n+1] = 1, a[1..n] = the original values. Define dp[l][r] = the maximum coins obtainable from bursting every balloon strictly between indices l and r (exclusive), given a[l] and a[r] are NOT burst as part of this subproblem (they persist as the current boundary). Considering balloon k (l < k < r) as the LAST one burst in this range means that at the moment it's burst, everything else strictly between l and r is already gone, so its neighbors at that moment are guaranteed to be exactly a[l] and a[r]: dp[l][r] = max over k in (l,r) of dp[l][k] + dp[k][r] + a[l]*a[k]*a[r]. Base case dp[l][r] = 0 whenever r <= l+1 (no balloons strictly between them). Fill by increasing interval length. The answer is dp[0][n+1].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<long long> nums(n);
    for (auto &v : nums) cin >> v;
    vector<long long> a(n + 2);
    a[0] = 1; a[n + 1] = 1;
    for (int i = 0; i < n; i++) a[i + 1] = nums[i];
    vector<vector<long long>> dp(n + 2, vector<long long>(n + 2, 0));
    for (int len = 2; len <= n + 1; len++){
        for (int l = 0; l + len <= n + 1; l++){
            int r = l + len;
            long long best = 0;
            for (int k = l + 1; k < r; k++){
                long long val = dp[l][k] + dp[k][r] + a[l] * a[k] * a[r];
                best = max(best, val);
            }
            dp[l][r] = best;
        }
    }
    cout << dp[0][n + 1] << endl;
    return 0;
}

Removal Game (Minimax Interval Game DP)

Problem

Two players alternately remove either the first or the last number from a given list of n numbers; the removed number is added to that player's score. Both players play optimally to maximize their own final score. Compute the maximum score the first player can guarantee.
Constraints: 1 <= n <= 5000, values fit in a 32-bit signed integer.

Approach

Define dp[l][r] = the best score the player CURRENTLY TO MOVE can guarantee from the remaining subarray a[l..r]. If that player takes a[l], the rest a[l+1..r] becomes a game where the opponent moves first and (optimally) secures dp[l+1][r]; since the opponent's optimal score plus the current player's eventual score from that same subrange must sum to its total, the current player is left with sum(l+1,r) - dp[l+1][r] from all their own future turns in that range. Symmetric reasoning applies if they take a[r] instead. So dp[l][r] = max(a[l] + (sum(l+1,r) - dp[l+1][r]), a[r] + (sum(l,r-1) - dp[l,r-1])), with base case dp[i][i] = a[i] (only one number left, take it). Precompute prefix sums for O(1) range-sum queries. Fill by increasing interval length; the answer is dp[0][n-1].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<long long> a(n);
    for (auto &v : a) cin >> v;
    vector<long long> pre(n + 1, 0);
    for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
    auto S = [&](int i, int j) -> long long { return pre[j + 1] - pre[i]; };
    vector<vector<long long>> dp(n, vector<long long>(n, 0));
    for (int i = 0; i < n; i++) dp[i][i] = a[i];
    for (int len = 2; len <= n; len++){
        for (int i = 0; i + len - 1 < n; i++){
            int j = i + len - 1;
            long long takeLeft = a[i] + (S(i + 1, j) - dp[i + 1][j]);
            long long takeRight = a[j] + (S(i, j - 1) - dp[i][j - 1]);
            dp[i][j] = max(takeLeft, takeRight);
        }
    }
    cout << dp[0][n - 1] << endl;
    return 0;
}

Rectangle Cutting (2D Interval DP)

Problem

Given an a x b rectangle with integer side lengths, you may repeatedly choose any current rectangle and cut it (horizontally or vertically, at an integer position) into two rectangles with integer sides. Find the minimum number of cuts needed so that every remaining piece is a square.
Constraints: 1 <= a, b <= 500.

Approach

Define dp[p][q] = minimum cuts to reduce a p x q rectangle entirely to squares. Base case dp[p][p] = 0 (already a square). Otherwise, one cut must be made first, either vertical (splitting p into i and p-i for some 1 <= i < p, giving two independent sub-rectangles i x q and (p-i) x q) or horizontal (splitting q similarly). Since the two pieces from a cut are handled by fully independent future cuts, their costs simply add: dp[p][q] = 1 + min( min over 1<=i<p of dp[i][q] + dp[p-i][q], min over 1<=j<q of dp[p][j] + dp[p][q-j] ). This is a 2D generalization of the classic 'try every split point' interval DP, with the state now a pair of side lengths instead of a single range. Every term on the right has a strictly smaller p+q than dp[p][q], so filling states in increasing order of p+q guarantees dependencies are ready; the answer is dp[a][b].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int A, B; cin >> A >> B;
    int M = max(A, B);
    vector<vector<int>> dp(M + 1, vector<int>(M + 1, 0));
    for (int s = 2; s <= 2 * M; s++){
        int aLo = max(1, s - M), aHi = min(M, s - 1);
        for (int p = aLo; p <= aHi; p++){
            int q = s - p;
            if (p == q){ dp[p][q] = 0; continue; }
            int best = INT_MAX;
            for (int i = 1; i < p; i++) best = min(best, dp[i][q] + dp[p - i][q]);
            for (int j = 1; j < q; j++) best = min(best, dp[p][j] + dp[p][q - j]);
            dp[p][q] = 1 + best;
        }
    }
    cout << dp[A][B] << endl;
    return 0;
}

String DP

3 worked examples

String DP almost always uses a 2D state dp[i][j] = 'considering the first i characters of string s and the first j characters of string t' (or a single string's substring bounds [i][j] for palindrome-style problems), because comparing or aligning two strings inherently needs two independent position pointers. The transition inspects the characters s[i-1] and t[j-1] (0-indexed strings, 1-indexed DP to cleanly represent 'zero characters used' as index 0) and branches on whether they match, whether one side has a wildcard, or whether a character is inserted/deleted/replaced.

The canonical checkpoint problem is Edit Distance: dp[i][j] = minimum insertions/deletions/substitutions to turn s[0..i) into t[0..j), with dp[i][j] = dp[i-1][j-1] when the characters match, or 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) (delete from s, insert into s, or substitute) otherwise; base cases dp[i][0] = i and dp[0][j] = j. Every harder string-matching DP (wildcard matching, regex matching) is a variation on this same alignment-table shape, with the added complexity of pattern metacharacters creating NON-LOCAL transitions: a '*' meaning 'zero or more of the preceding element' means dp[i][j] can depend not just on dp[i-1][j-1] but on dp[i][j-2] (treat the starred group as matching zero characters, skipping backward over it entirely) as well as dp[i-1][j] (treat it as consuming one more character of s and re-trying the same pattern position). Getting the 'zero occurrences' skip-back case right, without off-by-one errors in the index it skips back to, is the single most common source of bugs in this whole family.

Counting variants (Distinct Subsequences) replace 'min cost' with 'sum of ways': dp[i][j] = number of ways t[0..j) appears as a subsequence of s[0..i) is dp[i-1][j] (don't use s[i-1]) plus dp[i-1][j-1] if s[i-1] == t[j-1] (do use it to match t[j-1]) — a fork that resembles 0/1 knapsack's take-or-skip structure, transplanted onto two strings instead of items and a capacity. Finally, some 'string DP' problems are secretly a different family in disguise: minimum insertions to make a string a palindrome reduces exactly to n minus the longest common subsequence of the string and its reverse, which is worth recognizing rather than re-deriving an interval-DP palindrome recurrence from scratch.

Recognize it by

Two strings (or one string compared against itself/its reverse) with a request for minimum edit operations, whether one matches a pattern with wildcards, or a count of ways one appears as a subsequence/transformation of the other, all point to a dp[i][j] 2D alignment table. Pattern metacharacters ('*', '?', '.') are the tell for non-local transitions that need careful 'skip the whole starred group' handling.

Complexity

O(n*m) time and space for the standard alignment DP, where n, m are the two string lengths; easily reducible to O(min(n,m)) space with a rolling pair of rows since each row only depends on the previous one. Pattern-matching variants with '*' keep the same O(n*m) time/space, just with a slightly larger constant per cell for the extra case analysis.

Edit Distance (Canonical 2D Alignment DP)

Problem

Given two strings s and t, find the minimum number of single-character insertions, deletions, and substitutions needed to transform s into t.
Constraints: 1 <= |s|, |t| <= 5000, lowercase/uppercase letters.

Approach

dp[i][j] = edit distance between s[0..i) and t[0..j). Base cases: dp[0][j] = j (insert all of t's first j characters into an empty s) and dp[i][0] = i (delete all of s's first i characters to reach an empty t). Transition: if s[i-1] == t[j-1], the last characters already match for free, so dp[i][j] = dp[i-1][j-1]; otherwise dp[i][j] = 1 + min(dp[i-1][j] (delete s[i-1]), dp[i][j-1] (insert t[j-1]), dp[i-1][j-1] (substitute s[i-1] for t[j-1])). Fill row by row; the answer is dp[n][m].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    string s, t;
    cin >> s >> t;
    int n = s.size(), m = t.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1));
    for (int j = 0; j <= m; j++) dp[0][j] = j;
    for (int i = 0; i <= n; i++) dp[i][0] = i;
    for (int i = 1; i <= n; i++){
        for (int j = 1; j <= m; j++){
            if (s[i - 1] == t[j - 1]) dp[i][j] = dp[i - 1][j - 1];
            else dp[i][j] = 1 + min({dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]});
        }
    }
    cout << dp[n][m] << endl;
    return 0;
}

Regular Expression Matching ('.' and '*')

Problem

Given a string s and a pattern p containing lowercase letters, '.' (matches any single character), and '*' (matches zero or more of the preceding element), determine whether p matches the entirety of s. Print "true" or "false". The pattern is guaranteed valid (a '*' is always preceded by a literal character or '.').
Constraints: 1 <= |s| <= 20, 1 <= |p| <= 30.

Approach

dp[i][j] = true if s[0..i) matches p[0..j). Base case dp[0][0] = true (empty matches empty). dp[0][j] (matching empty s against a pattern prefix) is only true when p[j-1] is '*' and dp[0][j-2] is true (the starred element can vanish, leaving whatever was true before it). For i,j >= 1: if p[j-1] == '*', two ways to satisfy it: treat the preceding element as matched ZERO times, giving dp[i][j] |= dp[i][j-2] (skip the whole 'element*' group entirely, WITHOUT consuming any of s); or, if the preceding pattern element (p[j-2]) matches s[i-1] (equal, or p[j-2] is '.'), treat it as matched one more time, giving dp[i][j] |= dp[i-1][j] (consume one character of s, stay on the same '*' pattern position since it can repeat). If p[j-1] is a literal or '.' (no following '*'), it must match s[i-1] directly: dp[i][j] = dp[i-1][j-1] if p[j-1] == '.' or p[j-1] == s[i-1], else false. The answer is dp[n][m].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    string s, p;
    cin >> s >> p;
    int n = s.size(), m = p.size();
    vector<vector<char>> dp(n + 1, vector<char>(m + 1, 0));
    dp[0][0] = 1;
    for (int j = 1; j <= m; j++){
        if (p[j - 1] == '*' && j >= 2) dp[0][j] = dp[0][j - 2];
    }
    for (int i = 1; i <= n; i++){
        for (int j = 1; j <= m; j++){
            if (p[j - 1] == '*'){
                bool zero = (j >= 2) ? dp[i][j - 2] : false;
                bool one = false;
                if (j >= 2 && (p[j - 2] == '.' || p[j - 2] == s[i - 1])) one = dp[i - 1][j];
                dp[i][j] = (zero || one) ? 1 : 0;
            } else if (p[j - 1] == '.' || p[j - 1] == s[i - 1]){
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = 0;
            }
        }
    }
    cout << (dp[n][m] ? "true" : "false") << endl;
    return 0;
}

Distinct Subsequences (Counting Alignment DP)

Problem

Given strings s and t, count the number of distinct ways t appears as a subsequence of s (subsequences occurring at different index positions in s count separately even if they produce the same characters).
Constraints: 1 <= |s| <= 1000, 1 <= |t| <= 1000.

Approach

dp[i][j] = number of ways t[0..j) is a subsequence of s[0..i). Base cases: dp[i][0] = 1 for every i (the empty string is a subsequence of anything in exactly one way — pick nothing), and dp[0][j] = 0 for j >= 1 (a non-empty t cannot be a subsequence of an empty s). Transition: dp[i][j] = dp[i-1][j] (don't use s[i-1] at all — every way of matching t[0..j) inside the shorter prefix s[0..i-1) still works) plus, if s[i-1] == t[j-1], dp[i-1][j-1] (do use s[i-1] to match the last character of t[0..j), reducing to matching t[0..j-1) inside s[0..i-1)). These two branches never overlap (one excludes s[i-1] from the match, the other requires it), so they simply add. The answer is dp[n][m].

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    string s, t;
    cin >> s >> t;
    int n = s.size(), m = t.size();
    vector<vector<unsigned long long>> dp(n + 1, vector<unsigned long long>(m + 1, 0));
    for (int i = 0; i <= n; i++) dp[i][0] = 1;
    for (int i = 1; i <= n; i++){
        for (int j = 1; j <= m; j++){
            dp[i][j] = dp[i - 1][j] + (s[i - 1] == t[j - 1] ? dp[i - 1][j - 1] : 0ULL);
        }
    }
    cout << dp[n][m] << endl;
    return 0;
}

Bitmask DP

3 worked examples

Bitmask DP is used when the state you need to remember is "which elements of a small set have been used/visited/assigned" rather than a single position. Since a subset of an n-element universe (n usually <= 20-22, because 2^20 ~ 1e6 and 2^22 ~ 4e6) can be encoded as an n-bit integer mask, the DP state becomes dp[mask] or dp[mask][extra], where bit i of mask is 1 if element i has already been used. Transitions add one more element to the mask: for every unset bit i, you move from mask to mask | (1<<i), paying whatever cost/gain that choice incurs (often dependent on which element was used last, giving dp[mask][last]). This is exactly the state space of the Traveling Salesman / Hamiltonian-path DP: dp[mask][last] = best value achievable having visited exactly the cities in mask, ending at city 'last'. Base case dp[1<<i][i] = cost of starting at i alone (mask with a single bit set).

A second major bitmask pattern is the 'broken profile' (or 'plug') DP used for tiling problems: instead of one bit per element of a set, each bit represents whether a specific cell in a sliding 'frontier' of the grid is already filled. You process cells one at a time in row-major order, and the mask represents the fill-status of the next m cells (m = grid width) starting at the current cell. This lets you count/enumerate tilings (dominoes, etc.) in O(n*m*2^m) instead of exponential brute force over all placements.

A third pattern is 'partition into groups' bitmask DP: dp[mask] = (minimum number of groups, remaining capacity of the last group) needed to accommodate exactly the elements in mask, built by peeling off one element at a time from mask and deciding whether it joins the current group or starts a new one.

Recognizing which bit means what is the single most important design decision: bit = 'element used' (assignment/TSP-style), bit = 'cell filled' (profile DP), or bit = 'value already assigned' (e.g. permutation-construction DP) are the three most common conventions.

Recognize it by

n (or the size of some auxiliary dimension) is very small, at most ~20-22, and the natural state is 'which subset of items has been processed/chosen/visited' rather than a prefix. Phrases like 'assign each of n items to ...', 'visit all cities', 'partition into groups', or 'tile a grid' with a small dimension are strong signals. If a naive DP state would need to remember an unordered subset, encode it as a bitmask.

Complexity

Typically O(2^n * n) or O(2^n * n^2) time for assignment/TSP-style DP, and O(n*m*2^m) for broken-profile tiling DP (m = grid width); space is O(2^n) or O(2^n * n).

Dish Order With Adjacency Bonuses (Hamiltonian-path bitmask DP)

Problem

You are given n dishes (n <= 15). Dish i has satisfaction value a[i]. You may eat at most m distinct dishes (m <= n), choosing both which dishes to eat and the order to eat them in (no dish is eaten twice). In addition, you are given q ordered bonus pairs (x, y, c): if dish y is eaten immediately after dish x in your chosen order, you gain an extra c satisfaction (bonuses only apply for that exact immediate order, and a dish can trigger at most the bonuses that match its immediate predecessor/successor in your sequence). Maximize total satisfaction (sum of eaten dishes' values plus all triggered bonuses).

Input: first line n and m. Second line: n integers a[1..n]. Third line: q. Next q lines: x y c (1-indexed dish indices).
Output: the maximum total satisfaction.

Approach

This is the classic Hamiltonian-path-flavored bitmask DP (as in 'Kefa and Dishes'). State dp[mask][last] = maximum satisfaction achievable having eaten exactly the set of dishes in mask, with 'last' being the most recently eaten dish (so the next bonus, if any, depends on last).

Base case: dp[1<<i][i] = a[i] for every dish i (eating only dish i, first in the sequence, so no bonus applies yet).

Transition: from a state (mask, last) with popcount(mask) < m, try eating any unused dish nxt (bit nxt not set in mask): dp[mask | (1<<nxt)][nxt] = max(dp[mask | (1<<nxt)][nxt], dp[mask][last] + a[nxt] + bonus[last][nxt]), where bonus[last][nxt] is the extra value for eating nxt immediately after last (0 if no such bonus pair exists).

Answer: the maximum dp[mask][last] over all masks with popcount(mask) <= m and all valid 'last'. Since m <= n <= 15, iterating all 2^n masks and, for each, all n choices of 'last' and all n choices of 'nxt', costs O(2^n * n^2), fast enough for n <= 15.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, m;
    cin >> n >> m;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    int q; cin >> q;
    vector<vector<long long>> bonus(n, vector<long long>(n, 0));
    for (int i = 0; i < q; i++) {
        int x, y; long long c;
        cin >> x >> y >> c;
        x--; y--;
        bonus[x][y] = c;
    }
    int FULL = 1 << n;
    vector<vector<long long>> dp(FULL, vector<long long>(n, -1));
    for (int i = 0; i < n; i++) dp[1<<i][i] = a[i];
    long long best = 0;
    for (int mask = 1; mask < FULL; mask++) {
        int pc = __builtin_popcount(mask);
        for (int last = 0; last < n; last++) {
            if (!(mask & (1<<last))) continue;
            if (dp[mask][last] < 0) continue;
            if (pc <= m) best = max(best, dp[mask][last]);
            if (pc == m) continue; // can't extend further
            for (int nxt = 0; nxt < n; nxt++) {
                if (mask & (1<<nxt)) continue;
                long long val = dp[mask][last] + a[nxt] + bonus[last][nxt];
                int nm = mask | (1<<nxt);
                dp[nm][nxt] = max(dp[nm][nxt], val);
            }
        }
    }
    cout << best << endl;
}

Counting Domino Tilings (broken-profile bitmask DP)

Problem

Given an n x m grid (1 <= n, m <= 10, n*m even), count the number of ways to completely tile it using 1x2 dominoes (each domino covers exactly two orthogonally adjacent cells, placed either horizontally or vertically; every cell must be covered by exactly one domino). Print the count modulo 10^9 + 7.

Input: two integers n and m.
Output: the number of tilings mod 10^9 + 7.

Approach

This is the canonical 'broken profile' bitmask DP. Number the n*m cells in row-major order, position pos = row*m + col, pos from 0 to n*m-1. Think of a sliding window of m bits: state (pos, mask) means we are about to decide cell pos, and bit j of mask (0<=j<m) tells us whether the cell at absolute position pos+j is ALREADY covered by a domino placed earlier (specifically, a vertical domino placed when we processed the cell directly above it, m positions earlier).

Recursion solve(pos, mask):
- If pos == n*m: return 1 iff mask == 0 (a valid complete tiling leaves no dangling filled bits beyond the grid).
- If bit 0 of mask is set, cell pos is already filled (by a vertical domino from above); nothing to decide, so move to solve(pos+1, mask>>1) (the window slides forward by one, dropping the resolved bit and bringing in a fresh 0 bit at the top automatically).
- Otherwise cell pos is empty and must be covered now, by one of two choices (sum the ways from both if both are legal):
(a) Vertical domino down: legal only if row+1 < n. This pre-fills the cell directly below (m positions ahead), so we recurse into solve(pos+1, (mask>>1) | (1<<(m-1))).
(b) Horizontal domino right: legal only if col+1 < m AND bit 1 of mask is 0 (the cell to the right is not already filled). This fills both pos and pos+1 right now, so we recurse into solve(pos+1, (mask|2)>>1).
Memoize on (pos, mask); there are (n*m+1) * 2^m states, each O(1) work, giving O(n*m*2^m) total. This DP was cross-checked against known values (2x2 -> 2, 4x4 -> 36, 2x3 -> 3) before being used here.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long MOD = 1000000007;
int n, m;
vector<vector<long long>> memo;
vector<vector<char>> vis;
long long solve(int pos, int mask) {
    if (pos == n*m) return mask == 0 ? 1 : 0;
    if (vis[pos][mask]) return memo[pos][mask];
    vis[pos][mask] = 1;
    int row = pos / m, col = pos % m;
    long long res = 0;
    if (mask & 1) {
        res = solve(pos+1, mask >> 1);
    } else {
        // place vertical domino down (needs row+1 < n)
        if (row + 1 < n) {
            int nm = (mask >> 1) | (1 << (m-1));
            res += solve(pos+1, nm);
        }
        // place horizontal domino right (needs col+1<m and that cell free)
        if (col + 1 < m && !(mask & 2)) {
            int nm = (mask | 2) >> 1;
            res += solve(pos+1, nm);
        }
        res %= MOD;
    }
    memo[pos][mask] = res % MOD;
    return memo[pos][mask];
}
int main(){
    cin >> n >> m;
    memo.assign(n*m+1, vector<long long>(1<<m, 0));
    vis.assign(n*m+1, vector<char>(1<<m, 0));
    cout << solve(0,0) << endl;
}

Elevator Rides (minimum groups under a capacity bound)

Problem

n people (n <= 16) need to be transported by an elevator with weight capacity x. Person i weighs w[i] <= x. Partition all n people into the minimum possible number of elevator rides such that the total weight in each ride does not exceed x. (Order of people within a ride, and order of rides, does not matter.)

Input: n and x on the first line, then n integers w[1..n].
Output: the minimum number of rides.

Approach

This is a 'partition a small set into minimum-cost groups' bitmask DP. For a subset mask of people, define dp[mask] = (rides, load): the minimum number of rides needed to carry exactly the people in mask, and, among all ways achieving that minimum ride count, the minimum leftover load already used in the LAST (currently open) ride -- keeping the last ride as empty as possible is what lets future people be added cheaply.

Base case dp[0] = (1, 0): with nobody to carry we still conceptually have one open, empty ride ready to use (this sentinel makes the transition below uniform).

Transition: to build dp[mask], consider every person i in mask and let prev = mask with bit i removed. Let (r, l) = dp[prev]. Adding person i either fits in the currently open ride (if l + w[i] <= x, giving candidate (r, l + w[i])) or requires starting a new ride (giving candidate (r+1, w[i])). dp[mask] is the best candidate over all choices of i, compared first by fewer rides, then by smaller load. The final answer is the 'rides' component of dp[(1<<n) - 1]. This runs in O(2^n * n) and was cross-checked against a brute-force search over all ways to distribute people into labeled rides for many random small cases.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, x;
    cin >> n >> x;
    vector<int> w(n);
    for (auto &v : w) cin >> v;
    int FULL = 1 << n;
    vector<int> rides(FULL), load(FULL);
    rides[0] = 1; load[0] = 0;
    for (int mask = 1; mask < FULL; mask++) {
        int bestR = INT_MAX, bestL = INT_MAX;
        for (int i = 0; i < n; i++) {
            if (!(mask & (1<<i))) continue;
            int prev = mask ^ (1<<i);
            int r = rides[prev], l = load[prev];
            int nr, nl;
            if (l + w[i] <= x) { nr = r; nl = l + w[i]; }
            else { nr = r + 1; nl = w[i]; }
            if (nr < bestR || (nr == bestR && nl < bestL)) { bestR = nr; bestL = nl; }
        }
        rides[mask] = bestR; load[mask] = bestL;
    }
    cout << rides[FULL-1] << endl;
}

Tree DP

3 worked examples

Tree DP replaces the linear 'prefix' of array DP with a subtree: dp[u] captures the best answer restricted to the subtree rooted at u, computed from the dp-values of u's children via a single post-order DFS. Because a tree has no cycles, there's no risk of using a value before it is ready, as long as you always process children before their parent.

A very common building block is 'combine the two best child branches at each node' -- used for tree diameter, maximum-weight simple path, and similar problems. Define down[u] = the best value of a downward chain starting at u and going into one child (down[u] = w[u] + max(0, best down[child])), then at every node combine the top two children's down-values with w[u] itself to get the best path that bends at u; the global answer is the max of this quantity over all nodes.

A second building block is a 3-state (or small finite-state) DP per node, used for problems like minimum dominating set / camera placement: each node's state after processing its subtree is one of a handful of categories (e.g. 'has camera', 'covered but no camera', 'not yet covered'), and the parent combines its children's states to decide its own state and whether it must place a camera itself.

The third and most subtle technique is REROOTING (also called 'DP on trees with re-rooting' or 'the second DFS trick'): many problems ask for an answer computed for EVERY possible choice of root (e.g. sum of value[i] * distance(root, i) for every root). Rather than re-running an O(n) DFS from every root (O(n^2) total), root the tree arbitrarily at node 1, compute the answer for root 1 with one DFS, then do a second DFS that transfers the answer from a parent to each child in O(1): moving the root from u to a child v changes the contribution of every node in v's subtree by -1*(distance) and every node outside v's subtree by +1*(distance), which collapses into a simple closed-form update involving only the total sum and the subtree weight of v. This gives every root's answer in O(n) total.

Recognize it by

The input is a tree (n-1 edges, connected, no cycles) and you need a value defined recursively in terms of subtrees: best path/independent set/covering set within a subtree, or (the rerooting signal) the SAME aggregate computed for every possible root.

Complexity

O(n) time and O(n) space for a single-root tree DP; O(n) time total (two DFS passes) for the rerooting technique, versus a naive O(n^2).

Maximum-Weight Simple Path (weighted tree diameter)

Problem

You are given a tree with n nodes (1 <= n <= 2*10^5 in the original problem; kept small here for the worked example), each node i having a positive integer weight c[i]. A simple path is any path between two nodes (possibly the same node, i.e. a path of length 0) that does not repeat a vertex. Find the maximum possible sum of vertex weights along a simple path.

Input: n, then n integers c[1..n], then n-1 edges (each a pair of node indices).
Output: the maximum path weight.

Approach

Direct generalization of the classic 'tree diameter via DP' technique to weighted vertices. Root the tree anywhere (say node 1). Define dfs(u, parent) that returns down(u) = the best sum achievable on a downward chain starting at u and descending into at most one child subtree: down(u) = c[u] + max(0, best over children v of down(v)) (the max(0, ...) means we simply don't extend into a child whose chain would be negative -- not an issue here since all c[i] > 0, but it keeps the DP correct in general).

While computing down(u), also track the two LARGEST values of max(0, down(child)) among u's children, call them m1 >= m2. The best path that 'bends' at u (uses u as its highest point, possibly going down two different children) has weight c[u] + m1 + m2. Update a global answer with this quantity at every node, then return down(u) = c[u] + m1 to the caller. The final answer, after visiting every node, is the maximum path weight over the whole tree. This is O(n) and was cross-validated against a brute-force all-pairs BFS search.

Solution
#include <bits/stdc++.h>
using namespace std;
int n;
vector<long long> w;
vector<vector<int>> adj;
long long best = LLONG_MIN;
long long dfs(int u, int parent) {
    long long m1 = 0, m2 = 0; // top two child chain values (>=0)
    for (int v : adj[u]) {
        if (v == parent) continue;
        long long d = dfs(v, u);
        long long chain = max(0LL, d);
        if (chain > m1) { m2 = m1; m1 = chain; }
        else if (chain > m2) { m2 = chain; }
    }
    best = max(best, w[u] + m1 + m2);
    return w[u] + m1;
}
int main(){
    cin >> n;
    w.assign(n+1, 0);
    for (int i = 1; i <= n; i++) cin >> w[i];
    adj.assign(n+1, {});
    for (int i = 0; i < n-1; i++) {
        int a,b; cin >> a >> b;
        adj[a].push_back(b);
        adj[b].push_back(a);
    }
    dfs(1, 0);
    cout << best << endl;
}

Best Root by Weighted Distance Sum (rerooting technique)

Problem

You are given a tree with n nodes, each node i having a positive weight val[i]. For a chosen root r, define f(r) = sum over all nodes i of val[i] * dist(r, i), where dist is the number of edges on the tree path. Compute max over all r in 1..n of f(r).

Input: n, then n integers val[1..n], then n-1 edges.
Output: the maximum value of f(r) over all choices of root r.

Approach

Textbook rerooting. Let S = total sum of all val[i]. Root the tree at node 1 and, with one DFS, compute subW[u] = sum of val[] over the subtree of u, and f(1) directly as sum(val[i] * depth(i)) using depths relative to root 1.

The key identity: if v is a child of u, moving the root from u to v changes every node's distance by exactly +1 (nodes outside v's subtree, now farther from the new root) or -1 (nodes inside v's subtree, now closer). So f(v) = f(u) + (S - subW[v]) * (+1) + subW[v] * (-1) = f(u) + S - 2*subW[v].

A second DFS starting from the root propagates this relation to every node: f(v) = f(parent) + S - 2*subW[v] for each child v. Since each node's f-value is derived from its parent's in O(1), the whole tree's f-values are computed in O(n) total (after the O(n) preprocessing DFS), versus O(n^2) from re-running a full DFS per candidate root. The answer is the maximum f-value over all nodes. Verified against a brute-force O(n^2) BFS-from-every-root reference.

Solution
#include <bits/stdc++.h>
using namespace std;
int n;
vector<long long> val;
vector<vector<int>> adj;
vector<long long> subW;
vector<long long> f; // f[u] = sum of val[i]*dist(u,i) for that root
long long S;
long long f1accum;

void dfs1(int u, int parent, long long depth) {
    subW[u] = val[u];
    f1accum += val[u]*depth; // accumulate f for root=1 (node 1)
    for (int v : adj[u]) {
        if (v == parent) continue;
        dfs1(v, u, depth+1);
        subW[u] += subW[v];
    }
}
void dfs2(int u, int parent) {
    for (int v : adj[u]) {
        if (v == parent) continue;
        f[v] = f[u] + S - 2*subW[v];
        dfs2(v, u);
    }
}

    val.assign(n+1,0);
    for (int i=1;i<=n;i++) cin >> val[i];

    subW.assign(n+1,0);
    f.assign(n+1,0);
    S = 0; for (int i=1;i<=n;i++) S += val[i];
    f1accum = 0;
    dfs1(1, 0, 0);
    f[1] = f1accum;
    dfs2(1, 0);
    long long best = *max_element(f.begin()+1, f.end());
    cout << best << endl;
}

Minimum Cameras to Monitor a Tree (3-state tree DP)

Problem

You are given a tree with n nodes (rooted at node 1 for concreteness). You must choose a subset of nodes to place a camera on. A camera placed at node u monitors u itself, u's parent, and all of u's children. Find the minimum number of cameras needed so that every node in the tree is monitored by at least one camera.

(This is exactly a minimum dominating set on the tree, since a camera's monitoring range is precisely its graph neighborhood plus itself.)

Input: n, then n-1 edges.
Output: the minimum number of cameras.

Approach

Classic 3-state tree DP, processed bottom-up (post-order). Each node, after its subtree is fully decided, ends up in exactly one of three states: 0 = not yet covered by any camera, 1 = covered, but has no camera of its own (covered by a child's camera), 2 = has its own camera.

A greedy-flavored rule (which is provably optimal, not just a heuristic) determines a node u's state from its children's states: if ANY child is in state 0 (uncovered), u MUST place a camera on itself (state 0 children can only be covered by their parent, since their own children are already resolved) -- this increments the camera count and sets u's state to 2. Otherwise, if at least one child has a camera (state 2), u is covered by that child, so u's state is 1 (covered, no camera needed). Otherwise (every child is state 1: covered, no camera), u itself is not covered by anything yet, so u's state is 0, deferring the decision to u's parent.

After the DFS finishes at the root, if the root ends in state 0 (nothing above it to cover it), one final camera must be added at the root. This greedy/DP hybrid is correct because delaying the camera placement as late as possible (to the parent) never hurts and sometimes helps (one parent camera can cover multiple state-0 children at once). Verified by brute force (trying all 2^n camera placements for small trees and checking minimum dominating set size) with zero mismatches over 300 random trees.

Solution
#include <bits/stdc++.h>
using namespace std;
int n;
vector<vector<int>> adj;
int cameras = 0;
// state: 0 = not covered, 1 = covered no camera, 2 = has camera
int dfs(int u, int parent) {
    vector<int> childStates;
    for (int v : adj[u]) {
        if (v == parent) continue;
        childStates.push_back(dfs(v, u));
    }
    bool hasUncovered = false, hasCamera = false;
    for (int s : childStates) {
        if (s == 0) hasUncovered = true;
        if (s == 2) hasCamera = true;
    }
    if (hasUncovered) {
        cameras++;
        return 2;
    }
    if (hasCamera) return 1;
    return 0;
}

    cin >> n;
    adj.assign(n+1, {});
    for (int i=0;i<n-1;i++){int a,b;cin>>a>>b;adj[a].push_back(b);adj[b].push_back(a);}
    if (n == 1) { cout << 1 << endl; return 0; }
    int rootState = dfs(1, 0);
    if (rootState == 0) cameras++;
    cout << cameras << endl;
}

Digit DP

3 worked examples

Digit DP answers questions of the form 'how many integers in [L, R] satisfy property P?' when brute-force iteration over the range is too slow (R can be up to 10^18). The trick is to write count(N) = number of integers in [0, N] satisfying P, then answer = count(R) - count(L-1). count(N) is computed by processing the decimal digits of N one position at a time (most significant first) with a recursive function dfs(pos, ...extra state..., tight), where:

- pos is the current digit index (0 = most significant digit of N's decimal string).
- tight is true if every digit chosen so far exactly equals N's corresponding digit (i.e., the number built so far is still 'pinned' to a prefix of N). If tight is true, the next digit can range only from 0 up to N's digit at this position (otherwise the number would exceed N); if tight is false, the number is already guaranteed to be less than N in some earlier position, so the next digit can be any of 0-9 freely.
- extra state captures whatever property P depends on: a running digit sum, a running remainder modulo some number, a bitmask of digits used so far, or a small automaton state (for pattern-matching properties).

At the base case pos == length(N), you check whether the accumulated extra state satisfies P and return 1 or 0 accordingly.

Memoization only applies to the tight=false branches, because once tight becomes false the remaining computation depends only on (pos, extra state) -- it no longer depends on N's specific digits, so the same (pos, extra state) pair always yields the same count and can be cached (typically as memo[pos][extra state]). The tight=true branches are always computed fresh (there's only one tight path, of length = number of digits, so this costs nothing extra).

For a property whose 'divisor' is not fixed in advance (e.g. 'divisible by its own digit sum'), a common extension is to enumerate every plausible target digit sum value v (bounded by 9 * number_of_digits) and, for each v, run a small digit DP that counts numbers whose digit sum is EXACTLY v and are divisible by v, tracking (remainder mod v, digit sum so far) as extra state; summing the counts over all v gives the final answer.

Recognize it by

The problem asks to count (or sum, or find an extremal) integers in a range [L, R] (with R potentially astronomically large) satisfying some digit-based property: divisibility involving digits, a bound on distinct digits used, digits restricted to a given set, a forbidden digit pattern, etc. If direct iteration over [L, R] is infeasible but the property can be checked digit-by-digit with a small amount of extra bookkeeping, it's digit DP.

Complexity

O(digits * (size of extra-state space) * 10) per range endpoint, typically comfortably fast even for 18-19 digit numbers.

Count Numbers With Digit Sum Divisible by K

Problem

Given two integers L and R (1 <= L <= R <= 10^18) and an integer K (1 <= K <= 100), count how many integers x in [L, R] have a digit sum divisible by K.

Input: L, R, K on one line.
Output: the count.

Approach

Write count(N) = number of integers in [0, N] whose digit sum is divisible by K, then answer = count(R) - count(L-1).

For count(N): let s = decimal string of N. dfs(pos, sumMod, tight), where sumMod is the running digit sum taken modulo K (we never need the exact sum, only its residue, since only divisibility by K matters). At pos == len(s), return 1 if sumMod == 0 else 0. Otherwise, the digit at this position ranges from 0 to (tight ? s[pos] : 9); recurse with the new sumMod = (sumMod + digit) % K and new tight flag (tight && digit == limit). Memoize on (pos, sumMod) whenever tight is false. This runs in O(len(s) * K) per call to count(), easily fast enough. Cross-checked against a brute-force loop over the range for 200 random (L, R, K) triples with zero mismatches.

Solution
#include <bits/stdc++.h>
using namespace std;
string s;
int K;
long long memo[20][200];
bool vis[20][200];
// pos: current digit index, sumMod: digit sum so far mod K, tight: bound by s
long long dfs(int pos, int sumMod, bool tight) {
    if (pos == (int)s.size()) return sumMod == 0 ? 1 : 0;
    if (!tight && vis[pos][sumMod]) return memo[pos][sumMod];
    int limit = tight ? (s[pos]-'0') : 9;
    long long res = 0;
    for (int d = 0; d <= limit; d++) {
        res += dfs(pos+1, (sumMod+d)%K, tight && (d==limit));
    }
    if (!tight) { vis[pos][sumMod] = true; memo[pos][sumMod] = res; }
    return res;
}
long long countUpTo(long long n, int k) {
    if (n < 0) return 0;
    s = to_string(n);
    K = k;
    memset(vis, 0, sizeof(vis));
    return dfs(0, 0, true);
}
int main(){
    long long l, r; int k;
    cin >> l >> r >> k;
    cout << (countUpTo(r,k) - countUpTo(l-1,k)) << endl;
}

Numbers At Most N Using Only a Given Digit Set

Problem

You are given m distinct digits from '1' to '9' (never '0'), sorted ascending, and a positive integer N. Count how many positive integers <= N can be written using only digits from the given set, with repetition of digits allowed (any number of digits).

Input: m, then the m allowed digits, then N.
Output: the count.

Approach

Because the digit set never contains 0, every string of allowed digits is automatically a valid positive integer with no leading-zero issue -- this simplifies the classic 'branch at the first strictly-smaller digit' digit DP into a clean closed form.

Let L = number of decimal digits of N. Every number with fewer than L digits (length 1 to L-1) is automatically <= N and can use ANY of the m digits at each of its positions, contributing m^len choices for each length; sum these over len = 1..L-1.

For numbers with EXACTLY L digits, scan N's digits left to right while tracking whether we're still 'tight' (matching N's prefix exactly). At each position pos with N's digit nd: every allowed digit strictly less than nd lets the remaining (L-1-pos) positions be filled freely with any of the m digits, contributing (count of allowed digits < nd) * m^(L-1-pos) numbers that are guaranteed < N from this position onward. Then check whether nd itself is an allowed digit: if not, no length-L number can stay tight past this position, so stop; if yes, continue to the next position while remaining tight, and if we reach the end of N while still tight, N itself is achievable, so add 1. This is an explicit unrolled version of the digit-DP recursion (equivalent to memoized dfs(pos, tight) with no extra state needed beyond the running power of m), verified against a brute-force scan over all integers up to N for 300 random digit sets and N.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int m; cin >> m;
    vector<int> D(m);
    for (auto &d : D) cin >> d; // digits 1..9, given sorted ascending
    long long N; cin >> N;
    string s = to_string(N);
    int L = s.size();
    // lengths 1..L-1: all combinations valid (digits are 1-9, never leading zero issue)
    long long total = 0;
    long long p = 1; // m^0
    for (int len = 1; len < L; len++) {
        p *= m;
        total += p;
    }
    // length == L: digit DP style scan
    bool matchedFull = false;
    for (int pos = 0; pos < L; pos++) {
        int nd = s[pos]-'0';
        int cntLess = 0;
        for (int d : D) if (d < nd) cntLess++;
        long long power = 1;
        for (int i = 0; i < L-1-pos; i++) power *= m;
        total += (long long)cntLess * power;
        // check if nd itself is achievable (in D) to continue tight
        bool found = false;
        for (int d : D) if (d == nd) { found = true; break; }
        if (!found) { matchedFull = false; goto done; }
        if (pos == L-1) matchedFull = true;
    }
    done:
    if (matchedFull) total += 1;
    cout << total << endl;
}

Beautiful Numbers (divisible by their own digit sum)

Problem

Given L and R (1 <= L <= R <= 10^6 for this worked example; the technique scales to R up to 10^18), count how many integers x in [L, R] are divisible by the sum of their own decimal digits (a number is never divisible by a digit sum of 0, which cannot occur for x >= 1).

Input: L and R on one line.
Output: the count.

Approach

The difficulty versus the previous two examples is that the divisor (the digit sum) is not fixed -- it depends on the very number being counted. The safe, provably-correct approach: the digit sum of any number up to R is bounded (at most 9 * number_of_digits(R)). Enumerate every candidate digit-sum value V from 1 up to that bound, and for each V run a small digit DP that counts numbers whose digit sum is EXACTLY V and which are divisible by V, using state (pos, digitSumSoFar capped at V, remainder mod V, tight). Summing these counts over all candidate V gives count(N) = number of beautiful numbers in [0, N]; then answer = count(R) - count(L-1).

(Some editorials speed this further by tracking a remainder modulo LCM(1..9) = 2520 to reuse work across divisors -- but that shortcut is only valid when the candidate divisor divides 2520, which is not guaranteed once digit sums exceed 9, so this worked example deliberately uses the always-correct per-candidate-V version. It is still fast: for R up to 10^6 the total work across all V is negligible, and for R up to 10^18 the same idea works with the state space (pos <= 19, V <= 171) -- the CF-official-editorial LCM(1..9) optimization is an orthogonal speed-up on top of this, not a correctness requirement.)

Cross-checked against a brute-force digit-sum-and-mod scan over the range for many random sub-ranges, with zero mismatches.

DP on DAGs

2 worked examples

Many DPs are secretly 'find the longest (or shortest, or count of) path in a directed acyclic graph', where the DAG's edges encode the problem's dependency structure. If you can define a directed edge u -> v whenever 'v can immediately follow u' in some ordering, and this relation has no cycles, then the DP dp[v] = best value ending at v = (value of v) + max/min over incoming edges (u, v) of dp[u] is exactly a longest/shortest-path-in-a-DAG computation, and can be evaluated with memoized DFS (equivalent to processing nodes in topological order).

The key insight in many hard problems is recognizing that a DAG is present even when it isn't drawn explicitly: for example, a grid where you may only move to strictly larger cell values defines a DAG on the grid cells (an edge exists from a smaller cell to an adjacent larger one), and 'longest strictly increasing path' becomes 'longest path in this implicit DAG', solvable with memoized DFS in O(cells) rather than exponential re-exploration. Likewise, 'the longest common subsequence shared by k different permutations of 1..n' can be turned into a DAG problem: put an edge u -> v if u appears before v in EVERY one of the k permutations; the longest common subsequence is exactly the longest path in this DAG (and conveniently, iterating nodes in the order given by permutation 1 is already a valid topological order, since every edge in the DAG must also respect permutation 1's order).

Implementation is usually cleanest as memoized DFS (dfs(v) returns the best value achievable ending at v, recursing into predecessors or successors and caching results) rather than an explicit topological sort, especially when the DAG's edges are implicit (like the grid case).

Recognize it by

There is a natural 'can come after' or 'can come before' relation between elements that has no cycles (strictly increasing values, consistent relative order across several sequences, a partial order on tasks/prerequisites), and you need the longest/shortest chain, or a count of chains, respecting that relation.

Complexity

O(V + E) with memoized DFS / topological-order DP, where V and E are the DAG's node and edge counts (which may be implicit, e.g. O(rows*cols*4) for a grid).

Longest Increasing Path in a Matrix (implicit DAG, memoized DFS)

Problem

Given an m x n integer matrix, find the length of the longest path of cells such that each step moves to an orthogonally adjacent cell with a STRICTLY greater value than the current cell.

Input: m and n, then the m x n matrix.
Output: the length of the longest such path.

Approach

Treat each cell as a DAG node with a directed edge to any orthogonal neighbor of strictly greater value. Because values strictly increase along every edge, this graph is automatically acyclic (a cycle would require a value to be both strictly greater and strictly less than itself along the loop) -- so a naive-looking recursive DFS is actually safe to memoize.

dfs(r, c) = 1 + max over the (up to 4) neighbors (nr, nc) with grid[nr][nc] > grid[r][c] of dfs(nr, nc), or just 1 if no such neighbor exists. Memoize dfs(r, c) in a 2D array (each cell's answer never changes once computed). The overall answer is the maximum dfs(r, c) over all cells. Each cell is computed exactly once (O(1) amortized per cell given memoization) and looks at O(1) neighbors, giving O(rows*cols) total. Verified against the two official LeetCode examples (both giving 4).

Solution
#include <bits/stdc++.h>
using namespace std;
int R, C;
vector<vector<int>> g;
vector<vector<int>> memo;
int dr[4]={-1,1,0,0}, dc[4]={0,0,-1,1};
int dfs(int r, int c) {
    if (memo[r][c] != -1) return memo[r][c];
    int best = 1;
    for (int k = 0; k < 4; k++) {
        int nr=r+dr[k], nc=c+dc[k];
        if (nr>=0 && nr<R && nc>=0 && nc<C && g[nr][nc] > g[r][c]) {
            best = max(best, 1 + dfs(nr,nc));
        }
    }
    return memo[r][c] = best;
}
int main(){
    cin >> R >> C;
    g.assign(R, vector<int>(C));
    for (auto &row : g) for (auto &x : row) cin >> x;
    memo.assign(R, vector<int>(C, -1));
    int ans = 0;
    for (int i=0;i<R;i++) for (int j=0;j<C;j++) ans = max(ans, dfs(i,j));
    cout << ans << endl;
}

Longest Common Subsequence of k Permutations (DAG longest path)

Problem

You are given k permutations of 1..n. Find the length of the longest sequence of DISTINCT values that appears as a subsequence in ALL k permutations simultaneously.

Input: n and k, then k lines each containing a permutation of 1..n.
Output: the length of the longest common subsequence.

Approach

Reduce the multi-permutation LCS to a longest-path-in-a-DAG problem: define a directed edge u -> v (for distinct values u, v in 1..n) if u appears strictly before v in EVERY one of the k permutations. Any chain u1 -> u2 -> ... -> ut that follows these edges is, by construction, a common subsequence of all k permutations (each ui appears before u(i+1) in every permutation), and conversely every common subsequence corresponds to such a chain. So the answer is the length of the longest path in this DAG (counting nodes, not edges).

Crucially, this DAG's edges all agree with the relative order given by permutation 1 (if u -> v is an edge, u comes before v in every permutation, including permutation 1), so simply processing nodes in the order they appear in permutation 1 is already a valid topological order -- no separate topological sort is needed. dp[v] = 1 + max over already-processed u (earlier in permutation 1's order) with an edge u->v of dp[u], defaulting to 1 if no valid predecessor exists. Checking whether an edge u->v exists costs O(k) (compare positions in every permutation), so the total cost is O(n^2 * k). The answer is the maximum dp value. Verified against the official Codeforces sample (answer 3) and against a brute-force common-subsequence search over many random small permutation sets.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, k;
    cin >> n >> k;
    vector<vector<int>> perm(k, vector<int>(n));
    vector<vector<int>> pos(k, vector<int>(n+1));
    for (int i = 0; i < k; i++) {
        for (int j = 0; j < n; j++) {
            cin >> perm[i][j];
            pos[i][perm[i][j]] = j;
        }
    }
    // edge u->v (u!=v) if pos[i][u] < pos[i][v] for all i
    // process nodes in order of perm[0] (topological order valid since all edges agree with perm0's order)
    vector<int> dp(n+1, 1);
    int ans = 1;
    for (int idx = 0; idx < n; idx++) {
        int v = perm[0][idx];
        for (int jdx = 0; jdx < idx; jdx++) {
            int u = perm[0][jdx];
            bool edge = true;
            for (int i = 0; i < k; i++) {
                if (!(pos[i][u] < pos[i][v])) { edge = false; break; }
            }
            if (edge) dp[v] = max(dp[v], dp[u] + 1);
        }
        ans = max(ans, dp[v]);
    }
    cout << ans << endl;
}

Game-theory DP

3 worked examples

Game-theory DP (minimax DP) models a two-player game with perfect information and no randomness, where both players play optimally (each maximizes their own outcome, or equivalently minimizes the opponent's). The DP state is a game position, and the recurrence encodes 'the player to move picks whichever available move is best for them, anticipating that the opponent will then also play optimally.'

A very common and powerful trick for score-based games (rather than pure win/lose games) is to track the SCORE DIFFERENCE (current player's future score minus opponent's future score) instead of tracking each player's score separately. If dp[state] = best achievable (my remaining score - opponent's remaining score) for whoever is about to move from 'state', then for every move option m leading to a new state', the mover gains value(m) now, and then the opponent becomes 'the player to move' from state' -- from the ORIGINAL mover's perspective, whatever the opponent achieves as ITS OWN best difference from state' is subtracted. This gives the clean recurrence dp[state] = max over moves m of (value(m) - dp[state after m]), which automatically encodes optimal alternating play without tracking two separate scores. This is exactly how the classic 'pick from either end of an array' game and 'take up to k items from the front' games are solved.

For pure win/lose (no scores) combinatorial games -- e.g. 'the player who cannot move loses' -- the DP tracks a boolean per position: a position is WINNING for the player to move if at least one reachable position is LOSING for the (new) player to move there; a position with no moves at all is LOSING. This is the base case of Sprague-Grundy theory (a full Grundy-number DP generalizes this to combinations of independent games via the mex function and XOR, but plain win/lose DP suffices for a single pile/position).

Recognize it by

Two players alternate taking turns, both play optimally, and you need either (a) the final score / score difference under optimal play, or (b) which player wins from a given starting position. The state space (subarray bounds, remaining pile size, etc.) is small enough to tabulate directly.

Complexity

O(n^2) for interval-based games (dp[i][j] over subarrays), O(n * b) for suffix/pile games with branching factor b (often O(n) if b is a small constant).

Optimal Pick From Either End (score-difference interval DP)

Problem

An array of n integers is given. Two players alternate turns; on each turn the current player removes either the FIRST or the LAST remaining element of the array and adds its value to their own score. Both players play optimally to maximize their own final score. The first player moves first. Determine the first player's final score.

Input: n, then n integers a[1..n].
Output: the first player's score under optimal play by both.

Approach

Classic interval minimax DP tracking score DIFFERENCE. Let dp[i][j] = the best possible (current mover's score - opponent's score) achievable on the subarray a[i..j], for whichever player is about to move on that subarray. Base case dp[i][i] = a[i] (only one element left; the mover takes it). Recurrence: dp[i][j] = max(a[i] - dp[i+1][j], a[j] - dp[i][j-1]) -- taking a[i] yields a[i] now, then the opponent plays optimally on [i+1, j] achieving dp[i+1][j] as ITS OWN difference, which is subtracted from the current player's perspective (symmetrically for taking a[j]).

Fill dp by increasing subarray length. Once dp[0][n-1] (the difference for the whole array) is known, note that (first player's score) - (second player's score) = dp[0][n-1] and (first player's score) + (second player's score) = total sum of a[]. Solving these two equations gives first player's score = (total + dp[0][n-1]) / 2. Verified against a brute-force minimax recursion returning both players' actual scores, with zero mismatches over 200 random arrays, and matches the well-known reference example.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    vector<vector<long long>> dp(n, vector<long long>(n, 0));
    for (int i = 0; i < n; i++) dp[i][i] = a[i];
    for (int len = 2; len <= n; len++) {
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i][j] = max(a[i] - dp[i+1][j], a[j] - dp[i][j-1]);
        }
    }
    long long total = accumulate(a.begin(), a.end(), 0LL);
    long long firstPlayer = (total + dp[0][n-1]) / 2;
    cout << firstPlayer << endl;
}

Probability & Expected-Value DP

3 worked examples

Probability/expected-value DP comes in two closely related flavors. The first tracks, for each reachable STATE of a random process, the probability that the process is currently in that state; the DP transitions push probability mass forward from a state to its possible successor states, weighted by the transition probability of each outcome. This is exactly a (typically small, finite, absorbing) Markov chain evaluated by dynamic programming: dp[state] = sum over predecessor states p of dp[p] * P(p -> state). The answer is often the final probability mass that accumulates in one or more absorbing states (e.g. 'only rocks remain', 'the pile is exhausted').

The second flavor uses LINEARITY OF EXPECTATION to sidestep tracking a full probability distribution: instead of computing E[total] directly (which might require reasoning about a huge joint distribution), decompose the quantity of interest into a sum of simpler indicator-like pieces (e.g. 'is this specific pair inverted?', 'does the k-th occurrence of some event happen?') and use E[sum of pieces] = sum of E[each piece], since linearity of expectation holds regardless of independence between the pieces. Each individual E[piece] is often just a local probability computation (e.g. P(value at position i exceeds value at position j)), and a DP is then used to aggregate these local expectations efficiently (e.g. maintaining a running 'expected count of elements smaller than the current one seen so far' rather than recomputing pairwise sums from scratch).

A recurring pitfall: when a random process can have events that don't change the state (e.g. two same-type creatures meeting and nothing happening), you can safely condition the DP transition only on the state-changing events (renormalizing their probabilities to sum to 1), because the intervening no-op events don't affect which absorbing state is eventually reached -- this is a standard and valid simplification for this class of problem (an embedded Markov chain).

Recognize it by

The problem talks about probability, expected value, or 'compute the chance that ...' involving a randomized process with a small state space, OR asks for an expected aggregate quantity (expected number of inversions, expected length, expected score) that can be decomposed via linearity of expectation into simpler per-element or per-pair probabilities.

Complexity

Proportional to the size of the state space times the number of transitions per state; for linearity-of-expectation problems, often O(n^2) naively or O(n log n) with a Fenwick/segment tree to aggregate the running expectation.

Foundational probability DP. Let dp[i][s] = probability that the sum of the first i dice equals s. Base case dp[0][0] = 1 (before any rolls, the sum is 0 with certainty). Rock-Paper-Scissors Island Survival Probability

Problem

An island has r rock-creatures, s scissors-creatures, and p paper-creatures. Every so often, two random creatures on the island meet (each unordered pair of the currently-alive creatures is equally likely at each meeting). If the two creatures are of different types, the one that wins under standard rock-paper-scissors rules (rock beats scissors, scissors beats paper, paper beats rock) eliminates the other; if they are the same type, nothing happens. This repeats until only one type of creature remains. Compute the probability that rocks are the surviving type, the probability that scissors are the surviving type, and the probability that paper is the surviving type.

Input: r, s, p on one line.
Output: the three probabilities (rock, scissors, paper), each printed with 6 digits after the decimal point, space-separated.

Approach

3-dimensional absorbing-Markov-chain DP over the state (r, s, p) = counts of each type currently alive. A state is absorbing (terminal) once at most one of the three counts is positive; at that point the surviving type (if any creatures remain) is determined outright.

For a non-absorbing state, same-type meetings don't change the state, so it is valid (and standard for this class of problem) to condition the transition only on the meetings that DO change something: rock-vs-scissors meetings (count r*s, outcome: a scissors creature is eliminated, moving to state (r, s-1, p)), scissors-vs-paper meetings (count s*p, moving to (r, s, p-1)), and paper-vs-rock meetings (count p*r, moving to (r-1, s, p)). Renormalize by their sum (the total number of 'interesting' pairs) to get transition probabilities that sum to 1, then recurse: solve(r,s,p) = weighted average of solve() at the three successor states, weighted by these renormalized probabilities. Memoize on (r, s, p) since the state space is only O(R*S*P). Verified against the official Codeforces sample (r=s=p=2 gives exactly 1/3, 1/3, 1/3 by symmetry) and against manually-checked asymmetric cases.

        else if (s>0) res[1]=1;

        for (int i=0;i<3;i++) res[i] += w*sub[i];
    }
    memo[key] = res;
    return res;

Expected Number of Inversions (linearity of expectation)

Problem

There are n positions. Position i's actual value is chosen uniformly at random and independently to be either a[i] or b[i] (each with probability 1/2). Compute the expected number of inversions in the resulting sequence, where an inversion is a pair of indices i < j with value[i] > value[j].

Input: n, then n lines each with two integers a[i] and b[i].
Output: the expected number of inversions, printed with 6 digits after the decimal point.

Approach

By linearity of expectation, E[number of inversions] = sum over all pairs (i, j) with i < j of P(value[i] > value[j]) -- this holds regardless of any dependence between different pairs' outcomes, which is exactly what makes linearity of expectation so powerful here (we never need to reason about the full joint distribution over all n independent coin flips).

For a fixed pair (i, j), value[i] and value[j] are each uniformly one of two independent options, giving 4 equally likely combinations. P(value[i] > value[j]) = (number of the 4 combinations where value[i] > value[j]) / 4. Summing this local probability over all O(n^2) pairs gives the answer directly, with each pair costing O(1). (A faster O(n log n) version would maintain the running expectation via a Fenwick tree, aggregating 'expected count of previously-seen values smaller than the current position's expected contribution' -- the O(n^2) version shown here isolates the core probability/DP reasoning without that data-structure optimization.) }

DP Optimization Techniques

2 worked examples

Some DP recurrences have an inherently expensive transition -- e.g. dp[i] = min/max over ALL valid j < i of (dp[j] + cost(j, i)) -- which naively costs O(n) per state and O(n^2) overall. DP optimization techniques exploit extra structure in cost(j, i) to answer the 'best j for this i' query in less than O(n) amortized time.

MONOTONIC DEQUE optimization applies when the transition is a sliding-window max/min: dp[i] = a[i] + max(dp[j] for j in a fixed-size window [i-k, i-1]). Maintaining a deque of candidate indices with monotonically decreasing dp-values (popping from the back any index whose dp-value is dominated by the new one, and popping from the front any index that has fallen out of the window) lets each dp[i] be answered in O(1) amortized time, since each index is pushed and popped from the deque at most once, giving O(n) total instead of O(n*k).

The CONVEX HULL TRICK (CHT) applies when the transition can be rewritten as dp[i] = (a function of i alone) + min/max over j < i of (m_j * x_i + b_j) for some per-j 'slope' m_j and 'intercept' b_j, and some per-i 'query point' x_i -- i.e., each candidate j defines a line in (slope, intercept) space, and we need the lower (for min) or upper (for max) envelope of all lines-so-far, evaluated at x_i. When lines are inserted in order of monotonically decreasing (or increasing) slope AND queries x_i arrive in monotonically increasing (or decreasing) order, the envelope can be maintained with a simple deque (no need for the more general but slower Li Chao tree): a new line is pushed after popping any line from the back that the new line makes permanently obsolete (checked via comparing intersection x-coordinates), and queries advance a monotonic pointer forward along the hull rather than binary searching. This gives O(n) or O(n log n) total instead of O(n^2).

Other members of this family (not shown in full detail here, but good to know by name) include Divide & Conquer optimization (when the optimal split point is provably monotonic in the DP layer, letting a D&C over the layer avoid recomputing overlapping ranges) and Knuth's optimization (a similar monotonicity argument for interval DPs satisfying a quadrangle inequality). All of these techniques trade a harder correctness proof (monotonicity of some optimal-choice function) for a large constant-factor or asymptotic speedup, and they only apply when that monotonicity genuinely holds -- applying them to a cost function without the right structure silently produces wrong answers, so each should be validated (e.g. against a brute-force O(n^2) DP) before trusting it.

Recognize it by

A DP transition of the form dp[i] = best over j < i of (dp[j] + cost(j,i)) is the right shape but O(n) per state is too slow (n large, e.g. > 10^5): look at cost(j,i) -- if it is a sliding window of fixed width, monotonic-deque optimization applies; if it expands into (linear in i) + (linear combination of a per-j slope and per-j intercept), the convex hull trick applies.

Complexity

O(n) for monotonic-deque optimization (from O(n*k)); O(n) or O(n log n) for the convex hull trick (from O(n^2)).

Constrained-Gap Maximum Subsequence Sum (monotonic deque optimization)

Problem

Given an integer array nums of length n and an integer k, find the maximum possible sum of a non-empty subsequence of nums such that for every two CONSECUTIVE integers chosen in the subsequence (say at original indices i < j), we have j - i <= k.

Input: n and k, then n integers nums[1..n].
Output: the maximum such subsequence sum.

Approach

Let dp[i] = the maximum sum of a valid subsequence that ENDS at index i (using nums[i] as its last element). Since the previous chosen element (if any) must be within the last k positions, dp[i] = nums[i] + max(0, max(dp[i-k], dp[i-k+1], ..., dp[i-1])) -- the max(0, ...) allows starting a fresh subsequence at i when every candidate predecessor's dp-value is negative (better to not extend a negative chain). The naive computation of the window maximum costs O(k) per i, giving O(n*k) overall.

To speed this up, maintain a deque of indices whose dp-values are in strictly decreasing order (front = largest dp-value in the current window). Before computing dp[i]: pop any front index that has fallen outside [i-k, i-1]. The best previous value is then max(0, dp[deque.front()]) (or just 0 if the deque is empty). After computing dp[i], pop any back indices whose dp-value is <= dp[i] (they can never again be the maximum, since dp[i] is both later, hence still in-window longer, and at least as large), then push i. Each index enters and leaves the deque at most once, so the total cost is O(n). The answer is the maximum dp[i] over all i. Verified against the official LeetCode 1425 example (answer 37) and against an O(n*k) brute-force window-max reference across 300 random tests with zero mismatches, including all-negative arrays.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, k;
    cin >> n >> k;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    vector<long long> dp(n);
    deque<int> dq; // stores indices, dp values decreasing front to back
    long long ans = LLONG_MIN;
    for (int i = 0; i < n; i++) {
        // pop indices out of window [i-k, i-1]
        while (!dq.empty() && dq.front() < i - k) dq.pop_front();
        long long best = dq.empty() ? 0 : max(0LL, dp[dq.front()]);
        dp[i] = a[i] + best;
        ans = max(ans, dp[i]);
        // maintain decreasing order
        while (!dq.empty() && dp[dq.back()] <= dp[i]) dq.pop_back();
        dq.push_back(i);
    }
    cout << ans << endl;
}

Minimum-Cost Checkpoint Jumps (convex hull trick)

Problem

You must travel through n checkpoints in order, at positions h[1] < h[2] < ... < h[n] (strictly increasing). You must visit checkpoint 1 first and checkpoint n last, but you may skip any subset of the checkpoints in between (i.e., you choose an increasing subsequence of indices starting at 1 and ending at n). Jumping directly from checkpoint j to checkpoint i (j < i) costs (h[i] - h[j])^2 + C, where C is a fixed constant. Find the minimum total cost to go from checkpoint 1 to checkpoint n.

Input: n and C, then n integers h[1..n] (strictly increasing).
Output: the minimum total cost.

Approach

Let dp[i] = minimum cost to reach checkpoint i from checkpoint 1 (dp[1] = 0). The natural recurrence dp[i] = min over j < i of (dp[j] + (h[i]-h[j])^2 + C) costs O(n) per i (O(n^2) total) if evaluated directly.

Expand the square: dp[i] = h[i]^2 + C + min over j < i of ( (dp[j] + h[j]^2) - 2*h[j]*h[i] ). This is exactly the convex hull trick pattern: define, for each j, a line with slope m_j = -2*h[j] and intercept b_j = dp[j] + h[j]^2; then the min-over-j term is the lower envelope of all lines for j < i, evaluated at x = h[i]. dp[i] is then h[i]^2 + C plus that envelope value.

Because h[] is strictly increasing, lines are inserted in order of strictly DECREASING slope (m_j = -2h[j] decreases as j, hence h[j], increases), and queries x = h[i] arrive in strictly INCREASING order -- exactly the conditions for the simple monotonic (deque-based) convex hull trick, with no need for a Li Chao tree. New lines are appended to a deque after popping any trailing line that a geometric bad()-test shows is now dominated everywhere it used to matter (comparing the intersection x-coordinate of the new line against the last two lines already on the hull). Queries advance a monotonic pointer forward along the hull (never backward, since queries only increase), giving O(1) amortized per query and O(1) amortized per insertion, for O(n) total. This was stress-tested against an O(n^2) brute-force reference over 500 random instances (n up to 60, random strictly-increasing h, random C) with zero mismatches.

Solution
#include <bits/stdc++.h>
using namespace std;
struct Line { long long m, b; };
double interX(const Line&a, const Line&b){
    return (double)(b.b - a.b) / (double)(a.m - b.m);
}
bool bad(const Line&a, const Line&b, const Line&c){
    // returns true if line b is unnecessary given a and c
    return interX(a,c) <= interX(a,b);
}
int main(){
    int n; long long C;
    cin >> n >> C;
    vector<long long> h(n);
    for (auto &x : h) cin >> x;
    vector<long long> dp(n);
    dp[0] = 0;
    deque<Line> hull;
    // insert line for j=0
    hull.push_back({-2*h[0], dp[0] + h[0]*h[0]});
    int ptr = 0;
    for (int i = 1; i < n; i++) {
        long long x = h[i];
        if (ptr >= (int)hull.size()) ptr = (int)hull.size()-1;
        while (ptr+1 < (int)hull.size() &&
               hull[ptr+1].m*x + hull[ptr+1].b <= hull[ptr].m*x + hull[ptr].b) ptr++;
        long long minVal = hull[ptr].m*x + hull[ptr].b;
        dp[i] = x*x + C + minVal;
        // insert line for j=i
        Line nl = {-2*h[i], dp[i] + h[i]*h[i]};
        while (hull.size() >= 2 && bad(hull[hull.size()-2], hull.back(), nl)) {
            hull.pop_back();
            if (ptr >= (int)hull.size()) ptr = (int)hull.size()-1;
        }
        hull.push_back(nl);
    }
    cout << dp[n-1] << endl;
}

DP Combined with Data Structures

3 worked examples

Many DPs have a transition of the form dp[i] = 1 + best over j < i satisfying some ORDER CONDITION on an auxiliary value (dp[j]), which naively costs O(n) per i. When the order condition is a simple comparison (value[j] < value[i], or value[j] <= value[i]) on a value that can be coordinate-compressed into a small range, a Fenwick tree (or segment tree) keyed on that compressed value can answer 'best dp[j] among all j with value[j] <= v' (a prefix max or prefix sum query) in O(log n), and the corresponding update in O(log n), bringing the whole DP down to O(n log n).

The single most famous instance is the O(n log n) Longest Increasing Subsequence algorithm ('patience sorting'): maintain an array tails[] where tails[k] is the SMALLEST possible tail value among all increasing subsequences of length k+1 found so far. For each new value x, binary search tails[] for the first entry >= x and overwrite it with x (or append x if none exists); tails[] stays sorted throughout, and its final length is the LIS length. This is a specialized O(log n)-per-element trick that doesn't need an explicit Fenwick tree, but is doing conceptually the same thing (maintaining just enough summary information to answer 'best subsequence length achievable with a given tail bound' quickly).

A generalization -- 2D or 3D 'staircase' subsequence problems (choose points with x strictly increasing and y non-decreasing, or similar) -- sorts points by the first coordinate, then runs a 1D LIS-style DP on the second coordinate using a Fenwick tree keyed on (compressed) y-values to query the best dp-value among all smaller-or-equal y. A critical subtlety when two points share the same x-value (so they can never both appear in a valid chain, since the first coordinate must strictly increase): they must be processed as a BATCH -- compute every point's query using only Fenwick state from strictly smaller x, and only apply all of that batch's updates afterward. Skipping this batching (e.g. sorting ties by descending y and updating immediately) is a subtle bug that only manifests when two points with the SAME x AND the same y both appear, since then the descending-y tie-break provides no separation and the second point incorrectly 'sees' the first one's just-applied update.

Recognize it by

A DP transition needs the best (max/min/sum/count) dp-value among all previously processed elements satisfying value[j] <= value[i] (or a similar order relation), and n is large enough (> a few thousand) that the natural O(n^2) double loop is too slow.

Complexity

O(n log n): O(n) elements, each doing O(log n) work for a binary search, Fenwick query, or Fenwick update.

Longest Increasing Subsequence in O(n log n) (patience sorting)

Problem

Given an array of n integers, find the length of the longest strictly increasing subsequence.

Input: n, then n integers.
Output: the length of the longest strictly increasing subsequence.

Approach

Maintain tails[], where after processing a prefix of the array, tails[k] (0-indexed) holds the smallest possible last value among all strictly increasing subsequences of length k+1 discovered so far within that prefix; tails[] is always sorted in increasing order (this invariant is what makes binary search valid).

For each new value x: binary search (lower_bound) for the first entry in tails[] that is >= x. If none exists, x extends the longest subsequence found so far, so append it. Otherwise, overwrite that entry with x -- x cannot make an existing subsequence longer right now, but replacing a larger tail with the smaller x can only help future extensions (any suffix that could extend after the old, larger tail can also extend after x). The final length of tails[] is the LIS length (note tails[] itself is generally NOT an actual longest subsequence, only its LENGTH is meaningful). Each element does O(log n) work via binary search, giving O(n log n) total. Verified against the well-known LeetCode example ([10,9,2,5,3,7,101,18] -> 4) and against an O(n^2) brute-force DP reference over 200 random arrays.

Longest 2D Staircase Subsequence (Fenwick tree keyed on y)

Problem

Given n points (x, y) (with possible duplicate x or y values, or even duplicate points), find the maximum number of points that can be chosen, ordered so that x is STRICTLY increasing and y is NON-DECREASING along the chosen order.

Input: n, then n lines each with two integers x and y.
Output: the maximum length of such a chain.

Approach

This is a direct 2D generalization of the O(n log n) LIS trick. Sort all points by x ascending. For a point at compressed y-rank r (after coordinate-compressing all y-values), define dp(point) = 1 + (maximum dp-value among all ALREADY-PROCESSED points with y <= this point's y). A Fenwick tree keyed on the compressed y-rank, supporting prefix-maximum queries and point updates, answers this in O(log n) per point, for O(n log n) total.

The subtle correctness requirement is handling points that share the same x-value: since x must be STRICTLY increasing between chosen points, two points with equal x can never both appear in a valid chain, so neither should be able to 'see' the other's dp contribution via the Fenwick tree. The safe fix is to process points in BATCHES by x-value: for every group of points sharing the same x, first compute EVERY point's query (using only Fenwick state left over from strictly smaller x-values), and only AFTER the whole group's queries are done, apply all of that group's Fenwick updates. (A tempting but WRONG shortcut -- sorting same-x ties by descending y and updating immediately -- silently breaks when two points in the group also share the same y-value, since the descending-y tie-break then provides no separation and the second point's query incorrectly retrieves the first point's just-applied update; this was caught during testing by constructing exactly such a duplicate-point case.) The final answer is the maximum dp-value seen across all points. Verified against an O(n^2) brute-force reference across 500 random point sets, including many with duplicate x and y values, with zero mismatches after the fix.

Solution
#include <bits/stdc++.h>
using namespace std;
struct Fenwick {
    int n;
    vector<int> t;
    Fenwick(int n): n(n), t(n+1, 0) {}
    void update(int i, int v) { // i is 1-indexed
        for (; i <= n; i += i & (-i)) t[i] = max(t[i], v);
    }
    int query(int i) { // max over [1..i]
        int res = 0;
        for (; i > 0; i -= i & (-i)) res = max(res, t[i]);
        return res;
    }
};
int main(){
    int n; cin >> n;
    vector<int> x(n), y(n);
    for (int i = 0; i < n; i++) cin >> x[i] >> y[i];
    vector<int> idx(n);
    iota(idx.begin(), idx.end(), 0);
    sort(idx.begin(), idx.end(), [&](int a, int b){
        if (x[a] != x[b]) return x[a] < x[b];
        return y[a] > y[b]; // secondary order doesn't matter given batching below
    });
    vector<int> ys = y;
    sort(ys.begin(), ys.end());
    ys.erase(unique(ys.begin(), ys.end()), ys.end());
    auto comp = [&](int v){ return lower_bound(ys.begin(), ys.end(), v) - ys.begin() + 1; };
    Fenwick fen((int)ys.size());
    int ans = 0;
    int i = 0;
    while (i < n) {
        int j = i;
        while (j < n && x[idx[j]] == x[idx[i]]) j++;
        // process points with this x value as a batch: query first, then apply all updates
        vector<pair<int,int>> pending; // (compressed y, new dp value)
        for (int t = i; t < j; t++) {
            int id = idx[t];
            int c = comp(y[id]);
            int best = fen.query(c); // only sees points with strictly smaller x
            int dp = best + 1;
            ans = max(ans, dp);
            pending.push_back({c, dp});
        }
        for (auto &pr : pending) fen.update(pr.first, pr.second);
        i = j;
    }
    cout << ans << endl;
}

Count All Strictly Increasing Subsequences (Fenwick tree of sums)

Problem

Given an array of n integers, count the total number of strictly increasing subsequences (of any length >= 1), modulo 10^9 + 7. (A single element on its own counts as an increasing subsequence of length 1.)

Input: n, then n integers.
Output: the count modulo 10^9 + 7.

Approach

Extends the O(n log n) LIS idea from LENGTH to COUNTING. Let dp[i] = the number of strictly increasing subsequences that END exactly at index i (including the length-1 subsequence consisting of just a[i] itself): dp[i] = 1 + sum over all j < i with a[j] < a[i] of dp[j].

Rather than a Fenwick tree that tracks a running MAXIMUM (as in plain LIS), here the Fenwick tree tracks a running SUM keyed on (coordinate-compressed) value: fen.query(r-1) returns the sum of dp[j] over all previously-processed j whose (compressed) value rank is strictly less than a[i]'s rank r (i.e., a[j] < a[i], enforcing strict increase), and fen.update(r, dp[i]) adds dp[i] into the running sum at rank r for future queries. Both operations are O(log n), so computing all dp[i] and summing them into the final answer (total = sum of dp[i] for all i, taken mod 10^9+7) costs O(n log n). Verified against a brute-force enumeration of all 2^n subsets, checking strict monotonicity, across 150 random arrays (including many repeated values) with zero mismatches.

Solution
#include <bits/stdc++.h>
using namespace std;
const long long MOD = 1000000007;
struct Fenwick {
    int n;
    vector<long long> t;
    Fenwick(int n): n(n), t(n+1, 0) {}
    void update(int i, long long v) {
        for (; i <= n; i += i & (-i)) t[i] = (t[i] + v) % MOD;
    }
    long long query(int i) { // sum over [1..i]
        long long res = 0;
        for (; i > 0; i -= i & (-i)) res = (res + t[i]) % MOD;
        return res;
    }
};
int main(){
    int n; cin >> n;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    vector<long long> comp = a;
    sort(comp.begin(), comp.end());
    comp.erase(unique(comp.begin(), comp.end()), comp.end());
    auto rank = [&](long long v){ return lower_bound(comp.begin(), comp.end(), v) - comp.begin() + 1; };
    Fenwick fen((int)comp.size());
    long long total = 0;
    for (int i = 0; i < n; i++) {
        int r = rank(a[i]);
        long long dp = (1 + fen.query(r-1)) % MOD; // strictly smaller values -> prefix up to r-1
        total = (total + dp) % MOD;
        fen.update(r, dp);
    }
    cout << total << endl;
}
