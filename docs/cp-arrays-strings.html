Arrays & Strings

Two pointers, sliding window, prefix sums, and Kadane's algorithm are the four workhorse techniques for turning an O(n^2) or O(n^3) brute-force scan over an array or string into an O(n) or O(n log n) pass. They share a common theme: instead of recomputing information about a range from scratch every time the range changes, each technique maintains a running summary (a pointer position, a window's aggregate, a running sum, a running best) and updates it incrementally as the range slides or grows. Mastering when each invariant applies -- and, just as importantly, recognizing when it breaks (e.g. negative numbers breaking sliding-window monotonicity) and you need to fall back to prefix sums plus a hash map or monotonic deque -- is what separates easy-tier from hard-tier array problems. These techniques extend the Arrays & Strings toolbox with structural tricks for range updates, in-place multi-way partitioning, and windowed extrema, while Merge Intervals extends the Sorting & Binary Search idea of 'sort first, then sweep' to problems whose objects are ranges rather than points.

Two Pointers

3 worked examples

The two-pointer technique maintains two (or more) indices into a sequence and advances them according to a rule that guarantees each pointer only ever moves forward (or at least never revisits work already done). The key structural requirement is monotonicity: as one pointer advances, some measured quantity (a sum, a count, a difference) must change in a predictable, one-directional way, so that you never need to re-examine a position once you have moved past it. This is what lets an algorithm that looks like it should be O(n^2) (for every left endpoint, scan forward until some condition breaks) collapse to O(n): each pointer traverses the array once, so total pointer movement is bounded by O(n) even though there are two nested-looking loops.

The classic setups are: (1) opposite-direction pointers starting at both ends of a sorted array and moving inward, used for problems like pair-sum-to-target, 3Sum, and container/trapping-water problems, where sortedness gives you the monotonic guarantee that lets you decide deterministically which pointer to move; and (2) same-direction pointers (often called the 'fast/slow' or 'read/write' pattern) used for in-place partitioning, de-duplication, and merging. A subtler but very powerful variant fixes one pointer and lets the other pointer only ever move forward as the fixed pointer advances, which is the basis of the sliding window technique covered next -- sliding window is really just two pointers with the extra constraint that the region between them defines a contiguous window whose aggregate you maintain incrementally.

Two pointers is not just for searching -- it composes well with combinatorial counting. A common hard-problem pattern is: sort the array, then for each right pointer position find (via a monotonically advancing left pointer) the maximal valid window, and instead of enumerating pairs one by one, count how many subsequences/subsets that window supports using combinatorics (nCr). This turns an O(n^2) pair-counting problem into O(n log n) (dominated by the sort).

A critical failure mode to internalize: two pointers relies on monotonicity of the underlying quantity as a pointer moves. The moment negative numbers (or any non-monotonic element) enter the picture for a sum-based window, advancing/shrinking the window no longer has a well-defined 'always helps' or 'always hurts' direction, and two pointers silently gives wrong answers rather than failing loudly -- that is exactly when you should reach for prefix sums with a hash map instead.

Recognize it by

Look for problems on a sorted (or sortable) array/string asking about pairs, triplets, or windows defined by a monotonic condition (sum, difference, or count that only increases/decreases as a pointer moves) -- especially phrasings like 'find a pair/triplet with sum X', 'is the array a palindrome', or 'maximum area between two indices'.

Complexity

Typically O(n log n) if sorting is required first, otherwise O(n); O(1) extra space beyond the pointers and, if needed, an output buffer.

Bounded-Range Subsequences (Close Tuples, hard version)

Problem

You are given n integers a_1, ..., a_n and integers m and k. Count the number of subsequences (chosen by index, order in the original array does not matter for the value of the subsequence) of size exactly m such that the difference between the maximum and minimum element of the chosen subsequence is at most k. Two subsequences are different if the sets of chosen indices differ. Print the answer modulo 998244353. Constraints: 1 <= m <= n <= 2*10^5, 0 <= k <= 10^9, 0 <= a_i <= 10^9.

Approach

Because we are counting subsets of indices and the max-minus-min condition only depends on the multiset of chosen values (not their original positions), we can sort the array first: the number of size-m index-subsets of the original array satisfying the property equals the number of size-m index-subsets of the sorted array satisfying it, since sorting is just a relabeling. Once sorted, fix the subsequence's maximum element to be a[i] (the element at the largest chosen index i in the sorted order). Every earlier element a[j] with a[i]-a[j] <= k is a legal partner. Because the array is sorted, the condition a[i]-a[j] <= k is monotonic in j: as i increases, the smallest valid j (call it left) only moves right, never left. So we sweep i left-to-right and advance a single 'left' pointer forward whenever a[i]-a[left] > k -- classic two pointers, O(n) total pointer movement. For each i, the number of usable earlier elements is cnt = i - left, and we must choose m-1 of them to accompany a[i] as the fixed maximum, contributing C(cnt, m-1) subsequences (choosing a[i] itself fixes one slot). Summing C(cnt, m-1) over all i gives the total count, with no double-counting because each subsequence is counted exactly once, at the index of its maximum element in sorted order. Precomputing factorials and inverse factorials mod p makes each nCr O(1).

Solution
#include <bits/stdc++.h>
using namespace std;
const long long MOD = 998244353;

long long power(long long a, long long b, long long mod){
    long long res = 1; a %= mod;
    while (b > 0){
        if (b & 1) res = res * a % mod;
        a = a * a % mod;
        b >>= 1;
    }
    return res;
}

int main(){
    int n, m; long long k;
    cin >> n >> m >> k;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());

    vector<long long> fact(n + 1), inv_fact(n + 1);
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % MOD;
    inv_fact[n] = power(fact[n], MOD - 2, MOD);
    for (int i = n; i > 0; i--) inv_fact[i - 1] = inv_fact[i] * i % MOD;

    auto C = [&](int nn, int rr) -> long long {
        if (rr < 0 || rr > nn) return 0;
        return fact[nn] * inv_fact[rr] % MOD * inv_fact[nn - rr] % MOD;
    };

    long long ans = 0;
    int left = 0;
    for (int i = 0; i < n; i++){
        while (a[i] - a[left] > k) left++;
        int cnt = i - left;
        ans = (ans + C(cnt, m - 1)) % MOD;
    }
    cout << ans << "\n";
    return 0;
}

3Sum: Unique Zero-Sum Triplets

Problem

Given an integer array nums, find all unique triplets [nums[i], nums[j], nums[k]] (i, j, k distinct indices) such that nums[i] + nums[j] + nums[k] == 0. Print each distinct triplet's values in non-decreasing order, one triplet per line, with the triplets themselves ordered by their first element then second element (ties broken naturally by the scanning order described below). Do not print the same value-triplet twice even if it arises from multiple index choices.

Approach

Sort the array first. Fix the smallest element of the triplet at index i by iterating i from 0 to n-3, skipping any i where a[i] equals the previous element (to avoid emitting a duplicate triplet). For the remaining subarray a[i+1..n-1], we need a pair summing to -a[i]: since that subarray is sorted, use opposite-direction two pointers left = i+1 and right = n-1. If a[i]+a[left]+a[right] is too small, the only way to increase the sum is to move left rightward (monotonicity: increasing left only increases the value picked, since the array is sorted); if too large, move right leftward. When the sum equals zero, record the triplet, then advance both pointers past any run of equal values (again to avoid duplicate output). This is the two-pointer invariant in its purest form: because the array is sorted, moving a pointer always changes the sum in a known direction, so we never need to backtrack.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n; cin >> n;
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());

    for (int i = 0; i < n - 2; i++){
        if (i > 0 && a[i] == a[i - 1]) continue;
        int left = i + 1, right = n - 1;
        while (left < right){
            long long s = (long long)a[i] + a[left] + a[right];
            if (s == 0){
                cout << a[i] << " " << a[left] << " " << a[right] << "\n";
                int lv = a[left], rv = a[right];
                while (left < right && a[left] == lv) left++;
                while (left < right && a[right] == rv) right--;
            } else if (s < 0){
                left++;
            } else {
                right--;
            }
        }
    }
    return 0;
}

Trapping Rain Water

Problem

Given n non-negative integers representing an elevation map where the width of each bar is 1, compute how much water it can trap after raining. Constraints: 1 <= n <= 2*10^5, 0 <= height[i] <= 10^5.

Approach

The water trapped above position i equals min(maxHeightToLeft(i), maxHeightToRight(i)) - height[i]. Computing both max-to-left and max-to-right arrays with prefix/suffix scans works in O(n) time and O(n) space, but two pointers gets it down to O(1) extra space using the following invariant: maintain pointers left and right at the two ends and running maxima leftMax, rightMax. At each step, whichever side currently has the smaller height tells you the water level there with certainty -- if height[left] <= height[right], then even though we don't yet know the true maximum on the right side, we know it is at least height[right] >= height[left], so the water trapped at 'left' is fully determined by leftMax (the true bottleneck must be on the left since the right side already has a wall at least as tall as anything blocking us from the left). This lets us resolve position 'left' immediately and advance the left pointer inward, and symmetrically for the right side. Each position is resolved exactly once as one of the two pointers passes it, giving O(n) time and O(1) space.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n; cin >> n;
    vector<int> h(n);
    for (auto &x : h) cin >> x;
    int left = 0, right = n - 1;
    int leftMax = 0, rightMax = 0;
    long long water = 0;
    while (left < right){
        if (h[left] <= h[right]){
            leftMax = max(leftMax, h[left]);
            water += leftMax - h[left];
            left++;
        } else {
            rightMax = max(rightMax, h[right]);
            water += rightMax - h[right];
            right--;
        }
    }
    cout << water << "\n";
    return 0;
}

Sliding Window

3 worked examples

Sliding window is the specialization of two pointers to problems about contiguous ranges (subarrays or substrings) where you maintain some aggregate statistic of the current window (a sum, a frequency table, a count of distinct elements, a count of characters still needed) and update that aggregate incrementally as the window's boundaries move, rather than recomputing it from scratch. There are two flavors: fixed-size windows, where both endpoints move together by one step each iteration (e.g. 'maximum in every window of size k'), and variable-size windows, where the right endpoint always advances but the left endpoint only advances when some validity condition is violated (e.g. 'smallest window containing all of these characters').

The correctness argument for variable-size sliding window rests on a monotonicity property: as the window grows (right pointer advances), the tracked condition moves in one direction (e.g. adding more of a non-negative-sum array only increases the sum; adding more characters only increases or maintains the count of 'still needed' characters), and as the window shrinks (left pointer advances) it moves in the opposite direction. Because both endpoints are non-decreasing over the whole scan, the total work across the whole algorithm is O(n) even though it looks like a nested loop -- this is the amortized/two-pointer argument again, just applied to a window's aggregate instead of two independent search pointers.

When the aggregate you need is not a simple running sum/count but something like 'the maximum element currently in the window', a plain running variable cannot be updated in O(1) when elements leave the window from the left (you'd have to rescan). The standard fix is a monotonic deque: keep indices in the deque in an order such that their values are monotonic (decreasing for a max-window, increasing for a min-window), popping from the back whenever a new incoming element would make an existing back-of-deque element useless (it's smaller and will leave the window no later than the new element), and popping from the front when the front index falls outside the current window. Each index is pushed and popped at most once, so this maintains window max/min in amortized O(1) per step.

A very useful meta-trick when a problem asks for 'exactly K' of something (exactly K distinct values, exactly K odd numbers, etc.) is to solve the easier 'at most K' sliding-window version twice and subtract: countExactly(K) = countAtMost(K) - countAtMost(K-1). 'At most' conditions are monotonic in the window (shrinking the window can only decrease the count of distinct values, say), which is exactly the property plain sliding window needs, whereas 'exactly K' by itself is not monotonic and cannot be solved directly by a single sliding window.

Recognize it by

Look for 'contiguous subarray/substring' problems asking for a max/min/count over windows of a given size, or the smallest/largest window satisfying some containment or frequency condition -- especially when all values involved are non-negative (so growing the window is 'monotonically worse or better').

Complexity

O(n) or O(n log n) if a heap is used instead of a monotonic deque; O(k) or O(alphabet size) extra space for the window's aggregate structure.

Sliding Window Maximum

Problem

Given an integer array nums of size n and an integer k, there is a sliding window of size k which moves from the very left of the array to the very right, one position at a time. Return the maximum value in the window at each position it stops at (there are n-k+1 such positions). Constraints: 1 <= k <= n <= 10^5.

Approach

Maintain a deque of indices whose corresponding values are strictly decreasing from front to back. For each new index i: first pop from the back while the value at the back index is <= nums[i], since those back elements can never be the maximum again (nums[i] is at least as large and will outlive them in the window); push i onto the back. Then pop from the front if the front index has fallen out of the current window (index <= i - k). The front of the deque is now always the index of the maximum value within the current window, because it's the largest remaining value and everything larger that could have competed with it has already left the window or was popped for being smaller than something still present. Once i >= k-1 the window is fully formed and we record the front's value as this window's maximum. Each index enters and leaves the deque at most once, giving O(n) total time.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (auto &x : a) cin >> x;

    deque<int> dq;
    vector<int> res;
    for (int i = 0; i < n; i++){
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();
        dq.push_back(i);
        if (dq.front() <= i - k) dq.pop_front();
        if (i >= k - 1) res.push_back(a[dq.front()]);
    }

    for (size_t i = 0; i < res.size(); i++){
        cout << res[i];
        if (i + 1 < res.size()) cout << " ";
    }
    cout << "\n";
    return 0;
}

Minimum Window Substring

Problem

Given two strings s and t of lengths n and m, return the minimum-length contiguous substring of s that contains every character of t, including duplicates (i.e. for each character, the substring must contain at least as many occurrences as t does). If no such substring exists, print an empty line. Constraints: 1 <= m <= n <= 10^5, both strings consist of uppercase and lowercase English letters.

Approach

This is the canonical variable-size sliding window: expand the right endpoint one character at a time, updating a frequency map of the current window and a counter 'formed' tracking how many distinct required characters currently meet their required count. Once formed equals the number of distinct characters in t, the window is valid, and we greedily shrink from the left as far as possible while it stays valid, recording the shortest valid window seen. Shrinking is safe/correct because removing characters from the left can only ever reduce coverage (monotonic: a valid window that becomes invalid after removing one more character from the left is exactly the boundary we want to record right before it breaks). Because the right pointer only moves forward n times and the left pointer only moves forward at most n times total across the whole run, the algorithm is O(n + m) despite the nested while loop.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    string s, t;
    cin >> s >> t;

    unordered_map<char,int> need;
    for (char c : t) need[c]++;
    int required = (int)need.size();
    int formed = 0;
    unordered_map<char,int> windowCounts;

    int left = 0;
    int bestLen = INT_MAX, bestLeft = 0;
    for (int right = 0; right < (int)s.size(); right++){
        char c = s[right];
        windowCounts[c]++;
        if (need.count(c) && windowCounts[c] == need[c]) formed++;

        while (left <= right && formed == required){
            if (right - left + 1 < bestLen){
                bestLen = right - left + 1;
                bestLeft = left;
            }
            char lc = s[left];
            windowCounts[lc]--;
            if (need.count(lc) && windowCounts[lc] < need[lc]) formed--;
            left++;
        }
    }

    if (bestLen == INT_MAX) cout << "\n";
    else cout << s.substr(bestLeft, bestLen) << "\n";
    return 0;
}

Subarrays with Exactly K Different Integers

Problem

Given an integer array nums of length n and an integer k, return the number of contiguous subarrays that contain exactly k different (distinct) integer values. Constraints: 1 <= n <= 2*10^4, 1 <= k <= n, 1 <= nums[i] <= n.

Approach

'Exactly k distinct' is not directly monotonic under window growth/shrink in the way plain sliding window needs, but 'at most k distinct' is: as you shrink the window from the left, the number of distinct values can only stay the same or decrease. So define atMost(X) = number of subarrays with at most X distinct values, computed with a standard variable-size sliding window (expand right, track distinct count via a frequency map, shrink left whenever distinct count exceeds X; every window ending at 'right' that is currently valid contributes (right-left+1) new subarrays, since every subarray ending at 'right' with left endpoint in [left, right] is valid). Then exactly(k) = atMost(k) - atMost(k-1), because every subarray with at most k distinct values either has at most k-1 distinct values or has exactly k -- subtracting removes precisely the 'k-1 or fewer' subarrays, leaving only those with exactly k. This 'atMost(K) - atMost(K-1)' trick generalizes to many 'exactly K' window-counting problems.

Solution
#include <bits/stdc++.h>
using namespace std;

long long atMost(vector<int>& nums, int k){
    if (k < 0) return 0;
    unordered_map<int,int> cnt;
    int left = 0, distinct = 0;
    long long total = 0;
    for (int right = 0; right < (int)nums.size(); right++){
        if (cnt[nums[right]] == 0) distinct++;
        cnt[nums[right]]++;
        while (distinct > k){
            cnt[nums[left]]--;
            if (cnt[nums[left]] == 0) distinct--;
            left++;
        }
        total += (right - left + 1);
    }
    return total;
}

int main(){
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    cout << (atMost(a, k) - atMost(a, k - 1)) << "\n";
    return 0;
}

Prefix Sums

3 worked examples

A prefix sum array P, where P[0] = 0 and P[i] = a[0] + a[1] + ... + a[i-1], lets you answer 'what is the sum of the subarray a[l..r]?' in O(1) time as P[r+1] - P[l], after O(n) preprocessing. This is the single most important trick for turning repeated range-sum queries (or the search for a range with a target sum) from O(n) per query into O(1) per query. The invariant is trivial to maintain (a single running total as you scan left to right), but its consequences are powerful: any problem phrased in terms of 'sum of some contiguous range' can be re-expressed as a problem about a difference of two values in the prefix array, which converts a 2D search space (all pairs l, r) into effectively a 1D one.

The key unlock this gives you over two pointers/sliding window is handling negative numbers correctly. Sliding window relies on the property that growing a window changes the tracked sum in a known, monotonic direction; with negative elements present, growing the window could increase or decrease the sum, so you can no longer decide which pointer to move. Prefix sums sidestep this entirely: 'find a subarray with sum exactly x' becomes 'find two prefix indices i < j with P[j] - P[i] = x', i.e. 'for each j, has P[j] - x been seen before as some earlier P[i]?' -- which is answered by scanning once and looking up P[j] - x in a hash map of prefix sums seen so far, incrementing the map with P[j] afterward. This works regardless of the sign of any element, at the cost of O(n) extra space for the hash map (versus O(1) for plain sliding window when it applies).

Prefix sums generalize cleanly to two dimensions: a 2D prefix sum table lets you compute the sum of any axis-aligned submatrix in O(1) after O(R*C) preprocessing, using inclusion-exclusion (sum = P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]). This is the standard way to reduce 'submatrix sum' problems to repeated 1D 'subarray sum' problems: fix a pair of column boundaries, compute the resulting 1D array of row-range sums using the 2D prefix table, and run the 1D prefix-sum-plus-hashmap technique on that array.

Prefix sums also combine with a monotonic deque when a problem asks for something like the shortest (or otherwise optimal) subarray meeting a sum threshold, in the presence of negative numbers where a simple non-negative-only sliding window (which would work if all values were non-negative) breaks down. There, you keep prefix indices in a deque ordered by increasing prefix value; because a later, smaller prefix value always makes a better (or equal) starting point than an earlier, larger one, you can safely discard dominated candidates, giving an O(n) sweep even though sums are not monotonic.

Recognize it by

Look for 'count/find a subarray with sum exactly/at least X' where the array can contain negative or zero elements (ruling out plain sliding window), or any problem asking for repeated range-sum queries over a fixed array/matrix.

Complexity

O(n) preprocessing plus O(1) per range-sum query; O(n) or O(n) extra space for the prefix array and any hash map/deque used alongside it. 2D prefix sums cost O(R*C) preprocessing.

Subarray Sums II (allows negatives)

Problem

Given an array of n integers (which may be negative, zero, or positive) and a target integer x, count the number of contiguous subarrays whose sum equals exactly x. Constraints: 1 <= n <= 2*10^5, -10^9 <= a_i, x <= 10^9.

Approach

Because elements can be negative, growing or shrinking a sliding window does not change the window sum monotonically, so plain two pointers cannot be used here (unlike the easier variant of this problem restricted to non-negative values). Instead, compute the running prefix sum P as you scan left to right, and maintain a hash map from prefix-sum-value to how many times it has occurred so far (initialized with P=0 occurring once, representing the empty prefix before index 0). At each position, a subarray ending here with sum x exists for every earlier prefix value equal to (current prefix - x); look that up in the map and add its count to the answer, then record the current prefix value in the map. This is O(n) time with O(n) hash-map space, and correctly handles negative numbers because it never relies on the sum changing monotonically -- it only relies on prefix-sum equality.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n; long long x;
    cin >> n >> x;
    vector<long long> a(n);
    for (auto &v : a) cin >> v;

    unordered_map<long long,long long> cnt;
    cnt[0] = 1;
    long long prefix = 0, ans = 0;
    for (int i = 0; i < n; i++){
        prefix += a[i];
        auto it = cnt.find(prefix - x);
        if (it != cnt.end()) ans += it->second;
        cnt[prefix]++;
    }
    cout << ans << "\n";
    return 0;
}

Number of Submatrices That Sum to Target

Problem

Given an R x C integer matrix and an integer target, return the number of non-empty submatrices (axis-aligned, contiguous ranges of rows and columns) whose element sum equals target. Constraints: 1 <= R, C <= 100, -1000 <= matrix[i][j] <= 1000, -10^8 <= target <= 10^8.

Approach

Build a 2D prefix-sum table P where P[i][j] is the sum of the submatrix from (0,0) to (i-1,j-1), so any submatrix sum can be read off in O(1) via inclusion-exclusion. Then reduce the 2D problem to O(C^2) instances of the 1D 'count subarrays summing to target' problem: fix a pair of column boundaries (c1, c2) with c1 <= c2, and for each row r compute the sum of that row restricted to columns [c1, c2] using the 2D prefix table in O(1); this produces a 1D array of length R. Run prefix sums plus a hash map (exactly as in the previous example) on that 1D array to count how many row-ranges sum to target for this fixed column pair, and add that to the running answer. Trying every pair of column boundaries costs O(C^2), and each column pair does O(R) work, for a total of O(R * C^2), which is efficient enough given R, C <= 100.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int R, C; long long target;
    cin >> R >> C >> target;
    vector<vector<long long>> mat(R, vector<long long>(C));
    for (int i = 0; i < R; i++)
        for (int j = 0; j < C; j++)
            cin >> mat[i][j];

    vector<vector<long long>> prefix(R + 1, vector<long long>(C + 1, 0));
    for (int i = 0; i < R; i++){
        for (int j = 0; j < C; j++){
            prefix[i+1][j+1] = mat[i][j] + prefix[i][j+1] + prefix[i+1][j] - prefix[i][j];
        }
    }

    long long ans = 0;
    for (int c1 = 0; c1 < C; c1++){
        for (int c2 = c1; c2 < C; c2++){
            unordered_map<long long,long long> cnt;
            cnt[0] = 1;
            long long rowSum = 0;
            for (int r = 0; r < R; r++){
                long long s = prefix[r+1][c2+1] - prefix[r+1][c1] - prefix[r][c2+1] + prefix[r][c1];
                rowSum += s;
                auto it = cnt.find(rowSum - target);
                if (it != cnt.end()) ans += it->second;
                cnt[rowSum]++;
            }
        }
    }
    cout << ans << "\n";
    return 0;
}

Shortest Subarray with Sum at Least K

Problem

Given an integer array nums (which may contain negative numbers) of length n and an integer k, return the length of the shortest, non-empty, contiguous subarray whose sum is at least k. If no such subarray exists, return -1. Constraints: 1 <= n <= 10^5, -10^5 <= nums[i] <= 10^5, 1 <= k <= 10^9.

Approach

Because negatives are allowed, a plain sliding window (valid only when growing a window is guaranteed to help, i.e. all-non-negative arrays) does not work. Instead, build the prefix sum array P[0..n]. A subarray (i, j] with sum >= k corresponds to P[j] - P[i] >= k for some i < j; we want to minimize j - i. Maintain a deque of candidate left-endpoints i with the invariant that P over the deque is strictly increasing from front to back. For each new j (scanning P left to right): first, while the front of the deque gives P[j] - P[front] >= k, that candidate satisfies the sum condition -- record j - front as a candidate answer and pop it from the front, since any larger j' > j will only give an equal-or-worse (larger) length using that same front, so it can never be optimal again once beaten by this j. Second, before pushing j itself as a future left endpoint, pop from the back any index whose prefix value is >= P[j], because such an index is strictly dominated by j (j is a later, and at-least-as-low, starting point, so it will always produce an equal-or-shorter valid subarray whenever the dominated index would have worked). Each index enters and leaves the deque once, giving O(n) total time.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n; long long k;
    cin >> n >> k;
    vector<long long> nums(n);
    for (auto &x : nums) cin >> x;

    vector<long long> P(n + 1, 0);
    for (int i = 0; i < n; i++) P[i+1] = P[i] + nums[i];

    deque<int> dq;
    int ans = INT_MAX;
    for (int i = 0; i <= n; i++){
        while (!dq.empty() && P[i] - P[dq.front()] >= k){
            ans = min(ans, i - dq.front());
            dq.pop_front();
        }
        while (!dq.empty() && P[dq.back()] >= P[i]) dq.pop_back();
        dq.push_back(i);
    }
    cout << (ans == INT_MAX ? -1 : ans) << "\n";
    return 0;
}

Kadane's Algorithm

3 worked examples

Kadane's algorithm finds the maximum-sum contiguous subarray in O(n) time using a single dynamic-programming pass. Define best(i) as the maximum sum of a subarray ending exactly at index i. The recurrence is best(i) = max(a[i], best(i-1) + a[i]): either the best subarray ending at i is just a[i] on its own (restart), or it extends the best subarray ending at i-1 by adding a[i]. The overall answer is max over all i of best(i). The crucial insight that makes this a genuine dynamic-programming/greedy hybrid rather than a brute-force check is that once best(i-1) is negative, it can never help any future subarray sum (adding a negative running total only drags down whatever comes next), so restarting from a[i] alone dominates. This lets you keep only a single rolling value ('cur') instead of the full best(i) array, giving O(1) space in addition to O(n) time -- a dramatic improvement over the naive O(n^2) (try every start) or O(n^3) (try every start and end, resumming each time) approaches.

Kadane's is best understood as a special, very efficient case of the general prefix-sum reformulation: the maximum subarray sum ending at j is P[j] - min(P[0..j-1]) where P is the prefix sum array. Kadane's algorithm computes this implicitly by tracking the running minimum prefix (equivalently, the running best partial sum) as it scans, without needing to materialize the full prefix array or search it explicitly. Seeing this connection is what unlocks the harder variants below: whenever a variant constrains which earlier prefix indices are eligible (e.g. only prefixes within a certain distance back), you can no longer just track a single running minimum -- you need a windowed-minimum structure (segment tree or monotonic deque) over the eligible prefix indices, which is exactly sliding-window-minimum applied to the prefix array.

Two very common hard variants build directly on the base algorithm. First, length-constrained maximum subarray sum (maximize sum subject to the subarray length falling in [minLen, maxLen]): here you compute prefix sums P and, for each right endpoint r, need the minimum P[j] over j in the valid window [r-maxLen, r-minLen] -- a sliding-window-minimum problem over the prefix array, solved with a monotonic deque in O(n) total, since as r increases the valid window of j slides forward monotonically. Second, maximum subarray sum in a circular array (the subarray may wrap past the end back to the start): the best circular-wrapping subarray is total sum minus the minimum-sum non-circular subarray (removing the smallest-sum contiguous 'hole' from the full circle leaves the best wraparound segment), so compute ordinary Kadane's max, and a mirrored Kadane's-for-minimum, and take max(ordinarKadaneMax, total - minSubarraySum) -- with the edge case that if every element is negative, the minimum subarray is the entire array, making the wrap candidate an invalid empty selection, so you must fall back to the plain (negative) Kadane's max in that case.

Recognize it by

Look for 'maximum (or minimum) sum contiguous subarray' phrasing, especially when a plain 'sum of all elements' or 'largest element' answer is clearly too simple to be the intended solution -- length bounds, circularity, or a two-dimensional (submatrix) version are the standard ways these problems get escalated to hard difficulty.

Complexity

O(n) time, O(1) extra space for the base algorithm; O(n log n) or O(n) (with a monotonic deque) for length-constrained variants; O(n) time and space for the circular-array variant.

Maximum Subarray Sum with Witness Indices

Problem

Given an array of n integers (which may be negative), find the maximum possible sum of a non-empty contiguous subarray. In addition to the sum, output the 0-indexed start and end indices of a subarray achieving that maximum sum, specifically the one produced by scanning left to right and, whenever the running sum would need to restart, restarting exactly at the current element (this makes the output deterministic). Print the sum, then the start index, then the end index, separated by spaces. Constraints: 1 <= n <= 2*10^5.

Approach

This is the base Kadane recurrence, best(i) = max(a[i], best(i-1) + a[i]), tracked with a single rolling variable 'cur' plus its current start index. Whenever cur would become negative after adding the previous element (i.e. cur < 0 before processing a[i]), it is strictly better to restart the running subarray at a[i] alone, since carrying forward a negative running sum can only hurt any future extension -- so we reset cur = a[i] and mark the new candidate start as i. Otherwise we extend by cur += a[i]. After each update we compare cur to the best sum seen so far and, if it improves, record the sum along with the current candidate's start and the current index as its end. This single left-to-right pass is O(n) time and O(1) extra space (beyond the input array).

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){

    int bestStart = 0, bestEnd = 0, curStart = 0;
    for (int i = 1; i < n; i++){
        if (cur < 0){
            cur = a[i];
            curStart = i;
        } else {
            cur += a[i];
        }
        if (cur > best){
            best = cur;
            bestStart = curStart;
            bestEnd = i;
        }
    }

    return 0;
}

Maximum Subarray Sum with Length Bounds

Problem

Given an array of n integers (which may be negative) and two integers a and b with 1 <= a <= b <= n, find the maximum possible sum of a contiguous subarray whose length L satisfies a <= L <= b. Constraints: 1 <= n <= 2*10^5, -10^9 <= values <= 10^9.

Approach

Plain Kadane's does not enforce any length constraint, so instead work with prefix sums P[0..n] (P[0]=0). The sum of a subarray ending at prefix index r (i.e. covering original indices [j, r-1]) with left prefix-boundary j is P[r] - P[j], and its length is r - j; we need a <= r-j <= b, i.e. j must lie in the window [r-b, r-a]. To maximize P[r] - P[j] for fixed r we want the minimum P[j] over that window -- a sliding-window-minimum problem on the prefix array. As r increases by 1, the window [r-b, r-a] slides forward by exactly 1 on both ends, so maintain a monotonic increasing deque of prefix indices: each step, add the newly-eligible index r-a to the deque (popping any back entries with a prefix value >= the new one, since they're now dominated), then pop any front entries that have fallen below the window's lower bound r-b. The front of the deque is always the minimum-prefix eligible index, so P[r] - P[front] is the best achievable sum ending at r, and we take the max of that quantity over all valid r.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n, a, b;
    cin >> n >> a >> b;
    vector<long long> arr(n);
    for (auto &x : arr) cin >> x;

    vector<long long> P(n + 1, 0);
    for (int i = 0; i < n; i++) P[i+1] = P[i] + arr[i];

    deque<int> dq;
    long long best = LLONG_MIN;
    for (int r = a; r <= n; r++){
        int newJ = r - a;
        while (!dq.empty() && P[dq.back()] >= P[newJ]) dq.pop_back();
        dq.push_back(newJ);

        int lowBound = r - b;
        while (!dq.empty() && dq.front() < lowBound) dq.pop_front();

        best = max(best, P[r] - P[dq.front()]);
    }
    cout << best << "\n";
    return 0;
}

Maximum Circular Subarray Sum

Problem

Given a circular integer array nums of length n (meaning the subarray is allowed to wrap around past the last element back to the first), return the maximum possible sum of a non-empty contiguous (possibly wrapping) subarray. Constraints: 1 <= n <= 3*10^4, -3*10^4 <= nums[i] <= 3*10^4.

Approach

A subarray that does not wrap is just handled by ordinary Kadane's algorithm, giving maxSub. A subarray that does wrap around consists of a prefix of the array plus a suffix of the array, with some contiguous 'hole' in the middle excluded; its sum equals total - (sum of the excluded middle segment). To maximize the wrapped sum we therefore want to minimize the sum of the excluded middle segment, i.e. compute minSub, the minimum-sum non-empty contiguous subarray, using a mirrored Kadane's recurrence (curMin = min(a[i], curMin + a[i])). The best circular answer is then total - minSub, and the overall answer is max(maxSub, total - minSub). The one subtlety: if every element is negative, minSub equals the sum of the entire array, making total - minSub equal to 0, which corresponds to excluding everything -- an empty (invalid) selection. In that case the wrap candidate must be discarded and the answer is simply maxSub (which will correctly be the least-negative single element). This is handled by checking whether maxSub itself is negative before considering the wrap candidate.

Solution
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n; cin >> n;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;

    long long total = 0;
    long long curMax = 0, maxSub = LLONG_MIN;
    long long curMin = 0, minSub = LLONG_MAX;
    for (int i = 0; i < n; i++){
        total += a[i];
        curMax = max(curMax + a[i], a[i]);
        maxSub = max(maxSub, curMax);
        curMin = min(curMin + a[i], a[i]);
        minSub = min(minSub, curMin);
    }

    long long ans;
    if (maxSub < 0) ans = maxSub;
    else ans = max(maxSub, total - minSub);
    cout << ans << "\n";
    return 0;
}

Difference Arrays

2 worked examples

A difference array turns range-update problems into point-update problems. Given an array a[1..n], define d[1] = a[1] and d[i] = a[i] - a[i-1] for i > 1 (conceptually d[0] = a[0] = 0). The key identity is that a[i] = d[1] + d[2] + ... + d[i], i.e. a is the prefix-sum of d. This means adding a constant v to every element of a contiguous range a[l..r] can be done in O(1) by only touching the difference array: d[l] += v and d[r+1] -= v (if r+1 <= n). After all range updates are applied to d, a single prefix-sum pass over d reconstructs the final array a in O(n). This is the array analogue of a Fenwick/segment tree range-update, but with no logarithmic factor -- it is only valid when all updates are applied before any point is read back (an 'offline' batch of updates), which is exactly the situation in most of these problems.

The deeper and more powerful insight is the reverse direction: reconstructing the MINIMUM number of range-add operations that could have produced a given final array, starting from all zeros. Since each individual operation rangeAdd(l, r, +1) changes exactly two entries of the difference array (d[l] += 1, d[r+1] -= 1), and a value v > 0 at position i of d must be 'created' by v operations whose left endpoint is i (each contributing +1), the minimum number of operations equals the sum of all POSITIVE values in the difference array. This is because every operation contributes exactly one positive unit somewhere in d and exactly one negative unit (or falls off the end); an optimal strategy greedily starts a new range exactly when d[i] is positive, and closes ranges exactly when d[i] is negative, and it is never beneficial to start more ranges than the total positive mass requires.

This reconstruction insight generalizes further: when updates can be signed (+1 or -1 operations, as in turning nums into target), split the required delta d[i] = target[i]-nums[i] into a non-negative part (dpos[i] = max(0, d[i])) and a non-positive part (dneg[i] = max(0, -d[i])). Because a +1 range operation and a -1 range operation can never be merged into fewer operations (they move the value in different directions), the two parts are independent sub-problems, each solved by the same 'sum of positive jumps in the difference array' rule, and the answers simply add.

Difference arrays also compose naturally with other structures: 2D difference arrays extend the same trick to rectangle-add/point-query grids, and combining a difference array with a Fenwick tree (a 'Fenwick tree of differences') supports range-add + range-sum-query in O(log n) per operation when updates and queries are interleaved online rather than batched.

Recognize it by

The problem describes many operations of the form 'add v to every element in range [l, r]' (or 'increment/decrement a contiguous subarray'), especially when all updates happen before you need to read the final array; or the problem gives you a final array and asks for the minimum number of range-add operations that could have produced it from all zeros.

Complexity

O(n + q) time and O(n) space for q batched range updates followed by one reconstruction pass; O(1) per update, O(n) for the final prefix-sum reconstruction.

You are given the final array b[1..n] that resulted from applying some sequence of such operations. Find the minimum possible number of operations that could have produced b.

Approach

Build the difference array d[i] = b[i] - b[i-1] for i = 1..n, treating b[0] = 0. Every operation rangeAdd(l, r) increases d[l] by 1 and decreases d[r+1] by 1 (or has no effect on the 'far side' if r = n). Minimum Operations to Turn nums into target (signed range updates)

Problem

You are given two integer arrays nums and target, both of length n. In one operation you may choose a contiguous subarray of nums and either add 1 to every element in it, or subtract 1 from every element in it. Find the minimum number of operations needed to make nums equal to target.

Input: n, then n integers nums[1..n], then n integers target[1..n].
Output: the minimum number of operations.

Approach

Let d[i] = target[i] - nums[i] be the required signed delta at each position. A +1 range operation can only ever help positions that still need a positive delta, and a -1 range operation can only help positions that still need a negative delta -- the two kinds of operations never interact usefully in the same range, so the problem decomposes into two independent instances of the classic difference-array reconstruction: dpos[i] = max(0, d[i]) needs to be built with +1 range ops, and dneg[i] = max(0, -d[i]) needs to be built with -1 range ops. Each is solved exactly like the previous example: form the difference array of dpos (respectively dneg) with an implicit 0 before index 0, and sum the positive jumps. The final answer is the sum of the two independent costs. This is O(n) time and space.

Solution
#include <bits/stdc++.h>
using namespace std;
long long costOneDirection(vector<long long>& d) {
    // d[i] >= 0 required contribution at each index; cost = sum of positive jumps
    // treat as difference array with implicit d[-1] = 0
    long long ops = 0;
    long long prev = 0;
    for (long long x : d) {
        long long jump = x - prev;
        if (jump > 0) ops += jump;
        prev = x;
    }
    return ops;
}

    int n; cin >> n;
    vector<long long> nums(n), target(n);

    for (auto &x : target) cin >> x;
    vector<long long> dpos(n), dneg(n);
    for (int i = 0; i < n; i++) {
        long long d = target[i] - nums[i];
        dpos[i] = max(0LL, d);
        dneg[i] = max(0LL, -d);
    }
    long long ans = costOneDirection(dpos) + costOneDirection(dneg);
    cout << ans << endl;
}

Two-Pointer Partitioning (Dutch National Flag)

2 worked examples

The Dutch National Flag problem (Dijkstra) asks how to sort an array containing only three distinct values (conventionally 0, 1, 2) in-place in a single O(n) pass, without counting sort. The classic solution maintains three regions using three pointers: low marks the boundary of the region known to contain only 0s (everything in [0, low) is 0), high marks the boundary of the region known to contain only 2s (everything in (high, n) is 2), and mid scans forward through the unknown middle region. At each step, look at a[mid]: if it's 0, swap it with a[low] and advance both low and mid (the swapped-in element at position low was already known to be a 1 or already processed, so mid can safely advance too); if it's 1, it's already in its correct relative region, so just advance mid; if it's 2, swap it with a[high] and decrement high WITHOUT advancing mid, because the element swapped in from position high has not yet been examined and could be 0, 1, or 2.

The general pattern -- maintaining multiple pointers that each mark the boundary of a region with a known invariant, and advancing them based on a local test -- generalizes far beyond three-way sorting. It applies to any 'in-place partition into k labeled groups' problem, to problems that require partitioning a sorted or unsorted array into a 'low group' and a 'high group' related by some transformation (e.g. recovering an original array from a k-shifted interleaving), and to multi-region search problems where the boundaries of several valid segments must be discovered simultaneously by scanning with coordinated pointers rather than nested loops.

A second, related pattern is 'matching a multiset against a candidate transformation': given a shuffled combination of two related sequences (e.g. {v-k, v+k} pairs for unknown k), sort the combined multiset, then repeatedly peel off the smallest remaining value x and require its designated partner value (x plus some offset determined by the candidate k) to also be present; if this greedy peeling matches every element exactly once, the candidate k is validated and the matching directly reconstructs the original array. This only works correctly when applied to the SORTED order (so that 'smallest remaining element' always corresponds to the 'low' member of a pair, never a 'high' member whose partner has already been consumed) -- this is what makes it a genuine two-pointer/partition technique rather than arbitrary multiset matching.

Recognize it by

The array (or the target structure) has a small, fixed number of distinct categories/labels that must end up in contiguous, ordered regions in one pass (Dutch flag itself); or the array was formed by combining two related groups of values under some unknown shift/scale, and you must partition the sorted values back into a 'low' group and a 'high' group that pair up exactly.

Complexity

O(n) time, O(1) extra space for the classic three-way in-place partition; O(n log n) time (dominated by the sort) for multiset-matching reconstruction problems.

Sort an Array of 0s, 1s, and 2s (Dutch National Flag)

Problem

Given an array of n integers, each equal to 0, 1, or 2, sort the array in-place in a single pass (O(n) time, O(1) extra space), without using a library sort or counting sort.

Input: n, then n integers (each 0, 1, or 2).
Output: the sorted array, space-separated.

Approach

Maintain three pointers: low (next position to place a 0), mid (current element under examination), and high (next position to place a 2), initialized to 0, 0, n-1. Loop while mid <= high: if a[mid] == 0, swap a[low] with a[mid], then increment both low and mid (the element now at mid, previously at low, is guaranteed to be a 1 or already-examined 0, safe to skip past). If a[mid] == 1, just increment mid (it's already correctly placed in the middle region). If a[mid] == 2, swap a[mid] with a[high] and decrement high, but do NOT advance mid, since the newly swapped-in value at mid has not yet been classified. The invariant maintained throughout is: [0, low) contains only 0s, [low, mid) contains only 1s, [mid, high] is unexamined, and (high, n) contains only 2s. When mid exceeds high, the unexamined region is empty and the array is fully sorted.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<int> a(n);
    for (auto &x : a) cin >> x; // each x in {0,1,2}
    int low = 0, mid = 0, high = n - 1;
    while (mid <= high) {
        if (a[mid] == 0) {
            swap(a[low], a[mid]);
            low++; mid++;
        } else if (a[mid] == 1) {
            mid++;
        } else { // a[mid] == 2
            swap(a[mid], a[high]);
            high--;
            // do not advance mid: the swapped-in value must still be examined
        }
    }
    for (int i = 0; i < n; i++) cout << a[i] << (i+1<n?' ':'\n');
}

Recover the Original Array from a k-Shifted Interleaving

Problem

An array arr of n positive integers and an unknown positive integer k were used to build an array b of length 2n: for every arr[i], both arr[i]-k and arr[i]+k were placed somewhere into b (in arbitrary order, fully shuffled). Given b, recover any valid array arr and the value k that could have produced it (if multiple answers exist, any valid one is acceptable).

Input: 2n (the length of b), then the 2n integers of b.
Output: the n integers of a valid arr, sorted ascending, space-separated (print IMPOSSIBLE if no valid reconstruction exists, which will not occur in this example).

Approach

Sort b. The globally smallest element of b, b[0], must be a 'low' member of some pair (arr[i]-k), since arr[i]+k > arr[i]-k for k > 0, so nothing can be smaller than the smallest low value. Therefore the true k satisfies b[0] + 2k = (partner of b[0]) for SOME other element of b; try every candidate k = (b[i] - b[0]) / 2 for i = 1..2n-1 (skipping non-positive or odd differences). For each candidate k, attempt a greedy two-pointer-style matching using a multiset: repeatedly remove the current smallest remaining value x, and require x + 2k to also be present in the multiset (removing it too) as x's high partner; record x + k as a recovered element of arr. If this succeeds for all 2n elements (the multiset empties with no failed lookups), the candidate k is valid and the recovered elements form arr. Processing smallest-to-largest is essential: it guarantees every value taken as 'x' is genuinely a low member (its partner, if any, still lies ahead in sorted order), so the matching can never mistakenly try to pair two high members together.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n2; cin >> n2; // total length, must be even
    vector<long long> b(n2);
    for (auto &x : b) cin >> x;
    sort(b.begin(), b.end());
    int n = n2 / 2;

    vector<long long> result;
    bool found = false;
    for (int i = 1; i < n2 && !found; i++) {
        long long diff = b[i] - b[0];
        if (diff <= 0 || diff % 2 != 0) continue;
        long long k = diff / 2;
        // attempt greedy matching with this k using a multiset
        multiset<long long> ms(b.begin(), b.end());
        vector<long long> res;
        bool ok = true;
        while (!ms.empty()) {
            long long x = *ms.begin();
            ms.erase(ms.begin());
            auto it = ms.find(x + 2*k);
            if (it == ms.end()) { ok = false; break; }
            ms.erase(it);
            res.push_back(x + k);
        }
        if (ok && (long long)res.size() == n) {
            result = res;
            found = true;
        }
    }

Monotonic Deque

2 worked examples

A monotonic deque maintains a double-ended queue of candidate values (or indices) that is always sorted (monotonically increasing or decreasing) from front to back, and supports O(1) amortized insertion at the back and removal from either end. It is the standard tool for computing a sliding window's maximum or minimum in O(n) total, and more generally for online DP transitions of the form dp[i] = f(i) + best(dp[j] for j in a moving window [i-k, i-1]).

For sliding window maximum, the deque stores indices with strictly decreasing values front-to-back. When a new index i arrives: (1) pop from the back any index whose value is <= a[i], because such an index can never again be the window maximum while i is still in the window (a[i] is at least as large and will outlast it) -- this is what keeps the deque monotonic and is the reason the amortized cost is O(1) (each element is pushed once and popped at most once); (2) push i to the back; (3) pop from the front any index that has fallen outside the current window's left boundary; (4) the current window's maximum is now the value at the front of the deque.

A second major use case is when the naive two-pointer sliding window technique breaks because the array contains negative numbers, so prefix sums are not monotonic. For 'shortest subarray with sum >= K', a two-pointer approach that only ever advances both pointers forward is unsound because shrinking the window from the left doesn't necessarily decrease the sum. The fix is to work with prefix sums pre[0..n] and maintain a deque of indices with strictly INCREASING prefix-sum values front-to-back: for each new index j, first pop from the FRONT any index i where pre[j] - pre[i] >= K (recording the window length j - i as a candidate answer, and popping i because it can never again be useful -- any later j' > j gives an even longer, so worse, candidate through the same i); then pop from the BACK any index i where pre[i] >= pre[j] (such an i is dominated by j: j is a later index with an equal or smaller prefix sum, so j is always at least as good a left endpoint for future queries); finally push j to the back. Both directions of pruning together guarantee the deque never grows unboundedly and every index is pushed and popped at most once, giving O(n) total time.

Monotonic-deque DP optimization follows the same shape applied to a DP recurrence instead of a raw array: whenever the transition looks at a max (or min) of dp-values over a sliding window of previous states, replacing the naive O(window size) scan with a monotonic deque turns an O(n*k) DP into O(n).

Recognize it by

You need the max or min of every sliding window of an array (fixed or variable size) computed as the window moves, ideally in a single pass; or a DP transition needs 'the best dp-value among the last k states' computed online; or a two-pointer sliding-window sum breaks because the array contains negative numbers, requiring a monotonic structure on prefix sums instead.

Complexity

O(n) time and O(k) or O(n) space (amortized O(1) per element, since each index is pushed and popped from the deque at most once).

Sliding Window Maximum

Problem

Given an array nums of n integers and a window size k, return the maximum value of every contiguous window of size k as the window slides from the left end of the array to the right end (there are n - k + 1 such windows).

Input: n and k, then n integers nums[1..n].
Output: the n - k + 1 window maximums, space-separated.

Approach

Maintain a deque of indices whose corresponding values are strictly decreasing from front to back. For each index i from 0 to n-1: pop indices from the back of the deque while the value at the back is <= nums[i] (they can never be the max again once nums[i] is in play); push i to the back. Pop from the front any index that is no longer within the window (index <= i - k). Once i >= k - 1 (the window is full), the front of the deque holds the index of the current window's maximum, so record nums[front]. Each index enters and leaves the deque at most once, giving O(n) total time.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    deque<int> dq; // stores indices, values decreasing front-to-back
    vector<int> res;
    for (int i = 0; i < n; i++) {
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();
        dq.push_back(i);
        while (dq.front() <= i - k) dq.pop_front();
        if (i >= k - 1) res.push_back(a[dq.front()]);
    }
    for (size_t i = 0; i < res.size(); i++) cout << res[i] << (i+1<res.size()?' ':'\n');
}

Shortest Subarray with Sum at Least K

Problem

Given an integer array nums of n elements (which may include negative numbers) and an integer K, return the length of the shortest, non-empty, contiguous subarray whose sum is at least K. If no such subarray exists, return -1.

Input: n and K, then n integers nums[1..n].
Output: the length of the shortest qualifying subarray, or -1.

Approach

Because nums can contain negative numbers, prefix sums pre[0..n] are not monotonic, so a standard two-pointer sliding window (which relies on the sum only increasing as the right end grows and only decreasing as the left end shrinks) is unsound here. Instead, maintain a deque of indices into pre[] with strictly increasing pre[] values front-to-back. For each j from 0 to n: while the deque is non-empty and pre[j] - pre[front] >= K, that gives a candidate answer of length j - front; record it and pop the front (a smaller index can never yield a shorter valid subarray again once a later, equally-or-more-restrictive j has already worked for it -- any future j' > j would only produce a longer candidate through the same front). Then, while the deque's back has pre[] >= pre[j], pop it (index j is a strictly better or equal left endpoint for all future right endpoints, since it has an equal-or-smaller prefix sum at a later, closer position). Push j to the back. The answer is the minimum recorded length, or -1 if none was found.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; long long K;
    cin >> n >> K;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    vector<long long> pre(n+1, 0);
    for (int i = 0; i < n; i++) pre[i+1] = pre[i] + a[i];
    deque<int> dq; // indices into pre[], increasing prefix-sum order front-to-back
    int best = INT_MAX;
    for (int j = 0; j <= n; j++) {
        while (!dq.empty() && pre[j] - pre[dq.front()] >= K) {
            best = min(best, j - dq.front());
            dq.pop_front();
        }
        while (!dq.empty() && pre[dq.back()] >= pre[j]) dq.pop_back();
        dq.push_back(j);
    }
    cout << (best == INT_MAX ? -1 : best) << endl;
}

Merge Intervals

2 worked examples

Merge Intervals problems build on the Sorting & Binary Search idea that sorting objects by a key transforms an unordered comparison problem into a linear sweep. Here the objects are ranges [l, r] rather than points, and the standard first step is to sort all intervals by their left endpoint. Once sorted, a single left-to-right pass can merge overlapping or touching intervals: keep a running 'current merged interval'; for each new interval in sorted order, if its start is <= the current merged interval's end, extend the current interval's end to the max of the two ends (they overlap or touch, so they belong to the same merged group); otherwise, the current merged interval is finalized (push it to the result) and the new interval starts a fresh current interval. This is correct because sorting by start guarantees that once an interval's start exceeds the current merged end, no LATER interval (which has an even larger or equal start) can ever overlap the current merged interval either.

Many harder problems combine this sort-and-sweep idea with a secondary data structure to answer aggregate or per-query questions rather than just producing the merged list. A common pattern: sort both the intervals (by start) and a separate list of queries, then sweep through the queries in increasing order, incrementally adding to a min-heap (or other structure) every interval whose start has already been 'reached' by the sweep, lazily removing from the heap any interval that has expired (its end is now behind the current query point). This 'offline sweep with a heap keyed by a secondary attribute' technique answers many queries in O((n + q) log n) total instead of O(n) per query.

A third pattern extends interval merging into a full mutable data structure: rather than merging a static list once, the structure supports online insertions and/or deletions of ranges, automatically re-merging with neighbors on every update (e.g. a TreeMap/ordered-map of disjoint intervals keyed by start, where inserting a new point or range requires finding and splicing together any now-adjacent or overlapping neighboring intervals). This turns 'merge intervals' from a one-shot batch algorithm into an amortized-efficient online interval-set structure.

Recognize it by

You are given a list of ranges/intervals and need to combine overlapping ones into a canonical disjoint form, or you need to answer 'which merged range covers this point/query' efficiently, possibly across many queries or many incremental updates to the interval set.

Complexity

O(n log n) time to sort and merge n intervals once; O((n + q) log n) for an offline sweep answering q queries against n intervals with a heap.

Merge Overlapping Intervals

Problem

Given a collection of n intervals, each represented as [start, end] (inclusive), merge all overlapping (or touching) intervals and return the resulting list of disjoint intervals, sorted by start.

Input: n, then n pairs of integers start end.
Output: the number of merged intervals, followed by each merged interval on its own line as 'start end'.

Approach

Sort the intervals by start. Initialize the result with the first interval as the 'current' interval. For each subsequent interval in sorted order, compare its start to the current interval's end: if start <= current end, the intervals overlap or touch, so extend current's end to max(current end, this interval's end); otherwise, push the current interval to the result and make this interval the new current. After the loop, push the final current interval. This is a single O(n) pass after an O(n log n) sort.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<pair<long long,long long>> iv(n);
    for (auto &p : iv) cin >> p.first >> p.second;
    sort(iv.begin(), iv.end());
    vector<pair<long long,long long>> res;
    for (auto &p : iv) {
        if (!res.empty() && p.first <= res.back().second) {
            res.back().second = max(res.back().second, p.second);
        } else {
            res.push_back(p);
        }
    }
    cout << res.size() << "\n";
    for (auto &p : res) cout << p.first << " " << p.second << "\n";
}

Minimum Interval to Include Each Query

Problem

You are given n intervals, each [start, end] (inclusive), and q query points. For each query point x, find the size (end - start + 1) of the smallest interval that contains x. If no interval contains x, the answer for that query is -1.

Input: n, then n pairs start end, then q, then q query integers.
Output: q integers (one per query, in the original query order), space-separated, where an unanswerable query prints -1.

Approach

Sort intervals by start, and sort the queries by value (while remembering each query's original index so the output can be restored to input order). Sweep the sorted queries left to right: maintain a pointer into the sorted intervals and a min-heap keyed by (interval size, interval end). For each query x, first push into the heap every interval whose start is <= x that has not yet been pushed (advancing the interval pointer). Then pop from the heap any interval whose end < x (it has expired and can never contain this or any larger future query point). The top of the heap, if any remains, has the smallest size among all intervals currently containing x, which is exactly the answer for this query. Because both intervals and queries are processed in sorted order with a heap, each interval is pushed and popped at most once, giving O((n + q) log n) total time.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<pair<long long,long long>> iv(n); // start, end (inclusive)
    for (auto &p : iv) cin >> p.first >> p.second;
    int q; cin >> q;
    vector<long long> queries(q);
    vector<int> order(q);
    for (int i = 0; i < q; i++) { cin >> queries[i]; order[i] = i; }

    sort(iv.begin(), iv.end()); // by start
    sort(order.begin(), order.end(), [&](int i, int j){ return queries[i] < queries[j]; });

    // min-heap of (size, end)
    priority_queue<pair<long long,long long>, vector<pair<long long,long long>>, greater<>> pq;
    vector<long long> ans(q, -1);
    int idx = 0;
    for (int oi : order) {
        long long x = queries[oi];
        while (idx < n && iv[idx].first <= x) {
            pq.push({iv[idx].second - iv[idx].first + 1, iv[idx].second});
            idx++;
        }
        while (!pq.empty() && pq.top().second < x) pq.pop();
        if (!pq.empty()) ans[oi] = pq.top().first;
    }
    for (int i = 0; i < q; i++) cout << ans[i] << (i+1<q?' ':'\n');
}
