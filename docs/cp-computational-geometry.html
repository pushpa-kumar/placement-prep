Computational Geometry

Geometry problems in competitive programming rarely test deep mathematical insight so much as they test whether you can turn a picture into a small set of robust, integer-exact primitives: the orientation (cross-product) test, a sweep over sorted events, and the shoelace formula. Once those three are solid, most "find the convex hull", "union area of rectangles", "closest pair of points", and "is this point inside the polygon" problems reduce to composing them correctly. The single biggest source of bugs in this area is boundary handling — whether collinear points belong on the hull, whether a point exactly on an edge counts as inside, whether touching (not overlapping) rectangles double-count — so every subtopic below calls out its boundary convention explicitly. This topic was added after a recurring pattern surfaced across several real company OAs in this site's Company OA Bank: LeetCode's "Erect the Fence" (convex hull) was asked independently at two different companies, and "Rectangle Area II" (sweep-line union area) at a third, with zero prior coverage of the area anywhere in this guide.

Convex Hull (Andrew's Monotone Chain)

2 worked examples

The convex hull of a point set is the smallest convex polygon containing every point. Andrew's monotone chain algorithm builds it in O(n log n) by sorting points lexicographically by (x, y) and then constructing the lower hull and upper hull independently with the same one-pass greedy rule: walk the sorted points left to right (then right to left for the upper hull), maintaining a stack, and while the last three points on the stack make a non-left turn, pop the middle one before pushing the new point. "Turn direction" is decided by the 2D cross product cross(O,A,B) = (A.x-O.x)*(B.y-O.y) - (A.y-O.y)*(B.x-O.x): a positive value means A->B turns left (counterclockwise) from O, negative means it turns right, and zero means the three points are collinear. Using strictly-non-positive (<=0) as the pop condition produces the strict hull (collinear points on an edge are dropped, only true corners remain); using strictly-negative (<0) instead keeps collinear boundary points in the output, which is exactly what LeetCode's "Erect the Fence" requires (a fence must physically pass through every tree, including ones sitting exactly on a straight edge between two other trees) — this single operator difference is the most common reason a textbook-correct convex hull implementation fails that specific problem. Concatenating the lower and upper hull chains (dropping the duplicated last point of each) gives the full hull in counterclockwise order.

Recognize it by

"Find the smallest convex polygon/fence/boundary enclosing all points", "minimum-perimeter shape containing every given point", any problem literally titled convex hull, and problems about enclosing trees/houses/sensors on a 2D plane.

Complexity

O(n log n), dominated by the initial sort; the hull construction itself is a single O(n) pass per chain since each point is pushed and popped from the stack at most once.

Convex Hull of a Point Set

Problem

Given n distinct points on a 2D plane (2 <= n <= 1000, integer coordinates up to 1e9 in magnitude), output the vertices of their convex hull in counterclockwise order, starting from the point with the smallest x-coordinate (ties broken by smallest y). Points strictly inside the hull, and points lying exactly on a hull edge between two other points, should not be listed.

Approach

Sort all points by (x, y). Build the lower hull by scanning left to right, popping the last point off the hull stack whenever the last two hull points and the current point don't make a strict left turn (cross <= 0). Build the upper hull the same way scanning right to left. Concatenate lower + upper, dropping the final point of each chain since it duplicates the first point of the next chain.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
struct Pt{ ll x,y; };

ll cross(const Pt&O,const Pt&A,const Pt&B){
    return (A.x-O.x)*(B.y-O.y) - (A.y-O.y)*(B.x-O.x);
}

vector<Pt> convexHull(vector<Pt> pts){
    int n = pts.size();
    sort(pts.begin(), pts.end(), [](const Pt&a,const Pt&b){
        return a.x<b.x || (a.x==b.x && a.y<b.y);
    });
    if(n < 3) return pts;
    vector<Pt> hull(2*n);
    int k = 0;
    for(int i=0;i<n;i++){
        while(k>=2 && cross(hull[k-2],hull[k-1],pts[i])<=0) k--;
        hull[k++] = pts[i];
    }
    for(int i=n-2, lower=k+1; i>=0; i--){
        while(k>=lower && cross(hull[k-2],hull[k-1],pts[i])<=0) k--;
        hull[k++] = pts[i];
    }
    hull.resize(k-1);
    return hull;
}

int main(){
    int n; cin >> n;
    vector<Pt> pts(n);
    for(auto &p: pts) cin >> p.x >> p.y;
    auto hull = convexHull(pts);
    cout << hull.size() << "\n";
    for(auto &p: hull) cout << p.x << " " << p.y << "\n";
}

Erect the Fence (Convex Hull Including Collinear Boundary Points)

Problem

Given the positions of n trees on a 2D plane, find the fence with the minimum possible length that can enclose all the trees. Unlike a strict convex hull, a tree that sits exactly on a straight segment between two other selected trees must still be included in the answer, since a straight fence passing over that segment would pass through it.

Approach

Identical monotone-chain construction as the plain convex hull, except the pop condition changes from "cross <= 0" to "cross < 0": collinear points (cross == 0) are now kept rather than discarded, so every point lying exactly on a hull edge survives into the output. This is the one-line fix for the classic gotcha where a correct convex-hull implementation silently gives a wrong answer on this exact problem.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
struct Pt{ ll x,y; };

ll cross(const Pt&O,const Pt&A,const Pt&B){
    return (A.x-O.x)*(B.y-O.y) - (A.y-O.y)*(B.x-O.x);
}

vector<Pt> fenceHull(vector<Pt> pts){
    int n = pts.size();
    sort(pts.begin(), pts.end(), [](const Pt&a,const Pt&b){
        return a.x<b.x || (a.x==b.x && a.y<b.y);
    });
    if(n < 3) return pts;
    vector<Pt> hull(2*n);
    int k = 0;
    for(int i=0;i<n;i++){
        while(k>=2 && cross(hull[k-2],hull[k-1],pts[i])<0) k--;
        hull[k++] = pts[i];
    }
    for(int i=n-2, lower=k+1; i>=0; i--){
        while(k>=lower && cross(hull[k-2],hull[k-1],pts[i])<0) k--;
        hull[k++] = pts[i];
    }
    hull.resize(k-1);
    return hull;
}

int main(){
    int n; cin >> n;
    vector<Pt> pts(n);
    for(auto &p: pts) cin >> p.x >> p.y;
    auto hull = fenceHull(pts);
    cout << hull.size() << "\n";
    for(auto &p: hull) cout << p.x << " " << p.y << "\n";
}

Sweep Line for Rectangle Union Area

2 worked examples

To compute the total area covered by a union of possibly-overlapping axis-aligned rectangles, sweep a vertical line across all distinct x-coordinates that appear as a rectangle's left or right edge. Between two consecutive distinct x-coordinates x_L < x_R, every rectangle that spans the whole slab [x_L, x_R] contributes a constant covered height for that entire slab, so the area contributed by the slab is (x_R - x_L) times the total length of the y-axis covered by the union of those rectangles' y-intervals within the slab. Computing that covered y-length is itself a 1D interval-union problem: collect the y-intervals of every rectangle active in the slab, sort by start, and merge overlapping/touching intervals while summing their lengths. Repeating this for every slab and summing gives the total area in O(k) slabs times O(m log m) per slab for the m rectangles active in it — O(n^2 log n) worst case, which is simple to implement and plenty fast for n up to a few thousand; a segment tree keyed on compressed y-coordinates that tracks (coverage count, covered length) per node turns the per-slab query into O(log n), giving the fully optimized O(n log n) solution used when n is large (up to 1e5, as in the harder OA constraint reported for this problem).

Recognize it by

"Total area covered by a set of (possibly overlapping) rectangles", "union of intervals/rectangles", or any problem whose examples show axis-aligned rectangles and ask for a combined area or covered length rather than a per-rectangle sum.

Complexity

O(n^2 log n) with the simple merge-per-slab approach shown here (fine for n up to a few thousand); O(n log n) with a coverage-counting segment tree over compressed y-coordinates for larger n.

Rectangle Area II

Problem

Given n axis-aligned rectangles, each described as [x1, y1, x2, y2] (bottom-left and top-right corners), return the total area covered by all rectangles, counting any overlapping region only once. Since the answer can be very large, return it modulo 1e9+7.

Approach

Collect every rectangle's x1 and x2 into a sorted, de-duplicated list of x-coordinates. For each consecutive pair (x_L, x_R) in that list, gather the y-intervals of every rectangle with x1 <= x_L and x2 >= x_R (i.e. every rectangle spanning the whole slab), sort those intervals by start, merge overlapping ones while accumulating covered length, and add (x_R - x_L) * covered_length to a running total (mod 1e9+7).

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
const ll MOD = 1000000007;

int main(){
    int n; cin >> n;
    vector<array<ll,4>> rect(n); // x1,y1,x2,y2
    vector<ll> xs;
    for(auto &r: rect){
        cin >> r[0] >> r[1] >> r[2] >> r[3];
        xs.push_back(r[0]); xs.push_back(r[2]);
    }
    sort(xs.begin(), xs.end());
    xs.erase(unique(xs.begin(), xs.end()), xs.end());

    ll area = 0;
    for(size_t i=0; i+1<xs.size(); i++){
        ll xL = xs[i], xR = xs[i+1];
        ll width = xR - xL;
        if(width == 0) continue;
        vector<pair<ll,ll>> ys;
        for(auto &r: rect)
            if(r[0] <= xL && r[2] >= xR) ys.push_back({r[1], r[3]});
        sort(ys.begin(), ys.end());
        ll covered = 0, curL = 0, curR = 0;
        bool have = false;
        for(auto &yv: ys){
            if(!have){ curL = yv.first; curR = yv.second; have = true; }
            else if(yv.first <= curR){ curR = max(curR, yv.second); }
            else{ covered += curR - curL; curL = yv.first; curR = yv.second; }
        }
        if(have) covered += curR - curL;
        area = (area + (width % MOD) * (covered % MOD)) % MOD;
    }
    cout << area << "\n";
}

Problem

Given n axis-aligned rectangles, compute the total area they cover, treating overlapping regions only once (coordinates are small enough that the exact integer area fits comfortably in a 64-bit integer, no modulo needed).

Approach

Exactly the same slab-and-merge sweep as Rectangle Area II, just without the modulo reduction at the end — useful when the judge wants the exact area rather than a residue, and a good sanity check that the technique is understood independently of the modular-arithmetic bookkeeping.

Closest Pair of Points & Manhattan-Distance Tricks

2 worked examples

The classic divide-and-conquer closest-pair algorithm finds the minimum Euclidean distance among n points in O(n log n) (or the simpler-to-code O(n log^2 n) variant below): sort points by x, recursively solve the left and right halves, then check only the "strip" of points within the current best distance d of the dividing vertical line, sorted by y — a packing argument (at most a small constant number of points can fit in any d x 2d box without being closer than d to each other) guarantees each strip point only needs to be compared against a handful of its neighbors in y-order, not the whole strip. Comparing squared distances instead of true distances avoids floating point and sqrt entirely, which is both faster and exact. A completely different but very useful trick applies specifically to Manhattan distance |x1-x2|+|y1-y2|: rotating coordinates by 45 degrees via u=x+y, v=x-y turns Manhattan distance into Chebyshev distance max(|u1-u2|,|v1-v2|), which means the *maximum* Manhattan distance among all pairs of n points is simply max(max(u)-min(u), max(v)-min(v)) — no pairwise comparison or recursion needed at all, just a single O(n) scan after computing u and v for every point.

Recognize it by

"Find the minimum distance between any two points" (closest pair, Euclidean) or "find the maximum/minimum Manhattan distance among a set of points" (rotate-and-scan, no D&C needed).

Complexity

O(n log^2 n) for the closest-pair divide and conquer shown here (O(n log n) achievable by maintaining the y-sorted order incrementally instead of re-sorting the strip each call); O(n log n) for the Manhattan-distance trick, dominated purely by the sort/scan.

Closest Pair of Points

Problem

Given n points on a 2D plane (2 <= n <= 2*10^5, integer coordinates), find the minimum squared Euclidean distance between any two distinct points.

Approach

Sort points by x. Recurse: if a range has <=2 points, brute-force it directly. Otherwise split at the midpoint, recursively solve both halves to get the best squared distance so far, then build the "strip" of points within sqrt(best) of the splitting x-coordinate (compared as (dx)^2 < best to stay in integers), sort the strip by y, and for each strip point only compare forward while the y-gap squared stays below best (the packing argument bounds how many such comparisons are needed).

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
struct Pt{ ll x,y; };

ll sqDist(const Pt&a,const Pt&b){
    ll dx=a.x-b.x, dy=a.y-b.y;
    return dx*dx + dy*dy;
}

ll bruteForce(vector<Pt>&pts,int l,int r){
    ll best = LLONG_MAX;
    for(int i=l;i<=r;i++)
        for(int j=i+1;j<=r;j++)
            best = min(best, sqDist(pts[i],pts[j]));
    return best;
}

ll closestPair(vector<Pt>&pts,int l,int r){
    if(r-l <= 2) return bruteForce(pts,l,r);
    int mid = (l+r)/2;
    ll midX = pts[mid].x;
    ll best = min(closestPair(pts,l,mid), closestPair(pts,mid+1,r));

    vector<Pt> strip;
    for(int i=l;i<=r;i++)
        if((pts[i].x-midX)*(pts[i].x-midX) < best) strip.push_back(pts[i]);
    sort(strip.begin(), strip.end(), [](const Pt&a,const Pt&b){ return a.y<b.y; });

    for(size_t i=0;i<strip.size();i++)
        for(size_t j=i+1;j<strip.size() && (strip[j].y-strip[i].y)*(strip[j].y-strip[i].y) < best; j++)
            best = min(best, sqDist(strip[i],strip[j]));
    return best;
}

int main(){
    int n; cin >> n;
    vector<Pt> pts(n);
    for(auto &p: pts) cin >> p.x >> p.y;
    sort(pts.begin(), pts.end(), [](const Pt&a,const Pt&b){ return a.x<b.x; });
    cout << closestPair(pts,0,n-1) << "\n";
}

Maximum Manhattan Distance Among N Points

Problem

Given n points on a 2D plane, find the maximum Manhattan distance |x_i - x_j| + |y_i - y_j| over all pairs (i, j).

Approach

Transform every point (x, y) into (u, v) = (x+y, x-y). Manhattan distance between two original points equals the Chebyshev distance max(|u_i-u_j|, |v_i-v_j|) between their transformed points, and since Chebyshev distance decomposes independently per coordinate, the maximum over all pairs is simply max(max(u)-min(u), max(v)-min(v)) — track the running min/max of u and v in a single O(n) pass, no pairwise comparisons at all.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

int main(){
    int n; cin >> n;
    vector<ll> x(n), y(n);
    for(int i=0;i<n;i++) cin >> x[i] >> y[i];

    ll uMin=LLONG_MAX, uMax=LLONG_MIN, vMin=LLONG_MAX, vMax=LLONG_MIN;
    for(int i=0;i<n;i++){
        ll u = x[i]+y[i], v = x[i]-y[i];
        uMin=min(uMin,u); uMax=max(uMax,u);
        vMin=min(vMin,v); vMax=max(vMax,v);
    }
    cout << max(uMax-uMin, vMax-vMin) << "\n";
}

Polygon Area & Point-in-Polygon

2 worked examples

The shoelace formula computes the signed area of a simple polygon (vertices given in order, either orientation) directly from its vertices: 2*Area = |sum_i (x_i * y_{i+1} - x_{i+1} * y_i)|, summed cyclically over all edges. Multiplying by 2 before taking the absolute value keeps the result an exact integer for integer-coordinate polygons, avoiding any floating-point division — many judges (including CSES) deliberately ask for "2 * area" for exactly this reason. Determining whether a point lies inside a simple polygon combines two separate checks: first, an explicit boundary check (is the point exactly on one of the polygon's edges, via the same on-segment test used for collinearity: cross product zero and the point's coordinates within the edge's bounding box) since edge/vertex points must be reported as boundary rather than inside or outside; second, if not on the boundary, the standard ray-casting (PNPOLY) parity test — cast a ray from the point (conventionally horizontal) and count how many polygon edges it crosses, where crossing an odd number of edges means the point is inside.

Recognize it by

"Compute the area of a polygon given its vertices" (shoelace) and "determine whether a query point is inside, outside, or on the boundary of a polygon" (point-in-polygon / PNPOLY).

Complexity

O(n) per polygon for the area, and O(n) per query point for point-in-polygon (O(n) boundary check plus O(n) ray-casting pass), or O((n+q) log n) total if queries are batched with an angular sort against a fixed interior point for repeated fast lookups.

Polygon Area (Shoelace Formula)

Problem

Given the n vertices of a simple polygon in order (either orientation, 3 <= n <= 1000, integer coordinates), print 2*A where A is the polygon's exact area (printing double the area keeps the output an integer).

Approach

Apply the shoelace formula directly: sum x_i*y_{i+1} - x_{i+1}*y_i over all edges (indices taken cyclically, i.e. the last vertex connects back to the first), then print the absolute value of that sum.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

int main(){
    int n; cin >> n;
    vector<ll> x(n), y(n);
    for(int i=0;i<n;i++) cin >> x[i] >> y[i];

    ll sum = 0;
    for(int i=0;i<n;i++){
        int j = (i+1) % n;
        sum += x[i]*y[j] - x[j]*y[i];
    }
    cout << llabs(sum) << "\n";
}

Point in Polygon

Problem

Given a simple polygon with n vertices and m query points, classify each query point as INSIDE, OUTSIDE, or on the BOUNDARY of the polygon.

Approach

For each query point, first check every edge with an on-segment test (cross product zero and coordinates within the edge's bounding box) — if any edge matches, report BOUNDARY immediately. Otherwise run the standard ray-casting parity test: for each edge whose endpoints straddle the query's y-coordinate, compute where the edge crosses that horizontal line and flip an inside flag if the crossing is to the right of the query point; an odd total number of flips means INSIDE, even means OUTSIDE.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
struct Pt{ ll x,y; };

ll cross(const Pt&O,const Pt&A,const Pt&B){
    return (A.x-O.x)*(B.y-O.y) - (A.y-O.y)*(B.x-O.x);
}

bool onSegment(const Pt&a,const Pt&b,const Pt&p){
    if(cross(a,b,p) != 0) return false;
    return min(a.x,b.x)<=p.x && p.x<=max(a.x,b.x) && min(a.y,b.y)<=p.y && p.y<=max(a.y,b.y);
}

int classify(vector<Pt>&poly, Pt p){
    int n = poly.size();
    for(int i=0;i<n;i++)
        if(onSegment(poly[i], poly[(i+1)%n], p)) return 2; // boundary

    bool inside = false;
    for(int i=0, j=n-1; i<n; j=i++){
        Pt a = poly[i], b = poly[j];
        if((a.y > p.y) != (b.y > p.y)){
            double xCross = a.x + (double)(p.y-a.y)*(b.x-a.x)/(b.y-a.y);
            if(p.x < xCross) inside = !inside;
        }
    }
    return inside ? 1 : 0;
}

int main(){
    int n,m; cin >> n >> m;
    vector<Pt> poly(n);
    for(auto &p: poly) cin >> p.x >> p.y;
    while(m--){
        Pt q; cin >> q.x >> q.y;
        int r = classify(poly, q);
        cout << (r==2 ? "BOUNDARY" : r==1 ? "INSIDE" : "OUTSIDE") << "\n";
    }
}
