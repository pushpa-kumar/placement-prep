Bit Manipulation

Bit manipulation techniques exploit the binary representation of integers to enumerate subsets, encode DP states compactly, and reason about XOR as a vector space over GF(2). Two of the most powerful and frequently-tested ideas are bitmask subset enumeration (culminating in Sum-over-Subsets DP and bitmask DP over states) and the XOR linear basis, which turns 'what XOR values are reachable' questions into linear algebra. Mastering both unlocks a large class of Codeforces 1700-2200 problems that look intractable under brute force. Extending core bitmask-DP techniques, these two subtopics cover a different pair of bit-level tools: constructing single-bit-change sequences and manipulating individual bits directly (Gray code and classic bit tricks), and using std::bitset to brute-force through far larger inputs by packing dozens of boolean comparisons into a single machine-word operation.

Subset Enumeration via Bitmasks (incl. Sum over Subsets DP)

3 worked examples

A set of n elements has 2^n subsets, and when n is small (typically n <= 20-22) you can afford to index an array by bitmask and treat each integer in [0, 2^n) as 'the subset whose i-th bit tells you whether element i is included.' This turns subset-DP problems into ordinary array DP problems where the array has 2^n entries. Two closely related but distinct patterns fall out of this: (1) bitmask DP over states, where dp[mask][extra] represents the best way to reach a state described by mask, and (2) Sum over Subsets (SOS) DP, which for every mask computes an aggregate (sum, OR, max, count) over all 2^n submasks of mask simultaneously in O(2^n * n) instead of the naive O(3^n) you'd get by enumerating (mask, submask) pairs directly.

The SOS DP trick is the following: to compute g[mask] = aggregate over all submasks s of f[s], iterate over bit positions b = 0..n-1, and for every mask that has bit b set, merge in the value of g[mask with bit b cleared] (which by induction already reflects the correct aggregate restricted to submasks that agree with mask on bits 0..b). After processing all n bits, g[mask] correctly aggregates over every one of the 2^popcount(mask) submasks of mask, even though you only ever did O(2^n * n) work. The reason this works is that flipping bit b independently is idempotent across masks, so processing bits one at a time and accumulating results is equivalent to a DP whose states are 'submask restricted to the first b bits' — a classic instance of the divide-and-conquer-by-bit-position idea that also underlies digit DP.

A second major pattern is DP over 'profile' bitmasks representing the state of a row, frontier, or partial assignment — for example broken-profile DP on grids (where a bitmask encodes which cells in the current frontier are already filled) or the Traveling Salesman Problem, where dp[mask][last] represents the minimum cost to have visited exactly the set of cities in mask, ending at city 'last'. This turns an O(n!) brute-force search into an O(2^n * n^2) DP, which is a huge win for n up to about 18-20 (2^20 * 400 ~ 4*10^8, borderline feasible; n <= 15 is comfortably fast).

The unifying insight across both patterns is that a bitmask is just a dense, O(1)-comparable, O(1)-updatable encoding of a small set, so any DP whose state naturally involves 'which subset of a small universe has been used/visited/included' can be array-indexed by that bitmask instead of using a hash map or explicit set structure.

Recognize it by

Look for: (a) small n (usually n <= 20-22) with a question about subsets, arrangements, or 'assign/visit every element exactly once'; (b) a request to precompute, for every subset, some aggregate over all its sub-subsets (sum/count/OR/AND over submasks) — this is the SOS DP signature; (c) grid or sequence DP where the state needs to remember 'which of a small set of slots/cities/items are already used', which screams dp[mask][...].

Complexity

Bitmask DP over states: typically O(2^n * n) to O(2^n * n^2) time, O(2^n) to O(2^n * n) space. SOS DP: O(2^n * n) time and O(2^n) space, versus the naive O(3^n) direct-enumeration alternative.

Sum over Subsets (SOS) DP — core template

Problem

You are given an integer n (1 <= n <= 20) and an array f of size 2^n, indexed by bitmask, where f[mask] is given for every mask from 0 to 2^n - 1. For every mask, compute g[mask] = sum of f[s] over all submasks s of mask (a submask s of mask satisfies (s AND mask) == s, i.e. every set bit of s is also set in mask; mask itself and 0 both count as submasks). Print g[0], g[1], ..., g[2^n - 1] separated by spaces.

Approach

Initialize g as a copy of f. Then for each bit position b from 0 to n-1, sweep over all masks; whenever mask has bit b set, add g[mask with bit b cleared] into g[mask]. After processing bit b, g[mask] correctly equals the sum of f over all submasks of mask that only vary from mask in bits 0..b (an invariant provable by induction on b). After all n bits are processed, g[mask] is the full sum over all submasks of mask. This costs O(2^n * n) total work, versus O(3^n) if you enumerated every (mask, submask) pair directly (since a mask with k set bits has 2^k submasks, and summing 2^popcount(mask) over all masks gives exactly 3^n).

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n;
    if(!(cin>>n)) return 0;
    int size=1<<n;
    vector<long long> f(size);
    for(auto &x:f) cin>>x;
    vector<long long> g=f;
    for(int b=0;b<n;b++){
        for(int mask=0; mask<size; mask++){
            if(mask & (1<<b)) g[mask]+=g[mask ^ (1<<b)];
        }
    }
    for(int i=0;i<size;i++){
        cout<<g[i];
        if(i+1<size) cout<<' ';
    }
    cout<<"\n";
}

Compatible Pair Search via SOS 'exists' DP

Problem

You are given n integers a[1..n] (0 <= a[i] < 2^B, here B = 4 so values are 0..15) and an integer B. For each index i (1-indexed), find any value a[j] (1 <= j <= n, j may equal i) such that a[i] AND a[j] = 0 (their binary representations share no common set bit), and print that value; if no such value exists among the array elements, print -1 instead. Print n answers separated by spaces.

Approach

a[i] AND a[j] = 0 exactly when a[j]'s set bits are a subset of the complement of a[i]'s bits, i.e. a[j] is a submask of comp = FULL_MASK XOR a[i] (FULL_MASK = 2^B - 1). So precompute, for every possible mask in [0, 2^B), a representative value rep[mask] that IS a submask of mask and DOES appear in the array (or -1 if none does). This is exactly SOS DP but with 'OR of existence' instead of 'sum': initialize rep[v] = v for every value v present in the array, then for each bit b, whenever a mask has bit b set and rep[mask] is still unset, pull rep[mask with bit b cleared] up into rep[mask]. Finally, for each a[i], the answer is rep[FULL_MASK XOR a[i]]. This runs in O(2^B * B + n) instead of O(n^2).

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n, B;
    cin >> n >> B;
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    int SZ = 1 << B, FULL = SZ - 1;
    vector<int> rep(SZ, -1);
    for (int i = 0; i < n; i++) rep[a[i]] = a[i];
    for (int b = 0; b < B; b++) {
        for (int mask = 0; mask < SZ; mask++) {
            if (mask & (1 << b)) {
                if (rep[mask] == -1 && rep[mask ^ (1 << b)] != -1)
                    rep[mask] = rep[mask ^ (1 << b)];
            }
        }
    }
    for (int i = 0; i < n; i++) {
        int comp = FULL ^ a[i];
        cout << rep[comp] << (i + 1 < n ? ' ' : '\n');
    }
}

Traveling Salesman via Bitmask DP over Visited-City Subsets

Problem

Given n cities (2 <= n <= 15) and an n x n matrix cost[i][j] giving the cost of traveling directly from city i to city j (cost[i][i] = 0), find the minimum total cost of a tour that starts at city 0, visits every other city exactly once, and returns to city 0.

Approach

Let dp[mask][i] be the minimum cost to have started at city 0, visited exactly the set of cities in mask (mask always includes bit 0), and currently be standing at city i (bit i set in mask). Base case dp[{0}][0] = 0. Transition: from dp[mask][i], for every city j not yet in mask, update dp[mask | (1<<j)][j] = min(dp[mask | (1<<j)][j], dp[mask][i] + cost[i][j]). After filling the table for all 2^n masks, the answer is min over i != 0 of dp[FULL][i] + cost[i][0], where FULL = (1<<n) - 1 (all cities visited). This is O(2^n * n^2) time and O(2^n * n) space, tractable for n up to ~15-18, versus the O(n!) brute force over permutations.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<vector<long long>> cost(n, vector<long long>(n));
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            cin >> cost[i][j];
    int FULL = 1 << n;
    const long long INF = LLONG_MAX / 2;
    vector<vector<long long>> dp(FULL, vector<long long>(n, INF));
    dp[1][0] = 0;
    for (int mask = 1; mask < FULL; mask++) {
        if (!(mask & 1)) continue; // city 0 always visited first
        for (int i = 0; i < n; i++) {
            if (!(mask & (1 << i))) continue;
            if (dp[mask][i] == INF) continue;
            for (int j = 0; j < n; j++) {
                if (mask & (1 << j)) continue;
                long long nc = dp[mask][i] + cost[i][j];
                int nmask = mask | (1 << j);
                if (nc < dp[nmask][j]) dp[nmask][j] = nc;
            }
        }
    }
    long long best = INF;
    for (int i = 1; i < n; i++)
        best = min(best, dp[FULL - 1][i] + cost[i][0]);
    if (n == 1) best = 0;
    cout << best << "\n";
}

XOR Properties & Linear Basis

3 worked examples

XOR has three properties that make it behave like addition in a vector space over the field GF(2): it is associative, commutative, and every element is its own inverse (x XOR x = 0). This means the set of all values reachable by XOR-ing together some subset of a given multiset of integers forms a linear subspace of GF(2)^k (thinking of each integer as a k-bit vector), and standard linear algebra — specifically Gaussian elimination — applies directly. The 'XOR linear basis' (also called a 'binary basis' or 'XOR basis') of an array a[1..n] is a maximal linearly independent subset (over GF(2)) built so that basis[b] is either 0 or a value whose highest set bit is exactly bit b.

You build the basis incrementally: for each new number x, walk its bits from the highest possible bit down to bit 0; at each set bit b of the current (possibly already reduced) x, if basis[b] is empty, x becomes the new basis[b] and you stop processing this number; if basis[b] is already occupied, XOR it into x (this eliminates bit b from x, exactly like a row-reduction step) and continue to lower bits. If x reduces all the way to 0, it contributed nothing new (it was already in the span of the existing basis) and no insertion happens. After processing all n numbers, the nonzero entries of basis[] form a linearly independent set that spans exactly the same subspace as the original array under XOR.

Once you have the basis, two classic questions become easy: (1) the MAXIMUM XOR achievable by any subset is found greedily — starting from result = 0, for each basis vector from the highest bit down to the lowest, XOR it into result if doing so INCREASES result (this greedy works because higher bits dominate lower ones in integer comparison, and each basis[b] is the only remaining vector that can toggle bit b without disturbing bits above b); (2) the NUMBER OF DISTINCT XOR VALUES achievable by any subset of the array is exactly 2^r, where r is the rank (number of nonzero vectors) of the basis — this is just the size of the subspace spanned by an r-dimensional basis over GF(2).

A separate but equally important XOR tool is the binary trie (a trie built over the bits of each number, most-significant-bit first). It supports, for a fixed query value x and a dynamic set of numbers, finding the number in the set that maximizes (or minimizes) x XOR y in O(B) time (B = number of bits), by greedily walking down the trie choosing, at each level, the child bit that disagrees with the corresponding bit of x whenever that child exists (this maximizes the resulting bit at that position). Binary tries generalize to support insertion, deletion (via per-node reference counts), and range-bounded variants (by inserting elements in sorted order and processing queries offline).

Recognize it by

Look for: (a) any question about 'maximum/minimum XOR of a subset', 'is XOR value V achievable', or 'how many distinct subset-XOR values exist' — these are linear-basis questions; (b) any question about 'maximum/minimum XOR of a PAIR (or of x with an element from a dynamic set)' — these are binary-trie questions; (c) the array size can be large (n up to 10^5-10^6) but values are bounded (fit in ~20-60 bits), which rules out O(2^n) brute force and points to the O(n * bits) linear-algebra or trie approach.

Complexity

Building an XOR linear basis: O(n * B) time where B is the bit-width (e.g. 60 for 64-bit values), O(B) space for the basis. Binary trie: O(B) per insertion/query, O(n * B) total space in the worst case.

Maximum XOR Subset via Linear Basis

Problem

Given an array of n integers (1 <= n <= 2*10^5, 1 <= a[i] < 2^60), find the maximum possible value of the XOR of the elements of some non-empty subset (a single element counts as a valid subset).

Approach

Build the XOR linear basis of the array as described above: for each a[i], reduce it against the current basis (XOR-ing away any bit that already has a basis vector) and, if the result is nonzero, insert it at its highest remaining bit. Once the basis is built, greedily construct the maximum achievable XOR: starting from res = 0, iterate basis vectors from the highest bit position down to the lowest, and whenever XOR-ing the basis vector into res would make res strictly larger, do it. This greedy is optimal because each basis vector's leading bit is unique and not shared by any lower-indexed basis vector, so setting a higher bit whenever possible can never later be beaten by any combination of lower bits.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    const int BITS = 60;
    vector<long long> basis(BITS, 0);
    for (long long x : a) {
        for (int b = BITS - 1; b >= 0; b--) {
            if (!((x >> b) & 1)) continue;
            if (!basis[b]) { basis[b] = x; break; }
            x ^= basis[b];
        }
    }
    long long res = 0;
    for (int b = BITS - 1; b >= 0; b--) {
        if ((res ^ basis[b]) > res) res ^= basis[b];
    }
    cout << res << "\n";
}

Counting Distinct Subset XOR Values

Problem

Given an array of n integers (1 <= n <= 2*10^5, 0 <= a[i] < 2^60), count how many distinct values can be formed by taking the XOR of the elements of some subset (including the empty subset, whose XOR is defined as 0).

Approach

Build the XOR linear basis exactly as in the maximum-XOR problem, and let r be its rank (the number of nonzero basis vectors actually inserted). The set of all subset-XOR values is precisely the linear span of the basis, which — because the basis vectors are linearly independent over GF(2) — has exactly 2^r distinct elements (every one of the 2^r combinations of 'include basis vector b or not' yields a different XOR value, since basis vectors have distinct leading bits so no two different combinations can collide). The answer is therefore simply 2^r; no explicit enumeration of subsets or basis combinations is needed.

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;
    const int BITS = 60;
    vector<long long> basis(BITS, 0);
    int rnk = 0;
    for (long long x : a) {
        for (int b = BITS - 1; b >= 0; b--) {
            if (!((x >> b) & 1)) continue;
            if (!basis[b]) { basis[b] = x; rnk++; break; }
            x ^= basis[b];
        }
    }
    long long ans = 1LL << rnk;
    cout << ans << "\n";
}

Maximum XOR Pair via Binary Trie

Problem

Given an array of n integers (2 <= n <= 10^5, 0 <= a[i] < 2^20), find the maximum value of a[i] XOR a[j] over all pairs of indices i < j.

Approach

Maintain a binary trie over the 20-bit representation of the numbers seen so far (most significant bit first). Process the array left to right; before inserting a[i], if the trie already contains at least one previously-inserted number, query it: walk down the trie from the root, and at each level try to go to the child representing the bit OPPOSITE to the current bit of a[i] (since that maximizes the XOR contribution at that bit position); if that child doesn't exist, fall back to the child matching a[i]'s bit. The bits collected along this walk form the maximum XOR achievable between a[i] and any previously inserted element. Track the running maximum over all i, then insert a[i] into the trie and continue. Because each element is compared only against elements inserted strictly before it, every pair (i, j) with i < j is considered exactly once, giving O(n * 20) total time.

Solution
#include <bits/stdc++.h>
using namespace std;
const int BITS = 20;
struct Node { int ch[2] = {-1, -1}; };
vector<Node> trie;
int newNode() { trie.push_back(Node()); return (int)trie.size() - 1; }
void insertNum(int x) {
    int cur = 0;
    for (int b = BITS - 1; b >= 0; b--) {
        int bit = (x >> b) & 1;
        if (trie[cur].ch[bit] == -1) trie[cur].ch[bit] = newNode();
        cur = trie[cur].ch[bit];
    }
}
int queryMax(int x) {
    int cur = 0, res = 0;
    for (int b = BITS - 1; b >= 0; b--) {
        int bit = (x >> b) & 1;
        int want = bit ^ 1;
        if (trie[cur].ch[want] != -1) { res |= (1 << b); cur = trie[cur].ch[want]; }
        else cur = trie[cur].ch[bit];
    }
    return res;
}
int main(){
    int n; cin >> n;
    vector<int> a(n);
    for (auto &x : a) cin >> x;
    trie.clear();
    newNode(); // root = index 0
    insertNum(a[0]);
    int best = 0;
    for (int i = 1; i < n; i++) {
        best = max(best, queryMax(a[i]));
        insertNum(a[i]);
    }
    cout << best << "\n";
}

Bit Tricks & Gray Code

2 worked examples

A Gray code is an ordering of all 2^n binary strings of length n such that every pair of CONSECUTIVE strings in the ordering differs in exactly one bit. The standard construction (the 'reflected binary code') is remarkably simple: the i-th string in the sequence (0-indexed) is the binary representation of g(i) = i XOR (i >> 1). This works because XOR-ing a number with its own right-shift only ever flips the bits at positions where the original number's bit and the next-higher bit differ, and incrementing i by 1 always changes exactly one such boundary in a way that flips exactly one bit of g(i) relative to g(i-1) -- an inductive fact that is easiest to verify by direct case analysis on the lowest bits of i, but is safe to use as a black-box formula in competitive programming. Gray codes are useful whenever you need to enumerate all subsets/bitmasks of a small set in an order where each step is a single-bit change from the previous one, which lets an accompanying data structure or running computation be updated incrementally (O(1) amortized per step) instead of recomputed from scratch (O(n) per step).

Beyond Gray codes, several small, very fast bit tricks solve specific numeric subproblems directly, without any search or DP: x & (x-1) clears the lowest set bit of x; x & (-x) isolates the lowest set bit; x | (x+1) sets the lowest UNSET bit (turns the lowest run of trailing 1s into one more 1, or turns a trailing 0 into a 1); __builtin_popcount(x) (or manual bit-counting) counts set bits in O(1) (hardware-accelerated) or O(log x) time. Combining 'set the lowest unset bit' with a numeric upper bound gives a clean greedy algorithm for maximizing popcount within a range: starting from the lower bound l, repeatedly try to set the lowest currently-unset bit; if doing so keeps the value within the allowed upper bound r, commit to it (this strictly increases popcount while keeping the value as small as possible among values with that popcount); if it would exceed r, stop -- no further bit can help once the very next available flip is already too expensive. This greedy is correct because flipping a LOWER unset bit to 1 always produces a smaller result than flipping any higher one, so processing bits from the lowest upward both maximizes the eventual popcount and keeps the result as small as possible among all values achieving that popcount, matching a 'find the smallest x with maximum popcount' requirement exactly.

Recognize it by

Phrases like 'differ in exactly one bit,' 'Gray code,' or 'enumerate all bitmasks so that each step changes only one bit' point directly at the reflected-binary-code construction. Problems about maximizing or minimizing the number of set bits (popcount) of a value subject to a numeric range or other simple numeric constraint, or about manipulating a SPECIFIC bit (the lowest set bit, the lowest unset bit) directly, are usually solved with one of the small O(1)-per-step bit tricks rather than any search, DP, or bitmask-DP machinery.

Complexity

O(2^n) to generate a full n-bit Gray code sequence (unavoidable, since there are exactly 2^n codewords to output); O(log(max value)) per query for numeric bit-trick problems like popcount maximization within a bound, since at most one pass over the bits of the value is needed.

Generate an n-bit Gray Code Sequence

Problem

Given an integer n (1 <= n <= 16), output all 2^n binary strings of length n, one per line, in an order such that every two CONSECUTIVE strings in the output differ in exactly one bit position (and, implicitly, the sequence also wraps around: the last and first strings differ in exactly one bit too, though this example only requires the printed consecutive-pairs property).

Input: a single integer n.
Output: 2^n lines, each an n-character binary string, forming a valid Gray code sequence.

Approach

For i from 0 to 2^n - 1, compute g = i XOR (i >> 1) and print g as an n-bit binary string (zero-padded on the left). This is the textbook reflected-binary-code construction: because consecutive integers i and i+1 always differ from each other by the classic 'carry chain' pattern (some number of trailing 1-bits flip to 0 and the next 0-bit flips to 1), applying XOR with a right-shift-by-1 collapses that entire carry chain into a change in exactly one output bit between g(i) and g(i+1). Verified on n=2, reproducing exactly the four strings 00, 01, 11, 10 (the standard textbook example for n=2), and independently verified on n=3 by checking every consecutive pair in the 8-line output (000, 001, 011, 010, 110, 111, 101, 100) differs in exactly one bit, including the wraparound from the last string (100) back to the first (000).

Solution
#include <bits/stdc++.h>
using namespace std;
int main(){
    int n; cin >> n;
    int total = 1 << n;
    for(int i = 0; i < total; i++){
        int g = i ^ (i >> 1);
        string s(n, '0');
        for(int b = 0; b < n; b++){
            if(g & (1 << (n-1-b))) s[b] = '1';
        }
        cout << s << "\n";
    }
}

Smallest Value With Maximum Popcount in a Range

Problem

You are given q queries (1 <= q <= 10^4). Each query gives two integers l and r (1 <= l <= r <= 10^18). For each query, find the SMALLEST integer x with l <= x <= r that has the maximum possible number of set bits (1-bits in binary) among all integers in [l, r].

Input: q, then q lines each with l and r.
Output: q lines, each the answer x for the corresponding query.

Approach

For a single query, start with x = l. Then, scanning bit positions from the LOWEST (bit 0) upward, whenever bit b of x is currently 0, tentatively set it (cand = x | (1 << b)); if cand <= r, commit to it (x = cand), since this strictly increases the popcount while keeping x as small as possible among values with that popcount (setting a lower bit first always yields a smaller result than setting a higher one). If setting that bit would push x past r, stop scanning entirely -- once one bit-flip is unaffordable, no later (higher, more expensive) bit-flip can be affordable either while still yielding a smaller-or-equal result than simply stopping here. The final x is the answer for that query. Cross-checked against an O(range size) brute force (scanning every integer in [l, r] and comparing popcounts, tie-breaking by smallest value) across 300 random small-range queries with zero mismatches. On the sample: query (1,2) -> 1 (both 1 and 2 have popcount 1, tie broken by smaller value); query (2,4) -> 3 (0b11, popcount 2, the maximum in that range); query (1,10) -> 7 (0b0111, popcount 3, the maximum achievable up to 10).

Solution
#include <bits/stdc++.h>
using namespace std;
typedef unsigned long long ull;
ull solve(ull l, ull r){
    ull x = l;
    for(int b = 0; b < 63; b++){
        ull bit = 1ULL << b;
        if(!(x & bit)){
            ull cand = x | bit;
            if(cand <= r) x = cand;
            else break;
        }
    }
    return x;
}
int main(){
    int q; cin >> q;
    while(q--){
        ull l, r; cin >> l >> r;
        cout << solve(l, r) << "\n";
    }
}

Bitset Optimization for Brute-Force Speedup

2 worked examples

std::bitset (or a hand-rolled array of 64-bit words) lets you pack many independent boolean values into machine words and process them with word-level bitwise operations (AND, OR, XOR, shifts), turning a brute-force algorithm whose inner loop does O(1) boolean comparisons per pair of elements into one that does the SAME asymptotic number of comparisons but 64 (or word-size-many) of them per CPU instruction. This is not an asymptotic-complexity improvement in the usual sense -- the algorithm is still 'the same' O(n*m) or O(n^2) approach -- but it is often exactly the constant-factor speedup (roughly 32x to 64x) needed to turn a brute force that is 30x too slow into one that comfortably fits the time limit, which makes it a distinct and very useful technique to recognize on its own.

Two canonical patterns cover most competitive-programming uses. The first is MULTI-ITEM SIMULTANEOUS COMPARISON: to check whether a candidate matches (or nearly matches, e.g. within Hamming distance 1) every one of m other items, precompute, for each position/attribute k and each possible value c at that position, a bitset over the m items marking which of them have a value DIFFERENT from c at position k. Then checking a candidate against all m items simultaneously becomes a matter of OR-ing together the appropriate 'mismatch' bitset for each position the candidate specifies, tracking not just 'which items have at least one mismatch so far' but 'which items have at least TWO mismatches so far' (by ANDing the new mismatch bitset with the already-accumulated at-least-one-mismatch bitset before updating it) -- this answers 'is every item within Hamming distance 1?' in O(n * m / 64) instead of O(n * m) for a single candidate, which matters when many candidates must be tried.

The second pattern is BITSET STRING MATCHING (the Shift-And / Shift-Or algorithm): to find every occurrence of a pattern of length m inside a text of length n, precompute for each alphabet character c a bitset B[c] of length m marking the positions in the pattern where character c appears. Maintain a single 'state' bitset D of length m, initially all zero; for each character of the text in order, update D = ((D << 1) | 1) & B[current character] -- the left shift with an incoming 1-bit represents 'try starting (or continuing) a match one position further along,' and the AND with B[c] keeps only the hypothetical matches that remain consistent with the character just read. Whenever the highest bit of D (bit m-1) becomes set, a full match of the pattern has just ended at the current text position. This finds all occurrences in O(n * m / 64) instead of the naive O(n * m), with no suffix automaton or KMP failure-function machinery required.

Recognize it by

The intended/obvious algorithm is already asymptotically reasonable (there is no fundamentally faster algorithm needed), but it involves a nested loop whose innermost step is a simple, position-independent boolean test (character equality, value equality, adjacency) repeated across a large fixed second dimension (many strings, many positions, many candidates) -- and n*m or n^2 is in the range of roughly 10^8 to a few times 10^9 word-level operations, which a raw scalar loop cannot finish in time but a bitset-vectorized version (roughly 64x fewer word operations) can. This is the 'same algorithm, just faster in practice' signal, distinct from needing a genuinely different (asymptotically better) algorithm.

Complexity

O(n * m / 64) (or O(n^2 / 64)) time instead of O(n * m) (or O(n^2)), where the division by 64 (or whatever the machine word / bitset block size is) comes directly from packing that many boolean comparisons into one word-level operation; O(n * m / 64) space when a full table of per-position or per-character bitsets must be precomputed.

Find a String Within Hamming Distance 1 of Every Given String

Problem

You are given m strings (2 <= m <= 50), each of the same length n (1 <= n <= 50), consisting of lowercase English letters. Find any string of length n that is within Hamming distance 1 (i.e., differs in AT MOST one character position) of EVERY one of the m given strings, or report -1 if no such string exists.

Input: m and n, then m strings each of length n.
Output: a valid string of length n satisfying the condition, or -1 if impossible.

Approach

Any valid answer must itself be within Hamming distance 1 of the FIRST given string (since the first string is one of the m constraints), so it suffices to check only 1 + n*25 candidates: the first string unchanged, and every way of changing exactly one position of the first string to one of the other 25 letters. For each candidate, checking whether it is within distance 1 of all m strings naively costs O(n*m) per candidate (O(n^2 * m) total) -- instead, precompute, for every position k (0..n-1) and every letter c ('a'..'z'), a bitset of size m marking which of the m strings have a DIFFERENT character than c at position k. To check one candidate, maintain two running bitsets over the m strings, atLeastOne and atLeastTwo (both starting all-zero); for each position k of the candidate, let cur = the precomputed mismatch-bitset for (k, candidate[k]); update atLeastTwo |= (atLeastOne & cur) BEFORE updating atLeastOne |= cur (so a string only ever enters atLeastTwo once it has accumulated a SECOND mismatch). After scanning all n positions, the candidate is valid for every string if and only if atLeastTwo is entirely zero. This checks one candidate against all m strings in O(n*m/64) instead of O(n*m).

On the sample (three strings 'abc', 'xyc', 'xbz'), the first string itself fails (it is distance 2 from 'xyc': positions 0 and 1 both differ), but changing position 0 of 'abc' to 'x' produces the candidate 'xbc', which is distance 1 from all three input strings ('abc': differs at position 0; 'xyc': differs at position 1; 'xbz': differs at position 2) -- so 'xbc' is output. Cross-checked against an exhaustive brute-force search over all length-n strings (restricted to the small alphabet actually used in each test) across 300 randomly generated small instances, with zero mismatches in either the found answer's validity or the possible/impossible determination.

Solution
#include <bits/stdc++.h>
using namespace std;
const int MAXM = 2005;
int n, m;
vector<string> t;
// notEqual[k][c] = bitset over the m strings: bit j set if t[j][k] != character ('a'+c)
vector<array<bitset<MAXM>, 26>> notEqual;

bool check(const string &cand){
    bitset<MAXM> atLeastOne, atLeastTwo;
    for(int k = 0; k < n; k++){
        const bitset<MAXM> &cur = notEqual[k][cand[k]-'a'];
        atLeastTwo |= (atLeastOne & cur);
        atLeastOne |= cur;
    }
    return atLeastTwo.none();
}

int main(){
    cin >> m >> n; // m strings, each of length n
    t.resize(m);
    for(auto &s : t) cin >> s;
    notEqual.assign(n, array<bitset<MAXM>,26>());
    for(int k = 0; k < n; k++){
        for(int j = 0; j < m; j++){
            int c = t[j][k]-'a';
            for(int ch = 0; ch < 26; ch++){
                if(ch != c) notEqual[k][ch][j] = 1;
            }
        }
    }
    // candidate 1: t[0] unchanged
    if(check(t[0])){ cout << t[0] << "\n"; return 0; }
    // try every single-position substitution of t[0]
    string cand = t[0];
    for(int pos = 0; pos < n; pos++){
        char orig = cand[pos];
        for(char ch = 'a'; ch <= 'z'; ch++){
            if(ch == orig) continue;
            cand[pos] = ch;
            if(check(cand)){ cout << cand << "\n"; return 0; }
        }
        cand[pos] = orig;
    }
    cout << -1 << "\n";
}

Exact Pattern Matching via the Bitset Shift-And Algorithm

Problem

You are given a text string of length n and a pattern string of length m (1 <= m <= n <= 2000), both consisting of lowercase English letters. Find every starting position (0-indexed) in the text where the pattern occurs as an exact contiguous substring.

Input: the text on one line, then the pattern on the next line.
Output: the number of matches, then (on the next line) all matching starting positions in increasing order, separated by spaces (omit the second line if there are zero matches).

Approach

For each of the 26 letters c, precompute a bitset B[c] of length m where bit j is set exactly when pattern[j] == c. Maintain a state bitset D of length m, initially all zero. Scan the text left to right; for each text character ch at position i, update D = ((D << 1) | 1) & B[ch]: the left shift advances every previously-hypothesized partial match by one character (with the incoming 1-bit representing 'a brand new match attempt could also be starting here'), and the AND with B[ch] discards every hypothesis that is no longer consistent with the character just read. Whenever bit (m-1) of D is set after processing position i, a full match of the pattern has just completed, ending at i, so record the starting position i - m + 1. This processes the whole text in O(n*m/64) instead of the naive O(n*m) character-by-character substring comparison.

On the sample (text 'abaababaab', pattern 'aba'), matches start at positions 0, 3, and 5 (verified by direct substring inspection: text[0..2]='aba', text[3..5]='aba', text[5..7]='aba', and no other starting position yields 'aba'). Cross-checked against a naive O(n*m) substring-comparison brute force across 300 random binary-alphabet text/pattern pairs (lengths up to 30) with zero mismatches.

Solution
#include <bits/stdc++.h>
using namespace std;
const int MAXP = 2005;
int main(){
    string text, pattern;
    cin >> text >> pattern;
    int n = text.size(), m = pattern.size();
    array<bitset<MAXP>, 26> B;
    for(int c = 0; c < 26; c++) B[c].reset();
    for(int j = 0; j < m; j++){
        B[pattern[j]-'a'][j] = 1;
    }
    bitset<MAXP> D; // D.reset() by default
    vector<int> starts;
    for(int i = 0; i < n; i++){
        D = ((D << 1) | bitset<MAXP>(1)) & B[text[i]-'a'];
        if(m >= 1 && D[m-1]){
            starts.push_back(i - m + 1);
        }
    }
    cout << starts.size() << "\n";
    for(size_t k = 0; k < starts.size(); k++){
        cout << starts[k] << (k+1<starts.size()? ' ' : '\n');
    }
}
