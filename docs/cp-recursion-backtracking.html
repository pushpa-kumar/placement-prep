Recursion & Backtracking

Recursion and backtracking power almost every exact combinatorial search: build a partial solution one decision at a time, immediately reject (prune) any partial choice that can never lead to a valid or optimal answer, and carefully undo state before trying the next branch. The three subtopics below form a natural progression: generating permutations/subsets under constraints (the mechanics of choose-explore-unchoose), N-Queens-style pruning (using cheap incremental checks to cut the search tree early), and meet-in-the-middle (splitting a search space too large for 2^n into two halves that are brute-forced separately and joined efficiently). Beyond straightforward recursive backtracking, these two techniques show how the SHAPE of a recursion can itself be the source of an algorithm's speed: divide and conquer restructures a problem into cheaply-combinable independent halves (or pivot-split ranges), while minimax with alpha-beta pruning turns adversarial two-player search from a brute-force exponential tree walk into either a heavily pruned search or, for state spaces with cycles and draws, a rigorous backward (retrograde) analysis.

Permutation & Subset Generation with Constraints

3 worked examples

The core pattern is choose -> explore -> un-choose (undo). You maintain a partial solution (an array being built) and, at each recursive call, try every legal next element, recurse one level deeper, then remove that element before trying the next candidate so the partial solution is byte-for-byte the same as before you tried it. For permutations you typically track a used[] boolean array (or, for multisets, a count array) because any unused element can go in the next position. For subsets/combinations you instead pass a start index and only consider elements from start onward, which automatically avoids generating the same subset in more than one order and keeps the recursion tree at exactly 2^n leaves rather than n! orderings of each subset.

Constraints are enforced in one of two ways: filtering (generate the full unconstrained tree and check validity only at leaves) or pruning (check the constraint incrementally, the instant a partial candidate becomes invalid, and cut that whole subtree). Pruning is almost always dramatically faster because an invalid prefix kills every extension of itself. Two pruning idioms come up constantly: (1) duplicate-skipping - sort the input, and when choosing the i-th element of a combination/permutation, skip a candidate equal to the previous sibling candidate at the *same recursion depth* (not merely equal to the previous array element) so you don't regenerate an already-explored branch; (2) partial-sum bounding - if array is sorted ascending and the running sum plus the next candidate already exceeds the target, every later (larger) candidate at this level will also fail, so you can break out of the loop entirely instead of just continue-ing.

A subtle but critical correctness point: the 'un-choose' step must exactly mirror the 'choose' step. If you decremented a count array, incrementing it back must happen after the recursive call returns and *before* the next iteration of the loop tries a different branch - otherwise state leaks between sibling branches and produces silently wrong answers rather than a crash, which is why backtracking bugs are notoriously hard to spot by inspection alone.

Recognize it by

Look for phrasing like 'generate/list/print all distinct permutations or subsets', 'count the number of ways to choose a subset satisfying X', or 'output every arrangement in sorted/lexicographic order'. A strong signal is that the problem wants the actual objects (not just a count derivable by a formula) and n is small enough that the object count itself is the bottleneck - typically n <= 10-12 for permutations (since n! explodes past that) and n <= 20-25 for subset enumeration (2^n). If the input can contain repeated values but the expected output has each distinct arrangement exactly once, that's the signature of needing duplicate-skip pruning rather than generate-then-deduplicate-with-a-set.

Complexity

Permutations: O(n * n!) time to generate and output all n! sequences (the extra factor of n is the cost of copying/printing each one); with k groups of duplicate elements of sizes d_1..d_k, the duplicate-skip pruning generates exactly n! / (d_1! * ... * d_k!) sequences with zero wasted work, versus generating all n! and filtering with a hash set which costs extra memory and hashing time for no benefit. Subset generation is O(2^n) in the worst case, but sum-bound pruning (breaking early once a sorted running sum exceeds the target) typically prunes whole subtrees long before the recursion reaches depth n, so real-world running time on constrained instances is usually far below the 2^n worst case even though the worst-case bound itself does not change. Space is O(n) for the recursion stack and the current partial solution, plus O(number of outputs * n) if you must store every result.

Distinct Permutations of a Multiset

Problem

You are given a string s of at most 8 lowercase letters, which may contain repeated letters. Print the number of *distinct* permutations of its characters, followed by every distinct permutation, one per line, in lexicographically sorted order (this mirrors CSES 1622 'Creating Strings').
Input: a single line containing s.
Output: first line = count of distinct permutations; each following line one permutation, in sorted order.

Approach

Instead of generating all 8! permutations and deduplicating with a set (wasteful and, for longer strings, infeasible), recurse directly over a count array cnt[26] of remaining letters. At each position, try every letter c with cnt[c] > 0: decrement cnt[c], append c to the current string, recurse, then pop and restore cnt[c]. Because we always iterate letters in increasing alphabetical order (0..25) and never place two equal letters through two different 'copies', each distinct permutation is produced exactly once, and iterating letters in sorted order makes the output automatically lexicographically sorted with no extra sort step needed.

Solution
#include <bits/stdc++.h>
using namespace std;

int n;
string s;
vector<int> cnt(26, 0);
string cur;
vector<string> results;

void backtrack() {
    if ((int)cur.size() == n) {
        results.push_back(cur);
        return;
    }
    for (int c = 0; c < 26; c++) {
        if (cnt[c] == 0) continue;
        cnt[c]--;
        cur.push_back('a' + c);
        backtrack();
        cur.pop_back();
        cnt[c]++;
    }
}

int main() {
    cin >> s;
    n = s.size();
    for (char ch : s) cnt[ch - 'a']++;
    backtrack();
    cout << results.size() << "\n";
    for (auto &r : results) cout << r << "\n";
    return 0;
}

Subsets Summing to a Target (with Duplicate & Bound Pruning)

Problem

Given n (1 <= n <= 15) positive integers (possibly with repeated values) and a target T, find every subset (as a set of positions, but two subsets with identical multisets of values should be printed only once) whose elements sum exactly to T. Print the number of such subsets, then each subset's values in non-decreasing order, one subset per line, with subsets themselves printed in lexicographically increasing order of their value sequences.
Input: first line 'n target'; second line n integers.
Output: first line = number of qualifying subsets; each following line lists that subset's values separated by single spaces.

Approach

Sort the array ascending first. Recurse with (start index, running sum): at each call, iterate i from start to n-1. Skip i if a[i] equals a[i-1] and i > start (this is the duplicate-skip rule: it only skips a repeat *at the same branching level*, so '2,2,3' can still legitimately use both 2's - it just prevents choosing the second '2' as an *alternative* first choice when the first '2' at that level was already tried and undone). Also, since the array is sorted, the moment running sum + a[i] exceeds target we can 'break' (not 'continue') because every subsequent a[i] at this level is >= the current one and would only make the sum larger. When the running sum equals target exactly, record the current partial subset as a valid answer (and continue trying to extend further branches is unnecessary here since all values are positive, so we simply return without recursing deeper).

Solution
#include <bits/stdc++.h>
using namespace std;

int n, target;
vector<int> a;
vector<int> cur;
vector<vector<int>> results;

void backtrack(int start, int sum) {
    if (sum == target) {
        results.push_back(cur);
        return;
    }
    for (int i = start; i < n; i++) {
        if (i > start && a[i] == a[i - 1]) continue; // skip duplicate branch at this depth
        if (sum + a[i] > target) break; // sorted ascending -> all further are too big
        cur.push_back(a[i]);
        backtrack(i + 1, sum + a[i]);
        cur.pop_back();
    }
}

int main() {
    cin >> n >> target;
    a.resize(n);
    for (auto &x : a) cin >> x;
    sort(a.begin(), a.end());
    backtrack(0, 0);
    cout << results.size() << "\n";
    for (auto &r : results) {
        for (size_t i = 0; i < r.size(); i++) {
            if (i) cout << " ";
            cout << r[i];
        }
        cout << "\n";
    }
    return 0;
}

Permutations With No Adjacent Consecutive Values

Problem

Given n (1 <= n <= 9), count and list, in lexicographic order, every permutation of 1..n such that no two *adjacent positions* in the permutation hold values that differ by exactly 1 (i.e. for every i, |p[i] - p[i+1]| != 1). This sequence of counts is OEIS A002464.
Input: a single integer n.
Output: first line = number of valid permutations; each following line lists one valid permutation's values separated by spaces, in lexicographic order.

Approach

This demonstrates pruning a constraint *during* construction rather than generating all n! permutations and filtering afterward. Build the permutation left to right with a standard used[] array; the only addition is a single check before descending into a branch: if the permutation is non-empty and the candidate value differs from the last placed value by exactly 1, skip it immediately - never even recurse into that subtree. Because most violations happen early (adjacent to the most recently placed element), this prunes enormous swaths of the search tree compared to checking the full permutation only once it's complete. Iterating candidate values 1..n in increasing order guarantees lexicographic output order for free.

Solution
#include <bits/stdc++.h>
using namespace std;

int n;
vector<int> perm;
vector<bool> used;
vector<vector<int>> results;

void backtrack() {
    if ((int)perm.size() == n) {
        results.push_back(perm);
        return;
    }
    for (int v = 1; v <= n; v++) {
        if (used[v]) continue;
        if (!perm.empty() && abs(perm.back() - v) == 1) continue; // pruning: skip consecutive-value neighbors
        used[v] = true;
        perm.push_back(v);
        backtrack();
        perm.pop_back();
        used[v] = false;
    }
}

int main() {
    cin >> n;
    used.assign(n + 1, false);
    backtrack();
    cout << results.size() << "\n";
    for (auto &r : results) {
        for (size_t i = 0; i < r.size(); i++) {
            if (i) cout << " ";
            cout << r[i];
        }
        cout << "\n";
    }
    return 0;
}

Backtracking with Pruning (N-Queens Style)

3 worked examples

N-Queens is the canonical demonstration that a backtracking search's *asymptotic* worst case (here, roughly n^n naive placements, or n! if you already restrict to one queen per row) is almost never what determines real running time - what matters is how cheaply you can detect that a partial placement is already doomed, and how early you can detect it. The standard trick is to never rescan the board: maintain three pieces of state incrementally as you place/remove queens row by row - a bitmask (or boolean array) of occupied columns, and two more for the two diagonal directions (indexed by row - col + offset for one diagonal family, row + col for the other). Placing a queen at (row, col) and checking whether it's legal becomes an O(1) bitwise test instead of an O(n) or O(n^2) scan of previously placed queens, and undoing a placement is the exact symmetric bitwise operation.

This generalizes beyond queens to any constraint-satisfaction backtracking: Sudoku, graph coloring, exact placement puzzles. The second major lever - beyond making each check O(1) - is *variable ordering*: instead of always filling cells/rows in a fixed order, pick the most-constrained one next (in Sudoku, the empty cell with the fewest remaining legal digits; this is the 'minimum remaining values' or MRV heuristic). Committing to the most constrained decision first fails fast when a partial assignment is invalid, and succeeds with far less branching when it's valid, because you eliminate large numbers of hopeless possibilities before they can even be explored.

Extra hard constraints (like reserved/forbidden squares in a modified N-Queens board) don't change the algorithmic shape at all - they're just one more O(1) check alongside the column/diagonal checks, folded into the same incremental validity test before you recurse. This is why 'N-Queens with obstacles' (e.g. CSES 'Chessboard and Queens') is considered only a small step up from vanilla N-Queens: there is no closed-form combinatorial shortcut anymore, so you must actually run the row-by-row backtracking with attack-set pruning rather than looking up a precomputed queens-count sequence.

Recognize it by

Signals: 'place k non-attacking pieces', 'no two chosen items may conflict under rule R', grid-based puzzles with row/column/box uniqueness constraints, or 'count/enumerate all valid configurations' where n is small (n <= 12-16 for full board search, fixed 9x9 for Sudoku). If a brute-force enumeration of *all* placements (ignoring constraints) would be astronomically large, but checking a *partial* placement's validity is cheap and catches violations early, that's the setup for backtracking with pruning rather than plain generate-and-test.

Complexity

Worst-case complexity is still exponential (placing n queens one per row naively considers up to n choices per row, i.e. O(n^n) before any pruning, or O(n!) once you fix 'one per row'), and this bound is unavoidable in the worst case - but pruning changes the *constant factor* by orders of magnitude in practice. For n=8 queens there are 8^8 ~ 16.7 million naive row/column assignments, but column+diagonal pruning visits only a few thousand search-tree nodes to enumerate all 92 solutions, because an attacked column/diagonal kills an entire remaining subtree the instant it's detected rather than after fully constructing an invalid board. Sudoku backtracking is exponential in the number of blank cells in the absolute worst case, but the MRV heuristic (always branching on the cell with fewest candidates) keeps typical - even 'hard' - puzzles solving in well under a second because most cells end up with only 1-2 candidates once enough digits are fixed, so the effective branching factor collapses far below 9. Space is O(n) (or O(81) for Sudoku) for the incremental attack-set/candidate-mask state plus O(depth) recursion stack.

Counting N-Queens Solutions with Bitmask Pruning

Problem

Given n (1 <= n <= 12), count the number of ways to place n non-attacking queens on an n x n chessboard (no two queens share a row, column, or diagonal).
Input: a single integer n.
Output: a single integer, the number of distinct solutions.

Approach

Recurse row by row, always placing exactly one queen per row. Maintain three bitmasks: cols (columns already used), diag1 and diag2 (the two diagonal families, represented so that moving to the next row is a single shift). At each row, the set of legal columns is full & ~(cols | diag1 | diag2) where full has the low n bits set - this is an O(1)-per-candidate test instead of scanning previously placed queens. For the recursive call, cols simply gains the new queen's bit; the two diagonal masks are updated by OR-ing in the new bit and then shifting left/right by one respectively, which is exactly how a diagonal attack 'moves over' one column as you go down one row. Iterating over the available bits with available & -available and clearing them one at a time enumerates all legal columns for the row without ever looping over 0..n-1 explicitly. When row reaches n, a complete valid placement has been found.

Solution
#include <bits/stdc++.h>
using namespace std;

int n;
long long solutions = 0;

// cols, diag1 (r-c+n-1), diag2 (r+c) occupancy as bitmasks
void backtrack(int row, long long cols, long long diag1, long long diag2) {
    if (row == n) {
        solutions++;
        return;
    }
    long long full = (1LL << n) - 1;
    long long available = full & ~(cols | diag1 | diag2);
    while (available) {
        long long bit = available & (-available);
        available -= bit;
        int col = __builtin_ctzll(bit);
        backtrack(row + 1, cols | bit, (diag1 | bit) << 1 & full, (diag2 | bit) >> 1);
    }
}

int main() {
    cin >> n;
    backtrack(0, 0, 0, 0);
    cout << solutions << "\n";
    return 0;
}

N-Queens with Reserved Squares

Problem

Given an n x n board (1 <= n <= 10) where each cell is either '.' (usable) or '*' (reserved and unusable), count the number of ways to place n mutually non-attacking queens using only usable squares (this mirrors CSES 1624 'Chessboard and Queens', generalized to arbitrary n). Because some usable configurations are now forbidden there is no closed-form queens-count shortcut - you must run real backtracking.
Input: first line n; next n lines each a string of n characters ('.' or '*').
Output: a single integer, the number of valid placements.

Approach

This is the same row-by-row backtracking as vanilla N-Queens, with one extra O(1) check folded into the same loop: before checking column/diagonal availability for candidate column c in the current row, first check grid[row][c] != '*'. If the square is reserved, skip it immediately without touching any state - it never even becomes a candidate branch. Column and diagonal state are tracked with boolean arrays here (rather than bitmasks) for clarity; diag1 is indexed by row - c + n - 1 and diag2 by row + c, the two standard ways to give every diagonal a unique, collision-free index. Marking state on entry and precisely un-marking the same three flags on return from the recursive call is what makes sibling branches see a clean board.

Solution
#include <bits/stdc++.h>
using namespace std;

int n;
vector<string> grid;
vector<bool> colUsed, diag1Used, diag2Used; // diag1: r-c+n-1, diag2: r+c
long long count_ = 0;

void backtrack(int row) {
    if (row == n) {
        count_++;
        return;
    }
    for (int c = 0; c < n; c++) {
        if (grid[row][c] == '*') continue;          // reserved square pruning
        if (colUsed[c]) continue;                     // column attack pruning
        int d1 = row - c + n - 1;
        int d2 = row + c;
        if (diag1Used[d1] || diag2Used[d2]) continue;  // diagonal attack pruning
        colUsed[c] = diag1Used[d1] = diag2Used[d2] = true;
        backtrack(row + 1);
        colUsed[c] = diag1Used[d1] = diag2Used[d2] = false; // undo state
    }
}

int main() {
    cin >> n;
    grid.resize(n);
    for (auto &row : grid) cin >> row;
    colUsed.assign(n, false);
    diag1Used.assign(2 * n, false);
    diag2Used.assign(2 * n, false);
    backtrack(0);
    cout << count_ << "\n";
    return 0;
}

Sudoku Solver with Most-Constrained-Cell Pruning

Problem

Given a 9x9 Sudoku board with some cells filled (digits '1'-'9') and the rest blank ('.'), fill in the blanks so every row, column, and 3x3 box contains each digit 1-9 exactly once. The input is guaranteed to have a unique solution.
Input: 9 lines, each a string of 9 characters ('.' or a digit).
Output: 9 lines, the solved board in the same format (digits only, no dots).

Approach

Maintain three bitmasks per row, column, and 3x3 box recording which digits are already used (bit d set means digit d is taken). Naively picking the next blank cell in reading order and trying all 9 digits is *correct* but can be slow on harder boards because early wrong guesses aren't detected until deep into the recursion. Instead, before each recursive step, scan all blank cells once to find the one with the *fewest* remaining legal candidates (rowMask[r] | colMask[c] | boxMask[box] complemented and popcounted) - the 'most constrained variable' heuristic. If any blank cell has zero legal candidates, that whole branch is dead and we return false immediately (this is the pruning: we detect infeasibility without exploring further). Otherwise we branch only over that one cell's few candidates, place a digit, update the three masks, recurse, and if the recursion fails, undo the exact same three masks before trying the next candidate digit.

Solution
#include <bits/stdc++.h>
using namespace std;

int grid[9][9];
int rowMask[9], colMask[9], boxMask[9]; // bit d (1..9) set => digit d already used

int boxOf(int r, int c) { return (r / 3) * 3 + (c / 3); }

bool solve() {
    int br = -1, bc = -1, bestCount = 10, bestCands = 0;
    for (int r = 0; r < 9; r++) {
        for (int c = 0; c < 9; c++) {
            if (grid[r][c] != 0) continue;
            int used = rowMask[r] | colMask[c] | boxMask[boxOf(r, c)];
            int cands = (~used) & 0x3FE; // bits 1..9
            int cnt = __builtin_popcount(cands);
            if (cnt == 0) return false;      // dead end: pruning
            if (cnt < bestCount) {           // most-constrained-cell heuristic
                bestCount = cnt;
                br = r; bc = c; bestCands = cands;
            }
        }
    }
    if (br == -1) return true; // no empty cells left: solved

    int cands = bestCands;
    while (cands) {
        int bit = cands & (-cands);
        cands -= bit;
        int d = __builtin_ctz(bit);
        grid[br][bc] = d;
        rowMask[br] |= bit;
        colMask[bc] |= bit;
        boxMask[boxOf(br, bc)] |= bit;

        if (solve()) return true;

        grid[br][bc] = 0; // undo
        rowMask[br] &= ~bit;
        colMask[bc] &= ~bit;
        boxMask[boxOf(br, bc)] &= ~bit;
    }
    return false;
}

int main() {
    for (int r = 0; r < 9; r++) {
        string line;
        cin >> line;
        for (int c = 0; c < 9; c++) {
            int d = (line[c] == '.') ? 0 : (line[c] - '0');
            grid[r][c] = d;
            if (d != 0) {
                int bit = 1 << d;
                rowMask[r] |= bit;
                colMask[c] |= bit;
                boxMask[boxOf(r, c)] |= bit;
            }
        }
    }

    solve();

    for (int r = 0; r < 9; r++) {
        string line(9, '.');
        for (int c = 0; c < 9; c++) line[c] = char('0' + grid[r][c]);
        cout << line << "\n";
    }
    return 0;
}

Meet in the Middle

2 worked examples

Meet in the middle applies when a problem naturally wants a full O(2^n) (or O(3^n), etc.) search over subsets/assignments, n is too large for that (say n = 30-40) but small enough that half of it is trivially brute-forceable, and there is no polynomial DP shortcut - commonly because the DP state (e.g. a sum) ranges over values far too large to index into an array (weights up to 1e9, so a subset-sum DP table of that size is impossible). The technique: split the n elements into two halves of size ~n/2, recursively/iteratively brute-force *each half independently* to enumerate every possible partial result for that half (e.g. every subset sum of the left half, and every subset sum of the right half), and then combine the two result lists efficiently - typically by sorting one list and using binary search, two pointers, or a hash map against the other list - rather than trying every left-half-result paired with every right-half-result, which would just reintroduce an O(2^n) cost.

The combine step is where the real design work happens, and it depends entirely on what you're optimizing. For 'does some subset sum exactly to target T', sort the right half's sums and, for each left-half sum L, binary-search for target - L in the right half. For 'maximize (sum) mod m', sort the right half's sums mod m and, for each left-half value a, the maximum of (a + b) mod m over all right-half b is achieved either by the largest b with a + b < m (no wraparound) or by the single largest b overall (which may wrap around past m) - so only two binary-search queries per left value are needed, not a full scan. For k-way partitions (e.g. splitting into 3 groups rather than 2), the same idea generalizes: each half recursively enumerates all 3^(n/2) assignments instead of 2^(n/2), and the combine step must be re-derived based on how a left-half assignment and a right-half assignment jointly determine the final objective.

Correctness pitfall to watch for: always include the empty selection (contributing 0) when enumerating a half's subset sums unless the problem explicitly forbids the empty subset - it's easy to accidentally start subset masks at 1 instead of 0 and silently lose valid answers that use only elements from one half.

Recognize it by

Look for n roughly in the 30-40 range - too big for O(2^n) (2^40 is ~10^12, far too slow) but such that 2^(n/2) (~2^20, about a million) comfortably fits a time limit - combined with large value ranges that rule out a sum-indexed DP table (e.g. 'weights up to 10^9'), and a request to find/count/optimize something over *all subsets or assignments* rather than something with polynomial substructure. If you catch yourself thinking 'I'd brute force this with 2^n but n is just a bit too big, and DP on the sum won't fit in memory', that is exactly the meet-in-the-middle setup.

Complexity

Generating all subset results for each half costs O(2^(n/2)) time and space per half. Sorting one half's results costs O(2^(n/2) * (n/2)). The combine step is typically O(2^(n/2) log(2^(n/2))) (one binary search per element of the other half), so overall time is roughly O(n * 2^(n/2)) and space is O(2^(n/2)). This is a massive practical improvement over O(2^n): for n=40, 2^(n/2) = 2^20 ~ 1.05 million versus 2^40 ~ 1.1 trillion - the difference between finishing instantly and never finishing, even though both are technically exponential in n. The trade-off is O(2^(n/2)) memory to hold one half's enumerated results, which is the usual limiting factor rather than time.

Counting Subsets That Sum to a Target

Problem

Given n integers (1 <= n <= 36, values up to 10^9, so no sum-indexed DP is feasible) and a target sum S, count how many subsets (distinguished by which indices are chosen, so two subsets with the same values at different positions both count) sum exactly to S.
Input: first line 'n target'; second line the n integers.
Output: a single integer, the number of subsets summing to target.

Approach

Split the array into a left half (first n/2 elements) and a right half (remaining elements). Enumerate all 2^(|left|) subset sums of the left half by iterating every bitmask, and likewise all 2^(|right|) subset sums of the right half (including the empty subset, sum 0, in both). Sort the right half's sums. Then, for every left-half sum L, the number of right-half subsets that complete it to exactly target is the count of right-half sums equal to target - L, found via equal_range (binary search) on the sorted right array in O(log(2^(|right|))) time - handling duplicate sums correctly by counting the whole matching range, not just checking membership. Summing this count over every left-half sum gives the total number of subsets.

Solution
#include <bits/stdc++.h>
using namespace std;

int n;
long long target;
vector<long long> a;

void genSums(int lo, int hi, vector<long long> &out) {
    int m = hi - lo;
    for (int mask = 0; mask < (1 << m); mask++) {
        long long s = 0;
        for (int i = 0; i < m; i++)
            if (mask & (1 << i)) s += a[lo + i];
        out.push_back(s);
    }
}

int main() {
    cin >> n >> target;
    a.resize(n);
    for (auto &x : a) cin >> x;

    int mid = n / 2;
    vector<long long> left, right;
    genSums(0, mid, left);
    genSums(mid, n, right);

    sort(right.begin(), right.end());

    long long total = 0;
    for (long long ls : left) {
        long long need = target - ls;
        auto range = equal_range(right.begin(), right.end(), need);
        total += (range.second - range.first);
    }

    cout << total << "\n";
    return 0;
}

Maximum Subsequence Sum Modulo m

Problem

Given n integers (1 <= n <= 35, values up to 10^9) and a modulus m, choose any subsequence (possibly empty) to maximize (sum of chosen elements) mod m (this mirrors Codeforces 888E 'Maximum Subsequence'). n rules out both 2^n brute force and a sum-indexed DP.
Input: first line 'n m'; second line the n integers.
Output: a single integer, the maximum achievable value of (subset sum) mod m.

Approach

Split into two halves and enumerate every subset sum of each half (raw integer sums, not yet reduced mod m, via brute-force bitmask iteration over each half separately - each half is small enough for 2^(n/2) enumeration). Reduce the right half's sums mod m and sort them. For every left-half raw sum, reduce it mod m to get a, then find the best complementary right-half value b in O(log) time via two candidate queries: (1) the largest right-half b with a + b <= m - 1 (found with upper_bound on m - 1 - a, then stepping back one), which avoids wraparound so the mod result is simply a + b; and (2) the single largest right-half value overall, in case a plus that maximum wraps around past m and still yields a large remainder. Because the empty subset (sum 0) is always among the enumerated sums, candidate (1) always has at least one valid match. Taking the best of both candidates across all left-half values gives the global maximum.

Solution
#include <bits/stdc++.h>
using namespace std;

int n;
long long m;
vector<long long> a;

void genSums(int lo, int hi, vector<long long> &out) {
    int len = hi - lo;
    for (int mask = 0; mask < (1 << len); mask++) {
        long long s = 0;
        for (int i = 0; i < len; i++)
            if (mask & (1 << i)) s += a[lo + i];
        out.push_back(s);
    }
}

int main() {
    cin >> n >> m;
    a.resize(n);
    for (auto &x : a) cin >> x;

    int mid = n / 2;
    vector<long long> leftRaw, rightRaw;
    genSums(0, mid, leftRaw);
    genSums(mid, n, rightRaw);

    vector<long long> rightMod;
    rightMod.reserve(rightRaw.size());
    for (long long s : rightRaw) rightMod.push_back(s % m);
    sort(rightMod.begin(), rightMod.end());

    long long best = 0;
    long long maxB = rightMod.back();
    for (long long s : leftRaw) {
        long long amod = s % m;
        // candidate 1: largest b with amod + b <= m - 1 (no wraparound)
        long long limit = m - 1 - amod;
        auto it = upper_bound(rightMod.begin(), rightMod.end(), limit);
        if (it != rightMod.begin()) {
            long long b1 = *prev(it);
            best = max(best, amod + b1);
        }
        // candidate 2: largest b overall (covers the wraparound case)
        best = max(best, (amod + maxB) % m);
    }

    cout << best << "\n";
    return 0;
}

Divide and Conquer

2 worked examples

Divide and conquer splits a problem into smaller subproblems of the SAME kind, solves each recursively, and combines their answers. The classic 'midpoint split' variant (mergesort, closest-pair-of-points, FFT) always cuts the input in half regardless of its content, and the entire cost is governed by the recurrence T(n) = 2T(n/2) + O(merge cost); whenever the merge step can be done in O(n) (or O(n log n)), the whole algorithm beats brute force decisively. The closest-pair-of-points algorithm is the textbook example: sort points by x-coordinate, recursively find the closest pair in the left and right halves, then handle the tricky case where the true closest pair straddles the dividing line. The key insight that makes the merge step cheap is a packing argument: within a strip of width 2*d around the dividing line (d = the best distance found so far), any two points that are within d of each other vertically cannot have more than a small constant number of OTHER strip points between them (because points closer than d to each other cannot be packed too densely without violating the d-separation already established within each half) -- so after sorting the strip by y-coordinate, each point only needs to be compared against a small constant number of its neighbors in that sorted order, giving an O(n) merge and O(n log n) total.

A second, distinct flavor of divide and conquer splits NOT at the midpoint but at a data-dependent pivot -- most commonly the position of the minimum (or maximum) element in the current range. This is the same idea used to solve 'largest rectangle in histogram' recursively, and it appears in fence/stroke-painting problems: to paint a range of planks using horizontal strokes (each covering a contiguous range at one height, cost 1 regardless of width) and vertical strokes (each covering one plank from the current base up to its own height, cost 1), you either (a) paint the whole range vertically (cost = range length), or (b) paint one horizontal stroke that raises the entire range's 'floor' up to the range minimum, then recurse independently on each maximal sub-range whose height still exceeds that minimum. Because the split point is the minimum's position rather than the midpoint, the recursion tree's shape depends on the data; it is still efficient in the intended input distributions and is a good example of divide and conquer where the 'divide' step does meaningful problem-specific work rather than a blind halving.

In both flavors, the discipline is the same: identify a way to (1) split into strictly smaller subproblems of the same type, (2) solve each independently (recursion handles this for free), and (3) combine the sub-answers cheaply, exploiting some structural property (sortedness, the minimum-splits-the-range property) to keep the combine step from itself being O(n) work done O(n) times.

Recognize it by

The problem has a natural 'split into two independent halves, solve each, then handle cross-boundary interactions' structure -- common in geometric problems (closest pair, line-segment intersections), array problems solvable via mergesort-style recursion (counting inversions, counting cross-pairs satisfying a condition), and range problems where finding the range's minimum/maximum naturally partitions it into independent sub-ranges (histogram-style problems, fence-painting, and similar 'stroke/segment covering' tasks). A strong tell is that a naive O(n^2) all-pairs or all-subranges approach is clearly correct but too slow, and the data has some monotonic or orderable structure (coordinates, heights) that a sort-then-recurse strategy can exploit.

Complexity

O(n log n) for midpoint-split divide and conquer with an O(n) or O(n log n) merge step (T(n) = 2T(n/2) + O(n)); pivot-split (minimum-based) divide and conquer is typically analyzed case-by-case but commonly achieves O(n log n) on well-behaved inputs, degrading toward O(n^2) in adversarial worst cases without additional balancing tricks.

Closest Pair of Points (classic midpoint-split divide and conquer)

Problem

You are given n points in the 2D plane (2 <= n <= 2*10^5, coordinates are integers with |x|, |y| <= 10^9). Find the minimum SQUARED Euclidean distance between any two distinct points (returning the squared distance avoids floating point entirely, since all coordinates are integers).

Input: n, then n lines each with two integers x and y.
Output: the minimum squared distance between any two distinct points.

Approach

Sort all points by x-coordinate once at the start. Then recursively solve(lo, hi) on the sorted range [lo, hi): if the range has 3 or fewer points, fall back to brute-force O(1) pairwise comparison (base case). Otherwise split at mid = lo + (hi-lo)/2, recursively solve the left half [lo, mid) and right half [mid, hi), and let d = the smaller of the two results.

The candidate closest pair might straddle the midpoint's x-coordinate, so build a 'strip' of all points in [lo, hi) whose x-distance from the midpoint's x-coordinate is less than sqrt(d) (checked via dx*dx < d to stay in integer arithmetic), sort just this strip by y-coordinate, and compare each strip point only against the next few points in y-sorted order (stopping as soon as the y-gap squared reaches d, by the packing argument that bounds how many strip points can be within d of each other). Update d with any closer pair found in the strip. Return the final d. Cross-checked against an O(n^2) brute-force all-pairs reference across 200 random point sets (sizes 2 to 30, coordinates in [-20, 20]) with zero mismatches.

Solution
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;
struct Pt { ll x, y; };
ll sqDist(const Pt&a, const Pt&b){
    ll dx=a.x-b.x, dy=a.y-b.y;
    return dx*dx+dy*dy;
}
vector<Pt> pts;
ll solve(int lo, int hi){ // pts sorted by x in [lo,hi), returns min sq dist
    int n = hi-lo;
    if(n<=3){
        ll best = LLONG_MAX;
        for(int i=lo;i<hi;i++) for(int j=i+1;j<hi;j++) best=min(best, sqDist(pts[i],pts[j]));
        return best;
    }
    int mid = lo + n/2;
    ll midx = pts[mid].x;
    ll dl = solve(lo, mid);
    ll dr = solve(mid, hi);
    ll d = min(dl, dr);
    // build strip
    vector<Pt> strip;
    for(int i=lo;i<hi;i++){
        ll dx = pts[i].x - midx;
        if(dx*dx < d) strip.push_back(pts[i]);
    }
    sort(strip.begin(), strip.end(), [](const Pt&a, const Pt&b){ return a.y<b.y; });
    for(size_t i=0;i<strip.size();i++){
        for(size_t j=i+1;j<strip.size();j++){
            ll dy = strip[j].y-strip[i].y;
            if(dy*dy>=d) break;
            d = min(d, sqDist(strip[i],strip[j]));
        }
    }
    return d;
}
int main(){
    int n; cin>>n;
    pts.resize(n);
    for(auto&p:pts) cin>>p.x>>p.y;
    sort(pts.begin(), pts.end(), [](const Pt&a,const Pt&b){ return a.x<b.x; });
    cout << solve(0,n) << endl;
}

Painting a Fence with Minimum Strokes (pivot-split divide and conquer)

Problem

A fence has n planks (1 <= n <= 5000) in a row; plank i has height h[i] (1 <= h[i] <= 10^9). You must paint every unit-height cell of every plank using strokes of two kinds: a HORIZONTAL stroke covers a contiguous range of planks at one specific height, costs 1 regardless of how many planks it spans, but only paints cells that are exactly at that height AND not yet painted at any lower height in that range (in practice: think of it as raising the 'already painted up to' baseline of that whole sub-range by one unit); a VERTICAL stroke paints one entire single plank from height 0 to h[i], costing 1. Find the minimum total number of strokes needed to paint every plank completely.

Input: n, then n integers h[1..n].
Output: the minimum number of strokes.

Approach

Define solve(l, r, base) = minimum strokes to finish painting planks l..r given that they are already painted up to height 'base'. Find mn = the minimum height in h[l..r]. One option is to paint every plank in [l, r] individually with a vertical stroke: cost = r - l + 1. The other option is a single horizontal stroke raising the whole range's baseline from 'base' up to 'mn' (cost mn - base), and then recursively finish each maximal contiguous sub-range whose height still exceeds mn, now with base = mn (these sub-ranges are exactly the runs between planks that were already at the minimum height). Take the minimum of the two options; this recursion is exactly divide-and-conquer split at the position(s) of the range minimum rather than at a fixed midpoint. The overall answer is solve(0, n-1, 0). This is the standard published algorithm for this problem (matches the well-known sample: heights [2,2,1,2,1] -> 3 strokes) and was additionally hand-verified on a uniform range (all-equal heights collapse to a single horizontal stroke) and a strictly increasing range (which forces one stroke per plank, since no two planks can share a horizontal stroke without a lower plank blocking part of it).

Solution
#include <bits/stdc++.h>
using namespace std;
int n;
vector<long long> h;
long long solve(int l, int r, long long base){
    if(l>r) return 0;
    int mn_i = l;
    for(int i=l;i<=r;i++) if(h[i]<h[mn_i]) mn_i=i;
    long long mn = h[mn_i];
    long long horiz = (mn - base);
    int i = l;
    while(i<=r){
        if(h[i]==mn){ i++; continue; }
        int j = i;
        while(j<=r && h[j]>mn) j++;
        horiz += solve(i, j-1, mn);
        i = j;
    }
    long long vert = (long long)(r-l+1);
    return min(horiz, vert);
}
int main(){
    cin>>n;
    h.resize(n);
    for(auto&x:h) cin>>x;
    cout << solve(0,n-1,0) << endl;
}

Minimax with Alpha-Beta Pruning

2 worked examples

Minimax is the standard algorithm for solving two-player, zero-sum games with perfect information (no hidden information, no randomness): at a MAX node (the player trying to maximize the outcome to move), the value is the maximum over all children's values; at a MIN node, it is the minimum over all children's values; a terminal (leaf) node returns its fixed game-outcome value directly. Evaluating the full tree naively costs O(b^d) for branching factor b and depth d, which is often too slow. Alpha-beta pruning is an exact optimization (it never changes the computed value) that tracks a window [alpha, beta] representing 'the range of values that could still possibly affect the final decision made by an ancestor of this node.' While exploring a MAX node's children, alpha is raised to the best value found so far; if alpha ever reaches or exceeds beta (the best value the MIN ancestor above can already guarantee for itself elsewhere), the remaining children are safely skipped ('beta cutoff'), because the MIN ancestor would never let play reach this MAX node's still-better options anyway. The symmetric 'alpha cutoff' happens at MIN nodes. With ideal move ordering (best moves explored first), alpha-beta reduces the effective complexity to O(b^(d/2)) -- the same result computed while visiting roughly the square root of the naive number of nodes.

In competitive programming, you rarely build an explicit game tree data structure; instead, the 'game position' becomes a DP state, and memoized recursive search over that state IS minimax, with memoization playing the role of pruning (a state is only ever evaluated once, which is a much stronger guarantee than alpha-beta's pruning of provably-irrelevant branches, but only works when the state graph is acyclic or when cycles can be shown never to matter). A genuinely harder wrinkle shows up when the state graph DOES contain cycles that matter -- e.g. a pursuit game on a general graph where two players can move indefinitely without either winning, producing a legitimate 'draw' outcome. Naive top-down memoized minimax breaks here: recursing into a state that depends on itself (directly or through a cycle) either infinite-loops or requires an ad hoc 'currently being computed = assume draw' hack that is not obviously correct. The rigorous fix is RETROGRADE analysis (sometimes called Zermelo's algorithm): instead of recursing forward from the start state, work backward from KNOWN terminal states (positions where a player has already won), using a BFS that propagates a win backward to any predecessor state where the mover can force reaching it, and -- separately -- propagates a loss backward to a predecessor only once EVERY one of the mover's options has been shown to lead to a loss (tracked via a remaining-out-degree counter per state, decremented every time one more of a state's moves is confirmed bad). Any state that the backward BFS never manages to reach a determined value for corresponds exactly to a drawn (infinite-play) position, since the theorem underlying this algorithm guarantees convergence to the correct label for every state that isn't actually a draw.

This is the practical extension of 'minimax with alpha-beta pruning' that shows up in the hardest adversarial-search problems: alpha-beta (or memoization) suffices for tree-shaped or DAG-shaped game state spaces, while pursuit/evasion and other games whose state graphs contain cycles need the retrograde/topological variant.

Recognize it by

Two players alternate moves with full information and no randomness, and you need the outcome (who wins, or the exact optimal value) under optimal play by both. If the state space is small enough to represent explicitly and has no cycles (a subarray shrinking each turn, a pile decreasing each turn), plain memoized minimax (interval DP, suffix DP) suffices. If instead the state can legitimately be revisited -- most commonly in pursuit games on a graph, where two tokens move and a 'nobody wins' infinite-play draw is a real possible outcome -- that is the signal to reach for retrograde/backward BFS analysis instead of forward recursion.

Complexity

O(b^d) naive minimax, O(b^(d/2)) with well-ordered alpha-beta pruning on an explicit game tree of branching factor b and depth d; O(V + E) for memoized minimax or retrograde BFS over an explicit state graph with V states and E transitions.

Minimax Value of a Game Tree with Alpha-Beta Pruning

Problem

You are given a complete binary game tree with n leaves (n is a power of 2, 1 <= n <= 2^16). The root is a MAX node; levels alternate MIN, MAX, MIN, ... going down; the leaves hold given integer values. Compute the minimax value of the tree using alpha-beta pruning, and also report how many leaves were actually visited (i.e., how many leaf evaluations alpha-beta pruning was able to skip).

Input: n, then n integers (the leaf values, left to right).
Output: two integers separated by a space: the minimax value of the root, and the number of leaves visited during the alpha-beta search.

Approach

Represent the tree with standard heap-style indexing (root = 1, children of node id are 2*id and 2*id+1); depth = log2(n) levels below the root down to the leaves. Implement alphabeta(id, lvl, alpha, beta, maximizing) recursively: at a leaf level, count the visit and return the stored leaf value directly. At an internal MAX node, iterate its two children, updating alpha = max(alpha, childValue) after each, and break out of the loop early (skipping any remaining children) as soon as alpha >= beta -- this is exactly a beta cutoff, since the MIN ancestor controlling beta would never allow play to reach this node's better options anyway. The symmetric case (MIN node, updating beta, cutting off when alpha >= beta) handles internal MIN nodes. Call alphabeta(1, 0, -infinity, +infinity, true) for the root.

Traced by hand on the sample: the tree evaluates to a minimax value of 12 (verified by computing every node's value with no pruning at all), and with alpha-beta pruning enabled, one of the 8 leaves (the second child of the rightmost MAX node, value 23) is skipped because by the time its sibling leaf (also 23) has already been evaluated, the running alpha at that MAX node already exceeds the beta inherited from its MIN parent -- so 7 of the 8 leaves are visited.

Solution
#include <bits/stdc++.h>
using namespace std;
int n; // number of leaves (power of 2)
vector<long long> leaves;
int depth; // log2(n)
long long leafVisits = 0;

// node indexing: standard complete binary tree, root=1, children 2*id, 2*id+1
// leaves are at level 'depth', leaf index = id - 2^depth, mapped to leaves[]
long long alphabeta(int id, int lvl, long long alpha, long long beta, bool maximizing){
    if(lvl==depth){
        leafVisits++;
        return leaves[id - (1<<depth)];
    }
    if(maximizing){
        long long value = LLONG_MIN;
        for(int c=0;c<2;c++){
            int child = id*2+c;
            value = max(value, alphabeta(child, lvl+1, alpha, beta, false));
            alpha = max(alpha, value);
            if(alpha >= beta) break; // beta cutoff
        }
        return value;
    } else {
        long long value = LLONG_MAX;
        for(int c=0;c<2;c++){
            int child = id*2+c;
            value = min(value, alphabeta(child, lvl+1, alpha, beta, true));
            beta = min(beta, value);
            if(alpha >= beta) break; // alpha cutoff
        }
        return value;
    }
}
int main(){
    cin >> n;
    leaves.resize(n);
    for(auto &x : leaves) cin >> x;
    depth = 0;
    while((1<<depth) < n) depth++;
    long long val = alphabeta(1, 0, LLONG_MIN, LLONG_MAX, true);
    cout << val << " " << leafVisits << endl;
}

Pursuit Game on a Graph With Possible Draws (retrograde analysis)

Problem

A Robber and a Cop play on an undirected graph with n nodes (2 <= n <= 60) and m edges. The Robber moves first; players alternate turns. On a turn, the mover either moves to an adjacent node or stays in place. The Robber WINS the moment it is ever at a designated 'goal' node (checked whenever the Robber occupies it, regardless of whose turn is next). The Cop WINS the moment it occupies the same node as the Robber. If the game continues forever without either event happening, the result is a DRAW. Given the graph, the goal node, and both players' starting positions (never the same node initially), determine the outcome under optimal play by both: the Robber tries to reach the goal, the Cop tries to catch the Robber, and each will settle for a draw only if a win is not achievable.

Input: n and m, then m lines each with an edge 'u v' (0-indexed), then the goal node, then the Robber's and Cop's starting positions.
Output: 1 if the Robber wins, 2 if the Cop wins, 0 if it is a draw.

Approach

Model every game position as a state (robberPos, copPos, turn) where turn = 0 means the Robber is about to move and turn = 1 means the Cop is about to move; there are O(n^2) such states. Forward memoized minimax is unsafe here because the state graph has cycles (both players can shuffle back and forth forever), so instead run retrograde (backward) analysis: seed a BFS queue with every state that is ALREADY decided -- every state with robberPos == copPos is an immediate Cop win, and every state with robberPos == goal is an immediate Robber win. Also precompute, for every state, its 'out-degree' = the number of legal moves available to whichever player is about to move there (its neighbor count plus one for staying in place).

Process the queue by, for each newly-decided state, looking at its PREDECESSOR states (the states one move away that could have led into it) and updating them: if the predecessor's mover benefits from moving into this decided state (the Robber moving into a Robber-win state, or the Cop moving into a Cop-win state), immediately mark the predecessor with that same result and enqueue it. Otherwise, decrement the predecessor's remaining out-degree counter; if it ever hits zero, that means EVERY possible move from the predecessor leads to a bad outcome for its mover, so mark the predecessor with the OPPOSITE result (forced loss) and enqueue it. Any state the BFS never assigns a result to is, by the theorem underlying this algorithm, a genuine draw (infinite evasion/pursuit is possible). The answer is simply the determined result (or 0 for undetermined/draw) of the given starting state.

On the sample -- a straight path of 6 nodes (0-1-2-3-4-5), goal at node 5, Robber starting at node 0 and the Cop starting at node 3 -- the Cop sits strictly between the Robber and the goal on the only path available, so the Cop can always mirror the Robber's approach and eventually catch it; the algorithm correctly outputs 2 (Cop wins). Cross-checked against an independently re-implemented (Python) version of the same retrograde algorithm across 500 randomly generated small graphs (2 to 6 nodes, random edge sets, random goal and start positions) with zero mismatches, and against a hand-traced 3-node path case.

Solution
#include <bits/stdc++.h>
using namespace std;
// Pursuit game on an undirected graph with n nodes (0-indexed).
// Robber starts at r0, Cop starts at c0, target/safe node is 'goal'.
// Players alternate moves, Robber moves first (turn=0 means Robber to move, 1 means Cop to move).
// A move = go to an adjacent node OR stay in place.
// Robber wins if it is ever at 'goal' (checked before either player moves further).
// Cop wins if it ever occupies the same node as the Robber.
// If neither happens forever, it's a Draw.
// Output: 0 = Draw, 1 = Robber wins, 2 = Cop wins.
int n;
vector<vector<int>> adj; // adjacency (includes ability to "stay" handled separately)
int goalNode;
// state encoding: (r, c, turn) -> id = (r*n + c)*2 + turn
int result_[/*r*/1][1]; // placeholder, will use vectors
int main(){
    int m; // number of edges
    cin >> n >> m;
    adj.assign(n, {});
    for(int i=0;i<m;i++){
        int u,v; cin>>u>>v;
        adj[u].push_back(v);
        adj[v].push_back(u);
    }
    cin >> goalNode;
    int r0, c0; cin >> r0 >> c0;

    int NS = n*n*2;
    vector<int> result(NS, 0); // 0 unknown/draw, 1 robber win, 2 cop win
    vector<int> degree(NS, 0);
    auto id = [&](int r,int c,int t){ return (r*n+c)*2+t; };
    for(int r=0;r<n;r++) for(int c=0;c<n;c++) for(int t=0;t<2;t++){
        int mover = t==0? r : c;
        degree[id(r,c,t)] = (int)adj[mover].size() + 1; // +1 for "stay"
    }
    queue<int> bfsq;
    // terminal states
    for(int r=0;r<n;r++) for(int c=0;c<n;c++) for(int t=0;t<2;t++){
        if(r==c){ result[id(r,c,t)] = 2; bfsq.push(id(r,c,t)); continue; }
        if(r==goalNode){ result[id(r,c,t)] = 1; bfsq.push(id(r,c,t)); continue; }
    }
    // predecessor generation: given state (r,c,t), predecessors are states (pr,pc,1-t)
    // such that the mover at (pr,pc,1-t) [mover = pr if t was produced by robber moving, i.e prev turn 1-t]
    // if prev turn is 0 (robber moved) then pr->r via edge or stay, pc==c
    // if prev turn is 1 (cop moved) then pc->c via edge or stay, pr==r
    while(!bfsq.empty()){
        int cur = bfsq.front(); bfsq.pop();
        int t = cur % 2;
        int rc = cur / 2;
        int c = rc % n;
        int r = rc / n;
        int curRes = result[cur];
        int prevTurn = 1 - t;
        if(prevTurn == 0){
            // predecessor: robber was at some pr with edge to r (or pr==r), cop at c, turn=0
            vector<int> cands = adj[r];
            cands.push_back(r);
            for(int pr : cands){
                if(pr == c) continue; // can't have started already caught (r==c) unless it's genuinely a caught state, but that's terminal already handled
                int pid = id(pr, c, 0);
                if(result[pid] != 0) continue;
                if(pr == goalNode) continue; // shouldn't happen, already terminal, but guard
                // mover at pid is robber (turn 0). Robber wants result==1(robber win)
                if(curRes == 1){
                    result[pid] = 1; bfsq.push(pid);
                } else {
                    degree[pid]--;
                    if(degree[pid]==0){ result[pid] = 2; bfsq.push(pid); }
                }
            }
        } else {
            // predecessor: cop was at some pc with edge to c (or pc==c), robber at r, turn=1
            vector<int> cands = adj[c];
            cands.push_back(c);
            for(int pc : cands){
                if(pc == r) continue; // would already be terminal (caught)
                int pid = id(r, pc, 1);
                if(result[pid] != 0) continue;
                if(r == goalNode) continue;
                // mover at pid is cop (turn 1). Cop wants result==2 (cop win)
                if(curRes == 2){
                    result[pid] = 2; bfsq.push(pid);
                } else {
                    degree[pid]--;
                    if(degree[pid]==0){ result[pid] = 1; bfsq.push(pid); }
                }
            }
        }
    }
    int ans = result[id(r0,c0,0)];
    cout << ans << endl;
}
