Two Pointers & Sliding Window

20 problems

Twenty problems that build the two-pointer and sliding-window toolkit from a single forward scan up to the point where a window is only one subroutine inside a much larger algorithm. The early rungs establish why a pointer never has to move backwards; the middle rungs make the window carry state - a sum, a minimum, a covering condition - and turn 'find one' into 'count them all'; the last rungs reuse the same walk inside geometry, offline query ordering, meet in the middle, and a counting DP. Picked from the 74 problems tagged on AtCoder Categories — Two Pointers / Sliding Window. Theory and worked examples for this technique live on the Arrays & Strings — Two Pointers section.

Pointers that only move forward

274 - 884

The core move and the reason it is linear: on a sorted or otherwise ordered sequence the right pointer never has to go back. These rungs also introduce the two basic shapes - one window over one sequence, and one pointer per sequence.

01
Peak ABC 326 C 274
Fixed-width window

The base move: sort the values, then let a right pointer chase a left pointer so every candidate window is examined in one linear pass.

Nudge

An optimal half-open interval can always be slid until its left end sits exactly on some A_i, so only N candidate windows matter. Sort A, and for each left index advance the right index while A[r] - A[l] < M - the right index never moves backwards.

02
Souvenirs ABC 358 D 393
Merge two sorted lists

Two pointers over two different sorted sequences, where a greedy exchange argument is what makes the single forward pass correct.

Nudge

Sort both A and B. Handle the people in increasing order of B_i, always handing over the cheapest still-unused box that is large enough - one pointer per list, each moving forward only. If a pointer runs off the end of A, the answer is -1.

03
Count Close Pairs ABC 466 C 658
Amortised query budget

Why forward-only pointers are cheap: here the amortised argument is literally the problem, since you are allowed only 2N queries.

Nudge

The points are already given left to right, so for each i the set of j with distance at most 1 is a contiguous block [i, r_i], and r_i is non-decreasing in i. Never rewind r: each step either advances r or advances i, which is where the 2N budget comes from.

04
Intersecting Intervals ABC 355 D 735
Count pairs by sorting

Turning 'count the pairs' into a single ordered sweep instead of an O(N^2) check over all pairs.

Nudge

Once the intervals are sorted by left endpoint, i < j intersect exactly when l_j <= r_i. Sweep the 2N endpoints in sorted order keeping a running count of currently open intervals: each opening event contributes that count, and the whole answer falls out of one pass.

05
9 Divisors ABC 383 D 884
Two pointers over primes

A two-pointer walk over a derived sorted sequence - the primes - rather than over the input itself.

Nudge

Exactly nine divisors means the number is p^8 or (p*q)^2 with p != q prime. The first case has only a handful of members; the second reduces to counting prime pairs p < q with p*q <= sqrt(N). Sieve primes up to sqrt(N); as p walks up the list, the largest allowed q walks down.

Windows that carry state

914 - 1367

The window now holds something - a running sum, a matching, a feasibility test - so advancing a pointer means updating an aggregate rather than just comparing two values. Two rungs also show that the moving index need not be an array position at all.

06
Count Subgrid Sum = K ABC 461 D 914
Fix rows, slide columns

Collapsing one dimension so the other becomes a plain one-dimensional window, and counting sums equal to K as at-most(K) minus at-most(K-1).

Nudge

Fix the top and bottom rows (H^2 / 2 pairs) and use row prefix sums to collapse each column to a single non-negative number. Because zero columns break strict monotonicity, do not chase sum exactly K directly: count windows with sum at most K and subtract those with sum at most K-1.

07
Simultaneous Kagamimochi ABC 388 E 1068
Monotone feasibility on K

A feasibility predicate that is monotone in the answer, checked by pairing a prefix against a suffix in one scan.

Nudge

If K pairs are possible, an optimal choice is the K smallest against the K largest, matched in order: 2*A[i] <= A[N-K+i] for every i. Feasibility is monotone in K, so binary search K and verify with a single linear pass.

08
2-variable Function ABC 246 D 1148
Monotone 2D sweep

Two pointers where the pointers index the arguments of a monotone function, not positions in a given array.

Nudge

Rewrite X = (a+b)(a^2+b^2), which is non-decreasing in each of a and b separately. So the smallest valid b for a given a shrinks as a grows: walk a up from 0 to about 10^6 and let b slide down, never resetting it, recording the best value that is at least N.

09
Transformable Teacher ABC 181 E 1193
Prefix/suffix + insertion pointer

Combining prefix and suffix precomputation with a merge pointer over a second sorted sequence, so every insertion point is evaluated in O(1).

Nudge

With everyone sorted by height, an optimal pairing always pairs adjacent people. Precompute the cost of pairing up a prefix and, separately, a suffix; then dropping the teacher into slot i costs pre[i] + suf[i+1] plus one pairing. Sort W too and let a pointer over H advance monotonically as you scan W.

10
Printing Machine ABC 325 D 1367
Sweep pointer + heap

The sweep-line cousin of the two-pointer scan: one forward pointer over sorted events feeding a heap that resolves the greedy choice.

Nudge

Product i is available on the interval [T_i, T_i + D_i] and prints are one microsecond apart, so this is deadline scheduling. Sort by start time; sweep the candidate print times upward, pushing every product whose interval has opened into a min-heap keyed by its deadline, discarding expired ones, and always printing the one that expires soonest.

Counting, not finding

1545 - 1875

Every left endpoint has a monotone boundary; the real work is turning those N boundaries into the quantity the problem actually asks for - a count per length, an 'exactly K', a DP value, a digit sum.

11
Packing Potatoes ABC 258 E 1545
Window to functional graph

Using a two-pointer pass to build a next-state function, then exploiting the cycle that function necessarily creates.

Nudge

For each start index i, the number of potatoes the box swallows is found by prefix sums over two copies of W, and that count's endpoint is monotone in i - so one forward pass gives all N of them. That defines a map i -> next start; the box sequence is then a rho shape, so find its tail and cycle and index into it.

12
Interval Inversion Count ABC 452 F 1630
Exactly K by difference

The standard move for 'exactly K' under a monotone window predicate: count at-most-K and subtract at-most-(K-1).

Nudge

Inversion count of [l, r] grows when r grows and shrinks when l grows, so the boundary of 'at most K' is monotone in both directions. Slide two pointers while a BIT maintains the inversion count incrementally as elements enter and leave; run it for K and for K-1 and subtract.

13
At Least One ABC 260 E 1692
Minimal covering window

The minimal covering window for every left endpoint, and how to convert those N answers into a count for each window length at once.

Nudge

For each l let r(l) be the smallest right end whose window hits every pair; r(l) is non-decreasing, so two pointers plus a counter of still-uncovered pairs finds all of them. Then the window starting at l of length k is good exactly when l + k - 1 >= r(l) - a range increment over k, so accumulate with a difference array.

14
Christmas Present 2 ABC 334 F 1813
DP + sliding window min

A DP transition restricted to a window of the last K indices, made linear by a sliding window minimum.

Nudge

Let dp[i] be the cheapest way to have served the first i children. Going home after child j and serving j+1..i in one trip has a cost that splits into a part depending only on i and a part depending only on j, so dp[i] = f(i) + min over j in [i-K, i-1] of (dp[j] + g(j)) - a monotone deque gives that minimum in O(1) amortised.

15
All Pair Digit Sums ARC 158 C 1875
Digit carries as pairs

A change of representation - counting carries instead of digits - that converts a sum of digit sums into a threshold pair-count.

Nudge

f(x+y) = f(x) + f(y) - 9 * (number of carries in x + y). A carry leaves digit position k exactly when (x mod 10^k) + (y mod 10^k) >= 10^k, so for each of the ~16 positions sort the residues and count pairs above the threshold with two pointers.

Two pointers inside something bigger

2044 - 2957

Here the forward walk is the inner loop of a larger algorithm: a geometric search around a polygon, a two-dimensional window, an offline query order, a meet-in-the-middle count, a counting DP.

16
One Fourth ABC 250 F 2044
Cyclic two pointers

Two pointers on a cyclic structure, where convexity rather than sorting is what supplies the monotonicity.

Nudge

Fix one endpoint i and let j run forward; the area of the fan i..j increases with j, so the best j for i never moves backwards as i advances around the polygon. Walk both pointers once around, using prefix sums of cross products to get any fan's doubled area in O(1), and compare against a quarter of the total.

17
Stamp Game ABC 228 F 2179
2D sliding window max

Sliding window maximum in two dimensions, used as the inner solve of a minimax game.

Nudge

Aoki's reply is forced: he erases the best min(h1,h2) x min(w1,w2) block that fits inside the black rectangle. So precompute a 2D sliding window maximum of white-stamp sums (a row pass with a deque, then a column pass), and the answer is the maximum over black placements of its prefix-sum total minus that stored maximum.

18
Cubic? ABC 238 G 2254
Mo's algorithm

Mo's algorithm: two pointers walking over reordered offline queries, requiring only an O(1) add/remove invariant.

Nudge

Factor every A_i (all under 10^6) and track, for the current window, each prime's exponent sum mod 3 plus a single counter of how many primes are currently nonzero - the window is a cube exactly when that counter is 0. Adding or removing one element touches only its own primes, so sort the queries in Mo's order and let the two pointers do the rest.

19
P-smooth number ABC 300 G 2343
Meet in the middle merge

Meet in the middle followed by a merge-count, so the pointers walk two generated sorted lists rather than the input.

Nudge

You cannot enumerate all P-smooth numbers (there can be billions), but you can split the prime list: numbers built only from the small primes form a short sorted list, and numbers built only from the remaining primes are far fewer than the total. Sort both and count pairs with product at most N - as one factor grows, the largest allowed partner shrinks, so one two-pointer sweep counts them all.

20
Max Limited Sequence ABC 262 Ex 2957
Interval-cover DP window

A counting DP whose set of valid predecessors slides forward, combining the 'at least one per interval' idea with a running window sum.

Nudge

First push every constraint down to an upper bound ub[i] = min X_j over constraints covering i (range-chmin, then read off). Then group positions by ub value: within value X, each constraint of that value needs at least one of its positions to actually equal X while the rest are free in [0, X). Counting that is a DP over the compressed positions whose earliest allowed predecessor only moves forward, so maintain a window sum of dp values, and multiply the groups together.

Subarrays & Subsequences

20 problems

Twenty AtCoder problems built around the distinction the whole category rests on: a contiguous subarray is pinned down the moment you choose two endpoints, so a window or a prefix aggregate handles it, while a subsequence is chosen element by element and almost always needs a DP over positions. The ladder starts with one-pass counting of both kinds, moves through sliding windows, greedy splits and greedy subsequence matching, and finishes with problems whose answer is a sum over every subsequence or every string at once. Picked from the 312 problems tagged on AtCoder Categories — Subarrays / Subsequences. Theory and worked examples for this technique live on the Arrays & Strings — Kadane's Algorithm section.

Contiguous or Not

213 - 750

The split everything else builds on. These five drill counting each kind in a single pass: prefix aggregates and two pointers for the contiguous case, a small state-carrying DP for the non-contiguous one.

01
Piano ABC 346 B 213
Enumerate all substrings

A contiguous substring is determined by its two endpoints, so when the search space is tiny you enumerate every pair and stop thinking.

Nudge

The infinite string repeats with period 12, and W + B is at most 200, so build a few dozen copies and check the letter counts of every window (l, r) — the only real care is making the built string longer than any window you might need.

02
Count Arithmetic Subarrays ABC 369 C 315
Longest run per right end

Counting subarrays with a property that is closed under taking sub-subarrays: fix the right end and count how far left it can reach.

Nudge

Every subarray of an arithmetic subarray is arithmetic, so for each right end r the valid left ends form a contiguous block. Track the length of the longest arithmetic subarray ending at r (it extends the one ending at r-1 exactly when A[r]-A[r-1] equals the previous difference) and add that length to the answer.

03
DNA Sequence ARC 104 B 487
Prefix-sum pair counting

The core trick for counting subarrays: turn the condition into 'two prefix aggregates are equal' and count equal pairs.

Nudge

A substring works exactly when it holds as many A as T and as many C as G. Encode each letter as a step in two running counters, and the answer is the number of pairs of prefix positions where both counters agree.

04
Not Adjacent 2 ABC 456 D 586
Subsequence DP by last letter

The contrast rung: the same kind of counting question, but non-contiguous, so you carry the one piece of state the constraint needs.

Nudge

Keep, for each of the three letters, how many valid subsequences currently end in that letter. When you read letter x, every valid subsequence not already ending in x can be extended by it, plus the new length-one one — so f[x] gains the sum of the other two plus 1.

05
Truck Driver ABC 430 C 750
Two-pointer subarray count

When a subarray condition is monotone in each endpoint, the valid right ends for a fixed left end form an interval you can slide instead of recompute.

Nudge

For a fixed l, the r with at least A as form a suffix and the r with fewer than B bs form a prefix, so the valid r are one interval. Both of its endpoints only move right as l moves right, so two pointers give the whole count in one sweep.

Windows and Matches

841 - 1402

Now the property inside the window has structure. These rungs cover a greedy split into contiguous blocks, an invariant a sliding window can maintain, and greedy subsequence matching that turns a pair-counting problem into two independent scans.

06
Transmission Mission ABC 414 D 841
Greedy gap split

Splitting a sorted line into contiguous blocks: the cost of a partition is the total span minus the gaps you choose to cut at.

Nudge

Sort the houses. An optimal station covers a contiguous block and costs exactly (max - min) of that block, so the total over M blocks is the whole span minus the M-1 gaps you cut — cut at the M-1 largest gaps.

07
1122 Substring ABC 381 D 921
Sliding window invariant

Best-subarray optimisation where the window carries a violation you can repair by advancing the left end.

Nudge

A valid subarray is a chain of adjacent equal pairs A[i]=A[i+1], A[i+2]=A[i+3], ... whose values are all distinct. Precompute the positions where A[i]=A[i+1], then slide a window over chains of such pairs spaced two apart, shrinking from the left whenever a value repeats.

08
Joint Two Strings ABC 324 E 1153
Prefix/suffix subsequence match

Greedy subsequence matching is optimal prefix-wise, which lets a pair problem split into one number per string.

Nudge

Matching a subsequence greedily from the left gets you as far into T as possible, so compute for each S_i how far forward into T it reaches and how far backward from the end of T it reaches. Pair (i, j) works exactly when the forward reach of i plus the backward reach of j covers |T| — then count pairs with a sorted array or a suffix-count table.

09
Cross-free Matching ARC 126 B 1370
LIS reduction

Recognising a longest-increasing-subsequence in disguise: a geometric non-crossing condition is exactly 'increasing in both coordinates'.

Nudge

Two chosen segments may not cross or share an endpoint, which means one must be strictly to the left of the other on both rows. Sort by a, breaking ties by b descending so two segments with the same a can never both be picked, then take a strictly increasing longest subsequence of the b values.

10
Subsequence Path ABC 271 E 1402
Relax along edge order

When the allowed order of moves is fixed by a sequence, shortest paths need no priority queue — the sequence itself is the processing order.

Nudge

The road numbers used must appear in E's order, so walk E once from left to right and relax only that one edge each time. After processing a prefix of E, dist[v] is already the best cost reachable using a subsequence of that prefix.

Aggregates and Bounded Search

1518 - 1757

Two competing instincts, and when each one applies: enumerate when the constraints secretly bound the search space, and replace the enumeration with a prefix aggregate or a monotone pointer when they do not.

11
Maximize XOR ABC 386 E 1518
Complement-set enumeration

An odd-looking constraint like C(N,K) <= 10^6 is an invitation to enumerate — but read carefully which side of the choice is cheap to build.

Nudge

C(N,K) bounds the number of subsets but not their size, so enumerating K elements each time is still too slow when K is large. XOR of the chosen equals the XOR of everything XOR the unchosen, so enumerate whichever of K and N-K is smaller by DFS.

12
Adjacent Delete ARC 196 A 1569
Parity + half split

Reasoning about which elements can be paired: a parity invariant on indices reduces an operation game to a sorted-half sum.

Nudge

For even N the score can reach (sum of the larger half) minus (sum of the smaller half) after sorting. For odd N exactly one element survives, and since everything left of it is deleted in pairs its index must be odd — so sweep the odd candidate indices while maintaining the half-split incrementally instead of recomputing it.

13
Not Adjacent ABC 427 F 1605
Meet in the middle

N around 60 with a modular sum condition means splitting the sequence in half and joining the halves by residue.

Nudge

Enumerate the non-adjacent subsets of each half — there are only Fibonacci-many — recording each sum mod M, then join the halves with a hash map on the residue. The only subtlety is the seam: split each half's list by whether its boundary index is used, so you never glue two adjacent picks together.

14
Interval Inversion Count ABC 452 F 1630
Monotone two pointers

Counting subarrays whose aggregate hits an exact value, by exploiting that the aggregate is monotone in both endpoints.

Nudge

The inversion count grows as r grows and shrinks as l grows, so for each l the r with exactly K inversions form one contiguous block, and both of its ends only move right as l increases. Maintain two pointers and update the inversion count with a Fenwick tree as elements enter or leave the window.

15
Range Add Query ABC 288 D 1757
Residue-class prefix sums

Turning 'can these operations zero out this subarray' into an invariant that prefix sums can answer per query in O(K).

Nudge

One operation touches K consecutive positions, so it shifts every residue class mod K by the same amount. That makes the differences between the K residue-class sums invariant, so the subarray is good exactly when all K of those sums are equal — precompute a prefix sum per residue class and answer each query directly.

Counting Over All Subsequences

1820 - 2548

The answer is now a sum over every split, every subsequence, or every string at once, so the work is designing the DP state. Partition DP, gluing tokens before counting arrangements, uniqueness of an extraction, and an automaton for a pattern that must never appear.

16
Mod i ABC 207 E 1820
Partition DP by remainder

Counting all ways to cut a sequence into contiguous blocks, when each block's condition depends only on prefix sums.

Nudge

Let dp[k][i] count splits of the first i elements into k blocks. The k-th block's condition is just that prefix[i] - prefix[j] is divisible by k, so as you sweep i bucket the dp[k-1][j] values by prefix[j] mod k — that makes each layer linear and the whole table O(N^2).

17
Yet Another RGB Sequence ABC 266 G 2045
Glue-and-insert counting

Counting strings with an exact number of occurrences of a two-letter substring: glue the required occurrences into tokens, then forbid accidental extras.

Nudge

Fuse K of the Gs onto an R to make K indivisible RG tokens, and arrange those tokens with the remaining Rs and the Bs freely. Then drop the leftover Gs into the gaps of that arrangement by stars and bars — every gap is allowed except the ones immediately after a bare R, which would create an extra RG.

18
Unique Subsequence ARC 125 D 2187
Distinct subsequence DP

Distinct-subsequence counting done by index set: pin each subsequence to one canonical set of positions so nothing is double counted.

Nudge

An extraction is the only one exactly when it is simultaneously the leftmost and the rightmost match, which means between two consecutive chosen indices there is no other copy of the later value, and the final index is the last occurrence of its value in A. Do a DP over the ending index with a Fenwick tree for the sliding range sum.

19
Colorful Subsequence ABC 345 E 2356
Top-two color DP

Optimising over subsequences when the state you 'need' is unbounded: keep only the best two candidates that differ in that state.

Nudge

dp over (index, number removed so far) wants the colour of the last kept ball as extra state, which is too many colours. Notice you only ever need the best value overall and the best value whose last colour differs from the current one — so keep the top two entries by distinct last colour per removal count and each step is O(1).

20
Anti-DDoS ABC 301 F 2548
Subsequence-avoidance automaton

Counting strings that avoid a pattern as a subsequence: build the automaton of 'how much of the pattern is already matched' and never let it finish.

Nudge

Track how far along the forbidden pattern you are: how many distinct uppercase letters have been seen (repeating any of them completes the XX prefix), whether that XX has happened, and whether a lowercase has followed it — from that last state any further uppercase is fatal. Each ? branches into 26 uppercase choices split by whether the letter is one already seen, plus 26 lowercase ones.

Prefix Sums & Range Queries

21 problems

A climb from the plain running total to the data structures that replace it. The early rungs build the two reflexes — accumulate once and answer range queries in O(1), and record only the endpoints of a range update — then the ladder pushes the same idea onto counts, XORs, digit places, residue classes and DP transitions. The last tier is where a single accumulated array stops being enough: second-order differences, two dimensions, and Fenwick or segment trees once updates interleave with the queries. Picked from the 208 problems tagged on AtCoder Categories — Prefix Sums. Theory and worked examples for this technique live on the Arrays & Strings — Prefix Sums section.

The running total

214 - 524

One pass, one array, O(1) queries. These rungs establish the two directions the idea runs in: accumulate values so a range costs one subtraction, and record only what changes so a range update costs two writes.

01
Substr Swap ABC 419 D 214
Parity difference array

Range updates whose result is only read at the end collapse into one difference array plus a single sweep.

Nudge

A position only cares how many of the M ranges cover it, not in what order they came. Write +1 at L_i and -1 at R_i+1, sweep once, and take the count mod 2 to decide whether that character ends up from S or from T.

02
Rotate and Sum Query ABC 425 C 304
Prefix sums with an offset

The base case: never move the data, keep one prefix-sum array and translate the query indices instead.

Nudge

Build the prefix sums of A concatenated with itself. A rotation is just an offset s kept mod N, so a sum query on [l, r] becomes the sum of the window [s+l-1, s+r-1] in the doubled array — one subtraction.

03
Blue Spring ABC 318 C 400
Suffix sums after sorting

Enumerating how much of a resource you buy turns an optimisation into one accumulated-array lookup per candidate.

Nudge

Sort the fares descending — a pass should always cover the most expensive remaining day. Then for each number of batches k, the cost is k*P plus the sum of every fare after the first k*D, which is a single suffix-sum lookup. Try all k from 0 to ceil(N/D).

04
Sum of difference ABC 186 D 436
Contribution by rank

Sorting removes the absolute value, and then each element's whole contribution to an O(N^2) double sum is a rank times itself minus a prefix sum.

Nudge

After sorting, |A_i - A_j| for i < j is simply A_j - A_i. The element at 0-indexed sorted position j is the larger one in exactly j pairs, so it contributes j*A_j minus the sum of everything before it. One pass with a running total; the answer needs 64-bit.

05
Index x A(Continuous ver.) ABC 267 C 524
Index-weighted window sums

Some quantities need two accumulators at once: sliding a position-weighted window costs exactly one ordinary window sum.

Nudge

Let V be the weighted value of the window starting at l and S its plain sum. Moving one step right gives V' = V - S + M*A_{l+M}. Maintain both and update them together in a single pass.

Difference arrays and prefix counts

602 - 865

The accumulated array stops holding values and starts holding events, character counts, or DP mass. Two rungs here are the first time a prefix sum is what makes a DP transition O(1).

06
Reindeer and Sleigh ABC 334 D 602
Prefix sums + binary search

A sorted prefix-sum array is monotone, so 'how many can I afford' becomes one binary search per query.

Nudge

Cheapest sleighs first is optimal, so sort R ascending and prefix-sum it. That array is strictly increasing, so a query X is answered by the largest m with prefix[m] <= X — binary search, O((N+Q) log N) total. Sums reach 2*10^14, so use 64-bit.

07
Water Heater ABC 183 D 662
Imos difference array

The canonical range-update sweep: N interval demands become a pointwise curve by recording only the two endpoints of each.

Nudge

Add P_i at index S_i and subtract P_i at index T_i in one array over the time axis 0..2*10^5, then accumulate left to right. The answer is No exactly when that running total ever exceeds W; note the interval is half-open, so the subtraction goes at T_i, not T_i+1.

08
Longest X ABC 229 D 745
Prefix counts of a character

Counting occurrences of a character is itself a prefix sum, which reduces a window's feasibility test to one comparison.

Nudge

Let d[i] be the number of . among the first i characters. The window (l, r] can be made all X when d[r] - d[l] <= K. Since d is non-decreasing, sweep r and only ever advance l — or binary search the smallest valid l for each r.

09
Dice Sum ABC 248 C 787
Sliding-window DP sums

The first DP rung: a transition that sums over a contiguous block of predecessors is exactly one prefix-sum lookup.

Nudge

dp[i][s] counts length-i sequences with sum s, and dp[i][s] = dp[i-1][s-M] + ... + dp[i-1][s-1] — a fixed-width window over the previous row. Prefix-sum each row once so every state costs O(1) instead of O(M). Work mod 998244353.

10

Cumulative DP over values

When the DP is indexed by a value and the transition sums everything at most that value, the prefix sum runs along the value axis rather than the position axis.

Nudge

Let dp[i][v] be the number of valid prefixes with c_i = v. Then dp[i][v] is the sum of dp[i-1][u] for all u <= v, restricted to a_i <= v <= b_i. Replace each finished row by its running total over v and the transition is a single read.

Prefixes of things that are not values

1038 - 1757

Accumulate a prefix sum, an XOR, a digit place, a probability, or a residue class — whatever the problem's algebra actually needs. The rungs here are about recognising which quantity telescopes.

11

Prefix of prefix sums

Grouping all subarrays by length makes the inner sum a difference of prefix-sums-of-prefix-sums — the array gets accumulated twice.

Nudge

Group by length L: the contribution is inv(L) times sum over r of (P[r] - P[r-L]) where P is the prefix sum. Accumulate P itself into Q, and that whole inner sum is Q[N] - Q[L-1] - Q[N-L]. Precompute the modular inverses of 1..N in one pass.

Prefix XOR per bit

XOR telescopes exactly like addition, and once you split by bit the double sum becomes a count of unequal pairs.

Nudge

With X_i the XOR of the first i elements, the XOR of A_i..A_j is X_j ^ X_{i-1}. For each bit, count how many of X_0..X_N have it set; the pairs contributing are (set count)*(unset count). That counts all subarrays, so subtract the length-1 ones, which are just the A_i.

Digit place contributions

When each element contributes with a positional weight, accumulate the weights per place and normalise the carries once at the end.

Nudge

The digit at 1-indexed position i has i possible left endpoints, and for right endpoint j it sits in place 10^(j-i). So the total coefficient of 10^p is the sum of i*S_i over i <= N-p — one prefix sum of i*S_i. Build that array of place totals, then carry once; the answer has up to ~2*10^5 digits.

Nudge

dp[i][j] is the sum of dp over every reachable cell to the left, above, and up-left. Carry one accumulator per direction: each equals the previous cell's accumulator in that direction plus that cell's dp, and resets to 0 the moment the predecessor is a wall. Modulo 10^9+7, O(HW).

A backward expectation DP whose transition averages a contiguous block of future states — plus the self-reference you clear algebraically first.

E[i] = 1 + (1/(A_i+1)) * (E[i] + E[i+1] + ... + E[i+A_i]). The die can roll 0, so E[i] appears on both sides; solve to get E[i] = (A_i + 1 + S)/A_i with S = E[i+1]+...+E[i+A_i]. Fill right to left keeping a suffix sum of E so each S is one subtraction, mod 998244353.

The invariant of a K-wide range operation lives in residue classes mod K, so you keep K separate accumulated arrays.

Nudge

One operation adds the same c to exactly one element of each residue class mod K. So the differences between the class sums never change, and the subarray is good precisely when its K class sums are all equal. Precompute one prefix-sum array per residue and each query is K <= 10 lookups.

Order and Feasibility

202 - 677

Sorting as a first move, and the habit of turning 'what is the best answer' into 'is this answer achievable'. By the end of this tier the binary-search-on-the-answer template should feel mechanical.

01
Doubled ABC 196 C 202
Monotone generator search

When the answer space is huge but every valid object is generated by a small parameter, search the parameter instead.

Nudge

Every valid x is some k written twice, i.e. k * 10^d + k where d is the number of digits of k. That value strictly increases with k, so you only need to count the k up to about 10^6 whose doubled form is at most N.

02

Sorted multiset simulation

Keeping a collection sorted under updates lets you read off the current min and max in O(log N) while a process runs.

Nudge

Simulate it literally with an ordered multiset: take the current max and min, replace the max with max mod min, and delete it if it hits 0. Each step either removes an element or drops that element strictly below the current minimum, which is the same Euclidean-style shrinkage that bounds gcd, so the total number of steps stays small.

03
Many Oranges ABC 195 B 483
Feasibility interval

Writing 'is this count achievable' as a two-sided inequality is the first half of every binary search on the answer.

Nudge

Work in grams, so the target is 1000 * W. A count of n oranges can hit it exactly if and only if n * A <= 1000 * W <= n * B, since the weights are real numbers in the range. The feasible n form one contiguous block, so scan or bound it directly.

04

Binary search on the answer

The core template: guess the answer, write a check that is monotone in the guess, and let a greedy do the verifying.

Nudge

For a fixed width W, the greedy line break (put the next word on the current line if it fits, otherwise start a new line) uses the fewest lines possible, and that line count is non-increasing in W. So binary search W between max L_i and sum L_i + N - 1.

05

Maximize the minimum

'Make the smallest element as large as possible' is always a binary search whose check is a sum of independent per-element costs.

Nudge

Binary search the target X. Index i needs ceil((X - A_i) / i) operations when A_i < X and none otherwise, so the total cost is non-decreasing in X; compare it against K. Cap or short-circuit the running sum, since it can overflow long before it stops being a valid answer.

914 - 1282

Prefix sums + pair counting

Counting pairs of prefix sums that satisfy a relation is the shape every inversion-style count reduces to.

Nudge

Fix the top and bottom row of the rectangle, which is only O(H^2) choices, and collapse that horizontal strip into a 1-D array of column sums. Counting subarrays of that array with sum exactly K is then the classic prefix-sum frequency count.

Inversions via a Fenwick tree

Counting index pairs i < j whose values compare a given way is exactly an inversion count, and a BIT over values does it in O(N log N).

Score A as +1, B as -1 and C as 0, and take prefix sums P_0 .. P_N. The substring (l, r] qualifies exactly when P_r > P_l, so the answer is the number of pairs l < r with P_l < P_r — sweep r and query a Fenwick tree indexed by the shifted prefix value, the same sweep that counts inversions.

Top-k merge on DSU

When only the top few order statistics are ever queried, carry a truncated sorted list per component instead of the whole set.

Sort by rounding remainder

An exchange argument: once you write down each item's cost of being rounded up, sorting by that cost makes the optimal choice obvious.

Nudge

Write A_i * M = b_i * N + r_i with b_i = floor(A_i * M / N). Setting B_i = b_i costs r_i in the numerator |B_i * N - A_i * M| and setting B_i = b_i + 1 costs N - r_i, and you must round exactly M - sum(b_i) of them up. To minimise the maximum cost, round up the ones with the largest r_i.

Canonicalising a comparison key so equal things sort together is what turns an O(N^2) set of objects into groups you can count within.

Take all O(N^2) segments and reduce each direction (dx, dy) by its gcd with a fixed sign convention, then group by that key: two segments in the same group that are not on the same line give a trapezoid. Then fix the double counting — a parallelogram has two pairs of parallel sides, and parallelograms are exactly the segment pairs sharing a midpoint.

Searching the Answer Space

1479 - 1815

Binary search stops being a library call. The thing you guess is a value, a rank, a median, or a ratio, and each feasibility check is a small algorithm of its own.

11
Rotated Inversions ABC 396 F 1479
Incremental inversion updates

Recomputing an inversion count M times is too slow; find the O(1)-per-affected-element delta between consecutive states instead.

Nudge

Compute the k = 0 inversion count with a Fenwick tree, then move incrementally. Raising k by one only wraps the elements whose value is M - 1 - k, from the largest value to the smallest. Such an element stops inverting with everything after it and starts inverting with everything before it, so its contribution changes by (elements before it) - (elements after it), ignoring the others that share its value.

12

Heap over sorted triples

K-th largest over a product of sorted lists is a best-first expansion, not an enumeration of the product.

Nudge

All values are positive, so A_i * B_j + B_j * C_k + C_k * A_i is increasing in each of the three chosen values separately. Sort A, B, C descending and run a best-first search: push index triple (0,0,0) into a max-heap, and on popping (i, j, k) push (i+1, j, k), (i, j+1, k) and (i, j, k+1) with deduplication. 13

Binary search per query

A binary search per element is affordable when the feasibility check is itself O(log N) off a sorted prefix-sum table built once.

Nudge

For each candidate, binary search the extra votes X — safety is monotone in X. For the check, the opponents worth pushing past A_i + X are the ones already closest to it, so sort A once with prefix sums and use them to compute how many opponents the remaining K - sum(A) - X votes can lift strictly above that total. The candidate is safe when that number is at most M - 1.

14

A median condition becomes a plain counting condition the moment you threshold the values to 0 and 1.

Nudge

Binary search the answer x over the distinct values. Mark each cell 1 if A[i][j] > x and 0 otherwise, take 2-D prefix sums, and ask whether some K by K window contains at most floor(K*K / 2) ones — that is exactly 'this window's median is at most x', and it is monotone in x.

15

Binary search on a ratio

A fractional objective (sum over sum) becomes a linear one once you binary search the ratio and subtract it out.

Nudge

Binary search the ratio lambda and reweight edge i to b_i - lambda * c_i. A path with ratio at least lambda exists exactly when the maximum-weight 1 to N path under those weights is at least 0. Every edge runs from a smaller vertex to a larger one, so that maximum is one DP in increasing vertex order.

16

The inversion table is a bijective encoding of a permutation, and one adjacent swap moves exactly one of its entries by exactly one.

Nudge

Encode a permutation by v_i = #{ j < i : P_j > P_i }; this table determines the permutation uniquely, and swapping an adjacent out-of-order pair lowers exactly one v_i by 1. 18

Minimum adjacent swaps is an inversion count; once you say that out loud, the remaining choice is a bitmask DP.

Split the cost in two: sorting the chosen K elements among themselves, which is the inversion count of the chosen value sequence, plus pulling them together. Sweep positions with a DP over the bitmask S of which of 1..K are already chosen: picking value v adds the number of already-chosen values greater than v, and skipping an element adds min(popcount(S), K - popcount(S)), because it gets shifted past whichever side is smaller.

20

Parametric search reaches problems no greedy check could, once you accept that the check for a guessed answer may be an entire flow computation.

Nudge

Digits non-decreasing from the most significant end means the number is a sum of repunits 1, 11, 111, ..., and because the leading digit is at most 9, at most nine of them. So search over (how many repunits used, 0..9) x (residue mod N) using repunit residues mod N; minimising the value means preferring fewer and shorter repunits.

07
Integer Division ABC 288 F 2024
Split positions along digits

A DP that walks the digit string where the transition weight is itself built digit by digit, letting a quadratic sum collapse to a rolling accumulator.

Nudge

Let dp[i] be the sum of f(S) over all ways to cut the first i digits. The honest transition sums dp[j] * value(j+1..i) over every j, which is quadratic - but value(j+1..i) = 10*value(j+1..i-1) + d_i, so keep that whole sum as one rolling quantity: S_i = 10*S_{i-1} + d_i * (dp[0] + ... + dp[i-1]).

Bigger states, other bases, two bounds

2024 - 2197

The state stops being a small integer range: a digit product, three simultaneous tight flags in binary, a set of distinct hexadecimal digits. Each one forces a different trick for keeping the state space finite.

08
Digit Products ABC 208 E 2024
Digit product as state

When the state is an unbounded value, count the values that are actually reachable - here only 2,3,5,7-smooth numbers - and memoize on the value itself.

Nudge

The state is the product of the digits chosen so far. It looks unbounded, but every reachable product is a product of digits 1..9, so the reachable set is small enough to key a hash map on. Handle shorter numbers and the leading-zero prefix separately, or a leading zero will wipe the product to 0.

09
Nim ABC 317 F 2072
Three tight flags in base 2

Digit DP against several upper bounds at once: one tight flag per number, all sweeping the same bit positions.

Nudge

X1 xor X2 xor X3 = 0 means the three bits at each position sum to an even number, so only 4 of the 8 bit-triples are legal. Sweep bits from the top carrying three tight-vs-N flags and three residues updated as r_i = (2*r_i + bit) mod A_i - that is 8 * 10 * 10 * 10 states per bit.

10
Digits Paradise in Hexadecimal ABC 194 F 2197
Distinct digits in base 16

The same machinery in base 16, with a set-valued state compressed to its size and the free suffix finished off by combinatorics.

Nudge

The natural state is the 16-bit mask of digits seen, which is far too big - but only its popcount matters. Once a position goes free with j distinct digits already used, the number of completions depends only on j, the digits remaining, and K, so precompute that table. 'No leading zeros' is its own state.

Digits of a whole collection, and carries as state

2340 - 2664

The final tier stops sweeping a single number. Here the digit positions belong to a whole array or to every term of a huge sum, and the carries between positions become the thing the DP is actually about.

11
Count Strictly Increasing Sequences ABC 292 G 2340
Interval DP over digit positions

Comparing many numbers digit by digit at once: equal prefixes form blocks, and each digit position is a chance to split a block.

Nudge

All strings have length M, so numeric order is plain lexicographic order. Strings still equal on the first p digits form a contiguous block, and at position p that block must break into consecutive groups whose digits strictly increase. That gives an interval DP over (l, r, position, digit).

12
Xor Sum 5 ARC 156 D 2568
Carry-free binary parity

Kummer's theorem says a multinomial coefficient is odd exactly when its parts add without binary carries - which turns an XOR over N^K objects into a base-2 DP with a carry.

Nudge

Group the N^K sequences by their count vector (c_1..c_N); the multiplicity is a multinomial coefficient, and it is odd exactly when the c_i sum to K with no carries in binary - i.e. each set bit of K is handed to exactly one index. Now XOR the sums sum 2^b * A_{i_b} with a DP over bit positions carrying the addition carry, tracking only parities of counts.

13
Sum of Sum of Digits ARC 153 D 2664
Counting carries per digit

The identity relating digit sums to carry counts converts a digit-sum objective into a carry-maximisation that a bottom-up digit DP can drive.

Nudge

Use f(a) + f(x) - f(a+x) = 9 * (number of carries when adding a and x), so minimising the total digit sum is maximising the total carry count. A carry into position j happens exactly when (A_i mod 10^j) + (x mod 10^j) >= 10^j, so build x digit by digit from the bottom and count the qualifying A_i by binary search on sorted suffixes.

Foundations

704 – 1549

One DFS, one value per subtree. The goal here is to stop thinking about the tree and start thinking about what a child hands back to its parent.

01
Erase Leaves ABC 333 D 704
Subtree sizes

The single most reused primitive: root the tree, compute size[v] in one post-order pass.

Nudge

Root at vertex 1. Each neighbour of the root heads an independent subtree, and you must delete every one of them except the largest.

02
Minimize Sum of Distances ABC 348 E 1347
Rerooting · sum

The canonical introduction to rerooting: compute the answer at the root, then slide it to every other vertex in O(1) per edge.

Nudge

Get f(1) = sum of C_i * dist(1,i) with one DFS. Moving the root across edge (u,v) changes it by total weight - 2 * (subtree weight of v).

03
Path Decomposition of a Tree ABC 397 E 1484
Returned state

A child hands back more than a number — here it hands back how many loose path-ends it still has. Feasibility DP rather than optimisation.

Nudge

Any vertex with three or more children still needing to extend a path is immediately impossible. Track the count of dangling ends and close them greedily as you unwind.

04
Red and Blue Tree ABC 222 E 1491
Edge weights to knapsack

Reducing a tree problem to a sequence problem. Half the difficulty of tree DP is spotting when the tree stops mattering.

Nudge

Walk the given route once and count how many times each edge is traversed. What remains is a subset-sum over those counts hitting a fixed target.

05
Alkane ABC 394 F 1549
Best-k children

Merging children is not always a knapsack — often you just sort their values and take the top few. Learn to recognise that shape.

Nudge

Every internal vertex needs exactly four incident edges, so dp[v] keeps the best chain downward and you sum the three largest positive child contributions.

Core patterns

1819 – 2055

The workhorses: counting with subtree sizes, rerooting a non-trivial state, and the tree knapsack. Almost every harder problem is one of these wearing a costume.

06
Avoid Straight Line ABC 312 G 1819
Counting by complement

Counting triples on a tree by fixing the meeting vertex — and by counting the bad cases instead of the good ones.

Nudge

Total triples minus the collinear ones. For each vertex, the paths through it split the rest of the tree into its child subtrees plus everything above it.

07
Expensive Expense ABC 222 F 1934
Rerooting · max

The same rerooting machinery, but max instead of sum — so you need the best and second-best child in order to exclude the one you came from.

Nudge

Keep the top two downward values at each vertex; when descending into child c, pass down the best value that is not c's own.

08
Select Edges ABC 259 F 1961
dp[v][0/1] + greedy merge

Two states per vertex — edge to parent used or not — with a degree cap that turns the merge into a sort-and-take.

Nudge

dp[v][0/1] = best weight in v's subtree. For each child, taking its edge gains w + dp[c][0] - dp[c][1]; keep the positive gains, sort, take as many as the degree limit allows.

09
Components ABC 287 F 2034
Tree knapsack

The O(n^2) subtree knapsack, and the amortisation argument that proves it is quadratic and not cubic. Non-negotiable to know.

Nudge

dp[v][k][0/1] = ways to get k components in v's subtree, with v chosen or not. Merge children one at a time, looping only up to the sizes already accumulated.

10
As far as possible ABC 369 G 2055
Long-path decomposition

Decompose the tree into vertex-disjoint downward chains; answering for every K at once falls out of sorting the chain lengths.

Nudge

Each vertex keeps its deepest downward path and the leftover branches become separate chains. Sort all chain lengths descending — the answer for K is a prefix sum.

An outer loop around the DP

2217 – 2437

The DP is no longer the whole solution. Here it sits inside a binary search, a game-theoretic argument, a rerooting of a two-state DP, or a compressed tree.

11
Game on Tree 2 ABC 218 G 2217
Minimax on tree

Game DP where the optimising player alternates by depth, plus maintaining a running median down the DFS path.

Nudge

Leaves are terminal; internal vertices take max or min of their children by parity. Keep the median of the root-to-current path with two heaps, pushing on entry and popping on exit.

12
Game on Tree 3 ABC 246 G 2313
Binary search + tree DP

Parametric search: guess the answer X, rewrite the problem as a boolean, and let a much simpler DP decide it.

Nudge

Fix X and mark vertices with value >= X as dangerous. dp[v] = how many dangerous vertices in v's subtree cannot be erased in time; monotone in X, so binary search.

13
Vertex Deletion ABC 223 G 2351
Rerooting a matching DP

Rerooting where the state is itself a DP (maximum matching), not just a number. The real test of whether you understand rerooting.

Nudge

dp[v][0/1] = matching size in v's subtree with v unmatched / matched. A vertex is removable iff the whole tree keeps the same maximum matching without it — reroot to test all n at once.

14
Tree Patrolling ABC 207 F 2398
Three-state counting

The classic dominating-set state set — chosen / covered by a child / not yet covered — used for counting rather than minimising.

Nudge

dp[v][0] = v not covered, [1] = v covered by a child's guard, [2] = guard on v. Merge children as a convolution over the number of covered vertices.

15
Leaf Color ABC 340 G 2401
Auxiliary (virtual) tree

When a DP has to run once per colour, build the compressed tree over just that colour's vertices. Total size stays O(n log n).

Nudge

Sort a colour's vertices by DFS order, add pairwise LCAs, rebuild the edges with a stack. Then count connected subtrees whose leaf set is exactly that colour.

16
Zigzag Tree ARC 130 D 2437
Prefix-sum optimised merge

A naive child merge is quadratic per vertex here. Rewriting it as cumulative sums is the standard rescue for rank-indexed tree DP.

Nudge

dp[v][i] = ways in which v is the i-th smallest among v and its used children. Merging with binomials plus prefix sums keeps the whole thing quadratic overall.

Advanced machinery

2455 – 2920

Named techniques worth reusing for years: Steiner trees, inclusion–exclusion over a knapsack, multi-dimensional traversal states, and a DP that has to survive updates.

17
Last Major City ABC 364 G 2455
Steiner tree DP

Bitmask over terminals times vertices, with the two transitions — subset split and edge relax — that define the Steiner tree DP.

Nudge

dp[S][v] = cheapest tree connecting terminal set S and containing v. Split S into two halves at v, then relax over edges with Dijkstra for each fixed S.

18
Directed Tree ARC 121 E 2645
Knapsack + inclusion–exclusion

Counting permutations with forbidden positions: count arrangements with at least k bad pairs via a tree knapsack, then alternate signs.

Nudge

f[k] = ways to choose k disjoint ancestor–descendant pairs, which is a subtree knapsack. The answer is the alternating sum of f[k] * (n-k)!.

19
Portable Gate ARC 179 D 2717
Return-or-not states

Traversal DP where the state carries both a budget and whether you come back to the vertex. The dimension people forget to add.

Nudge

dp[v][k][0/1] over v's subtree, k = gate uses, last flag = whether the walk returns to v. Merge children like a knapsack, allowing exactly one non-returning branch.

20
Hash on Tree ABC 351 G 2920
Dynamic tree DP

The DP has to survive point updates. Express each vertex's transition as an affine map and hang it off a heavy-light decomposition.

Nudge

dp[v] = A[v] + X[v] * (product of dp over children). Linearise along heavy paths, keep the light-child products aside, and put a segment tree of composed affine maps on each path.

Graphs: Traversal, DSU, MST & Shortest Paths

20 problems

Twenty rungs that build graph technique from the ground up: reachability and connected components, then search on graphs the statement never draws, then Dijkstra, DSU and MST used as tools rather than templates. The climb ends with problems where the graph is the answer to a modelling question - cycle spaces, difference constraints, functional graphs and counting over forests. Picked from the 1238 problems tagged on AtCoder Categories — Graph Algorithms. Theory and worked examples for this technique live on the Graph Algorithms — Shortest Paths section.

Walking the graph you are given

249 - 862

The graph is handed to you, or is one rewrite away. These rungs drill the four primitives everything else is built from: reachability, component counting, BFS distance, and a first weighted shortest path.

01
Straw Millionaire ABC 454 C 249
Directed reachability

That 'what can I end up with' is almost always the reachable set of a directed graph, not a simulation.

Nudge

Each friend is a directed edge from item A_i to item B_i. Nothing about the order of trades matters - run one BFS or DFS from item 1 and count what you can reach.

02
Make it Forest ABC 399 C 312
DSU component count

The vertex/edge/component identity for forests, and DSU as the cheapest way to count components.

Nudge

A forest on N vertices with k connected components has exactly N - k edges, so you must delete M - (N - k). Union-find over the M edges just to get k.

03
Add One Edge ABC 309 D 621
BFS from two roots

Decomposing a path through a chosen edge into two independent BFS distances you can maximise separately.

Nudge

If you add edge (u, v) the distance becomes d(1,u) + 1 + d(v, N1+N2). Since u and v are free, run one BFS from vertex 1 and one from vertex N1+N2 and add the two largest distances, plus one.

04
Super Takahashi Bros. ABC 340 D 784
Dijkstra on stages

Recognising a plain weighted shortest path inside a statement written as a sequence of choices.

Nudge

Stage i is a node with exactly two outgoing edges: cost A_i to stage i+1 and cost B_i to stage X_i. That is 2N weighted edges - Dijkstra from 1 to N. Greedily taking the cheaper option fails because a jump can skip many stages.

05
Multiply and Rotate ABC 235 D 862
BFS over implicit states

That the vertex set can be a range of values rather than a given list, and unit-cost operations make it a BFS.

Nudge

Every integer below 10^6 is a vertex; multiply-by-a and rotate are unit-cost edges. BFS from 1 and prune any value that reaches 10^6 or more - the reachable state space stays small enough to visit each state once.

Cycles, parity and edge order

1029 - 1304

Now the structure of the graph is the point: whether a cycle is odd, where the unique cycle of a functional graph sits, and what changes when you process edges in sorted order instead of arbitrary order.

06
Odd Cycle ABC 472 E 1029
Bipartite check to odd cycle

That two-colouring is not just a yes/no test - the failing edge plus its tree path is a constructive witness.

Nudge

Two-colour the graph with a DFS or BFS tree. An odd cycle exists exactly when some edge joins two vertices of the same colour; take that edge together with the tree path between its endpoints up to their meeting vertex, and the resulting simple cycle has odd length.

07
Routing ARC 177 C 1055
0-1 BFS on a grid

Shortest path when every edge costs 0 or 1, using a deque instead of a heap.

Nudge

Stepping onto a cell whose colour already suits your route costs 0, otherwise it costs 1 (repaint it purple). That is 0-1 BFS with a deque: push 0-cost moves to the front, 1-cost moves to the back. Solve the red route and the blue route independently and add the two answers.

08
Shortest Path Queries 2 ABC 208 D 1190
Floyd-Warshall by k

What the outer loop of Floyd-Warshall actually means: the set of permitted intermediate vertices.

Nudge

After the k-th iteration of Floyd-Warshall's outer loop, the table holds exactly f(s,t,k) - the shortest paths allowed to pass only through vertices 1..k. So run the standard triple loop and add the whole table into the running total at the end of every outer step.

09
Takahashi's Anguish ABC 256 E 1224
Functional graph cycles

That one out-edge per vertex means every component holds exactly one cycle, and only cycles obstruct a topological order.

Nudge

Each person i forces the constraint 'i before X_i', so the graph i -> X_i has out-degree one everywhere: a functional graph whose every component has a single cycle. Constraints off the cycles can always be satisfied for free; on each cycle exactly one must break, and you pay the minimum C_i on that cycle.

10
MST + 1 ABC 235 E 1304
MST cycle property

The cycle property of minimum spanning trees, and answering edge queries offline by folding them into Kruskal.

Nudge

A candidate edge (u, v, w) belongs to the MST exactly when w is smaller than the largest edge on the current MST path between u and v. Sort the real edges and the queries together by weight and run Kruskal: a query is Yes iff u and v are still in different DSU components when it comes up.

Building the graph the problem hides

1476 - 1878

The hard part stops being the algorithm and becomes the modelling: which vertices, which edges, which direction, and what extra nodes you have to invent so a textbook routine applies.

11
Last Train ABC 342 E 1476
Reverse Dijkstra on times

Running Dijkstra backwards with a max-heap when the quantity to optimise is a latest time rather than an earliest one.

Nudge

Let f(B) be the latest moment you may still be standing at station B. Work backwards from station N with a max-heap over the reversed graph: for a train A -> B, the best usable departure is the largest l + j*d with j < k and l + j*d + c <= f(B), which is one division to compute - relax A with it.

12
GCD Maximum Spanning Tree ABC 469 F 1567
Divisor-sieve spanning tree

Running Kruskal over candidate weights rather than over edges, when the edge set is a dense implicit clique.

Nudge

Never enumerate the N^2 pairs. Sweep d from 10^6 down to 1; all indices whose A_i is a multiple of d are pairwise joined by an edge of weight at least d, so union them all in DSU and charge d for each union that actually merges. The harmonic sum of multiples keeps this near 10^6 log.

13
Rush Hour 2 ABC 204 E 1710
Time-dependent Dijkstra

That Dijkstra survives edge costs that depend on the current time, as long as arrival time is still monotone and each relaxation can be minimised in O(1).

Nudge

Waiting can pay: relaxing an edge means minimising t + C + floor(D/(t+1)) over departure times t at or after your arrival. That function is convex in t with its minimum near sqrt(D) - 1, so test only the arrival time itself and a couple of integers around sqrt(D) - 1, then run Dijkstra unchanged.

14
Big Banned Grid ABC 413 G 1723
Dual blocking barrier

Searching the obstacles instead of the cells - the planar duality between 'a path exists' and 'no barrier exists'.

Nudge

The grid has up to 4*10^10 cells but only 2*10^5 obstacles, so search those. A path from (1,1) to (H,W) is blocked exactly when obstacles, adjacent in any of the 8 directions, chain the top-right boundary (row 1 or column W) to the bottom-left boundary (column 1 or row H). Hash the obstacle coordinates, union 8-neighbours, and add one virtual node per boundary side.

15
Range Connect MST ABC 364 F 1878
Auxiliary-node range MST

Handling an MST over an implicit range-to-vertex edge set by sorting operations and merging each consecutive pair only once.

Nudge

Sort the Q operations by C ascending and run Kruskal. Operation i always spends C_i once to attach vertex N+i to the range. Beyond that, every pair of consecutive vertices inside [L_i, R_i] still in different components costs another C_i to merge - keep a 'next unmerged index' DSU so the total number of merges over all operations is O(N).

Graph structure as algebra

2091 - 2758

The final tier treats a graph as an algebraic object: paths as potentials, cycles as a linear space, constraints as edges, and forests as things to count. Each rung needs a correct model before any code helps.

16
Minimum Reachable City ABC 295 G 2091
DSU collapsing tree paths

Amortised path collapsing in a DSU: each vertex is absorbed into an ancestor blob at most once over the whole run.

Nudge

G_S is a rooted tree with edges parent -> child, and a type-1 edge u -> v is only offered when v is an ancestor of u, so it makes the whole tree path from u up to v mutually reachable. Keep a DSU whose representative is the shallowest vertex of each blob; to add the edge, jump from u to the parent of its representative repeatedly until you land in v's blob, merging as you go. Since ancestors carry smaller labels, a type-2 answer is just the representative.

17
Minimum XOR Walk ABC 451 G 2221
XOR cycle space basis

That walk values in a XOR-weighted graph are a coset: a spanning-tree potential plus the linear span of the fundamental cycles.

Nudge

Root a spanning tree and set d[v] to the XOR of edges from the root to v. Every walk from x to y has value d[x] xor d[y] xor c where c ranges over the XOR span of the fundamental cycles, and every such c is achievable. Build that linear basis, reduce each d[v] by it, and count pairs whose reduced XOR is at most K with a binary trie.

18
01 Balanced AGC 056 C 2481
Difference constraints

Turning a system of inequalities on prefix sums into a graph, so that a shortest-path run produces the extremal feasible assignment.

Nudge

Let x_i be the number of ones in the first i characters. Adjacent positions force 0 <= x_i - x_{i-1} <= 1, and each condition forces x_R - x_{L-1} = (R-L+1)/2, i.e. two opposite inequalities. That is a difference-constraint system, so its extremal solution is a shortest-path computation over N+1 nodes - and every constraint edge has weight 0 or 1, so 0-1 BFS handles N up to 10^6.

19
Return to 1 ABC 306 G 2563
GCD of cycle lengths

That the set of closed-walk lengths through a vertex is generated by a single gcd, computable from DFS potentials inside one strongly connected component.

Nudge

Only the strongly connected component containing vertex 1 matters. Give each of its vertices a DFS depth pot[v], and let g be the gcd of pot[u] + 1 - pot[v] over all edges inside that component - g generates every closed-walk length through vertex 1. The answer is Yes exactly when g divides 10^(10^100), that is, when g has no prime factor other than 2 and 5.

20
We Love Forest ABC 253 Ex 2758
Subset DP over forests

Counting labelled forests over a fixed edge list with subset DP, and converting an ordered random process into a count of edge sets.

Nudge

Picking the same index twice creates a multi-edge, which is a cycle, so the K picks must be K distinct edges forming a forest: the probability is K! * (number of K-edge forests) / M^K. With N at most 14, count forests by subset DP - first spanning trees of each vertex subset using only the given edges, then glue components together, always fixing the lowest-numbered remaining vertex so each forest is counted once.

Trees: Diameter, LCA & Path Queries

16 problems

This ladder is about tree shape rather than tree DP: rooting, depth, ancestors, and the paths between vertices. It opens on graphs you have to root yourself — a parent function, a DFS tree, a functional graph — then meets trees hiding inside arrays and near-trees carrying one extra edge, before installing the standard toolkit: the Euler tour that turns a subtree into an interval, root-to-node prefixes that collapse a path aggregate into a two-term formula, and binary lifting for LCA and k-th ancestor. The last tier is where one root pass stops being enough — centroid decomposition, an undoable union-find carried down the DFS, and queries answered by cutting a path at its midpoint. Picked from the 330 problems tagged on AtCoder Categories — Tree Algorithms. Theory and worked examples for this technique live on the Trees — Tree Diameter section.

Root it and read off depth

839 - 1238

Every rung here is a graph you have to root yourself. The habits to take away: a parent function defines a tree even when nobody draws one, DFS depth behaves better than BFS depth, and a doubling table turns "follow the parent T times" into O(log T).

01
X to Y ABC 465 D 839
Implicit K-ary tree

A parent function is enough to define a tree, and the shortest edit sequence between two values is just the tree distance.

Nudge

Each value y has exactly one parent, floor(y/K), so all reachable values form a tree rooted at 0 and every operation is one edge of it. Depth is at most about 60 because K >= 2, so lift the deeper of X and Y until the depths match, then step both up in lockstep until they collide.

02
Ascending Labels ARC 224 C 969
DFS tree depths

The DFS tree of an undirected graph has no cross edges, which is exactly the property that makes DFS depth a valid label where BFS depth is not.

Nudge

BFS levels fail: a vertex can have several neighbours one level up. Run a DFS from vertex 1 and set A_v to the DFS depth — every non-tree edge of an undirected DFS tree joins an ancestor to a descendant, and the only ancestor sitting at depth A_v - 1 is the parent, so the "exactly one" condition is automatic.

03
Heavy Buckets ABC 438 E 1226
Doubling with path sums

Binary lifting is not only for ancestors — carry an aggregate in the table alongside the destination and you can sum a path of length T in O(log T).

Nudge

Bucket B is held by person B, then by A_B, then by A[A_B], and each holder adds its own number, so the answer is the sum of the first T iterates of A starting at B. Build two doubling tables side by side: where a vertex lands after 2^j steps, and the total added over those 2^j steps.

04
Tree Game ABC 398 E 1238
Depth parity 2-coloring

A tree's bipartition is just depth parity, and when no move can ever block another the whole game reduces to counting the moves.

Nudge

Forbidding odd cycles means keeping the graph bipartite, and the tree already fixes the 2-colouring by depth parity — an edge is legal exactly when its endpoints have different parity, and adding one never invalidates another. So the number of moves is fixed at a*b - (N-1) for colour class sizes a and b; its parity alone decides whether to go first, and then you may play any remaining legal pair.

Trees that arrive disguised

1385 - 1627

Objects that are not presented as trees but behave like one: a permutation split at its maximum, a graph with exactly one cycle, a functional graph, a binary tree far too large to store. The skill is spotting the tree and deciding where to root it.

05
Cat exercise ABC 435 F 1385
Cartesian tree by maximum

Recursively splitting an array at its maximum is a tree construction, and once you name it the problem becomes a walk down that tree.

Nudge

Removing the tallest tower first cuts the line at its position, and the cat then has to jump to the tallest tower of the left part or of the right part — recurse on each. That recursion is the Cartesian tree of P built on maxima; the answer is the best root-to-leaf descent where the cost of an edge is the index gap between a node and the child it moves to.

Namori cycle removal

A connected graph with one extra edge is a cycle with trees hanging off it, and labelling each vertex by its cycle root answers a whole class of queries.

Nudge

N vertices and N edges means exactly one cycle. Strip it out by repeatedly deleting degree-1 vertices, then label every vertex with the cycle vertex whose hanging tree it belongs to. The simple path from x to y is unique exactly when those two labels agree — otherwise you can round the cycle either way.

07
Packing Potatoes ABC 258 E 1545
Functional graph rho

When a state transition is a function on N states, indices as large as 10^12 collapse to a tail plus a cycle.

Nudge

One two-pointer sweep over the doubled prefix sums gives, for every start index i, how many potatoes that box takes and where the next box starts. That makes next a function on N states, so the sequence of box starts is a tail into a cycle — find the entry point and the cycle length once, then reduce every K_i into it.

08
Complete Binary Tree ABC 321 E 1627
Huge binary tree counting

With N up to 10^18 the tree is never built, but its shape is regular enough that depth-level counts are closed-form intervals.

Nudge

Euler tour, root prefix, binary lifting

1638 - 1939

The core toolkit. One DFS gives `tin`/`tout`, so a subtree becomes an interval; a root-to-node prefix turns a path aggregate into two or three lookups once you can locate the LCA.

09
Count Descendants ABC 202 E 1638
Euler tour depth buckets

The Euler tour turns "is u in U's subtree" into an interval test, so a subtree-and-depth query becomes a binary search.

Nudge

One DFS gives tin and tout, and u lies in U's subtree exactly when tin[U] <= tin[u] < tout[U]. Bucket vertices by depth, sort each bucket's tin values, and each query is two binary searches inside the bucket for depth D.

The canonical rolling-hash setup: a substring is a palindrome exactly when its forward hash equals the backward hash of the mirrored range.

Linearity of expectation on an ordering: the expected rank is a sum of pairwise comparison probabilities, and each probability depends only on the first place two strings differ.

Encoding a set of items as an integer mask and enumerating all 2^N subsets — the base move of every bitmask solution.

Reading a minimax over pairings as a parity argument on the top bit: counts decide whether any pair is forced to cross the split.

The Euclidean Spine

01

Euclidean algorithm

That the Euclidean algorithm is exactly repeated subtraction, and that turning the subtractions into one division is what makes it fast enough for 10^18.

Nudge

Subtracting the smaller from the larger over and over is A % B, done one step at a time. 1036 - 1495

The step up is counting over the divisor lattice instead of over the input. Enumerate divisors in O(sqrt n), sweep multiples in harmonic time, and use gcd to describe the shape of a process rather than just a number.

That stepping by D around a ring of N visits exactly the multiples of gcd(N,D), which turns a simulation of 10^9 steps into a closed-form index.

Running an operation set backwards when the forward branching factor is unbounded but the reverse one is not.

Orders and Lattices

2081 - 2536

16

Compressing a whole orbit of operations into two numbers - a sign and a shift living in a coset of gcd*Z - so optimisation becomes picking one residue.

Nudge

Stop searching and construct. Expand (N+1)^n by the binomial theorem modulo N^2: every term from the quadratic one onward vanishes, so it is 1 + n*N. That is 1 mod N^2 exactly when N | n, so the order is precisely N - and both numbers stay inside 10^18 because N is at most 10^9.

Direct Counts

Counts that close in a formula, a single scan, or one subtraction of overlaps. The habit to build here is describing the set you are counting precisely enough that a formula falls out.

01

That when every object you want is built from a smaller object, you should enumerate the smaller object instead of testing every candidate.

Nudge

You cannot walk 1..N when N is up to 10^12, but every valid x is exactly some k written twice. So enumerate k from 1 to 10^6, build the number k * 10^(digits of k) + k, and count the ones that are at most N.

Change the Object

1336 - 1745

Each rung here is unlocked by counting something other than what the statement names — a canonical representative, a single bit, a divisor class, a tree. The arithmetic only gets easy after the object is chosen well.

06

Canonical representative

Counting distinct results rather than distinct recipes, by pinning each result to one canonical way of producing it — here, fixing the maximum.

Nudge

Many (l, r, b) triples give the same set, so charge each set to exactly one of them. Per-bit contribution

Summing a XOR-transformed array by counting each bit's contribution across all elements instead of evaluating each element.

Nudge

Two ideas stack. First, more than one operation is pointless: after xoring everything by A_i, the available values are A_j xor A_i, and applying one of those returns A_j xor A_k — the same array you would have got from a single operation with A_k. 08

Recognising that a merge process is just a set partition, and that enumerating all partitions of 12 elements is small enough to do by brute force.

Signed Sums

2047 - 2488

Inclusion-exclusion proper: a set of forbidden conditions, a sum over which of them you deliberately violate, and an alternating sign. These rungs are about finding the right conditions to index the sum by, and keeping the sum small enough to evaluate.

11
Groups ABC 217 G 2047
Surjection inclusion-exclusion

The surjection formula: count into labelled boxes that may be empty, strip the empty ones with an alternating binomial sum, then divide by k! to unlabel.

Nudge

Residue classes mod M are the only thing that matters: within a class all people must land in different groups, and classes are otherwise independent. So with k labelled groups allowed to be empty, the count is the product over classes of the falling factorial k*(k-1)*...*(k-n_r+1). Call that F(k). Then the number of ways with all k groups non-empty is sum over j of (-1)^j * C(k,j) * F(k-j), and the answer for k is that divided by k!.

12

Deferring the multinomial coefficient: build a DP over items carrying probabilities divided by the per-item factorials, and multiply the K! back in only at the end.

Nudge

Decide, prize by prize, how many of the K draws it wins. Let dp[i][j][k] be the sum over ways to use the first i prizes, having won j distinct prizes with k draws spent, of the product of p^c / c! over those prizes. Transition by choosing c = 0 or c >= 1 copies of prize i. Because the per-prize factorials were divided out, the multinomial coefficient is restored in one shot: the answer is K! * dp[N][M][K]. 13

The derangement pattern generalised: count placements avoiding a forbidden board by an alternating sum over j forbidden matches, with the j-counts built as a polynomial product.

Nudge

Drawing without replacement means the outcome is a uniformly random permutation of the balls, and score 0 means the ball at step k never has colour G_k. Let r_j be the number of ways to pick j (step, ball) pairs that are all forbidden, with distinct steps and distinct balls; then the good permutations number sum over j of (-1)^j * r_j * (N-j)!. The forbidden board is a disjoint union of full rectangles, one per colour c of size (steps wanting c) x (balls having c), whose own generating polynomial is sum over j of C(g_c,j)*C(cnt_c,j)*j! * x^j — so r is the product of those polynomials, which you multiply together with divide-and-conquer plus NTT.

14

Inclusion-exclusion as DP

The moment inclusion-exclusion stops being a formula: there are 2^(N-1) subsets of violated constraints, so the signed sum has to be swept as a DP over the blocks they induce.

Nudge

Index the inclusion-exclusion by which of the N-1 adjacency constraints you force to be violated. Forcing a set of them cuts the sequence into blocks of positions that must all be equal, and a block [l, r] admits min(A_l..A_r) values with sign (-1)^(r-l). So dp[i] = sum over j < i of dp[j] * (-1)^(i-j-1) * min(A_{j+1..i}), with dp[0] = 1. Evaluate that in O(N) by keeping a monotonic stack of minima together with the running weighted sum over each stack segment.

15

That 'the maximum is exactly k' is almost never counted directly — you count 'the maximum is at most k' and subtract consecutive values.

Nudge

Answer(k) = AtMost(k) - AtMost(k-1), where AtMost(k) counts schedules whose every holiday run has length <= k. The forced workdays cut S into independent maximal blocks of dots, so AtMost(k) is the product over blocks of f(L, k) = the number of binary strings of length L with no run of holidays longer than k. Any block with L <= k contributes a free 2^L, so only the blocks longer than k need real work.

Counting Over Structures

2645 - 2898

The signed sum is now indexed by something with shape — subtrees, orbits, weak orderings, set partitions — and is evaluated by a DP over that structure. These are the hardest rungs and each one is a different structure to sum over.

16
Directed Tree ARC 121 E 2645
Tree IE with (N-k)!

The standard permutation-with-forbidden-positions inclusion-exclusion, where the count of k forbidden choices is itself produced by a tree knapsack.

Nudge

The bad event for index i is that a_i is a proper ancestor of i. Let g_k be the number of ways to pick k indices and give each a distinct proper-ancestor value; then the answer is sum over k of (-1)^k * g_k * (N-k)!. Build g with a tree knapsack: merge children into dp[v][j] = ways to make j such pairs inside the subtree of v, then let v itself serve as the ancestor of one unused descendant, dp[v][j+1] += dp[v][j] * (sz_v - 1 - j).

17
Reverse and Reverse ARC 218 E 2705
Rotation class counting

Collapsing an exponential space of operation sequences to the small group of end states it can reach, then counting how many sequences land on each one.

Nudge

Reversing the prefix of length i and the suffix separately is the same as reversing the whole permutation and then rotating it by N-i, and rotations commute past a second reversal — so after M operations the array is a cyclic rotation of P (M even) or of reverse(P) (M odd), and only the total rotation matters. Each step contributes a uniformly random non-zero shift, so the number of sequences with total shift 0 is ((N-1)^M + (N-1)*(-1)^M)/N and every other shift shares the rest equally. That leaves you needing the inversion count of the base array and the sum of inversion counts over all N of its rotations, both maintainable under an adjacent swap.

18

Finding the potential function a process is draining, and then maintaining a sum over all pairs under point updates by contribution rather than recomputation.

Take Phi = (1/2) * sum over i < j of |A_i - A_j| as a potential: one operation gaining x points lowers Phi by at least x, and by exactly x when you only ever move between values that are adjacent in sorted order — so the limit is just Phi. When N is tiny but values are huge, enumerate the order type instead of the values, and count how many value assignments realise each order type.

Turning 'guarantee a win against any opponent choice' into a concrete count of the adversary's best sabotage.

Bounded Nim: capping a move at k makes each pile's Grundy value `A_i mod (k+1)`, and then the question becomes which k the first player should want.

Nudge

With cap k the Grundy of a pile is A_i mod (k+1), so Alice wins for that k exactly when the XOR of A_i mod (k+1) is nonzero. If the XOR of the A_i themselves is nonzero, every k above max A works, so print -1. Otherwise note that two equal piles cancel for every modulus, so delete values appearing an even number of times; the answer is the largest remaining value minus 1, or 0 if nothing remains.

09
Unfair Sugoroku ABC 298 E 1300
Win-probability DP

The same backward evaluation as win/lose DP, but the value of a state is a probability averaged over the die instead of an OR over moves.

Nudge

The state is (Takahashi's square, Aoki's square, whose turn), at most 100 * 100 * 2 of them, and it always advances, so there is no cycle. f(a, b, T) = (1/P) * sum over i of f(min(a+i, N), b, A) with an immediate 1 when a reaches N; symmetric for Aoki with a 0. Do all arithmetic modulo 998244353 using the modular inverse of P and Q.

10
Weighted Tic-Tac-Toe ABC 349 E 1464
Memoized game search

That when the state space is small but unstructured, plain memoized minimax is the right tool — and how to fold a scoring tiebreak into a win/lose value.

Nudge

There are only 3^9 colorings of the grid, so recurse on the state (which cells are red, which are blue) and memoize. After each move check the eight lines for an immediate win; if the board fills with no line, the odd total guarantees no tie, so compare the two accumulated scores. Each player picks any move whose value says they win.

Splitting a game into independent parts

1716 - 2009

Real positions rarely arrive as a list of piles. These rungs practise finding the piles: cells at odd distance, segments between fixed cells, phases of a two-stage game, or a matching that lets the second player mirror forever.

11
Grid Game ARC 219 D 1716
Staircase Nim on a grid

Staircase Nim: when tokens move toward a sink, only the cells at odd distance are real piles, because moves onto even cells can always be mirrored away.

Nudge

Give cell (i, j) the distance d = (i-1) + (j-1) to the corner. Stones on even d are worthless — whatever the opponent pushes onto an even cell you push straight on again — so only odd d counts, and the cap K makes each such cell a bounded-Nim pile. Alice wins exactly when the XOR of A[i][j] mod (K+1) over all cells with odd i+j is nonzero.

12
Constrained Nim 2 ABC 297 G 1834
Grundy for L..R subtraction

Deriving a closed-form Grundy value for a modified subtraction game instead of tabulating it, so piles of size 1e9 are still fine.

Nudge

Tabulate the Grundy values of a single pile for small L and R and the pattern is clean: g(a) = (a mod (L + R)) / L, integer division. The intuition is that a block of L stones is one 'unit' and the L+R period comes from the opponent being able to complete any block you start. XOR the g(A_i); Taro wins on nonzero.

13
Let's Play Nim ARC 105 D 1871
Two-phase Nim parity

Analysing a game that has a forced setup phase before the real game: count the setup moves, then ask who is on move when Nim actually starts.

Nudge

Phase one is exactly N moves — every bag must be dumped once — so the parity of N fixes who opens the Nim phase, and the players are really fighting over which dish sums appear. Brute-force small cases: the second player wins whenever N is odd, and for even N whenever the multiset of a_i splits into pairs of equal values (he mirrors the first player's dumps onto the same dish). Otherwise the first player wins.

14
01 Game ARC 151 C 1940
Grundy of gap segments

Decomposing a line into independent segments cut by the fixed cells, then handling N up to 1e18 by finding the period of each segment's Grundy sequence.

Nudge

The M pre-filled squares cut the row into independent runs of empty squares, and writing a digit inside a run splits it into two smaller runs — a sum of games. A run is characterised only by its length and by its two boundary digits being absent, equal, or different (relabelling 0 and 1 is a symmetry). Brute-force the Grundy value of each of those four families for small lengths, spot the period, then XOR over the runs.

15
mod M Game ARC 148 D 2009
Mirroring pair invariant

That a draw-seeking second player wins exactly when a pairing of the objects lets him answer every move with its partner, and how to state the condition that pairing must satisfy.

Nudge

Bob's only real strategy is to fix a perfect matching of the 2N numbers and always take the partner of what Alice took. The running difference then telescopes: an equal pair contributes 0, and a pair differing by M/2 (only possible when M is even) contributes M/2. So Bob wins exactly when the numbers can be matched into equal pairs and M/2 pairs with an even number of the M/2 pairs; check that with counts per value and per residue class.

Grundy at scale, and counting games

2221 - 2741

The last tier keeps the same three ideas but pays for them with an algorithm: Grundy over O(N^2) sub-segments, a binary search over the game's value, a Dijkstra-like sweep on a graph that can cycle forever, an explicit mirroring construction, and XOR convolution to count winning starts.

16
Interval Game 2 ABC 206 F 2221
Grundy over intervals

Grundy numbers indexed by a coordinate range: choosing an interval splits the free space into two independent games, so the recursion is over sub-ranges.

Nudge

Coordinates only go to 100, so define g(l, r) as the Grundy value of the free coordinate segment [l, r). A move is any given interval [L_i, R_i) contained in it, and it leaves g(l, L_i) XOR g(R_i, r). Take the mex of those over all fitting intervals, memoize the O(100^2) states, and Alice wins when g(1, 101) is nonzero.

17
Game on Tree 3 ABC 246 G 2313
Binary search the game value

Turning an optimise-the-score game into a sequence of yes/no games by binary searching the answer and reducing the values to 0/1.

Nudge

Binary search X and mark each vertex 1 if A_i >= X, else 0; the question becomes whether Takahashi can reach a marked vertex. Aoki gets exactly one erase per Takahashi step, so let f(v) = max(0, mark(v) + sum of f over children - 1) count the surplus threats a subtree pushes upward. Takahashi achieves X exactly when the sum of f over the root's children is at least 1.

18
Game on Graph ABC 261 Ex 2531
Game Dijkstra on a graph

Solving a weighted game on a graph that may contain cycles: values are settled in increasing order like Dijkstra, with the two players finalised by different rules.

Nudge

States are (vertex, whose turn), and you relax them backwards along reversed edges in increasing order of value with a priority queue. Takahashi, who wants a finite game with small weight, is settled the moment his first successor is settled; Aoki, who prefers infinity, is settled only when the last of his successors is, so keep an out-degree counter per Aoki state. Anything never popped is INFINITY.

19
Generalized Subtraction Game ABC 278 G 2533
Symmetry strategy

The explicit mirroring construction: make the position symmetric on your first move, then copy the opponent forever — with a Grundy fallback for the case where symmetry is unreachable.

Nudge

If L < R you never need Grundy numbers: pick y in {L, L+1} with N - y even, remove that block from the middle so the two sides have equal length, then mirror every opponent move on the other side. If L == R the row is a sum of independent rows, so run the O(N^2) DP g(n) = mex over x of g(x) XOR g(n - L - x) up to N = 2000, and choose to go first exactly when g(N) is nonzero.

20
Nim Counting ABC 212 H 2741
XOR convolution counting

Counting how many starting positions are first-player wins: the Nim condition is a XOR constraint, and XOR-constrained counting is a Walsh-Hadamard transform.

Nudge

Removing 1..X stones from a heap of size X is plain Nim, so a position loses exactly when the XOR of heap sizes is 0; count those and subtract from K + K^2 + ... + K^N. Let f be the 2^16 indicator vector of A; the count of length-i sequences with XOR 0 is the 0-th entry of the inverse transform of WHT(f)^i, so transform once, sum the geometric series t + t^2 + ... + t^N pointwise (handling t = 1 separately), and transform back.

Geometry & Sweep Line

20 problems

A climb through coordinate reasoning that never needs a floating-point library: integer distances on grids and lines, gcd-normalised directions, the 45-degree rotation that decouples Manhattan and diagonal moves, and sweep lines carrying segment trees over the second axis. The progression goes from brute force over points, to sorting along one coordinate, to event sweeps with lazy range structures, and finally to rotations, convex-polygon point location and offline sweeps where the geometry collapses into pure counting. Picked from the 287 problems tagged on AtCoder Categories — Geometry. Theory and worked examples for this technique live on the Computational Geometry — Sweep Line section.

Points, Grids and Manhattan Distance

246 - 840

Small inputs where the whole job is to read the statement as integer coordinates and compute distances honestly. These rungs build the habit of asking what the coordinate actually is before reaching for a technique.

01
Humidifier 2 ABC 383 B 246
Brute force over cell pairs

Reading a grid as a set of integer points and computing Manhattan distance directly, with no geometry machinery at all.

Nudge

H and W are at most 10, so there are under 100 floor cells and fewer than 5000 placements; for each pair just scan every floor cell and count it if its Manhattan distance to either humidifier is at most D. Note a humidifier cell has distance 0 to itself, so it always counts.

02
Duodecim Ferra ABC 185 C 373
Stars and bars on cut points

A statement about physically cutting a bar is really a choice of positions on a line, so the geometry evaporates into a single binomial coefficient.

Nudge

The only freedom is which integer positions carry the 11 cuts, and there are L-1 interior positions to choose from. The answer is C(L-1, 11) — build it as a product so nothing overflows before the final value.

Reachable-sum DP on a line

Reachability along a coordinate axis as a boolean table over positions — the one-dimensional ancestor of the subset-sum step the ladder ends on.

Nudge

Keep a boolean array over positions 0..X. After jump i, position p is reachable exactly when p - a_i or p - b_i was reachable before it, so sweep the array once per jump. X is only 10000, so the whole table is tiny.

04
Teleportation ABC 226 D 706
Primitive direction vectors

Normalising an integer displacement by its gcd, so two directions can be compared exactly without ever forming a slope or a float.

Nudge

One spell (a,b) used repeatedly reaches only positive multiples of (a,b), so it serves the ordered pair (i,j) exactly when the difference (dx,dy) is such a multiple. Divide each of the N*(N-1) differences by gcd(|dx|,|dy|) and count how many distinct reduced vectors appear.

05
Snuke Panic (1D) ABC 266 D 840
Time-position DP

A speed limit on a moving point becomes a purely local transition once you index the DP by both time and coordinate.

Nudge

There are only 5 positions, so carry dp[t][x] = best total collected by time t while standing at x. Waiting is free and one time unit lets you shift by one, so between consecutive events relax dp[x] against dp[x-1] and dp[x+1] once per elapsed unit — or note that a gap of g units lets you move up to g, which with 5 slots is a handful of relaxations.

One Coordinate at a Time

982 - 1557

The pivot from brute force to structure: sort or bucket along one axis, keep an aggregate as points arrive, and repair only the part that changed. This is also where the 45-degree rotation first appears.

06
Neighbor Distance ABC 430 D 982
Ordered set neighbours

Maintaining a global aggregate over a sorted set of coordinates under insertions by touching only the entries whose value actually moved.

Nudge

Hold the occupied coordinates in an ordered set and keep a running total. Inserting a new point only changes three contributions — its predecessor's, its successor's, and its own — so subtract the two old ones and add the three new ones. Everything else is untouched.

07
Bomber ABC 176 E 1204
Row and column counts

Splitting a 2D placement into independent per-axis counts, then paying attention to the single cell where the two axes interact.

Nudge

Compute the best row count R and best column count C separately. The answer is R + C if some best-row / best-column intersection is empty, otherwise R + C - 1. There are at most M occupied cells, so if the number of (best row, best column) pairs exceeds M an empty intersection must exist; otherwise check those pairs directly.

08
Manhattan Christmas Tree 2 ABC 437 F 1332
Chebyshev rotation + segment tree

The rewrite of Manhattan distance as a maximum over four sign choices, which turns a distance query into ordinary min/max range queries.

Nudge

Store u = x + y and v = x - y per tree. Then max |x-a| + |y-b| over a set equals the largest of max(u) - (a+b), (a+b) - min(u), max(v) - (a-b), (a-b) - min(v). A segment tree over indices holding min and max of u and v handles both the point update and the range query.

09
Placing Rectangles ABC 223 E 1510
Rectangle split case analysis

An existence question over dimensions up to 1e9 that is settled by exhaustive case analysis plus ceiling division, with no search anywhere.

Nudge

If a packing exists, one full-width or full-height cut separates one rectangle from the other two, and the same argument applies recursively to the remaining strip. Try all 6 assignments of A,B,C to slots and both cut orientations, and use ceil(A/X) = (A + X - 1) / X for the minimum strip a given area needs. Areas reach 1e18, so keep everything in 64-bit integers.

10

Value sweep + BIT over index

Turning a pairwise merge-and-sum-positions quantity into a count of cross pairs, then answering that count by sweeping one coordinate while a Fenwick tree indexes the other.

Nudge

For an element a of S_i, its position after merging with S_j is its rank inside S_i plus the number of elements of S_j below it. So the answer is C(N,2) * M(M+1)/2 plus, over all N*M values in increasing order, the number of already-inserted elements whose set index is greater than a's — one Fenwick tree over set indices, swept by value.

Events and Segment Trees

1624 - 2047

The core sweep-line tier: each object becomes an interval or a rectangle of parameters, and a segment tree riding the sweep answers the aggregate. Two rungs deliberately break the pattern to show when discretising or a plain window beats a sweep.

11

Rectangle stabbing sweep

Mapping each item to the axis-aligned rectangle of parameter choices that capture it, so 'pick the best parameters' becomes 'find the most-covered point'.

Nudge

Apple (T,X) is caught exactly when S lies in [T-D+1, T] and L lies in [X-W+1, X] — an axis-aligned rectangle in the (S,L) plane. Sweep S upward with add/remove events and keep a lazy segment tree over L doing range +1 / -1 with a global maximum.

Range chmin + point query

Representing a shrinking grid frontier by two arrays of 'first blocking coordinate', updated with range-chmin and read with point queries.

Nudge

You never need the board. Keep one tree over columns giving the smallest row that already blocks that column, and one over rows giving the smallest blocking column. A query from the top at column x reads its blocking row m, flips m - 2 stones, and then blocks rows 2..m-1 at column x — a range chmin on the other tree. The symmetric query mirrors this.

Sliding-window min DP

A DP whose transition is a minimum over a fixed-width window of earlier states, made linear by a monotone deque or a segment tree.

Nudge

Let dp[i] be the best cost once child i has a present and Santa is free to continue. Walking straight from child to child telescopes into a prefix sum, so subtract that prefix from the state: dp[i] is then a minimum over the last K values of dp[j] - prefix[j] + d(house_j, home) + d(home, house_{j+1}). Prefix balance as displacement

A physical simulation on a line collapsing to the prefix sums of a +1 / -1 sequence, after which summing over all completions is pure counting.

Nudge

Read + as +1 and - as -1. The total distance travelled for a fixed string depends only on the prefix sums of that sequence — equivalently on the bracket-matching structure — not on the actual coordinates. So instead of enumerating strings, count for each prefix position and each balance value how many valid completions pass through it, which is a product of two binomial-style counts. Rotations, Polygons and Offline Sweeps

2241 - 2914

The hard tier, where the right coordinate change is the whole solution: exact integer orientation tests, Mo's ordering of query points, and the 45-degree rotation that splits coupled moves into independent one-dimensional ones.

16
Polygon and Points ABC 296 G 2241
Convex polygon point location

Point location in a strictly convex polygon by binary searching the fan of triangles from one vertex, decided entirely by integer cross products.

Nudge

Anchor at vertex 1. Because the polygon is strictly convex, the rays from it to the other vertices are already sorted by angle, so a binary search on cross-product signs finds the single wedge containing the query point; one more cross product against that wedge's outer edge separates IN, ON and OUT, plus a special check for the two boundary rays. Coordinates reach 1e9, so cross products need 64-bit integers and must never touch floating point.

17
Abs Sum ABC 384 G 2343
Mo's algorithm + BIT

Treating prefix-pair queries as points in a plane and reordering them offline so each pointer step is one Fenwick update plus one Fenwick query.

Nudge

Each query is the point (X_k, Y_k); sort them in Mo's order and move two pointers. Adding one A_i against the current B prefix contributes cnt_below * A_i - sum_below + sum_above - cnt_above * A_i, so keep two Fenwick trees over compressed B values (and two more over A for the symmetric move). Each of the O((N+K) sqrt(N)) steps costs a log.

18
Teleporting Takahashi ABC 240 G 2462
Lattice walks via rotation

Decoupling a lattice walk into independent one-dimensional walks by rotating the plane 45 degrees, turning a path count into a sum of binomial products.

Nudge

Split the N steps into those along z and the rest. For the steps left in the xy-plane, substitute u = x + y and v = x - y: each such step changes u by +-1 and v by +-1 independently, so the count for a fixed number of xy steps is a product of two central-binomial terms. Sum over the split (parity and the target pin most of it) with factorials precomputed to 1e7.

19
InterSections ABC 360 F 2563
Crossing-interval sweep

Counting properly crossing intervals — not merely overlapping ones — with a sweep over the left endpoint and a lazy range-add / range-max tree over the right endpoint.

Nudge

Interval i is crossed by [l,r] only when exactly one endpoint of each lies strictly inside the other. Fix l and sweep it upward: each interval then contributes +1 to a contiguous range of r values, and that contribution is switched on and off at two specific values of l. So it is two events on the l axis plus a range add on a lazy max segment tree over r. Remember (0,0) with value 0 is always available, and ties break by smallest l then smallest r.

20
Jumping sequence ABC 221 G 2914
45-degree rotation + bitset

The capstone rotation: four-direction moves of fixed length become two independent sign choices, reducing a 2D reachability question to two bitset subset sums with reconstruction.

Nudge

Substitute u = x + y and v = x - y. Every move changes u by +-D_i and v by +-D_i, and the two signs are independent — so you need signs summing to A+B in u and to A-B in v, separately. Each is 'choose a subset of D to be positive', i.e. subset sum for (target + sum D) / 2; check the parity, run a bitset DP, then walk the DP backwards to recover which jumps were positive and map the two sign patterns back to U/D/L/R.
