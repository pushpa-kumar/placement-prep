How to use this

Sit with a rung for 30–45 minutes before opening anything. The "nudge" under each problem is the one idea the problem turns on, not a solution — read it only when you are genuinely stuck, and read the editorial after you have solved it either way. If a rung takes more than two sittings, drop back and do a second problem in the same model before continuing.

Tree DP

20 problems

Twenty problems out of the 102 tagged Tree DP, from 704 to 2920. The progression is deliberate: one DFS returning one number, then a returned state, then rerooting, then the knapsack merge, then a DP with something wrapped around it, and finally the named machinery (Steiner trees, virtual trees, dynamic tree DP) that shows up in ARC/AGC. Picked from the 102 problems tagged on AtCoder Categories — Tree DP. Theory and worked examples for this technique live on the Dynamic Programming — Tree DP section.

Foundations

704 – 1549

One DFS, one value per subtree. The goal here is to stop thinking about the tree and start thinking about what a child hands back to its parent.

01
Erase Leaves ABC 333 D 704
Subtree sizes

The single most reused primitive: root the tree, compute size[v] in one post-order pass.

Nudge

Root at vertex 1. Each neighbour of the root heads an independent subtree, and you must delete every one of them except the largest.

02
Minimize Sum of Distances ABC 348 E 1347
Rerooting · sum

The canonical introduction to rerooting: compute the answer at the root, then slide it to every other vertex in O(1) per edge.

Nudge

Get f(1) = sum of C_i * dist(1,i) with one DFS. Moving the root across edge (u,v) changes it by total weight - 2 * (subtree weight of v).

03
Path Decomposition of a Tree ABC 397 E 1484
Returned state

A child hands back more than a number — here it hands back how many loose path-ends it still has. Feasibility DP rather than optimisation.

Nudge

Any vertex with three or more children still needing to extend a path is immediately impossible. Track the count of dangling ends and close them greedily as you unwind.

04
Red and Blue Tree ABC 222 E 1491
Edge weights to knapsack

Reducing a tree problem to a sequence problem. Half the difficulty of tree DP is spotting when the tree stops mattering.

Nudge

Walk the given route once and count how many times each edge is traversed. What remains is a subset-sum over those counts hitting a fixed target.

05
Alkane ABC 394 F 1549
Best-k children

Merging children is not always a knapsack — often you just sort their values and take the top few. Learn to recognise that shape.

Nudge

Every internal vertex needs exactly four incident edges, so dp[v] keeps the best chain downward and you sum the three largest positive child contributions.

Core patterns

1819 – 2055

The workhorses: counting with subtree sizes, rerooting a non-trivial state, and the tree knapsack. Almost every harder problem is one of these wearing a costume.

06
Avoid Straight Line ABC 312 G 1819
Counting by complement

Counting triples on a tree by fixing the meeting vertex — and by counting the bad cases instead of the good ones.

Nudge

Total triples minus the collinear ones. For each vertex, the paths through it split the rest of the tree into its child subtrees plus everything above it.

07
Expensive Expense ABC 222 F 1934
Rerooting · max

The same rerooting machinery, but max instead of sum — so you need the best and second-best child in order to exclude the one you came from.

Nudge

Keep the top two downward values at each vertex; when descending into child c, pass down the best value that is not c's own.

08
Select Edges ABC 259 F 1961
dp[v][0/1] + greedy merge

Two states per vertex — edge to parent used or not — with a degree cap that turns the merge into a sort-and-take.

Nudge

dp[v][0/1] = best weight in v's subtree. For each child, taking its edge gains w + dp[c][0] - dp[c][1]; keep the positive gains, sort, take as many as the degree limit allows.

09
Components ABC 287 F 2034
Tree knapsack

The O(n^2) subtree knapsack, and the amortisation argument that proves it is quadratic and not cubic. Non-negotiable to know.

Nudge

dp[v][k][0/1] = ways to get k components in v's subtree, with v chosen or not. Merge children one at a time, looping only up to the sizes already accumulated.

10
As far as possible ABC 369 G 2055
Long-path decomposition

Decompose the tree into vertex-disjoint downward chains; answering for every K at once falls out of sorting the chain lengths.

Nudge

Each vertex keeps its deepest downward path and the leftover branches become separate chains. Sort all chain lengths descending — the answer for K is a prefix sum.

An outer loop around the DP

2217 – 2437

The DP is no longer the whole solution. Here it sits inside a binary search, a game-theoretic argument, a rerooting of a two-state DP, or a compressed tree.

11
Game on Tree 2 ABC 218 G 2217
Minimax on tree

Game DP where the optimising player alternates by depth, plus maintaining a running median down the DFS path.

Nudge

Leaves are terminal; internal vertices take max or min of their children by parity. Keep the median of the root-to-current path with two heaps, pushing on entry and popping on exit.

12
Game on Tree 3 ABC 246 G 2313
Binary search + tree DP

Parametric search: guess the answer X, rewrite the problem as a boolean, and let a much simpler DP decide it.

Nudge

Fix X and mark vertices with value >= X as dangerous. dp[v] = how many dangerous vertices in v's subtree cannot be erased in time; monotone in X, so binary search.

13
Vertex Deletion ABC 223 G 2351
Rerooting a matching DP

Rerooting where the state is itself a DP (maximum matching), not just a number. The real test of whether you understand rerooting.

Nudge

dp[v][0/1] = matching size in v's subtree with v unmatched / matched. A vertex is removable iff the whole tree keeps the same maximum matching without it — reroot to test all n at once.

14
Tree Patrolling ABC 207 F 2398
Three-state counting

The classic dominating-set state set — chosen / covered by a child / not yet covered — used for counting rather than minimising.

Nudge

dp[v][0] = v not covered, [1] = v covered by a child's guard, [2] = guard on v. Merge children as a convolution over the number of covered vertices.

15
Leaf Color ABC 340 G 2401
Auxiliary (virtual) tree

When a DP has to run once per colour, build the compressed tree over just that colour's vertices. Total size stays O(n log n).

Nudge

Sort a colour's vertices by DFS order, add pairwise LCAs, rebuild the edges with a stack. Then count connected subtrees whose leaf set is exactly that colour.

16
Zigzag Tree ARC 130 D 2437
Prefix-sum optimised merge

A naive child merge is quadratic per vertex here. Rewriting it as cumulative sums is the standard rescue for rank-indexed tree DP.

Nudge

dp[v][i] = ways in which v is the i-th smallest among v and its used children. Merging with binomials plus prefix sums keeps the whole thing quadratic overall.

Advanced machinery

2455 – 2920

Named techniques worth reusing for years: Steiner trees, inclusion–exclusion over a knapsack, multi-dimensional traversal states, and a DP that has to survive updates.

17
Last Major City ABC 364 G 2455
Steiner tree DP

Bitmask over terminals times vertices, with the two transitions — subset split and edge relax — that define the Steiner tree DP.

Nudge

dp[S][v] = cheapest tree connecting terminal set S and containing v. Split S into two halves at v, then relax over edges with Dijkstra for each fixed S.

18
Directed Tree ARC 121 E 2645
Knapsack + inclusion–exclusion

Counting permutations with forbidden positions: count arrangements with at least k bad pairs via a tree knapsack, then alternate signs.

Nudge

f[k] = ways to choose k disjoint ancestor–descendant pairs, which is a subtree knapsack. The answer is the alternating sum of f[k] * (n-k)!.

19
Portable Gate ARC 179 D 2717
Return-or-not states

Traversal DP where the state carries both a budget and whether you come back to the vertex. The dimension people forget to add.

Nudge

dp[v][k][0/1] over v's subtree, k = gate uses, last flag = whether the walk returns to v. Merge children like a knapsack, allowing exactly one non-returning branch.

20
Hash on Tree ABC 351 G 2920
Dynamic tree DP

The DP has to survive point updates. Express each vertex's transition as an affine map and hang it off a heavy-light decomposition.

Nudge

dp[v] = A[v] + X[v] * (product of dp over children). Linearise along heavy paths, keep the light-child products aside, and put a segment tree of composed affine maps on each path.
